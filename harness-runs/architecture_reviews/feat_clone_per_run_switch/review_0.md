Violates `.claude/context/cli.md` → `## How a module in this layer is written` (**One string, one producer** and its "single declarations … read rather than copied") and → `## What "done" means here` (*"A reviewer holds a change to its module's own header. That is a second shell copy of `cli/src/generators/writeProtection.ts` → `fileToolDenyRules` (the `file` / `directory` / `entry` → rule-shape map, including the four-rule `entry` form). `run_profile_entries` also refuses *"any character the generator refuses in an entry (`cli/src/generators/profileEntries.ts` → `assertUsableInEntry`)"*, which is a shell copy of that module's `FORBIDDEN_IN_ENTRY` / `FORBIDDEN_IN_COMMAND` set. The plan declares only two mirrors and tests only those two: Task 5 declares `COPY_GIT_PATHS` and `SANDBOX_OPT_OUT_MARKER`, and Task 14's **The mirrors.** step holds only those two equal. `writeProtection.ts`'s module header says *"A mirror this header does not declare is a defect"*, and the plan leaves that header stating a rule its own change breaks. If the TypeScript kind map changes, the per-run copy's `permissions.deny` silently stops matching what `doctor` grades, and no test notices.
   **Fix:**
   - `task_5_plan.md`, the module-header bullet under **The two projections and the new exports.**: declare the watcher's copy of `fileToolDenyRules`'s kind → rule map as a third mirror, beside `COPY_GIT_PATHS`, held equal by `cli/test/watcher-run-profile.test.mjs`.
   - For the entry screen, pick one of two fixes. Either drop the *"any character the generator refuses"* clause from `task_13_plan.md` → `run_profile_entries`, and keep only the watcher's own stated refusals (a quote and a `*`) as its own rule, not a copy. Or add `cli/src/generators/profileEntries.ts` (header only) to Task 5's targets and declare that mirror there.
   - `task_14_plan.md` → **The mirrors.**: add a case that drives `run_profile_render` with one entry of each kind and asserts the rules equal `fileToolDenyRules({ path, kind })` imported from `cli/dist`. If the entry-screen mirror is kept, add a case asserting the watcher refuses every needle of the imported set.

Violates `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` → the persisted-key bullet (*"a new persisted artifact joins the module that owns it rather than being named at its use site"*), and → `## What accompanies a new unit of each kind`, row *A persisted machine-state key* (*"Its constant in the module that owns that artifact"*).
   Task 13's `run_profile_render` builds `$(hr_lane_dir)/run-profiles/$HARNESS_REPO_SLUG/<hr_sanitize_branch branch>.json` inline in `autonomous-watcher.sh`. Every artifact path under the lane directory is owned by `cli/templates/scripts/lib/harness-run-lib.sh`, beside `hr_lane_dir`. It builds `hr_lane_state_file` and its sibling there, and its own comment reads *"The two artifact paths, so no caller re-joins either string."* The new `run-profiles/` artifact is a third persisted machine-state path, and the plan names it only at its use site. Tasks 21–24 then document a path that no single function owns. Task 1 states that it is *"the only one that edits the library"*, so Task 13 cannot place the path there itself.
   **Fix:**
   - `task_1_plan.md`: add a **Work** bullet defining `hr_run_profile_file <repo slug> <branch>` (or a similarly named helper) in the library's lane-directory section, beside `hr_lane_state_file`. It prints `<lane dir>/run-profiles/<slug>/<sanitized branch>.json` and returns `1` when `hr_lane_dir` cannot anchor. Its comment names the watcher as its caller.
   - `task_13_plan.md` → `run_profile_render`: get the path from that helper rather than joining it, and list the helper under **Depends on:** Task 1.
   - `task_14_plan.md`: assert the stub's `--settings` argument equals what the helper prints for the fixture's slug and branch.

## Should Fix

1. **`cleanup-merged-worktrees.sh` reads a per-branch registry field with raw `jq` when the library already has the reader for it** — `task_9_plan.md`, first **Work** bullet (*"read its registry record's `worktree` and `copy_kind` with `jq` over the file, never creating it"*). `cli/templates/scripts/lib/harness-run-lib.sh` → `hr_registry_peek <file> <branch> <key>` exists for exactly this: it reads one record field without creating the file, taking a lock or initialising. Task 1 and Task 13's copy-kind read use it too. A third, hand-written read is a second home for one responsibility (`.claude/context/conventions.md` → `### Where a new responsibility goes`, *"Before adding a copy of anything, grep for it"*). **Fix:** read `worktree` and `copy_kind` with `hr_registry_peek`. Keep the script's existing enumeration `jq`, which `hr_registry_peek` does not cover, and keep the fail-closed refusal for an unreadable registry.

2. **The plugin command restates the one-live-copy rule without naming where the rule is owned** — `task_20_plan.md`. Restating it in the command's own words is right, because the plugin cannot execute `cli/` code (`.claude/context/conventions.md` → `## The layers`). But `.claude/context/plugin.md` → `## Citation` asks that anything outside the plugin be cited by its repo-relative path plus a symbol anchor. Without that citation, a later change to `hr_run_copy_live_var` has no grep path back to check (b). **Fix:** in the rewritten check (b), add one prose citation, `cli/templates/scripts/lib/harness-run-lib.sh` → `hr_run_copy_live_var`, naming it as the rule the three conditions restate.
