## Must Fix

1. **The mention agent has been placed where the `plugin` layer puts flow-dispatched sub-agents, but no plugin instruction or command dispatches it. The plan breaks that rule knowingly and raises only a `stale-rule` note.** Offending files:
   - `task_7_plan.md`: the whole task, i.e. **Goal**, `## Invocation contract` (*"This agent's dispatcher is a shipped script, not a plugin instruction or command … nothing inside `plugin/` dispatches this agent"*), and the `README.txt` roster edit (*"the one agent a shipped script, not a flow, runs … as the main agent of a one-shot read-only session"*).
   - `task_2_plan.md`: **The session**, `--plugin-dir … --agent "$MENTION_AGENT"`.
   - The story index `<branch>_story_plan.md`: `## Context`, *Where the agent lives, and how the control job reaches it*, plus scope-register rows 46 and 48.
   - Tasks 1 and 5 depend on the same placement through `MENTION_AGENT` / `MENTION_AGENT_NAME` and the plugin check for `agents/mention-reader.md`.

   Rule sources:
   - `.claude/context/plugin.md` → `## Where a new asset goes`. An agent definition is *"a role the flow dispatches as a sub-agent → `plugin/agents/<name>.md`"*. What a script outside the flow invokes is *"a slash command a user or the watcher invokes → `plugin/commands/<slash-command-name>.md`"*. `mention-reader` matches neither row. The flow never dispatches it, and the plan says outright that it runs as a session's main agent, launched from a shipped script.
   - `.claude/context/conventions.md` → `## What accompanies a new unit of each kind`, the agent-definition row: *"Frontmatter …; **the instruction or command that dispatches it**; and `${CLAUDE_PLUGIN_ROOT}`-rooted citations that resolve."* The same document's `### The order files are created…` point 3 says: *"A plugin contract — the asset itself with valid frontmatter, then the instruction or command that dispatches it."* The plan names no such instruction or command. Register row 48 admits the gap.

   Register row 48 says the agent-definition row *"does not name a shipped script as a dispatcher"*, and so treats the rule as silent on this case. The rule is not silent. It names the dispatcher kinds an agent definition must land with, and a shipped script is not one of them. The plan cites `autonomous-watcher.sh` as precedent, but that precedent is a script invoking plugin **commands**. That is exactly the case `plugin.md`'s placement table routes to `plugin/commands/`. No existing file in `cli/templates/`, `cli/src/` or `scripts/` passes `--agent` to `claude` (a `grep -rn -e "--agent"` over those trees finds nothing). Running a plugin agent definition directly from a shipped script is therefore a new class of dispatch, not the established one. As iteration 0 already recorded, a `stale-rule` entry is a recommendation for supervised follow-up and does not license an implementing run to break the rule it names in the meantime.

   **Fix:** Re-plan the asset's kind or its dispatcher. Do not keep the current shape with only the row-48 `stale-rule` note. Take one of these routes:
   - **(a) Make the asset a kind the placement table gives to a script-invoked role.** Make the mention reader a plugin **command**, `plugin/commands/<harness-…>.md`, carrying the slash-command name verbatim (`.claude/CLAUDE.md` → `## File naming conventions`). The script invokes it as `claude -p "/autonomous-sdlc-harness:<name>"`, the way `autonomous-watcher.sh` invokes the plugin's commands. Give it everything `.claude/context/plugin.md` → `## What accompanies a new unit of each kind` requires of a slash command: `description:`, an `argument-hint:` only if it takes one, `## Resolved values`, `## Steps`, and the instruction file it loads. A command declares no `tools:` (`.claude/context/plugin.md` → `## Frontmatter`), so state in the plan that the read-only closure then rests on the session's `--tools Read,Grep,Glob --restricted`, which Task 2 already passes. Drop `--disable-slash-commands` from Task 2's argv. Re-point Task 1's `MENTION_AGENT*` names, Task 2's and Task 5's `agents/mention-reader.md` presence check, Task 7's targets and README roster edit, and Tasks 8–10's prose at the command.
   - **(b) If the writer holds that the definition must stay an agent run directly by the script, do not schedule it on a `stale-rule` note.** Raise it in the plan's `## Questions` to the maintainer: may a shipped script run a `plugin/agents/` definition as a session's main agent, with no plugin instruction or command dispatching it? Cite both rules above and the evidence on each side: the watcher's command precedent, and the absence of any `--agent` dispatch today. Leave Task 7, and the parts of Tasks 1, 2 and 5 that name `agents/mention-reader.md`, unscheduled until the question is answered. Remove register row 48's `stale-rule` premise either way.
