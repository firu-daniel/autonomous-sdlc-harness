1. **`heartbeat_age` adds a second portable-mtime reader beside the one the sourced library already owns** — `task_1_plan.md` (the **Constants, the seam, and the mtime read.** bullet, and the `stat -c %Y|stat -f %m` **Verification:** bullet). Rule: `.claude/context/conventions.md` → `### Where a new responsibility goes`: *"A responsibility that already has a home does not get a second one"* and *"Before adding a copy of anything, grep for it."*, with `cli/src/core/repoPaths.ts` given as the cost of drifted copies.
   `cli/templates/scripts/run-test-suite.sh` already sources `cli/templates/scripts/lib/harness-run-lib.sh` (the `hr_lib="$script_dir/lib/harness-run-lib.sh"` / `. "$hr_lib"` lines). That library already owns the BSD/GNU mtime read: `hr_lane_mtime`, which reads a path's mtime as an epoch with `stat -f %m` and `stat -c %Y`, and accepts only an all-digit value. Its header records the hazard the plan's design depends on avoiding: *"THE FALLBACK IS CHOSEN ON THE VALUE, NOT THE EXIT STATUS: `-f` means `--file-system` to GNU `stat`"*. The plan tells Task 1 to write its own `stat -c %Y` / `stat -f %m` fallback inside `heartbeat_age`, in the reverse order, and its Verification bullet requires both `stat` spellings to sit inside `heartbeat_age`. That gives the outer-loop scripts two implementations of the same platform-dependent answer. They would differ in order and in how they fail. That is the drift the cited rule exists to prevent.
   **Fix:** In `task_1_plan.md`, have `heartbeat_age` read the mtime through `hr_lane_mtime "$running_file"` instead of calling `stat` itself. Keep `date +%s` for "now", and keep the negative-age clamp. Map `hr_lane_mtime`'s `0` result, which it prints for a missing path or an unreadable mtime, to `heartbeat_age`'s non-zero return. `run_alive`'s existing `-f` re-test then still tells "vanished, so finished" from "present but unreadable, so refuse". State in the header that the read is the library's. Leave `cli/templates/scripts/lib/harness-run-lib.sh` unedited, so Task 3's statement still holds: only `scripts/run-test-suite.sh` differs from its template. Replace the `grep -nE 'stat -c %Y|stat -f %m'` Verification bullet with two checks: `grep -n 'stat ' cli/templates/scripts/run-test-suite.sh` hits only comment lines, and `grep -n 'hr_lane_mtime' cli/templates/scripts/run-test-suite.sh` hits `heartbeat_age`. In `task_2_plan.md`'s header bullet and `task_4_plan.md`'s **Depends on:** paragraph, describe the read as `hr_lane_mtime`'s rather than as a GNU-first order the script chooses.
