## Must Fix
1. **The profile's untrack route gets a second, divergent producer in `generators/`**. Offending file: `task_3_plan.md`, the `writePermissionProfile` Work bullet (*"a copy an earlier release committed stays tracked until it is untracked with `git rm --cached .claude/settings.autonomous.json` and committed"*). Rule violated: `.claude/context/conventions.md` → `## Shared code, and where it lives` (*"A value or behaviour two `cli/src` areas need lives there, never duplicated into both"*) and `### Where a new responsibility goes` → *"A responsibility that already has a home does not get a second one"*.
   Task 4 defines the untrack route in `cli/src/doctor/checks.ts` → `profileUntrackRemedy` as three commands with two reasons: `git rm --cached …`, the commit, and `git push --no-verify origin <defaultBranch>`. Task 4 also argues why the commit must land on the default branch: *"an untrack pushed only to a run branch covers that one run and the next branch carries the profile again"*. Task 3 then has `cli/src/generators/permissionProfile.ts` print its own version of the same remedy in `init`'s closing note. That version already disagrees with Task 4's: it stops at "committed", names no default branch and no push, and so describes exactly the incomplete route Task 4 says fails. This is the same pattern iteration 0 found for the push: one remedy spelled independently in two `cli/src` areas and kept in step by nothing. Here the two copies already differ in the plan, before any code exists.
   **Fix:** In `task_3_plan.md`, remove the untrack commands from `writePermissionProfile`'s note. The note should say the profile is gitignored and machine-specific, and that a copy an earlier release committed stays tracked until untracked by hand. For the untrack route itself it should send the reader to `doctor`, whose `profile-tracked` check reports that state and prints the route. This is the same pointer form Task 1 already uses in the `.gitignore` template comment (*"`doctor` reports that state"*). Update Task 3's Verification to match: the note contains no `git rm --cached`. Alternatively, if the note must print the commands, `permissionProfile.ts` owns them and both sides import: `checks.ts` already imports from that module. `profileUntrackRemedy` would then build its first command from that export, and Task 5's and Task 8's/Task 9's "as `profileUntrackRemedy` prints them" references stay valid. Either way, `cli/src` must end up with one producer of the untrack route.
