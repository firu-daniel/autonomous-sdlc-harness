# Architecture review — iteration 0

## Must Fix
1. **The default-branch setup push gets three producers in two `cli/src` areas instead of one owner** — offending files: `task_4_plan.md` (`profileUntrackRemedy`), `task_11_plan.md` (`init.ts` → `reportGithubSteps` and `checks.ts` → `REMOTE_EXECUTION_CHECK`), and the story index's `## Context` bullet *"The setup push the code prints changes with the documents."* Rule violated: `.claude/context/conventions.md` → `## Shared code, and where it lives` (*"A value or behaviour two `cli/src` areas need lives there [`cli/src/core/`], never duplicated into both"*) and `### Where a new responsibility goes` → *"A responsibility that already has a home does not get a second one"* / *"Before adding a copy of anything, grep for it."*
   The plan makes `commands/` (`init.ts` → `reportGithubSteps`) and `doctor/` (`checks.ts` → `REMOTE_EXECUTION_CHECK`, and the new `checks.ts` → `profileUntrackRemedy`) each spell `git push --no-verify origin <branch>` on its own, together with the same `--no-verify` reason sentence. Task 11 also has `init.ts` and `REMOTE_EXECUTION_CHECK` each spell `gh auth refresh -s workflow` and its reason. Both are values two `cli/src` areas need. The plan keeps them in step by prose alone: *"restated byte-for-byte"*, *"the same reason Task 11 gives"*, *"Task 11's reason, stated the same way"*, and a Task 11 verification that compares them *"by reading"*. That is the drift `cli/src/core/repoPaths.ts`'s header records as the cost of a private copy per module. The plan's own second and third top risks are this drift.
   **Fix:** Give the setup push one owner in `cli/src/core/`, and have every printer import from it.
   - In `task_4_plan.md`, the first task to need the push, add a Target that creates a new `cli/src/core/` module (e.g. `cli/src/core/defaultBranchPush.ts`). Its header states what it owns in the words *"The rule this module exists to enforce"* (`.claude/context/conventions.md` → `## What accompanies a new unit of each kind`, the `cli/src/` module row). It exports a function returning `git push --no-verify origin ${branch}` and the one-sentence `--no-verify` reason. `profileUntrackRemedy` builds its third command and its reason from these exports instead of spelling them.
   - In `task_11_plan.md`, add to that module the `gh auth refresh -s workflow` command and its reason sentence. `reportGithubSteps` and `REMOTE_EXECUTION_CHECK` then import all four values rather than spelling them. Add the module to `### Targets` and to **Depends on** (Task 4). Replace the "compare by reading" verification with `grep -rn "no-verify origin" cli/src`, which should find the spelling only in the new core module.
   - Amend the story index `## Context` bullet and `task_5_plan.md`'s contract text to name the core module as the single producer that `profileUntrackRemedy` and the two Task 11 sites consume.
   - Tasks 8–10 keep restating the commands in the documents. That is the documents' job, and it is unaffected.

Do the same for the `git rm --cached` command in `task_3_plan.md`'s `writePermissionProfile` note.
