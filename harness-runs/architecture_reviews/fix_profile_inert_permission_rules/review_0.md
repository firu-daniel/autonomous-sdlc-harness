## Must Fix
1. **The watcher's new wrapper-prefix mirror is undeclared by the module that owns the wrapper rows** — `task_1_plan.md` (the mirror's creator) and `task_3_plan.md` (owner of `cli/src/generators/permissionProfile.ts`'s module header). Rules violated: `.claude/context/cli.md` → `## How a module in this layer is written` → **One string, one producer.** and `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` → *"The shared constants have owners, and a value is imported from its owner rather than retyped"*, with its persisted-key rule *"a mirror the header does not declare is a defect"*. That declaration pattern is the one `cli/src/generators/writeProtection.ts`'s header already follows for the watcher's other mirrors (*"Mirrors outside this package, each held equal by the suite named … A mirror this header does not declare is a defect."*).
   Task 1 adds `run_profile_wrapper_prefixes` to `cli/templates/scripts/autonomous-watcher.sh`. The function rebuilds, in shell, the exact spelling the generator gives the base profile's main-checkout wrapper rows: `Bash(bash <MAIN_REPO>/<scripts_dir>/`, including the generator's `join(repoRoot, scriptsDir)` collapse of a `.` scripts directory. Those rows come from `permissionProfile.ts`'s `RowTokens` / `rowValues` families and the template's `{{repoRoot}}` rows. Twinning works only if the prefix matches those rows byte for byte. The story index's first `Top risks:` entry says a mismatch "re-roots nothing and fails silently". That silent drift is exactly what **One string, one producer.** warns about. The watcher is a shell template and cannot import the generator, so the only option the conventions documents allow is a mirror that the owning module's header declares, with the suite that pins it. Neither task plans that declaration. Task 3 rewrites `permissionProfile.ts`'s header and the `RowTokens` doc comments only to say *"the run copy's exact form in the watcher's per-run copy"*. Task 1's new tests do pin the behaviour, but nothing in the owner names the mirror. A later change to the main-checkout row spelling would therefore not be told it must edit the watcher in the same change.
   **Fix:** In `task_3_plan.md`, add a sub-step to the `permissionProfile.ts` work: the module header gains a declared-mirror bullet, in the form `writeProtection.ts` uses. It names `cli/templates/scripts/autonomous-watcher.sh` → `run_profile_wrapper_prefixes` as a copy of the main-checkout wrapper-row prefix (`Bash(bash <repoRoot>/<scriptsDir>/`, with a `.` scripts directory collapsing to the root), names `cli/test/watcher-run-profile.test.mjs` as the suite that holds them equal, and states that any change to that row spelling edits the watcher in the same change. In `task_1_plan.md`, have the header comment of `run_profile_wrapper_prefixes` name that owner (`cli/src/generators/permissionProfile.ts`, the wrapper row families) and the pinning suite, matching the existing `run_profile_render` mirror comment.
