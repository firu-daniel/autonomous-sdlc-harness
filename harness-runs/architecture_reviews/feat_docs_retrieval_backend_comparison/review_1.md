# Architecture review — iteration 1

Both iteration-0 Must Fix items are resolved. Tasks 3 and 5 now take the database URL from `pythonDatabaseUrl(process.env)`, and neither imports `PYTHON_DEFAULT_DATABASE_URL` any more. The story index's first **Manual setup required** bullet now cites that function. Task 13 is in place as the `cli`-layer owner of `EMBEDDING_EXTRACT_OPTIONS`, ordered first in `## Phase 2 Readiness — Ordered Fix List` with `_(layer: cli)_`. Task 7 imports that constant and spells no pooling or normalisation of its own.

## Must Fix

1. **Task 6 reads the Python vectors from the compose database regardless of the database the index was written to** — offending file: `task_6_plan.md` (Work → **Python vectors.**). Rule source: `.claude/context/conventions.md` → `### Where a new responsibility goes`: *"A responsibility that already has a home does not get a second one"* and *"Before adding a copy of anything, grep for it."*
   The plan makes `cli/src/retrieval/pythonBackend.ts` → `pythonDatabaseUrl` *"the one place the default is decided, for the launcher, `doctor` and this eval alike"* (story index → **Manual setup required**). Tasks 3 and 5 follow that. Task 6 does not. Its write and its read go to two separately decided databases:
   - `indexPythonCorpus` writes the vectors to `pythonDatabaseUrl(process.env)`. That is the variable's value when `HARNESS_DOCS_RETRIEVAL_DATABASE_URL` is set, and the compose default only otherwise.
   - The read is a fixed `docker compose exec -T postgres psql -U harness -d docs_retrieval …`. It always reaches the compose container, with its user and database retyped from `compose.yaml`.

   So which database holds the Python index is decided a second time, inside the eval, and differently from its owner. With the variable set to any other database, the measurement reads a different index from the one just built, possibly a stale one. The cosine summary that the embedder-id decision rests on would then be computed over the wrong vectors, and nothing would refuse. The literals `harness` / `docs_retrieval` are also a second copy of what `PYTHON_DEFAULT_DATABASE_URL` already encodes.
   **Fix:** In `task_6_plan.md` → **Python vectors.**, have the module compute `pythonDatabaseUrl(process.env)` (imported from `cli/dist/retrieval/pythonBackend.js`). Before anything is indexed, refuse by name, without printing the URL, unless that value equals `PYTHON_DEFAULT_DATABASE_URL`. The `docker compose exec … psql` route can reach only the compose database, and the refusal says so. Take the `psql` user and database name from `new URL(PYTHON_DEFAULT_DATABASE_URL)` (its `username` and its `pathname` without the leading `/`) rather than retyping `harness` / `docs_retrieval`. Keep the compose service name `postgres` as the one literal whose owner (`compose.yaml`) the header names. Add a verification bullet: with `HARNESS_DOCS_RETRIEVAL_DATABASE_URL` exported to a non-default value for one probe run, the measurement refuses by name before indexing, and the output contains no `postgresql://` string.

## Should Fix

1. **The wrapper's not-provisioned exit status is still a bare `3`** — `task_3_plan.md` → **Header and preconditions.** (*"the wrapper exiting `3`"*). This carries over unaddressed from iteration 0, and the index has no `## Rejected findings` entry for it. The same bullet requires that *"the names the CLI does not own are spelled once, as module constants, and the header names each one's owner"*. Add the status to that list as a module constant whose header line names `scripts/python-service.sh` as its owner. Do not reuse `PYTHON_BACKEND_UNAVAILABLE_EXIT`: that constant is the launcher's exit code, a different contract that only shares the value.
2. **Task 7's arranged-leg id retypes the embedder id template** — `task_7_plan.md` → **Pairs, summaries, render.** (*"`id: '<EMBEDDING_MODEL>:fp32:cls:384'`"*). The `cls` and `384` segments are a second spelling of what `cli/src/retrieval/models.ts` produces in the embedder's `id:` template, from the pooling and `EMBEDDING_DIMENSIONS`. Task 7 itself requires that *"Pooling and normalisation are never spelled in this module"*, and its grep does not catch this one (`.claude/context/cli.md` → *"One string, one producer"*). Either label the leg without restating the template, for example `` `${EMBEDDING_MODEL}` at dtype fp32, extraction options as `EMBEDDING_EXTRACT_OPTIONS` ``, or build the dimension segment from the imported `EMBEDDING_DIMENSIONS` and drop the literal `cls`.
3. **Task 6's SQL names have an owner the header does not cite** — `task_6_plan.md` → **Header.** / **Python vectors.**. The table and key names `chunks`, `meta`, `key`, `text`, `embedding` and the `embedder` meta key are owned by `docs-retrieval-service/src/harness_docs_retrieval/store.py` (`CHUNKS_TABLE`, `EMBEDDER_META_KEY`, the `create_chunks` / `create_meta` statements). Spell them once as module constants, and have the header name `store.py` as their owner. This is the same treatment Task 3 gives `http_app.py`'s and `cli.py`'s names.
4. **Task 5's `postgresMemory` has the same database mismatch as Must Fix 1** — `task_5_plan.md` → **Memory, then teardown.**. The figure always comes from the compose container, even when `pythonDatabaseUrl(process.env)` points elsewhere. Set `postgresMemory` to `null`, with a stated reason, unless that value equals `PYTHON_DEFAULT_DATABASE_URL`. That way the footprint never attributes another database's memory to the compose container.
