# Architecture review — iteration 0

## Must Fix

1. **Task 1 cites `### The order files are created…` item 1 for the model-before-schema order, and that item says the reverse** — offending file: `task_1_plan.md` (the `**Goal:**` paragraph). Rule source: `.claude/context/conventions.md` → `## The layers` → `### The order files are created, so a half-built feature is still coherent`, item 1 (*"`schemas/harness.config.schema.json`, then `cli/src/config/model.ts`, then `cli/src/config/check.ts`, then `docs/config.md` §5"*), and `.claude/context/cli.md` → `## What this layer owns, and what it is not` (*"A new `harness.config.json` shape starts in `schemas/`… the model, the check and the generator here are downstream of it"*).
   Task 1 says the model and check land first, with the schema property following in Task 8 and the `docs/config.md` row in Task 11, and calls that *"the order this project's precedent ships a key in (`.claude/context/conventions.md` → `### The order files are created…`, item 1, and `feat_docs_catalog_retrieval`'s Tasks 1 and 18)"*. Item 1 puts the schema **first**. The precedent is real (`feat_docs_catalog_retrieval`'s story index has Task 1 `cli` and Task 18 `general`), but a precedent is not a rule. What actually allows this order is the task-plan writer's harness doctrine, which ships the catch-all `general` layer, and so the schema, last (`plugin/agents/task-plan-writer.md` → the `## Phase 2 Readiness — Ordered Fix List` bullet, *"bottom-up ship order… with the catch-all layer… last"*). As written, the plan tells the implementer that the conventions document endorses an order it forbids. It also hides the window this order opens. Between Task 1's commit and Task 8's, `config set docs.retrievalBackend python` (which Task 1's own test exercises) writes a `docs` object that `check.ts` accepts and the schema rejects, because `properties.docs` is `"additionalProperties": false`. Item 1's own header warns about exactly that case: *"a key in the model that is not in the schema is a key no configuration may legally carry"*.
   **Fix:** In `task_1_plan.md` → `**Goal:**`, stop citing item 1 as the authority for this order. State that item 1 orders the schema first, and that this plan departs from it because the task-plan writer's catch-all-last ship order puts the `general`-layer schema edit (Task 8) after the `cli` tasks. Keep `feat_docs_catalog_retrieval`'s Tasks 1 and 18 only as the record of the same departure, not as its licence. Add one sentence naming the transient window: until Task 8 lands, a configuration carrying `docs.retrievalBackend` passes `check.ts` and fails `npm run validate:config`-style schema validation. Mirror the corrected sentence in the story index's `## Context` (the **Layers.** paragraph), which currently presents the `cli`-then-`general` order without noting the schema-first rule it departs from.

2. **Task 8's Verification asks for runs of gates 3a and 3b and for `validate:config:example`, which are gate commands and run fixtures the unit neither creates nor edits** — offending file: `task_8_plan.md` (`**Verification:**`, first and second bullets). Rule source: `plugin/instructions/unit_loop_core.md` → `## The test-run rule`, points 1 and 4.
   `npm run validate:config` is `scripts/run-gates.sh`'s gate `3a example validates`, and `npm run validate:config:negative` is its gate `3b negative fixtures are refused`. The negative chain runs `ajv test … --invalid` over eight pre-existing fixtures under `schemas/negative/` that this unit does not create or edit, and `validate:config:example` validates `examples/notes-app/harness.config.json`. Point 1 bars a unit from running a gate or a test file it did not create or edit. Point 4 bars a plan from asking for one, and the full suite runs once, in Phase G.
   **Fix:** In `task_8_plan.md` → `**Verification:**`, replace the first two bullets with a run of the one fixture this unit creates: `ajv test -s schemas/harness.config.schema.json -d schemas/negative/docs-retrieval-backend-unknown.json --invalid` exits 0, with the document rejected. Add a statement that the edited `validate:config:negative` chain, `validate:config` and `validate:config:example` are graded by Phase G's gates 3a and 3b, not by the unit. Keep the side-by-side read of the enum and default against `cli/src/config/model.ts`.
