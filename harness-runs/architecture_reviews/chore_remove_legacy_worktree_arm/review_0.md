## Should Fix

1. **The "a linked worktree is not a run copy" decision is written three times instead of being owned once by the run library**: `task_11_plan.md` and `task_12_plan.md`, measured against `task_1_plan.md`. Rule source: `.claude/context/conventions.md` → `### Where a new responsibility goes` (*"A responsibility that already has a home does not get a second one"*, *"Before adding a copy of anything, grep for it"*), together with the header of `cli/templates/scripts/lib/harness-run-lib.sh`, which describes that library as the place that derives what *"the scripts would otherwise each re-derive slightly differently"*.
   Task 1 puts the new rule in `hr_run_copy_check_var`: after `hr_wrapper_target_check_var`, a `worktree` kind is refused, because a run copy is a clone. Task 11 then adds a second copy of that kind test inline in `launch-sandboxed-gates.sh` check 6, and Task 12 adds a third inline in `setup-worktree.sh`'s `--target` placement block. Each copy has its own refusal sentence. The story's stated reason for not routing those two scripts through `hr_run_copy_check_var` is that they do not need its registry and tip reads. That reason argues against reusing that whole check, but it does not argue for three copies of the kind predicate. The three refusal texts can drift apart, and a later change to what counts as a run copy, such as a new copy kind, has to find all three by hand.
   **Fix:** In `task_1_plan.md`, add one small library function to `cli/templates/scripts/lib/harness-run-lib.sh`, for example `hr_run_target_check_var <main> <dir>`. It calls `hr_wrapper_target_check_var` and then refuses `HR_TARGET_KIND=worktree`, setting a single `HR_TARGET_REFUSAL` sentence (*"'<top>' is a linked worktree of <main>, and a run copy is a clone the run registry records"*). It reads no registry and no tip. `hr_run_copy_check_var` then calls it in place of its own new kind test. In `task_11_plan.md` and `task_12_plan.md`, replace the inline `HR_TARGET_KIND = worktree` refusal with a call to that function, keeping each script's own exit route (`refuse` / exit 2 in the launcher; the ` — refusing to bootstrap` tail and exit 1 in `setup-worktree.sh`). Then update Task 8's restatement of the refusal text to match. If the writer keeps the three copies, record that decision and its reason under `## Rejected findings` in the story index.
