Rules violated: `.claude/context/conventions.md` → `## Configuration is the source of truth…` → *"The shared constants have owners, and a value is imported from its owner rather than retyped"*; `### Where a new responsibility goes` → *"A responsibility that already has a home does not get a second one"* and *"Before adding a copy of anything, grep for it"*; `## Registries and dispatch tables` (a single source with no second list beside it).
   The plan has `readPerQuery` find *"the block between `<!-- eval:corpus:<id>:start -->` and its end marker"* and parse its fenced `json` by itself. That marker spelling and the block layout are owned by `evals/docs-retrieval/results.mjs` (`corpusStart` / `corpusEnd`, and `renderCorpusBlock`, whose header says both halves are rendered from one object). As planned, `calibrate.mjs` would be a second spelling of the per-corpus marker and a second parser of the block, so a change to the format in `results.mjs` would fail silently in the calibration. The planned signature also defaults `mode = 'fused-rerank'`. That is a mode string retyped outside the arm table, which `evals/docs-retrieval/arms.mjs`'s header forbids (*"no mode string and no arm letter is retyped anywhere else"*), with `cli/src/retrieval/search.ts` → `SEARCH_MODES` as the one source.
   **Fix:** In `task_6_plan.md`, add `evals/docs-retrieval/results.mjs` to `### Targets`. Plan one exported reader there, beside `rewriteGeneratedRegion`, e.g. `readCorpusMachineHalf(text, corpusId)`. It uses the module's own `corpusStart` / `corpusEnd`, parses the fenced `json` block, and refuses by name when the block is missing. Have `calibrate.mjs` → `readPerQuery` import and call that reader, and keep only its own job: pick the arm and check that `bestRerankScore` is present. Remove the `'fused-rerank'` default so the committed module carries no mode literal. Make `mode` a required argument, check it against `SEARCH_MODES` imported from `cli/dist/retrieval/search.js`, and refuse an unknown value by name. The scratch launchers in Tasks 22 and 23 then pass it. Update the interface block that Tasks 22 and 23 quote (`readPerQuery(resultsText, corpusId, mode)`) so it matches.
