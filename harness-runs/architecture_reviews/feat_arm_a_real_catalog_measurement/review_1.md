## Must Fix

1. **`negativeKind`'s closed value set is declared once in `queries.mjs` but planned to be retyped as `'near'` / `'far'` literals in `calibrate.mjs` and `spread.mjs`**. Offending files: `task_4_plan.md` (first **Work** bullet: *"declare each legal-value list once as a module constant"*, with no export), `task_6_plan.md` (`calibrateThreshold`: `N` = the `near` negatives, `points[].kind: 'positive' | 'far' | 'near' | 'unclassed'`), and `task_11_plan.md` (`breakdown` → `negatives: { far, near, unclassed }`, *"the `far` / `near` / `unclassed` split reads `negativeKind`"*). Rule violated: `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` → *"The shared constants have owners, and a value is imported from its owner rather than retyped"*, and `### Where a new responsibility goes` → *"Before adding a copy of anything, grep for it"*. This is the same rule iteration 0 applied to the grade `3` and to the mode strings.
   Task 4 makes `queries.mjs` the owner of the `far` / `near` set: it is the loader that refuses any other value by name. Task 4 does not plan an export, though. So `calibrate.mjs` has to spell `'near'` itself to build `N`, which is the one class the overlapping case reads. `spread.mjs` has to spell `'far'` and `'near'` itself to split `answeredNone`. That puts three copies of one closed set in the eval, and only one of them is validated. If a value is renamed or added in `queries.mjs`, the loader accepts it while `calibrateThreshold` silently counts those negatives as `unclassed`, outside `N`. That moves the calibrated value with no error. Task 6's own no-literal grep (`'(lexical|vector|fused|fused-rerank)'|eval:corpus:|grade …`) does not look for these strings, so its verification would not catch this.
   **Fix:** In `task_4_plan.md`, make `queries.mjs` export the `negativeKind` set. For example, export a frozen `NEGATIVE_KINDS` object (`{ far: 'far', near: 'near' }`) and derive the legal-value list the loader refuses against from it, so the set has one declaration. Add that export to the record-contract list Tasks 6 and 11 consume. In `task_6_plan.md`, have `calibrate.mjs` import it from `./queries.mjs` for the `N` membership test and for the `far` / `near` members of `points[].kind`. Extend the no-literal grep in **Verification** with `'(far|near)'`. In `task_11_plan.md`, have `spread.mjs` import it from `../queries.mjs` for the `far` / `near` split and key `negatives` from it. Add the same grep over `evals/docs-retrieval/arm-a/spread.mjs` to its **Verification**.
