# Architecture review — iteration 0

Reviewed: `harness-runs/story_plans/fix_watcher_multi_question_resume_loop_story_plan.md` (`## Context`, readiness list, `## Scope register`) and `task_1_plan.md` through `task_13_plan.md`, against `.claude/context/conventions.md`, `.claude/context/cli.md`, `.claude/context/plugin.md` and `harness-runs/lessons.md`.

Most of the layering holds. Every target sits under the `layers[].path` its `_(layer: …)_` tag names. The coupling runs the permitted way: the watcher and registry live in `cli/templates/`, the plugin commands read that status, and the plugin forks match the prompt text the watcher writes. The new test helper and suites are named and placed as `.claude/CLAUDE.md` → `## File naming conventions` requires, and build on `cli/test/helpers/fixture.mjs` instead of copying it. The catch-all `general` task only copies files and ships last. Two placement problems remain. Both put a run-specific fact into a file that ships to adopters.

## Must Fix

1. **Task 7 writes this repository's branch name and defect history into a shipped plugin contract** — offending file: `task_7_plan.md` (Work bullet 2, the **Why one file per park** bullet). Rules violated: `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` (*"No branch name, no directory name and no command name from any one adopter appears as a literal in `plugin/`"*), and `.claude/context/conventions.md` → `### Where a new responsibility goes` (*"a measured fact or a decision of record → `docs/`, and nowhere else"*). `.claude/context/plugin.md` → `## What this layer is` repeats the first rule for this layer.
   The planned bullet ends *"one file per question let a watcher consume part of a park and resume again for pairs already read, which is the defect `fix_watcher_multi_question_resume_loop` fixed."* This repository has adopted its own harness, so that branch name is an adopter's branch. It would be the only branch literal in `plugin/instructions/` (a grep of `plugin/` outside `samples/` finds none today). The sentence is also a decision of record, a dated history of which branch fixed what, placed in an agent contract. Every adopting repository would load it, and in those repositories the branch does not exist.
   **Fix:** In `task_7_plan.md`, keep the **Why one file per park** bullet to the contract reason alone: every site that writes a question does so at the moment it parks and then ends the session, so a park's questions are known together, and one file per question lets a watcher consume part of a park. Remove the branch name and the "the defect … fixed" clause. Move the history (the observed `feat_docs_catalog_retrieval` sequence and the branch that fixed it) into `task_12_plan.md` → the `docs/watcher.md` §4 work, which already records the measured basis. If the plugin section needs to point there, cite it in prose the way Task 7 already cites `docs/watcher.md` §4.

2. **Task 2 puts this repository's measured watcher-log timings into the adopter template's tunables comment** — offending files: `task_2_plan.md` (Work bullet 1, the comment on `PARK_LOOP_MAX_CYCLES` / `PARK_LOOP_WINDOW_SECS`) and `task_5_plan.md` (Work bullet 1, the header that quotes *"from Task 2's tunable comment"*). Rules violated: `.claude/context/conventions.md` → `### Where a new responsibility goes` (*"a measured fact or a decision of record → `docs/`, and nowhere else"*), and `.claude/context/cli.md` → `## What this layer owns, and what it is not` (*"`cli/templates` … change what a *future adopter* receives"*).
   Task 2 has the comment in `cli/templates/scripts/autonomous-watcher.sh` state *"real park-resumed sessions ran 50m04s, 38m28s and 3h01m56s and the two spurious ones 41s and 39s (this repository's watcher log, 2026-09-17)"*. That template is copied byte for byte into every adopting repository, where "this repository's watcher log" names a log that does not exist. A dated measurement is a fact of record, and `docs/` owns those. Task 12 already writes the same measurement into `docs/watcher.md` §4, so the template comment would be a second, drifting copy. Task 5 then copies the fact again into a test header and names the template comment as its source.
   **Fix:** In `task_2_plan.md`, the tunables comment says what each knob does, what `0` does, and that the defaults are sized from measured sessions. It points to `docs/watcher.md` §4 (**A resume that makes no progress is bounded.**) for the numbers and does not repeat them. `task_12_plan.md` stays the only place the timings are written. In `task_5_plan.md`, the suite header cites `docs/watcher.md` §4 as the source of the measured basis rather than *"Task 2's tunable comment"*.
