# Architecture review — iteration 0

## Must Fix

1. **The layer-reviewer's new registration trigger demands a cross-layer edit inside a single-layer unit** — `task_5_plan.md`, the `layer-reviewer.md` → **Testing** bullet (and the matching `branch-reviewer.md` bullet, which copies its wording "in the same diff"). Rule sources: `.claude/context/conventions.md` → `## The layers` (*"A change whose files sit under `cli/` or `plugin/` belongs to that layer and never to `general`"*; `harness.config.json` at the root is `general`'s) and `plugin/agents/task-plan-writer.md` → `## Process` step 7 layer-tag rule (*"the task's `**Work:**` bullets all sit within that layer's `layers[].path`. A capability spanning layers is split into one task per layer … with the catch-all layer … last"*).
   A tree-reading test lives under `cli/test/`, so the unit that adds it is a `cli`-layer unit. The `treeGuards` entry that registers it lives in the root `harness.config.json`, which is the `general` layer's and which a `cli` unit may not edit; the plan writer must put that edit in a separate, later `general` task. `plugin/agents/layer-reviewer.md` → `## Process` step 2 grades only the unit's own uncommitted set (`git status --short` / `git diff HEAD`). The trigger Task 5 writes, *"with no `treeGuards` entry for it in `harness.config.json` in the same diff (**Must Fix**)"*, can therefore never be satisfied by a correctly layered `cli` unit. It fails every legal plan and pushes implementers to edit outside their layer. This branch shows the case itself: Task 8 (`general`) seeds the entries for tests that are `cli` files.
   **Fix:** In `task_5_plan.md`, rescope the registration check to the levels that can see both layers. (a) **branch-reviewer**: grade "a test the branch adds that reads a tree of repository files as text, with no `treeGuards` entry for it in `harness.config.json` anywhere in the branch diff", citing point 7. (b) **task-plan-reviewer**: grade "a plan adding such a test with no catch-all-layer task that adds its `treeGuards` entry" (and the task-plan-writer clause should say the same). (c) **layer-reviewer**: either drop the trigger, or reword it so that it never requires the entry in the unit's own diff. One acceptable rewording: flag a tree-reading test only when the unit's `<task_file>` and the story index name no task that registers it. Update the Task 5 Goal sentence and the `**Verification:**` grep (*"names exactly these four files"*) to match the files that end up carrying the line.
