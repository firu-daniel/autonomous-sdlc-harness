# Architecture review — iteration 0

## Must Fix

1. **The per-checkout index is written into the adopting repository outside `core/writer.ts`, and a code comment is the only licence** — `task_5_plan.md` (the `openPgliteStore` bullet), with `task_12_plan.md` (the `writer.ts` header bullet) and the story index `feat_docs_catalog_retrieval_story_plan.md`. Rule: `.claude/context/conventions.md` → `### Where a new responsibility goes`: *"`cli/src/core/writer.ts` is the only module that writes into an adopting repository, and every mutating filesystem call in it is inside its single commit boundary."* That list is introduced as *"a stated monopoly, and the code must keep it true"*, and it has no exception.
   Task 5 has `cli/src/retrieval/store.ts` run `mkdirSync` on `<repoRoot>/<stateDir>/docs_index` and has PGlite persist its data there at query time. That is a write into the adopting repository from a module other than the write engine. The only justification is a comment Task 5 asks to put in `store.ts`: *"this derived cache is written outside `core/writer.ts` by design: it is not an `init` artifact"*. Nothing licenses it. The conventions document limits the monopoly to no class of artifact, and `cli/src/core/writer.ts`'s header today names one out-of-engine artifact only, the machine registry, which lives **outside** the repository. The header change that would record the new exception comes in Task 12, seven tasks after the write lands. So Tasks 5 through 11 ship a write that no header states, and `.claude/context/cli.md` → `## What "done" means here` requires *"the change either satisfies it or amends the header in the same edit"*. The plan also says nowhere that it departs from a conventions-document monopoly. The index points at a `## Corpus staleness` section (register rows 13 and 14), but that section does not exist.
   **Fix:** In the story index, add the missing `## Corpus staleness` section. Record there that the task prompt's per-checkout, gitignored index conflicts with the writer monopoly in `.claude/context/conventions.md` → `### Where a new responsibility goes`. The entry names the one module that writes (`cli/src/retrieval/store.ts`) and the one path (`<stateDir>/docs_index/`), for a supervised amendment. Carry rows 13 and 14's entries in the same section. In `task_5_plan.md`, move the `cli/src/core/writer.ts` header amendment for the index out of Task 12 and into Task 5, so the exception is declared in the same task that introduces the write. Add `cli/src/core/writer.ts` to Task 5's Targets. Reword the `store.ts` comment to point at that header paragraph and the staleness entry, not to argue the exception itself. In `task_12_plan.md`, drop the index clause from the `writer.ts` bullet and keep only the machine-state runtime and model cache.

2. **"Is the retrieval runtime installed?" is defined twice, in `setup.ts` and in `doctor`** — `task_12_plan.md` (the `setUpRetrieval` (1) Runtime bullet) and `task_13_plan.md` (the `RETRIEVAL_DEPENDENCIES_CHECK` bullet). Rules: `.claude/context/conventions.md` → `### Where a new responsibility goes` (*"A responsibility that already has a home does not get a second one"*, and *"Before adding a copy of anything, grep for it"*). Also `.claude/context/cli.md` → *"`doctor` asks, grades and repairs nothing … nothing it reports is re-derived from a second copy"*, and `cli/src/doctor/checks.ts` → header choice 1.
   Task 12 decides "already installed" by three tests: `<runtime>/<RUNTIME_CLI_RELATIVE>` exists, its `package.json` `version` equals this package's own, and every peer's `<runtime>/node_modules/<name>/package.json` exists. Task 13 spells out the same three tests again, inline in `cli/src/doctor/checks.ts`, to decide `pass`. That gives two bodies for one predicate, so a later change to one (a new peer-presence rule, or a range check) can leave `init` skipping an install that `doctor` then fails, with no compile error. That is exactly the drift `cli/src/core/repoPaths.ts`'s header records.
   **Fix:** In `task_2_plan.md`, add one export to `cli/src/retrieval/runtime.ts`, for example `retrievalRuntimeState(): { installed: boolean; version: string | undefined; missing: readonly string[] }`. It performs the three file tests and resolves nothing. In `task_12_plan.md`, have `setUpRetrieval` skip the install when that export answers `installed`. In `task_13_plan.md`, have `RETRIEVAL_DEPENDENCIES_CHECK` grade from the same export, naming its `missing` list, and state in both files that neither re-spells the tests.

3. **The launcher's machine-path mirror is not fully declared in its owner's header** — `task_2_plan.md` (the `retrieval/runtime.ts` exports bullet), against `task_9_plan.md`. Rule: `.claude/context/conventions.md` → `## Configuration is the source of truth…`, the persisted-key bullet: *"where a shipped template must know the same literal — that mirror declared in the owning module's header … a mirror the header does not declare is a defect"*. The same row appears in `## What accompanies a new unit of each kind`.
   Task 9's `docs-search-server.sh` hardcodes `$(hr_cache_dir)/retrieval/runtime/node_modules/autonomous-sdlc-harness/dist/cli.js`. Its Depends-on says the script mirrors three things and that *"Task 2's module header declares the mirror"*: `machineCacheDir()`, `retrievalRuntimeDir()` (the `retrieval` and `runtime` segments) and `RUNTIME_CLI_RELATIVE`. Task 2 declares only two of them: `machineCacheDir()` in `machine/paths.ts` choice 2, and a header note on `RUNTIME_CLI_RELATIVE`. It never declares `RETRIEVAL_CACHE_DIRNAME` or the `runtime` segment as mirrored. The Task 2 implementer reads only `task_2_plan.md`, so the undeclared mirror would ship.
   **Fix:** In `task_2_plan.md`, have `cli/src/retrieval/runtime.ts`'s header name `cli/templates/scripts/docs-search-server.sh` as the one declared mirror of `RETRIEVAL_CACHE_DIRNAME`, of the `runtime` segment (preferably exported as its own constant, e.g. `RETRIEVAL_RUNTIME_DIRNAME = 'runtime'`, which `retrievalRuntimeDir()` joins) and of `RUNTIME_CLI_RELATIVE`. In `task_9_plan.md`, have the script's header comment name `cli/src/retrieval/runtime.ts` and `cli/src/machine/paths.ts` as the owners it mirrors.

## Should Fix

- **The out-of-repository machine state is not added to the enumeration.** Tasks 3 and 12 write the runtime and model cache under `machineCacheDir()/retrieval/`. `.claude/context/cli.md` → *"Machine-scoped state is not an adopter's file"* says that what this layer writes outside the repository is enumerated, one owner per piece: the registry, the daemon unit and the push settings. The plan records the new pieces in `writer.ts`'s header only. Add a `## Corpus staleness` entry (see Must Fix 1) naming the two new pieces and their owners, `cli/src/retrieval/setup.ts` for the runtime and `cli/src/retrieval/models.ts` → `fetchModels` for the model cache, so the enumeration in `cli.md` can be amended.
- **`doctor`'s index probe runs a child process, which choice 3 argues against, and the header is not amended.** `task_13_plan.md` → `RETRIEVAL_INDEX_CHECK` runs a child CLI that loads the embedder and builds a whole index, with a 600-second timeout. The plan argues this only in the check's own doc comment and in a new header paragraph. Header choice 3 in `cli/src/doctor/checks.ts` still reads *"Reachability is command resolution by default … never a launch"*. Have Task 13 amend choice 3 itself in the same edit (`.claude/context/cli.md` → `## What "done" means here`, header clause), and not only add a separate paragraph.
- **The schema lands after its readers.** Task 18 adds the schema after the model and check (Task 1) and after the plugin contracts that read `docs.retrieval` (Tasks 15–16). `.claude/context/conventions.md` → `### The order files are created…` item 1 and `## The layers` (*"a plugin contract reading a shape the schema does not carry is a defect"*) require the schema first. The inversion is licensed by `plugin/agents/task-plan-writer.md`'s harness doctrine: single-layer tasks, with the catch-all last. It is still a conflict with a conventions document, so record it in `## Corpus staleness` rather than only in `## Context`.
