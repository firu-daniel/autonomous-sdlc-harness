## Must Fix

1. **The launcher's file name has no named owner, and Task 10 needs it as a second consumer** — `task_9_plan.md` (the `outerLoopScripts.ts` bullet) and `task_10_plan.md` (Depends-on, **Task 9**; Work, **`repoRoot.ts`** → `retrievalWiring(scriptsDir)`).
   Rule: `.claude/context/cli.md` → `## How a module in this layer is written` → **One string, one producer**: *"The shipped tables are single declarations of their sets and are read rather than copied: … `OUTER_LOOP_SCRIPTS` (`cli/src/generators/outerLoopScripts.ts`) … A `.sh` name spelled as a string literal elsewhere in this layer is a second source for one of these tables **where it is resolved, joined or read as a path**."* The owning module already shows how a row with a second consumer is written. `cli/src/generators/outerLoopScripts.ts` → `WATCHER_SCRIPT_NAME` and `NOTIFY_SCRIPT_NAME` are each exported *"because a second consumer needs it"*, and their rows are built from those constants (*"so the file is renamed here and nowhere else"*).
   Task 9 adds the row as `Object.freeze({ file: 'docs-search-server.sh', … })`, with the name as an inline literal and no exported constant. Task 10 then has `repoRoot.ts` build the `.mcp.json` argument from `scriptInvocation(scriptsDir, <file>)`, which joins that file name into a path. Task 10 never says where `<file>` comes from. Task 10's implementer reads only `task_10_plan.md` and has no constant to import, so the obvious move is to type `'docs-search-server.sh'` a second time in `repoRoot.ts`. That is the second source the rule forbids. It is also the drift that would stall an unattended run: rename the row and the `.mcp.json` entry names a script that was never written, the server never starts, and nothing fails at compile time.
   **Fix:** In `task_9_plan.md`, have `outerLoopScripts.ts` export `DOCS_SEARCH_SERVER_SCRIPT_NAME = 'docs-search-server.sh'`. Give it a doc comment in `WATCHER_SCRIPT_NAME`'s register that names its second consumer, `generators/repoRoot.ts` → `retrievalWiring`, which joins it into `.mcp.json`'s launcher argument. Build the new row from the constant: `Object.freeze({ file: DOCS_SEARCH_SERVER_SCRIPT_NAME, mode: 0o755, agentInvocable: false })`. In `task_10_plan.md`, add the constant to the **Task 9** Depends-on bullet, and in the `retrievalWiring` bullet say that `docsSearchServerPath` is `invokedPath(scriptInvocation(scriptsDir, DOCS_SEARCH_SERVER_SCRIPT_NAME))`, imported from `outerLoopScripts.ts` and never retyped. Add a Verification line: `grep -rn "docs-search-server.sh" cli/src` reports only the constant's declaration in `cli/src/generators/outerLoopScripts.ts`, plus any doc-comment or message text.
