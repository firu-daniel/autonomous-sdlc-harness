## Must Fix

1. **Task 1 types `harness-scripts` out again in two `cli/src` strings instead of reading `INIT_SCRIPTS_DIR`.** Offending file: `task_1_plan.md`. Rule source: `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` (*"The shared constants have owners, and a value is imported from its owner rather than retyped"*), plus `.claude/context/cli.md` → `## How a module in this layer is written` → **One string, one producer**.
   Task 1 makes `INIT_SCRIPTS_DIR` in `cli/src/config/model.ts` the owner of the generated value, and the story index's Context says *"There is no second spelling"*. Two Work bullets in `cli/src/commands/init.ts` break that anyway:
   - The new `INIT_OPTIONS` row's summary is the fixed literal `Repo-relative directory the wrapper and outer-loop scripts are written to (default: harness-scripts)`.
   - The unreadable-config warning on the `--reset-config` path is spelled *"…writes `scriptsDir` as `harness-scripts`…"*.

   If the constant ever changes, `--help` and that warning will name a directory `init` no longer writes, and no compiler error or test will catch it.
   **Fix:** In both Work bullets of `task_1_plan.md` that change `cli/src/commands/init.ts`, build each string from the imported `INIT_SCRIPTS_DIR`, for example `` `… (default: ${INIT_SCRIPTS_DIR})` `` and `` `… writes scriptsDir as ${INIT_SCRIPTS_DIR} …` ``. Name the import of `INIT_SCRIPTS_DIR` from `../config/model.js` in that file's target line. Extend the Verification grep so that `harness-scripts` appears as a literal nowhere in `cli/src` except the declaration in `model.ts`.

2. **Task 2's absent-key warning types out the absent-key default instead of reading `DEFAULTS.scriptsDir`.** Offending file: `task_2_plan.md`. Rule source: `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` (shared constants are imported from their owner, not retyped). `cli/src/config/check.ts` already imports its vocabulary from `./model.js`, so the import is the established pattern.
   The message Task 2 fixes says *"every reader falls back to `scripts`"* as a literal. That value is `DEFAULTS.scriptsDir`, which `model.ts` owns. Every CLI reader of the absent key resolves through that constant: `scripts.ts` → `resolvedScriptsDir`, `outerLoopScripts.ts` → `outerLoopScriptsDir`, `permissionProfile.ts` and `layerCoverage.ts`. So the warning is a second copy of the one value whose meaning this branch exists to protect.
   **Fix:** In the `check.ts` Work bullet of `task_2_plan.md`, say the message interpolates `DEFAULTS.scriptsDir` (imported from `./model.js` next to the existing imports) where it names the fallback directory. If it names the directory a fresh `init` writes, it interpolates `INIT_SCRIPTS_DIR`. Change the "Grep `cli/src/config/check.ts`" Verification bullet to require that neither directory name appears there as a literal.

3. **Task 13 waives the guard re-measurement rule by misquoting its source.** Offending file: `task_13_plan.md` (`**Where this task stops.**` → **The hooks.**). Rule source: `.claude/context/plugin.md` → `## Guards, the shared library and the helper scripts` (*"A change to any guard or to the library re-measures itself in `docs/guard-verification.md`"*). That rule is backed by `plugin/hooks/README.md`'s closing paragraph: *"…`docs/guard-verification.md`, which is also where a change to any guard or to the shared library records its own re-measurement."*
   Task 13 edits three guards: `git-commit-branch-guard.sh`, `autonomous-protected-branch-guard.sh` and `autonomous-script-allowlist-guard.sh`. It then states that *"the re-measure rule binds a change to a guard's behaviour or its library (`plugin/hooks/README.md`, closing paragraph)"*. The cited paragraph says *any* change, so the citation does not authorise the exception. `docs/guard-verification.md` has a precedent for exactly this case: a comment-and-reason-text edit to these same guards was recorded there with *"no cell of this matrix moves under them, which is the check that licensed them"*. So a comment-only edit is recorded, not exempted.
   **Fix:** In `task_13_plan.md`, replace the "needs no re-measure" sentence with an accurate statement: the edits are comment-only, and the record they owe lands in `docs/guard-verification.md`. That file is in the `general` layer, so add it to a `general` task's Targets. Task 17 is the natural owner because it already records measured facts. That task appends a short entry, in the style of the existing comment-edit precedent, naming the three guards and the comment lines changed. It states that no matrix cell moves, with `git diff -U0 -- plugin/hooks` showing only `#` lines as the evidence. Add a line to Task 13's `**Where this task stops.**` pointing to that task. The other option is to drop the three hook comment edits and add the hits to the deliberate set in Task 14 / gate 6f. Choose one and record it.
