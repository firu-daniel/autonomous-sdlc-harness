# Architecture review — iteration 0

## Must Fix

1. **`task_4_plan.md` writes the run registry path and the state-directory `--add-dir` as `harness-runs` literals, when the run library already resolves them from `stateDir`.** Violates `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` (*"each consumer re-reads the file on each run, from the root it resolved for itself"*) and `### Where a new responsibility goes` → **A responsibility that already has a home does not get a second one** / **Before adding a copy of anything, grep for it.**
   Under `sp_setup` → **Clone**, the plan reads the clone path from `hr_registry_peek <main>/harness-runs/autonomous_logs/registry.json …`. `sp_session` passes `--add-dir <main>/harness-runs`, and teardown step 2 passes `<registry>` with no resolver named. So the probe becomes a second place that knows where `stateDir` is, frozen at this repository's current value. The probe sources `scripts/lib/harness-run-lib.sh`, and that library already owns the answer: `hr_state_dir <root>` reads `stateDir`, and `hr_state_path <main> autonomous_logs/registry.json` is how `hr_clone_remove_var` itself finds the registry. The watcher's launch line, which this task says it reproduces flag for flag, spells that argument `--add-dir <MAIN_REPO>/<state_dir>` (`scripts/autonomous-watcher.sh` → the `spawn_engine` header comment), not a literal. If `stateDir` ever changes, the probe would read one registry while the wrappers and the watcher read another, and nothing would report the mismatch.
   **Fix:** In `task_4_plan.md`, resolve the registry once in `sp_setup` with `hr_state_path "$SP_MAIN" autonomous_logs/registry.json` and keep it in a variable such as `SP_REGISTRY`. Use that variable in `hr_registry_peek` and in teardown's `hr_registry_drop`. Build `sp_session`'s state-directory argument as `--add-dir <main>/<hr_state_dir <main>>`. Add a verification bullet: grep `session.sh` for `harness-runs` and find no match.

2. **`task_5_plan.md` places the scratch probe file at the literal `harness-runs/scratch/sbx_probe.sh`.** Violates `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time`, the same rule as Finding 1.
   `sp_leg_scratch` (SR1/SR2) writes and calls `bash scripts/scratch-run.sh harness-runs/scratch/sbx_probe.sh` in the clone. The scratch root is `<stateDir>/scratch/`, and the run library resolves `stateDir` (`hr_state_dir`). A literal here duplicates that answer inside a leg file.
   **Fix:** In `task_5_plan.md`, derive the scratch file's repo-relative path from `hr_state_dir "$SP_CLONE"` (for example `"$(hr_state_dir "$SP_CLONE")/scratch/sbx_probe.sh"`, computed inside the probe script, not in the session's call text), and issue the session call with the resolved path. Add a verification bullet: grep `legs-local.sh` for `harness-runs` and find no match.

3. **`task_13_plan.md` drives `preflight` and the `shasum` guard through the probe at `WORKSPACE_ROOT`, which aims those cases at this repository.** Violates `.claude/context/conventions.md` → `## The testing bar` (*"No fixture is ever created inside this checkout, and no test is ever aimed at this repository."*).
   `task_1_plan.md` has the entry point resolve its own checkout from `${BASH_SOURCE[0]}` (`git -C "$script_dir" rev-parse --show-toplevel`), and `task_2_plan.md` makes that checkout `SP_MAIN`. Every later preflight check runs against `SP_MAIN`: the default-branch check, the watcher's `running_count`, `SETTINGS_PROFILE`, and the snapshot of `harness.config.json`, `.git/config` and `.claude/settings.autonomous.json`. `task_13_plan.md` → **How the probe is reached** runs the script at `join(WORKSPACE_ROOT, 'scripts', 'sandbox-probe.sh')`, "As in Task 12". So the probe would judge this checkout, not the `createFixture` fixture, whatever cwd the test passes. The three `SANDBOX_PROBE_*` seams replace `uname`, `doctor` and the agent CLI only, not the root. Two cases in the plan cannot be reached against a fixture at all as written: "a fixture off its default branch", and the snapshot cases that mutate "one of the three files". Run against this checkout, the mutation case would modify this repository's own `harness.config.json`.
   **Fix:** In `task_13_plan.md`, make every case that reaches `preflight`, `sp_snapshot_take`/`sp_snapshot_check` or the watcher run a copy of the probe inside the fixture. Build the fixture with `createFixture` plus `init` (as `cli/test/watcher-run-profile.test.mjs` does, so `scripts/lib/harness-run-lib.sh` and `scripts/autonomous-watcher.sh` are the fixture's own). Copy `scripts/sandbox-probe.sh` and `scripts/lib/sandbox-probe/` into the fixture's `scripts/`, and invoke `join(fixtureDir, 'scripts', 'sandbox-probe.sh')`, so `${BASH_SOURCE[0]}` resolves into the fixture. Keep `WORKSPACE_ROOT` only for `--list` and `judge`, which touch no checkout state. Add a verification bullet: grep the suite and confirm that no `preflight` or snapshot case invokes the probe at `WORKSPACE_ROOT`.

## Should Fix

1. **`task_4_plan.md` → `sp_teardown` asks for SP_TMP to be removed "in process, never a shelled-out recursive removal", which a bash script cannot do as written.** `.claude/context/conventions.md` → `## Shell assets` states the no-recursive-removal rule, and its worked form is the CLI's in-process removal. A bash script has no in-process recursive removal. Meanwhile SP_TMP will hold directories, such as Task 8's scratch repositories, and the run library's own `hr_clone_remove_var` uses `rm -rf`. Name the mechanism the implementer is to use: for example, remove each tracked file by name, remove each tracked scratch repository through a named helper, then `rmdir` SP_TMP. Otherwise state explicitly that the hand-run probe takes the same `rm -rf` exception the run library takes, and why. Without that, Task 4's grep-for-`rm -r` verification sets a test the work cannot pass.

2. **Tasks 1–11 do not state the shell-asset rules for the ten sourced library files.** `.claude/context/conventions.md` → `## Shell assets` requires `#!/usr/bin/env bash` on every shell file. It also says *"A sourced library sets no shell options at all"*. `task_1_plan.md` states the shebang and `set -u` for `scripts/sandbox-probe.sh` only. Add one line to `task_1_plan.md`'s `core.sh` bullet, restated in each of Tasks 2–11's Targets: each `scripts/lib/sandbox-probe/*.sh` opens with the shebang and a `# <basename> — …` header, and sets no shell option, because the entry point owns `set -u`.
