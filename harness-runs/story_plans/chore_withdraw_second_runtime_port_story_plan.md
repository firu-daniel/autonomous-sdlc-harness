# Story: Withdraw the second-runtime reference port

## Context

This branch withdraws the `ROADMAP.md` item **Second-runtime reference port** and records why. The item proposed reimplementing one flow stage, the plan-writer and plan-reviewer approval loop, on an open-source agent runtime (LangGraph was the suggested one). Research on 2026-09-24 concluded that the harness's existing mechanism is the better one: an orchestrator-walked graph, with flow steps as nodes, verdicts as edges and the committed progress ledgers as durable state. The branch delivers three things: a durable decision record under `docs/`, a `ROADMAP.md` that no longer lists the item as outstanding, and every other document brought into line with both.

The work is four `general`-layer tasks. Every target is root prose or a document under `docs/`, which `.claude/context/conventions.md` → `## The layers` assigns to the catch-all layer. Task 1 writes the decision record, `docs/second-runtime-port-decision.md`. Every later task links to that path and needs the file committed first; `scripts/check-llms-txt.sh` (gate 6c) accepts a link only to a **tracked** file. Task 2 withdraws the row and renumbers the index. Task 3 amends the one `ARCHITECTURE.md` sentence the record falsifies. Task 4 adds the record to the two lists that enumerate every document under `docs/`, which are `README.md`'s reference-documents list and `llms.txt` → `## Where to read more`.

Four constraints hold across the branch:

- **What is not withdrawn.** The engine seam stays a design (`ARCHITECTURE.md` → `## 7. The seam: what an adapter would have to carry`). The **Engine / provider abstraction** row stays `Open` and its text stays unchanged. Nothing changes in the planning loop, the orchestration instructions or the dispatch discipline.
- **No new roadmap item.** No roadmap item is added for replacing the orchestration prose with a declarative flow graph. That idea is tracked separately, and per `harness-runs/lessons.md` → *"never write the change into other documents as pending work until the maintainer has decided to execute it"*, no document on this branch mentions it as pending work.
- **Run artifacts are not published.** `harness-runs/` is this repository's self-adoption run tree. `scripts/publish-main.sh` → `removed_paths` strips it from the published `main`, and the run logs are also git-ignored (`.gitignore` → `harness-runs/autonomous_logs/*`). So a published document cites a `harness-runs/` path as a code span, never as a link, and says that the file is not in the published tree.
- **Self-containment.** No file may carry a machine path (gate 6a). A roadmap priority number is local to `ROADMAP.md`. The tree cites roadmap numbers as *"roadmap item N"* and as the constant `ROADMAP_ITEM = N`, and `README.md` → the closing line of `## Where to read more` states that those numbers are listed in `docs/development.md` → `## 6. The roadmap this tree defers to`, a separate numbering. The register below re-derives every such citation (entries B and F). None resolves against a `ROADMAP.md` priority, so the renumbering breaks none. One, `evals/README.md` → *"roadmap item 8"*, already resolved against neither numbering before this branch (register row 24).

**The status-legend decision, taken here so all four tasks agree:** add `Withdrawn` to the legend and set the row's status to `Withdrawn`. The index lists only outstanding work, and until now the only rows missing from it were `Done` ones. A row missing from the index while its status says `Open` would contradict itself, and `Done` would be false. Task 1 records this choice and its reason in the decision record. Task 2 applies it.

**Top risks:** The first is that the renumbering leaves a gap or a repeat, or breaks a citation of a priority number. Task 2 guards it by checking the index runs 1..N without gaps and by re-running the priority-citation derivation below. The second is that the record states a figure without its source, carries a machine path, or links a `harness-runs/` file that the published tree does not have. Task 1 guards it by naming the field, the file glob, the read date and the read command for every figure, and by citing run artifacts as code spans only. The third is that `ARCHITECTURE.md` → `### Why no candidate is named here` keeps saying *"no file in it names a candidate"* after the record names LangGraph. Task 3 guards it.
