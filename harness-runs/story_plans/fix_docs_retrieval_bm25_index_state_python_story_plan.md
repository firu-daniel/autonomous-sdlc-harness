# Story: End every Python refresh in the BM25 state the TypeScript fix ships — store, refresh, container test, after-fix figures

## Context

This branch ports what `fix_docs_retrieval_bm25_index_state_typescript` shipped (merge commit `3063e12c`) to the Python docs-retrieval service under `docs-retrieval-service/`, so both backends end every refresh in the same BM25 index state. **What the TypeScript branch shipped, re-verified against `cli/src/retrieval/` at `3063e12c`** (`git diff 3e0ed0ce 3063e12c -- cli/src/retrieval`), and therefore what this branch ports:

- **`store.ts`** exports `LEXICAL_SEARCH_STATEMENT` (`SELECT id, <BM25_ORDER_CLAUSE> AS score FROM chunks ORDER BY <BM25_ORDER_CLAUSE> LIMIT $2`), `END_STATE_STATEMENTS` (`['REINDEX INDEX chunks_bm25']`, frozen), `INDEX_STATE_META_KEY` (`'index_state'`), `INDEX_STATE_PENDING` (`'pending'`) and `INDEX_STATE_REBUILT` (`'rebuilt'`). `DocStore.rebuildIndexes()` issues `END_STATE_STATEMENTS` in order, outside any transaction. `lexicalSearch` issues `LEXICAL_SEARCH_STATEMENT` and drops every row whose `score` is exactly `0`, on every plan, before ranking. The width-change path issues `DELETE FROM meta WHERE key = ANY($1::text[])` over `[EMBEDDER_META_KEY, INDEX_STATE_META_KEY]`. The header's spliced-token clause counts four tokens, the fourth being the constant index or table name in each `END_STATE_STATEMENTS` entry.
- **`refresh.ts`** → `refreshIndex` reads `index_state` first; records `pending` once, immediately before the refresh's first write (the embedder-change `clear`, a non-empty delete, or each upsert batch after its embeddings return); deletes only when `gone` is non-empty; and ends with `rebuildIndexes()` then `writeMeta(index_state, 'rebuilt')` when it wrote anything **or** the stored value was not `rebuilt`. An unchanged refresh over a rebuilt index issues nothing. `RefreshResult` did not change.
- **The parity bridge** (`docs-retrieval-service/tests/ts_bridge.mjs` → `constants`) already prints `END_STATE_STATEMENTS`; it does not print `LEXICAL_SEARCH_STATEMENT` or the three `INDEX_STATE_*` constants, which `store.ts` exports.

**What the Python side lacks, re-verified at this branch's base:** `store.py` issues `SELECT id FROM chunks ORDER BY … LIMIT $2`, no end-state statement, and `DELETE FROM meta WHERE key = $1` over `embedder` alone; its `DocStore` protocol has no `rebuild_indexes`; `refresh.py` → `refresh_index` has no step (6). `RefreshResult.rebuilt` means *"a stored embedder id differed"*, not *"the index was rebuilt"*, and **keeps its shape and meaning** (goal 2). The eval module does not need a new field: `evals/docs-retrieval/bm25-refresh-rule.mjs` uses `rebuilt` only as an input of the *candidate* rule it still prints, and already prints `not reported by indexPythonCorpus, taken as false` for Python; the shipped rule decides from the writes and the meta marker, as on TypeScript.

**How the work is cut.** Every target sits outside `cli/` and `plugin/`, so every task is the catch-all `general` layer, in dependency order:

- Tasks 1–2 are the store: Task 1 ports the statements, the method, the matching-only filter and the width-change delete, with the statement-parity assertions; Task 2 adds the store's own container cases (the width-change marker and the Seq Scan filter).
- Task 3 is the refresh rule, with unit cases on the in-memory fake. **Task 1 ships before Task 3 on purpose**, as on the TypeScript branch: a `REINDEX` end state without the filter puts `fixture-catalog` (41 chunks, under the 63-row crossover) on a Seq Scan that returns score-`0` rows, and no commit may leave that state behind.
- Task 4 is the container test of goal 3, shown failing with the fix removed and passing with it.
- Task 5 re-runs the refresh-level probe on the Python backend (goal 4) into scratch captures.
- Tasks 6–7 update the behaviour documents; Task 8 records every figure in `docs/retrieval-eval-results.md` and is **the park point** for the maintainer's hand runs.

**Single owners.** Each file has exactly one task that edits it. In particular `docs/retrieval-eval-results.md` is Task 8's alone: Tasks 4 and 5 write their evidence into gitignored scratch files under `harness-runs/scratch/fix-bm25-python/`, which Task 8 reads, and no document points at a scratch file.

**How a Python test file is run here.** No conventions document states a single-file Python test command; `docs-retrieval-service/README.md` → `## Testing` states `bash scripts/python-service.sh test <path>`, and the precedent this plan follows is `chore_docs_retrieval_pg_textsearch_upgrade` Task 7: a task runs **only the test files it creates or edits**, each as one plain foreground command from the repository root — `bash scripts/python-service.sh test tests/<file>.py` for an unmarked file, and `HARNESS_DOCS_RETRIEVAL_TEST_DATABASE_URL=postgresql://harness:harness@127.0.0.1:5432/docs_retrieval bash scripts/python-service.sh test tests/<file>.py` for a `container`-marked file, against the default compose project's `postgres` service. Where the command is refused, the task records the skip and raises no blocker, except Task 4, whose whole deliverable is that run. No task runs `bash scripts/python-service.sh lint`, `typecheck` or `container-test`, `scripts/run-gates.sh`, `commands.test`, or a test file it neither creates nor edits (`${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md` → `## The test-run rule`); gates 13a–13d run at the Run gates phase. `npm run build` is a build, not a test run, and the bridge needs it.

**Constraints that bind every task** (task prompt, `## Constraints` and `## Decisions taken before planning`):

- Both backends issue the same end-state statements for the same refresh outcome: the Python `END_STATE_STATEMENTS` is asserted equal to the TypeScript one through the bridge, and the Python rule is `refresh.ts` step (6) line for line.
- **Never score with the index scan disabled.** Forcing it, as `SET enable_seqscan = off` does, is allowed and is how every score here is read.
- No retry, re-score, average or tolerance. Scores are compared exactly. **A residual after `REINDEX` is recorded, not attributed, and is not a defect** only when it has the ruled shape: one hit, `operator` identical, index summary identical. A test still compares exactly, so a residual is recorded beside the figures and never absorbed by a test. Any other difference is a stop.
- Nothing is retuned: not the abstention threshold, the floor, `k` or any fusion weight. **No `evals/docs-retrieval/floor.json` row is re-recorded**: it grades the TypeScript backend, and this branch changes nothing the TypeScript backend ranks by. No file under `cli/` is a target.
- `scripts/run-gates.sh` must pass with no Docker and no Python weights: every new case that needs a database is `container`-marked, and no unmarked case needs weights.
- No wall-clock figure is taken or recorded (`harness-runs/lessons.md` → `## Evidence and measurement`, the wall-clock rule). The rebuild's lock is stated from PostgreSQL's own reference; its duration comes only from an operator's hand run of the probe's `--reindex-cost`.
- **`test_both_backends_answer_byte_identically` going green is an acceptance signal** (goal 6). Its failing query is `'what is actually encoded in the barcode printed on the label'`, results 4 and 5 swapped between `docs/labels.md#the-routing-barcode` and `#label-anatomy`. No task edits `tests/test_backend_parity_e2e.py` or its expected output, and none may run it (the test-run rule); its run is the maintainer's at Task 8's park point, or the Run gates phase's gate 13d where containers are opted in. **A failure after the fix is a stop**, not a residual.
- The corpus behind `gate10-catalog` is identified by its commit, its size and its character, never by a filesystem path (gate 6a).

**Top risks:** the first is a **regressing intermediate commit** — the `REINDEX` end state landing before the matching-only filter — which Task 1 guards by shipping the filter and Task 2 by pinning it on the Seq Scan plan before Task 3 calls `rebuild_indexes()`. The second is a **container test that would pass without the fix**, which would pin nothing: Task 4 removes step (6) from `refresh.py` by hand, runs its own file and requires every history-dependent case to fail, then restores the file byte for byte before passing. The third is **goal 6 still failing after the fix**, because the lead (*TypeScript ranks from a rebuilt index while Python ranks from its unspilled fresh build*) is research, not a decision: Task 4's case (b) pins the Python fresh build against the rebuilt reference, and Task 8 parks for the maintainer's run of the parity case, which stops the branch if it fails.
