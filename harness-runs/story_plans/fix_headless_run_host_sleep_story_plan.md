# Story: Keep the host awake for the life of every headless run, and stop the stall watchdog killing a run because the host slept

## Context

Today nothing in the harness holds a sleep assertion. `cli/templates/scripts/autonomous-watcher.sh` → `spawn_engine` starts `"$AGENT_CLI" -p "$launch_prompt" …` as the first element of a `| tee | formatter` pipeline inside a detached `( … ) &` subshell, and the service manager starts the watcher, so no shell rc file wraps it. On a Mac with the lid shut, clamshell sleep freezes the run until wake. This branch adds a hold that lives exactly as long as the engine process, an opt-out key, a watchdog that discounts host-suspended time, a `doctor` check and the docs. The anchors were re-verified on this branch's tip: `spawn_engine`, `open_log_terminal`, `check_stalled_runs`, `rc=${PIPESTATUS[0]}`, `STALL_KILL_SECS` (2700) and `STALL_BUSY_CPU_PCT` all stand as the task prompt quotes them. `scripts/` and `cli/templates/scripts/` are byte-identical at the start.

**The decisions this plan settles.**

- **The key is `execution.keepAwake`**, a boolean that defaults to `true`. It sits beside `execution.progressComments` because it governs how a run executes on this host, not what the flow does. The watcher reads it from the **main checkout** every pass, never from a run copy, the way `sandbox.optOut` is read.
- **The engine's own pid, with no `$BASHPID`.** `$BASHPID` does not exist on the bash 3.2 floor (`/bin/bash` on macOS, which a launchd-started watcher can get). So the pipeline's first element becomes a `{ …; exec "$AGENT_CLI" … 2>>"$log_path"; }` group. Inside it, `$(exec sh -c 'echo "$PPID"')` yields the group subshell's pid. The hold is started for that pid, and the `exec` then turns that same process into the engine. The holder therefore waits on the engine itself. `rc=${PIPESTATUS[0]}` still reads the engine's status, because the head of the pipe *is* the engine. The registry `pid` stays the outer subshell's `$!`, unchanged.
- **macOS:** `caffeinate -s -i -w <engine pid>`, gated on the probed host being `macos` and `caffeinate` resolving. `-s` holds only on AC power, as the prompt intends, and `-w` ends the hold when the engine exits, whether that is a normal exit, a crash, the watchdog's `kill -9`, or the session ending itself on a usage-gate `PAUSE`.
- **Linux:** while `/sys/class/power_supply/*/online` reports mains power — counting only a mains-class supply (`type` `Mains` or the `USB` family) whose `scope` is not `Device`, so a wireless peripheral's battery never reads as mains, and a host with no such entry counts as AC — `systemd-inhibit --what=sleep:handle-lid-switch --mode=block --who=autonomous-sdlc-harness --why="run <branch>"` wraps a portable waiter, `sh -c 'while kill -0 "$1" 2>/dev/null; do sleep 1; done' keep-awake-wait <engine pid>`. Before that, a synchronous `systemd-inhibit … true` probe tells a refused or unanswered logind apart. Each watcher pass re-reads the power state: it releases the hold on battery and takes it again on AC.
- **Off and silent** in job mode, when `GITHUB_ACTIONS` is `true`, when `execution.keepAwake` is `false`, and on a WSL1 or unsupported host. **Off with one log line per launch** on WSL2, when the tool is missing, when logind refuses, and when the key is not a boolean.
- **WSL detection is the existing one.** #160 has not landed (`git log --all --grep=wsl -i` is empty), but the sandbox preflight already classifies WSL2: `cli/src/doctor/sandboxPrerequisites.ts` → `sandboxHostKind` and its shell mirror inside `hr_sandbox_prereq_judge_var`. The shell classifier is extracted into `hr_host_kind_var` and reused, and the TS side reuses `sandboxHostKind`, so #160 has one detection to plug into rather than two.
- **The watchdog discounts sleep through tick-gap detection, not a monotonic clock.** No suspend-excluding clock is reachable from bash on both platforms. At the start of every pass the watcher compares now with the last pass's epoch, kept in `<state_dir>/autonomous_logs/.host_last_tick`. A gap over `POLL_INTERVAL_SECS + STALL_WAKE_GAP_SECS` (a new tunable, default 300) means the host slept or the watcher was down. It records the wake epoch in `.host_woke_at`, and `check_stalled_runs` then measures silence from `max(newest liveness mtime, wake epoch)`. A run silent across a long sleep is therefore given one full `STALL_KILL_SECS` of awake time after the wake, and a genuinely hung run with no gap is killed exactly as before. A watcher restarted after downtime also reads as a wake. The only cost is one deferred window, and the header says so.
- **The `tunables:` line** that `autonomous-watcher.sh status` prints gains `STALL_WAKE_GAP_SECS=` and `KEEP_AWAKE=<caffeinate|logind|off>`, followed by a `keep-awake:` line giving the reason when the hold is off. The `watcher starting (…)` start-up log line carries the same mode, so both lines the prompt could mean say so.
- **`doctor`'s check is `keep-awake`**, placed right after `sandbox-prerequisites`. It is `pass` or `warn` and never `fail`, `--remote-job` included. On Linux it takes a test lock through `systemd-run --user --wait` when that resolves, which is the user manager the watcher's unit runs under. Otherwise it takes the lock from its own shell and says which context answered. The probe is bounded, and its output is discarded. In the test tree it is never taken unasked: Task 8 declares `KEEP_AWAKE_LOCK_PROBE_ENV` in `cli/src/doctor/checks.ts`, `cli/test/helpers/fixture.mjs` → `ISOLATED_ENV` sets it to `off` for every subprocess, and no shipped path ever sets it.
- **#160 is cited as the GitHub issue**, `feat_wsl2_support` (#160), the way `docs/sandbox-verification.md` cites `fix_committer_plain_push_call` (#163). It is not cited as a roadmap item, so the `items? [0-9]+` roadmap sweep (`docs/development.md` §6) does not reach it, and no roadmap row is owed.

**Ship order.** Eight `cli` tasks, then two `general` tasks. Task 1 adds the key's model and check. Task 2 owns every library function the hold and the doctor mirror need. Task 3 tests that library. Task 4 is the single owner of the watcher template's changes, which are the launch hold, the Linux power pass, the two status lines and the wake discount. Tasks 5 and 6 drive the real watcher. Tasks 7 and 8 build the `doctor` check. Task 9 adds the schema property and the `docs/config.md` §5 row, and mirrors the two changed templates into this repository's own `scripts/` byte for byte. Task 10 writes the remaining docs. The schema lands after the model it describes, because the catch-all layer ships last. The transient mismatch never reaches a gate: the gates run once, after Task 10.

**Accepted test cost, stated so nobody rediscovers it.** Task 5 gives `cli/test/helpers/watcher.mjs` a default keep-awake probe override reporting an unsupported host, which is silent, as it already overrides the sandbox probe. Suites that drive the watcher through their own scripts (`watcher-stall-reset-payloads`, `watcher-run-profile`, `watcher-main-anchor`, …) are not edited. On a macOS developer machine they briefly start the real `caffeinate -w` against the stub session, and it exits with the stub. In CI, `GITHUB_ACTIONS=true` turns the hold off. Tasks 3 and 5 clear `GITHUB_ACTIONS` in their own environments so that CI still exercises the hold paths. After merge, the hold on a real lid-closed Mac and on a lingering systemd user service is owed a hand check outside any headless session (ledger: *"A wall-clock figure in a document of record is never one a run measured inside its own session"*). This branch records no such figure. This repository's own watcher picks up the mirrored `scripts/` only after an operator restart (`restart-watcher.sh`).

**Top risks:** The likeliest defect is a hold that outlives the run or changes its exit status. That could come from waiting on the wrong pid (the subshell, not the engine), from a holder that keeps the pipe open, or from the `exec` rewrite reading the formatter's status. Task 4 waits on the exec'd pid and detaches every holder's stdio. Task 5 asserts the holder's `-w` pid equals the stub engine's own `$$`, that the holder is gone once the engine exits, that a stub exiting 3 is classified `failed`, and that no `keep-awake` text leaks into `<branch>.stream.jsonl`. The second risk is a wake discount that also spares a truly hung run. Task 6 pins both halves: a back-dated last-pass epoch defers the kill, the same hang with no gap is killed, and a wake older than `STALL_KILL_SECS` is killed. The third risk is a hold that silently never engages on Linux because of polkit or battery. Task 4 logs exactly one line per launch for each of those, Task 5 drives the refused, battery and AC-again transitions, and Task 8's `keep-awake` check names the polkit remedy.
