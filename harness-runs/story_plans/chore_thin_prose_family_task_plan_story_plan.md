# Story: Thin the task-plan family's agent prose

## Context

This branch is the **task-plan family session** of the agent-thinning series (`docs/work-report-research/README.md` → `## Follow-ups`, item 3, `**Task plan:**`). It thins `plugin/agents/task-plan-writer.md` and `plugin/agents/task-plan-reviewer.md` in one session, because the reviewer grades plans against the writer's definition. Work reports are dropped (`## User verdict` in the same README), so this is thinning only. The research reports `docs/work-report-research/task-plan-writer.md` and `docs/work-report-research/task-plan-reviewer.md` are input through their `## Prose classification` and `## Thinning plan` sections only; their template, storage and shared-base proposals do not apply, and their line numbers describe an older tree.

**The standard every task applies** is `.claude/context/plugin.md` → `## Writing agent prose`: rules are direct instructions, each stated once; rationale the agent does not act on is dropped; every edge case stays; a wire literal or a cited anchor is never paraphrased; and a change to an agent definition never raises its up-front word count. **Behaviour does not change**: every rule the writer, the reviewer or a caller acts on today still holds after the edit, stated more briefly. Where two statements of one rule are found to disagree, the task records it in its return and keeps the stricter one; it never merges them silently.

**Frozen text.** A line or sentence of either definition that also appears in an agent definition **outside** this family was thinned identically across its copies by the base session (`chore_thin_shared_agent_prose`, PR #101) and stays byte-for-byte here — the shared `## Resolved values` rows and intro sentences, the docs-retrieval tool bullet, the `## Questions` sentence, the readiness "Binding on you as the author" sentence, the writer-side rejected-findings paragraph, the reviewer-side recorded-rejection bullet, `**Guard carve-out.**`, the whole `## Unsolicited dispatch guidance` section and the reviewer's verdict and findings-file lines. Each per-task file lists the frozen text inside its own section range; Task 8's probe checks all of it mechanically against `4cbe7f72`. One sentence is exempt: the reviewer's generic disclaimer *"This rule is harness doctrine and is stated here in full rather than cited; …"*, which is rationale attached to a different rule in each file that carries it and may be dropped here.

**Anchors other files quote, which survive byte-for-byte**: the writer's `## Revision mode` heading with the rejected-findings line formats and `call stands` under it, and the `## Rejected findings` and `## Scope register` headings (parsed by `scripts/lib/flow-walker-gates.sh` and its template under `cli/templates/`); the `**Scope closure:**` bullet under `## Process` (cited by `plugin/samples/sample_story_plan.md` and `plugin/samples/sample_task_plan.md`); the `**Conventions-document prohibition:**` label together with its fact that a `.claude/**` target parks a run (cited by `plugin/agents/conventions-writer.md`); the `## Corpus staleness` heading and its `stale-rule` / `undescribed-layer` type tokens (matched by `plugin/instructions/plan_orchestration_instructions_autonomous.md` and by the Corpus-staleness Done-summary bullet of `plugin/instructions/plan_orchestration_instructions_core.md`, and cited by `docs/analyze.md`); the `## Invocation contract` prompt blocks and the reviewer's five dispatch keys (cited by `docs/flow-graph-walker.md`); both files' citation of `${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md` → `## The test-run rule` (its `**Who may cite this.**` roster lists both); and the writer's `## Process` step numbers 1–9, because the reviewer cites "step 5's conventions-document prohibition".

**Read lists.** Both definitions read `plugin/samples/sample_task_plan.md` up front today; everything it states for the task-plan family is already in the definitions, and the rest covers four other artifact families. Tasks 1 and 5 move it to an on-demand pointer rather than editing it — it is also read by the supervised `/autonomous-sdlc-harness:branch-start-plan` and by `layer-reviewer`. The story-plan sample and its three per-task files are not edited: they are the format-and-taste reference, read up front by `/autonomous-sdlc-harness:branch-start-plan` as well, which has no agent definition to fall back on, and they are one worked fixture (`plugin/samples/README.md`). The reviewer's restatement of the `## Scope register` shape is replaced by a read of the writer's `**Scope closure:**` bullet, so that shape is stated once for the pair (Task 6).

**Measurement.** Up-front words = the definition + `unit_loop_core.md` → `## The test-run rule` + every sample read up front, counted as runs of non-whitespace characters; `CLAUDE.md`, the conventions documents and conditional reads are excluded. `Before` was measured at `4cbe7f72`; Task 8 fills `After` and `Δ`. Every task's `**Work:**` edits only the section range its file names, and Tasks 1–7 are chained only to fix the order in which those ranges are edited. The branch's verification bar — `cli/test` and `scripts/run-gates.sh` — is the Run gates phase's; no task runs either.

**Top risks:** the likeliest failure is a thinned sentence that drops a rule or an edge case — each per-task file names the rules its range must keep, and the reviewer pair is the guard: Tasks 5–7 re-read the writer as Tasks 1–4 left it, so a writer rule the reviewer still grades but the writer no longer states shows up there. The second is a touched frozen line or a paraphrased anchor, which silently forks a cross-family copy or breaks a parser; each task greps its own frozen text and anchors, and Task 8's probe checks every one against `4cbe7f72`. The third is an up-front count that does not fall; Task 8 measures both agents and returns a blocker on any rise.
