# Story: Gate 10 run against a real catalog — measured figures replace the extrapolation, and the 60 s rule is struck

## Context

`docs/development.md` §5 **gate 10** has been run by hand, in full, against a real documentation catalog — **a private real documentation catalog held outside this checkout, at commit `010c50e`, 156 files / 1,960 chunks** — on 2026-09-22, on a MacBook Air (Apple M4, 10 cores, 16 GB, macOS 15.7.4 / `Darwin 24.6.0`, Node v22.23.2, Claude Code 2.1.278, package `autonomous-sdlc-harness@0.2.0`). All six legs and acceptance 2a's eval-route cross-check are recorded in this branch's task prompt at `harness-runs/task_prompts/chore_gate_10_real_catalog_measurement_task_prompt.md` → `## The figures block — gate 10 RUN IN FULL, legs (i)-(vi)`. **This branch re-runs nothing and re-derives no figure.** Every task below is document work that follows from that block, and each per-task file carries the figures its own edits need so that no implementer has to go hunting.

The branch delivers four things. **The measured figures replace the extrapolation** everywhere it appears — time held (60.87 ms per chunk measured against 62.51 ms predicted, within 2.6%, which is *linear-and-lucky* rather than linear-and-right, because the thermal spread straddles the predicted value), size missed by 5.6× (37.6 kB per chunk measured against 244 kB predicted; the two-point fit over 43.2 MB @ 177 chunks and 72 MB @ 1,960 chunks is **~40.3 MB fixed plus ~16.5 kB per chunk**, so the index is fixed-cost dominated and no new projection is published on the strength of one more point). **The 60 s rule is struck outright** — research in a supervised session against Claude Code 2.1.278 established that `MCP_TOOL_TIMEOUT` defaults to `1e8` ms (~27.8 h), that `MCP_TIMEOUT`'s 30 s is *server startup* and a different setting, that what can end a long stdio MCP call is silence rather than duration (`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT`, 1,800,000 ms), that `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS` backgrounds rather than fails, that a 75 s tool call returned normally under `claude -p`, and that the only `60000` near MCP is an HTTP-transport request *floor*. No replacement constant works, because the premise — that wall time causes a failure — is false on every path the harness uses. **Roadmap item 17 is cancelled**, not deferred, on a reason that is not a measurement: the cold build stays inside the first `search_docs` call because that is the only mechanism serving every entry point, including a plain interactive session in the main checkout that never runs `setup-worktree.sh`. And **the cost the move would have accepted is restated**: the index is built once per worktree and shared by every dispatch in it, so the question is never *which agents query* but *whether the worktree queries at all*; the model load is 0.31% of the total at 1,960 chunks, and the cost of warming is the **refresh**, which is 98.8% of it.

Every figure carries the host that produced it. The two 177-chunk figures and the two real-catalog figures are recorded **side by side with their own host and corpus stamps, never as a before/after series** — the hosts differ (Node v20.19.5 against v22.23.2) and the corpora differ by 11×. The leg (iii) spread of 13.7% is reported **with its cause** — runs 1–3 rise monotonically back-to-back and run 4 returns to baseline after a pause, which is thermal behaviour of a fanless M4 Air under sustained ~4.5-core load — and the existing sub-1% spread is stated as **not comparable**. No single bandwidth number appears anywhere: throughput on the recording host is route-dependent (~1.1–1.4 MB/s Cloudflare and npm, ~17.5–19.1 MB/s HuggingFace on the same link), which is why leg (i)'s measured 128 s replaces the ~six minutes a single-number extrapolation predicted.

The work is cut as **one task per file**, in citation order: the file of record first, then the three documents that cite it. `docs/retrieval-eval-results.md` → `## Cold build and index size` is the one place the numbers are written; every other site cites it rather than restating it. Task 1 also owns the two other sentences in that same file that the run has made false — `### The limit on this calibration` and `## The shipped default against fusion alone`, each of which still records the real-catalog hand run as unperformed — and records leg (iv)'s confirmation there **without re-calibrating**: `ABSTAIN_SCORE_THRESHOLD` stays at `0.32` and `evals/docs-retrieval/floor.json` does not move. All four tasks land in the catch-all `general` layer, because every target is a prose document at the repository root's `docs/`. Four hard prohibitions bind every task. **The corpus is identified by its commit, its size and its character — never by its filesystem path**: no absolute path under `/Users/…` or `/home/…` may enter any file this branch changes, because the self-containment gate (`.claude/context/conventions.md` → `## The testing bar`, implemented as `scripts/run-gates.sh` gate `6a no machine paths`) forbids this tree naming a location on the machine that wrote it, and gate `6a` is **already red in this checkout by design**, so a newly added hit is invisible to a *"no new failure"* reading of the gate and every task carries its own independent `grep` for it instead. The same rule binds the `strings -a` citation the timeout research carries: it is written in its tilde form `~/.local/share/claude/versions/2.1.278` and never expanded. Then: **nothing may be typed inside the `<!-- eval:generated:start -->` / `<!-- eval:generated:end -->` markers** of `docs/retrieval-eval-results.md` (the cold-build section is below the end marker and is hand-written territory); **neither `scripts/setup-worktree.sh` nor `cli/templates/scripts/setup-worktree.sh` may change by a byte** — making the move is cancelled work, and a reviewer proposing it, or proposing to gate it on `docs.retrieval`, is proposing work that has been decided against; and **no agent's `tools:` allowlist under `plugin/agents/` may change** — establishing who holds the `search_docs` grant is Task 2's work, changing who holds it is not this branch's.

**Top risks:** the likeliest failure is a **missed site** — a figure left described as extrapolated, or a rule restated against some new number — which Task 4 guards by re-running the register's own derivation commands across the whole tree as its verification rather than trusting the four files named here. The second is **restating the constant in a new coat**: a rule rebuilt against 1,800 s, against `${MCP_TOOL_TIMEOUT}`, or against a fresh crossover chunk count would carry the same defect, so Tasks 2 and 3 replace the constant with a *property* of the build (it must not go silent longer than the idle timeout) plus a cost question, and Task 4's sweep fails on any surviving wall-clock threshold. The third is **publishing a second extrapolation** from the new data point — the size fit has two anchors and no projection, and Task 1 is the only task allowed to write a size figure at all. The fourth is **committing a machine-local path** while recording the corpus stamp: gate `6a` is already red here, so Tasks 1, 2 and 3 each verify with their own `grep -rnE '/(Users|home)/[a-z]'` over the file they own and Task 4 re-runs that sweep over all four changed files.
