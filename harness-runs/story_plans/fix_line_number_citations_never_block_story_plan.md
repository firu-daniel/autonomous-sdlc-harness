# Story: Line-number citations never block

## Context

**Who reads this:** the implementer and reviewer of each task below, who read this `## Context` plus one per-task file, and the task-plan reviewers, who grade the whole set. It closes the `ROADMAP.md` → `## Quality and testing` row *"Line-number citations never block"*: after this branch a per-finding file, a fix-plan finding and a reviewer's findings file anchor on a symbol, a heading or a quoted substring, and no reviewer's verdict turns on a line number being right. Every target is durable corpus text, so every task is a prose edit to a contract; this run's own reviewers still load the old definitions and grade by them, and the next run is the first to obey the new ones.

**The three decisions, taken once here and restated verbatim in the tasks that carry them.**
(1) **How long a finding lives — keep the two classes and add the no-dependence rule** (the prompt's second option). The durable class is enumerated rather than defined by "the round": an instruction file, an agent definition, a catalog document, a standing tracked artifact under `<state_dir>`, a code comment — it carries no line coordinate. The point-in-time class is a plan, a review, a finding, a QA report — it anchors like everything else and may add a line number beside its anchor as a navigation hint, never in its place. The disproven gloss *"consumed within its own round"* is deleted from the Nice to Have clause, and `layer-implementer.md`'s *"keeps the `<file>:<line>` its own contract requires"* becomes *"may add one beside its anchor as a navigation hint, never in its place"* (Task 2). The prose-volume paragraphs that also say "point-in-time" are untouched: their membership lists already agree with this split.
(2) **What counts as a precise enough anchor** — one clause, byte-identical in every finding contract (Task 2 defines it; Tasks 3, 4, 5 and 7 restate it): the repo-relative path plus the symbol, heading or short quoted substring that locates the change, a quoted substring beside any symbol whose body spans more than the change, and a bare path only when the change is the whole file. Written form, which the samples in Tasks 8 and 9 show: `` `<file>` (`<symbol>`) — "<quoted substring>" ``. The `**File:**` label stays — no label is renamed; the phrase "file-and-line reference" becomes "site anchor" at every quoter.
(3) **`<reference_impl>` citations are in scope** although the reference tree does not change during a run: `task-plan-reviewer.md` step 3 (*"the line range supports the claim"*) and the parity reviewers' *"traces to a cited `<reference_impl>` source line"* are verdicts that turn on a coordinate, and `business-parity-reviewer.md` requires `<reference_impl>/<file>:<line>` literally. They become "source anchor", with a line range allowed only as a hint (Tasks 2, 3, 4, 5, 6); the deferral marker `<reference_impl> <file>:<lines>` — a code comment, so durable — becomes `<reference_impl> <file> (<symbol>)` (Task 6). The adopter-facing parity README follows (Task 1).

**How each grading reviewer's route closes.** `branch-reviewer`, `skeptic-reviewer` and `layer-reviewer` carry the rewritten Should Fix / Nice to Have / `**Guard carve-out.**` clauses (Tasks 2, 3). `review-plan-reviewer` had two routes — the per-finding check that made an omitted file-and-line reference a Must Fix, and the `lessons.md` missed-check trigger — closed by *"omits the site anchor or the fix is a Must Fix, and a missing or stale line number never is"* plus the carve-out (Task 4). In this file C3's pointer-resolution half adds no trigger — it has no pointer-resolution rule for finding anchors and no not-downgradable guard for that half to modify — so only C3's *"a line coordinate — stale, missing or present — never binds it … `lessons.md` entry"* half does work, closing the missed-check route; Task 4 adds no anchor-resolution Must Fix. `task-plan-reviewer` had step 3's line-range test and its `lessons.md` Must Fix, closed by *"verify the anchor resolves and the anchored source supports the claim"* — scoped to `<reference_impl>` sources, which exist before the plan does — plus the carve-out (Task 6). There too C3's pointer-resolution half adds no trigger — the file has no not-downgradable guard and no resolution rule over plan citations — so C3 sits in `## Read first` after the ledger bullet, outside every `(Must Fix)` group, and a `(new)` target or quoted text a task is about to write is never a finding under it. `business-parity-reviewer` had check (e) and its template, closed by *"traces to a cited `<reference_impl>` source anchor, never invented"* (Task 5). `architecture-reviewer` has no route (*"Only architecture violations are Must Fix."*; it reads `lessons.md` for layer-ownership entries only, and no meta-reviewer grades its finding files) — its only edit is its finding contract. `ui-tests-plan-reviewer` has no route (its Must Fix triggers name ids, backend names, capabilities, sections and correspondence; its `lessons.md` use is behaviour classes) — its only edit is the finding wording *"the source line that settles it"*. `conventions-reviewer` has no route (*"No severity band and no verdict field, on either axis."*) and is not edited. `docs-reviewer` is binary: a missing coordinate is the required state and a stale one cannot pass check 1's two-halves anchor test by its number, so nothing turns on a coordinate being right; the ban stays, and **a coordinate left in a catalog document is a `FAIL`**, because a PASS commits the document with no writer round, so a non-failing correction would never be applied, while the three-round cap bounds what the FAIL costs (Task 5 writes that into the FAIL definition).

**Dead pointers still block, against the new wording.** A finding anchored `` `src/data/search/searchServce.ts` (`fetchRecentSearches`) `` — the path does not exist — and one anchored `` `src/data/search/searchService.ts` (`fetchRecentSearchs`) `` — the symbol no longer resolves in that file — are each Must Fix under *"a pointer's target does not exist"* and the carve-out's *"a cited path, symbol, heading or quoted substring that does not resolve"* (Tasks 2, 3). A routing row dispatching a non-existent agent file stays Must Fix under `layer-reviewer.md`'s *"A routing-table row dispatches an agent whose file does not exist on disk"*, and a `**Finding 4**` readiness entry with no `finding_4.md` stays Must Fix under `review-plan-reviewer.md`'s *"A pointer with no matching file is a Must Fix"* — neither is edited. By contrast, `` `src/data/search/searchService.ts` (`fetchRecentSearches`) — "store.query('recent_searches'" `` with a line hint the code has since moved away from grades Nice to Have at most.

**Ripple established, not assumed.** `docs/`, `README.md`, `ARCHITECTURE.md` and `CONTRIBUTING.md` describe no finding shape — the register's derivation reaches none of them. `cli/test/` pins no finding shape: its one hit is a CLI message about a command-source line. `examples/notes-app/sdlc-harness/` is a frozen capture (`examples/notes-app/README.md` → *"The capture is frozen; the fixture is live"*): its `**Where:** [src/…:NN](…#LNN)` findings stay as recorded. `plugin/instructions/improvement_observations_instructions.md`'s `convention` example (*"line-number coordinates in a maintained doc"*) is still accurate — a maintained doc is durable. `.claude/context/plugin.md`'s citation rule stays true, so nothing is raised as corpus staleness. No detector is added: the mechanical anchor check is roadmap item `Citation groundedness gate`.

**Top risks:** a clause meant to be byte-identical drifts between the reviewers that carry it — every carrying task quotes the exact text in a fenced block, and Task 10's closing sweep checks the carrier set with a fixed-string search. A quoter of "file-and-line reference" or of a sample header note is missed, leaving a contract that still demands a coordinate — Tasks 3–9 each re-run the grep that finds their file's quoters, and Task 10 runs the prompt's acceptance grep, whose surviving hits must stay within the user-input sites the register names. Self-containment weakens because an anchor is vaguer than a line — the precision clause forbids a bare path except for a whole-file change, and Tasks 8 and 9 make every sample `**File:**` line show a symbol plus a quoted substring an implementer can grep.
