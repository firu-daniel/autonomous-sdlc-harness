### 3. Nothing records whether an agent ever calls `search_docs`

**Site anchors.**
- `cli/src/retrieval/server.ts` → `answer` (the `CallToolRequestSchema` handler's body: `session.refresh()`, then `searchDocs({ … mode: 'fused-rerank' })`, then `renderResults(result)`) and `serveDocs` (the `server.setRequestHandler(CallToolRequestSchema, …)` registration and its `queue` serialization).
- `cli/src/retrieval/models.ts` → `RETRIEVAL_STUB_ENV = 'AUTONOMOUS_SDLC_HARNESS_RETRIEVAL_STUB'` — the seam shape to copy.
- `cli/templates/scripts/docs-search-server.sh` → the closing `exec node "$entry" docs serve --cwd "$root"`.
- `cli/templates/repo/mcp.retrieval.json` → the `harness-docs` entry's `"env": {}` object.
- `cli/src/core/writer.ts` → the module header's **"Two writes are deliberately outside this engine."** paragraph, and within it the sentence `` `cli/src/retrieval/store.ts` is the **one** module that makes that write and `<stateDir>/docs_index/` the **one** path ``.

**Problem.** The feature ships opt-in and explicitly **not yet measured** against the index-first navigation agents use today — `docs/retrieval.md` says so in its second paragraph, and the follow-up branch `feat_docs_retrieval_eval` exists to settle it. But the server keeps no record of a single call. There is no way to distinguish a tool no agent ever reaches for from a tool agents reach for and get nothing from. The eval branch has no data to start from, and an adopter who turns the feature on cannot tell whether it earned its 300 MB.

**Fix.**

- [ ] **The seam is its own module: `cli/src/retrieval/queryLog.ts`.** `cli/src/retrieval/` is already one module per responsibility (`chunk.ts`, `corpus.ts`, `models.ts`, `refresh.ts`, `runtime.ts`, `search.ts`, `server.ts`, `session.ts`, `setup.ts`, `store.ts`), and this is a new one: resolve an environment variable to a path, decide whether logging is on, shape and serialize a JSONL record, append it, and degrade on an unwritable path. It does **not** go inside `server.ts`, whose own header declares a narrower rule (*"the server's name, its tool's name and the permission string built from them are a wire"*). This matters beyond tidiness: the JSONL field list is the input contract the `feat_docs_retrieval_eval` branch will read, and a contract inlined into its first caller has no owner file a later reader can find. The new module carries:
  - a module header stating what it owns;
  - the **exported environment-variable constant** — suggested `AUTONOMOUS_SDLC_HARNESS_RETRIEVAL_LOG`, in the same shape as `RETRIEVAL_STUB_ENV`. It belongs here, beside the module that owns the artifact, not beside the first code that reads it. Its value is a **path to a file**. Set and non-empty: one JSON line is appended per `search_docs` call. Unset or empty: nothing is opened, nothing is written, and no code path changes. **No configuration key and no schema change** — an adopter who does not set the variable gains no new surface, so there is nothing for `config`, `doctor` or the config check to grow;
  - the **record type** holding the nine fields enumerated below, the outcome union among them;
  - **one exported function** taking that record plus a `Reporter`, which appends or no-ops.

  `server.ts` then calls that one function from `answer`'s exits and holds **no logging logic, no field list and no `fs` call of its own**.

- [ ] **What one line carries** (the record type's fields, owned by `queryLog.ts`). One JSON object per line (JSONL), appended, written after the call is answered. Fields:
  - the **outcome**, naming how the call ended. Its values are a **closed set declared as a union type in `queryLog.ts`**, not a free string — the eval branch reads this file as a contract and a free string makes it unparseable. Three values, one per exit from `answer`: answered, refresh failure, search failure. Every record carries it, the answered ones included, so a consumer never infers the outcome from which other fields are absent.
  - the timestamp (ISO 8601, UTC)
  - the query string as received
  - `k` as resolved (after whatever default/clamp `answer` applies)
  - the hit count in the rendered result
  - the best score (the top hit's score; `null` when there are no hits)
  - whether the call abstained (`fused-rerank`'s `no confident match` path)
  - the refresh counts from `RefreshResult` — `embedded`, `unchanged`, `deleted`
  - the wall time in milliseconds for the whole call, refresh included

- [ ] **Where the call sites are in `answer`.** Take a monotonic start timestamp at the top of `answer`, and **call `queryLog.ts`'s exported function** on **every** exit from it, including the two error returns (the refresh failure and the search failure) — a call that failed is exactly the signal this finding exists to capture. Record an error exit with the same schema, the outcome field enumerated above carrying the matching union value, so a consumer parses one shape. Fields a failed exit cannot fill (the hit count, the best score, the abstention flag, the refresh counts on a refresh failure) are written `null` rather than omitted — one shape means one key set.

- [ ] **Failing to log never fails a call.** `queryLog.ts`'s function absorbs the failure itself: an unwritable path, a missing parent directory or a full disk degrades to a `report.warn` on stderr and returns, so the caller has nothing to catch and the search result is returned unchanged. (`answer` already takes `report: Reporter`, so the `Reporter` the function needs is in hand at the call site.) Rationale: stdout belongs to the MCP transport, and a logging seam that can break a search is worse than no seam. Calls are already serialized by `serveDocs`'s `queue`, so appends cannot interleave and no locking is needed — state that in `queryLog.ts`'s comment so a later reader does not add any.

- [ ] **Stdout is untouchable.** The log goes to the file the variable names and nowhere else. Never to stdout: `docs-search-server.sh`'s own header states that a stray byte on stdout before the transport is a malformed frame for the client, and the same holds for every byte after it.

- [ ] **Establish how the variable reaches the server process, and write the answer down.** The server is started by the agent runner from `.mcp.json` → `bash <scriptsDir>/docs-search-server.sh`, not from an operator's shell, so "export it and run the server" is not the path. Determine, by running it, which of these holds and document the one that does:
  - **(a) Inheritance.** The agent runner passes its own environment to the stdio server child, so a variable exported in the environment that starts the runner reaches `docs-search-server.sh`, and `exec` carries it into `docs serve` with no change to either file. This is the preferred answer because it costs nothing.
  - **(b) The `.mcp.json` `env` object.** `cli/templates/repo/mcp.retrieval.json` already carries `"env": {}` on the `harness-docs` entry. If (a) does not hold, the route is an entry the operator adds to that object by hand in their own `.mcp.json` — a merged file, so a hand-added key survives a re-run. `init` must **not** generate the key (that would make it a surface), and the template's `"env": {}` stays empty. **State in `queryLog.ts`'s header that this is deliberate and that no shipped template mirrors the variable's name**: `.claude/context/conventions.md` → `## What accompanies a new unit of each kind` (row *A persisted machine-state key*) makes a shipped-template copy of a constant something the owning module's header must declare, and route (b) is exactly where such a mirror would otherwise be born. Under route (b) the spelling lives in `queryLog.ts` and in the adopter's own hand-edited `.mcp.json` only — never in `cli/templates/` — so there is no mirror to declare, and the header records that rather than leaving a later reader to create one.

  Record the finding in `docs/retrieval.md` under `## How it fits together` → the **Server** paragraph or the **Launcher and registration** paragraph, in one or two sentences: the variable's name, that it takes a path, what a line holds, that unset writes nothing, and the route established above. If route (b) turns out to be the one, show the `env` entry as a fenced snippet an adopter can paste.

- [ ] **Join the write-surface enumeration in `docs/cli.md`.** The log path comes from an operator-set environment variable, so it may land outside the target repository, and this layer keeps a closed list for that case: `docs/cli.md`'s *"**Nothing is written outside the repository** except the machine-local artifacts named individually below…"* paragraph — the same paragraph this feature already extended once, for the retrieval runtime directory, the model cache and the `<stateDir>/docs_index/` cache. A new write surface that joins neither list leaves that sentence false the moment this fix lands. Amend it **in the same change** with one clause naming the query log: that its path is the operator's own, by the environment variable, rather than this CLI's choice; that nothing is created when the variable is unset; and that it is written by no `init` request and carries no write-engine policy. This is in addition to — not instead of — the `docs/retrieval.md` sub-step above: the two documents own different halves, the enumeration and the feature's own design description. The finding's `_(layer: cli, general)_` tag already covers this edit and does not change.

- [ ] **Amend the code-side enumeration in `cli/src/core/writer.ts`'s header, in the same change.** The `docs/cli.md` sub-step above fixes the *adopter-facing* list only. The write-engine monopoly's exceptions are also enumerated in the owning module's own header — `writer.ts`'s **"Two writes are deliberately outside this engine."** paragraph, which names the registry and the retrieval runtime/model cache and then closes the in-repository exception in *closed* terms: `` `cli/src/retrieval/store.ts` is the **one** module that makes that write and `<stateDir>/docs_index/` the **one** path ``. This finding adds a second such module and a second such path, so that sentence becomes false the moment the fix lands — and it is the enumeration a `cli` implementer and a `cli` reviewer read before touching a write, which makes it the more load-bearing of the two. `.claude/context/cli.md` → `## What "done" means here` is the governing rule: a change either satisfies its module's stated header rule or amends the header in the same edit, and here the stated rule *is* the monopoly. **Re-word the closed sentence so it stays true rather than leaving a second claim beside it**, and state, in the same paragraph:
  - that the query log is a **third** write outside this engine;
  - that its path is the **operator's own**, set through the environment variable `queryLog.ts` owns, rather than this CLI's choice — so it may land inside or outside the target repository and **no policy in the table below applies to it**;
  - that `cli/src/retrieval/queryLog.ts` is the one module that makes the write;
  - that nothing is opened or created when the variable is unset;
  - that it is no `init` artifact.

  Keep the paragraph's existing closing move for the new exception on the same terms the `<stateDir>/docs_index/` one already uses: `.claude/context/conventions.md` → `### Where a new responsibility goes` does not record it, and it is raised as a `stale-rule`-class amendment for a supervised pass rather than edited into that document from here.

- [ ] **Tests.** Extend `cli/test/docs-retrieval.test.mjs`, under the existing hash-stub setup (`AUTONOMOUS_SDLC_HARNESS_RETRIEVAL_STUB`), with: a case that sets the log variable to a temp path, drives one `search_docs` call and asserts the file holds exactly one line that parses as JSON and carries every field above; a case where the variable is unset and asserts no file is created anywhere; and a case where the variable points at an unwritable path and asserts the search result is still returned, with a warning on stderr rather than an error result.
