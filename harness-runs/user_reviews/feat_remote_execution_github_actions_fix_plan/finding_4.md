## Problem (verified against the working tree)

Neither `harness-run.yml` nor `docs/remote-execution.md` mentions the interactive-test phase (a grep for `qa`, `Phase E`, `headless` and `xvfb` in both finds nothing relevant), and this branch never exercised it because this repository runs with `phases.qa: false`. With `phases.qa: true`, a remote run reaches Phase E on a runner. `cli/templates/repo/mcp.json` declares `playwright` (`@playwright/mcp@0.0.75 --isolated`) and `chrome-devtools` (`chrome-devtools-mcp@1.1.1 --isolated`) with no headless flag, and nothing in the workflow starts a display server, so the first navigation most likely fails. The job installs nothing of the application's own beyond `setup-worktree.sh`, so `commands.devServer` may not start. The gitignored `qa.credentialsPath` file is absent in the job, so every auth-gated test would report `blocked`.

## Decision: option (b) — QA is declared unsupported remotely

The user offered two routes. This plan takes **(b)**. Reasons: (a) needs a headless launch mode for two pinned browser servers, a dependency-install step for an arbitrary adopter application, and a new secret-to-file step. This repository can exercise none of them (it runs `phases.qa: false`), so each would ship as unverified behaviour. (b) is fully testable here, leaves the local declaration and the QA flow untouched, and still ends the branch at "ready for review" with the gap recorded and a local route to close it (`/autonomous-sdlc-harness:branch-qa-test <branch>`). (a) stays open as a follow-up, and the docs section says so. If the user prefers (a), say so in the review round and this finding is rewritten.

## Where the mode-specific text lives (architecture review, iteration 0)

The Done-summary wording and the local route are **mode-specific**. Only the autonomous flow runs in a GitHub Actions job, because job mode is a watcher launch. The two cores (`plan_orchestration_instructions_core.md`, `user_review_fixes_instructions_core.md`) are shared with the semi-autonomous forks and are literal-free (`.claude/context/plugin.md` → `## Cores, forks and the single-owner rule`, rule 4; owned by `plugin/instructions/mode_contract.md` → `## (4) Cores are literal-free`). **This plan takes the architecture review's route (b):** the whole Done-summary arm, slash command included, is stated as an **override in each autonomous fork**, the same way Overrides I and J already add Done-summary bullets "alongside" the core's D.2 without editing its bullet list. No new binding is declared. The cores receive only mode-free pointers: no slash-command name, no `execution: github-actions`, no spelling of the ledger line. Each pointer cites the ledger rule's owner, `${CLAUDE_PLUGIN_ROOT}/instructions/autonomous_pause_and_ledger.md` → `### 1.3`.

Route (a), a new binding in both cores bound in every fork, was rejected. The semi-autonomous forks would have to bind a value for a situation they can never reach, and the precedent in both autonomous forks (Overrides D, I and J, each marked "Do not propagate into the core") is an override.
