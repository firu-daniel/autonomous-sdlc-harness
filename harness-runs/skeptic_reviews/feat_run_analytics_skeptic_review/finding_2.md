### 2. The `branch-status` digest's remote arm is still gated on the mirror's file, and its `git show` path breaks on the default `stateDir`

**File:** `plugin/commands/branch-status.md` (`## Steps`, step 4, the **Run analytics** bullet), which begins "When `$ARGUMENTS` focuses one branch and `<worktree>/<state_dir>/run_analytics/<branch>/run-analytics.json` exists"

**The problem.** The code review's Finding 1, commit `26b518ce`, added a Remote-record read from `origin/<branch>`. It also told the fixer to keep the bullet's opening condition unchanged. As a result the bullet now reads:

> When `$ARGUMENTS` focuses one branch and `<worktree>/<state_dir>/run_analytics/<branch>/run-analytics.json` exists — `<worktree>` from step 3. For a **Remote record**, read the record from the branch on GitHub instead, … run `git -C <MAIN_REPO> show origin/<branch>:<state_dir>/run_analytics/<branch>/run-analytics.json` **once** … The **No local record** arm has no record to read and prints nothing — read it **once** and print exactly three lines from its `.run` object:

The bullet has three defects. An agent that follows it as written prints wrong or no figures.

1. **The remote read is gated on the file it replaces.** For a Remote record, `<worktree>` is the mirror. Finding 1 established that `remote-run.sh` → `verb_sync` → `hr_remote_bundle_restore … mirror` never places `run_analytics/` there. The bullet applies only when the mirror's file exists. So when the mirror never had a local session, the opening condition is false and nothing is printed. That is the case Finding 1 was opened for. When an earlier local session did leave a stale file, the remote read runs, but only by accident of that stale file.
2. **The `git show` path breaks on the default `stateDir`.** The schema default is `"sdlc-harness/"`, with a trailing slash (`schemas/harness.config.schema.json` → `stateDir.default`). Substituting it gives `origin/<branch>:sdlc-harness//run_analytics/<branch>/run-analytics.json`. Git does not normalise a doubled slash in a tree path. Measured in this checkout: `git show HEAD:harness-runs//run_analytics/README.md` exits `128` with `fatal: path 'harness-runs//run_analytics/README.md' exists on disk, but not in 'HEAD'`. The bullet reads any non-zero exit as "no such ref or file, and prints nothing". So in every adopting repository on the default `stateDir`, the remote digest is silently empty. A filesystem read tolerates `//`, which is why the local arm never showed the problem.
3. **The print instruction now hangs off the arm that prints nothing.** "The **No local record** arm has no record to read and prints nothing — read it **once** and print exactly three lines" gives one subject two opposite instructions. The instruction to print three lines no longer attaches to the record that was read.

**Fix.** Edit only that bullet's lead-in, up to and including the colon before the three line formats. Replace everything from "When `$ARGUMENTS` focuses one branch" through "print exactly three lines from its `.run` object:" with:

> When `$ARGUMENTS` focuses one branch, read that run's `run-analytics.json` **once**, from the source its step 3 arm names. For a local record, the source is `<worktree>/<state_dir>/run_analytics/<branch>/run-analytics.json`, with `<worktree>` from step 3. For a **Remote record**, it is the branch on GitHub, because the job commits the record there and `remote-run.sh sync` restores only the clarification and pause files into the mirror. Run `git -C <MAIN_REPO> show origin/<branch>:<state_dir>/run_analytics/<branch>/run-analytics.json`, with any trailing `/` stripped from `<state_dir>` first, because git does not resolve a doubled `/` in a tree path. That command reads the remote-tracking ref as of the main checkout's last fetch. The **No local record** arm has no record to read. An absent local file, a non-zero `git show` exit and the **No local record** arm each print nothing. From the record read, print exactly three lines from its `.run` object:

Change nothing else in the bullet: the bold label, the three line formats, the sentence "A file that does not parse, or whose `schema` is not `1`, is one line saying which, never a guess at its figures; an absent file prints nothing." and "Name no tunable, write nothing, and run no script."

This file has no test. Verify the change by reading the bullet again for each of the three arms: a local record with the file, a Remote record with an empty mirror, and No local record. Then substitute `sdlc-harness/` into the `git show` path and check that the result has no `//`.
