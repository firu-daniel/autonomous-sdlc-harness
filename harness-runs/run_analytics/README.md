# run_analytics/

Two files per branch, under a per-branch **subdirectory** the writer creates itself if it is absent: `<branch>/run-analytics.json`, one record per headless session keyed by `session_id` and the source of truth, and `<branch>/run-analytics.md`, regenerated from the JSON every time — a whole-run summary, then one section per session, oldest first. A recorded session is never rewritten; a new one is appended, and a hand-deleted `.md` comes back on the next write. Where a Run gates round wrote its own timing records beside its log in `<state_dir>/test_run_logs/<branch>/`, the JSON also keeps one entry per finished round with every gate's and test file's seconds, copied from those records and never from the log, and `run-analytics.md` gains a `## Gate rounds` section showing the slowest test files; a branch whose rounds wrote no such records gets neither. The format of record is `lib/run-analytics.jq`'s header (mode `rounds` → *Round record*) for the entry's keys, and `run-analytics.sh`'s (`GATE ROUNDS`) for which rounds are read. Every session record also lists the network calls the sandbox refused, each with the call's command, the host and port where the refusal names them and the refusal line, rendered as `## Network refusals`. Each finished Run gates round's log is scanned for possible network attempts — the only reason the log is read — and only the matching lines are kept, with paths redacted, rendered as `## Possible network attempts in gate logs (best effort)`; a document carrying them is `schema: 3`. The format of record is `lib/run-analytics.jq`'s header (*Session record* → `network_refusals`, and mode `gate_logs`) for those keys, and `run-analytics.sh`'s (`GATE LOGS`) for which logs are read.

They are written by `run-analytics.sh` and committed by the run watcher after every headless session — locally and in a GitHub Actions job alike — and read by the operator and by `/devscene:branch-status`. The directory is committed with the branch, since no ignore rule reaches it.

The mistake worth naming is reading host-suspended or idle time as the run's fault. These files are measurement only and nothing in the flow acts on them; the raw `<state_dir>/autonomous_logs/<branch>.stream.jsonl` they were derived from stays the deep-debug copy. The same goes for reading `Input tokens (uncached)` as the run's input volume: the API counts only each request's uncached tail there, and the volume is the `Total input tokens (incl. cache)` row beside it — input plus cache read plus cache write. A round's test-file total is likewise the sum of each file's own seconds, not the gate's wall time. Nor is the gate-log section complete, or a match in it a refusal: a test that catches the error leaves no trace, a plain connect error looks the same as an unreachable host, and on macOS Seatbelt's own records go to the system log rather than to the log.
