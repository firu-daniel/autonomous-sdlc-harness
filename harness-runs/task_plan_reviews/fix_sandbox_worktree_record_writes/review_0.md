4. **Manual setup step 1 and Task 1 rest on a false claim about this checkout's root `scripts/lib`** — story index (`fix_sandbox_worktree_record_writes_story_plan.md`) → `Manual setup required:` step 1, and `task_1_plan.md` → the first Work bullet's closing sentence.
   Step 1 offers the maintainer the choice of re-rendering "that one file" (`<main>/scripts/commit-on-branch.sh`) on the grounds that *"The wrapper calls only library functions `push-branch.sh` and `refresh-branch.sh` already call."* Task 1 repeats that reasoning: *"Use only library functions those two wrappers already call: this checkout's root `scripts/lib` lags the template on purpose."* The claim holds for the template wrappers but not for the root copies. `hr_git_env_drop`, which Task 1's step 2 calls, is defined in `cli/templates/scripts/lib/harness-run-lib.sh`, but nothing under `scripts/` at this checkout's root defines or calls it (`grep -n hr_git_env_drop scripts/*.sh scripts/lib/*.sh` prints nothing). The script runs `set -uo pipefail` without `-e`. A rebuilt wrapper copied alone into root `scripts/` would therefore hit `command not found` and carry on with the inherited `GIT_*` environment, running outside the sandbox. That is the exact protection the story's first `Top risks:` entry depends on.
   **Fix:** In the story index, rewrite Manual setup step 1 so that it either requires re-rendering `scripts/lib/` together with `commit-on-branch.sh`, or names `hr_git_env_drop` as missing from the root lib and makes copying the library a prerequisite. Drop the "only library functions … already call" justification. In `task_1_plan.md`, correct the closing sentence the same way. If the plan wants the single-file copy to stay safe, have the wrapper refuse with exit 1 when `hr_git_env_drop` is not defined (`declare -F`), and add that refusal to the contract block that Tasks 2 and 3 restate.
