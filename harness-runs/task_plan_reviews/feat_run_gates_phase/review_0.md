## Must Fix

1. **Task 23 tells a unit to run the gate script** — `task_23_plan.md`
   The `**Work:**` bullet **Criterion 6.** says: *"Run `bash scripts/run-gates.sh` once. Record the gate names it reports as failing, or that none failed, together with the date."* `scripts/run-gates.sh` is the gate script `commands.test` points at (`.claude/context/conventions.md` → `## The testing bar`: *"`scripts/run-gates.sh`, which `commands.test` points at"*). So this bullet is the per-unit full-suite run the branch exists to remove.
   The task prompt's `## Decisions already taken` rules it out for this plan by name: *"No plan asks for a test run before the phase … a plan that names `<test_cmd>`, a gate script it runs, or even a single targeted test file brings the per-unit run back through the plan … This holds for every plan written before the Run gates phase: the task plan, …"*. The plan's own rule says the same. Task 5's `## The test-run rule` point (1) says *"No unit runs `<test_cmd>`, a gate script it runs, …"*, and point (4) says *"A `**Verification:**` bullet, a finding's fix and a sub-step never name … a gate script"*. Task 16's new `task-plan-reviewer` check would reject this bullet too. The breach is in a `**Work:**` bullet rather than a `**Verification:**` bullet, and the prompt's rule does not depend on which list the request sits in.
   **Fix:** In `task_23_plan.md`, remove the instruction to execute `bash scripts/run-gates.sh`, together with its "record the failing gate names / whether the diff touches them" sub-bullets. Criterion 6's evidence is the gate verdict the flow itself produces over the finished tree, not a run by this unit. Have the unit record that criterion 6 is shown by the flow's own gate run and point at where that verdict is recorded. Leave the criterion's line saying so explicitly rather than *pending*. Then adjust Task 23's `**Verification:**` `grep -c "pending"` expectation to match.

4. **The test fix plan commits machine paths quoted from the gate log** — `task_7_plan.md` (and `task_3_plan.md` → the `test_run_logs` README text)
   The story index `## Context` states that *"Gate output carries machine paths, and the self-containment gate refuses those"*. Task 21 exists because gate 6a greps the whole working tree for the running user's `$HOME`. Yet Task 7 tells the writer to copy log text into committed files:
   - the per-finding file carries *"the failure quoted from the log"*;
   - `## Not fixable on this branch` carries *"the log line quoted"*.

   Task 3's README text adds *"A fix plan quotes what the log showed"*. G.3 then commits that index and folder (`test_fix_plans` is *"committed"*, per Task 3's table). A quoted absolute path lands in a tracked file outside `test_run_logs`, so the next gate run fails 6a on the fix plan itself. That is a failure this branch introduced, and every later round repeats it until the cap parks the run. The self-containment gate also binds every commit (`.claude/context/conventions.md` → `## The testing bar`: *"nothing in this tree may name a location on the machine that wrote it"*). The same risk applies to `architecture-reviewer`'s insertion-point-4 findings, which read the log at `prompt_path` and are committed through `meta_findings_folder`.
   **Fix:** In `task_7_plan.md`, add a `**Work:**` rule and a matching quality check to the writer's contract. Before any quoted log text is written, rewrite every absolute path under the checkout root to repo-relative, and every other home-directory path to a placeholder. Before returning, grep every written file for the checkout root's absolute path and the home directory, and require no hit. Mirror this in the `### Process` bullets rather than leaving it to judgement. In `task_8_plan.md`'s sub-case (c) bullet, add the same "quote log text with machine paths rewritten" constraint to the findings the reviewer writes. In `task_3_plan.md`, reword the `test_run_logs` README's mistake so it says a fix plan quotes what the log showed **with machine paths rewritten**.
