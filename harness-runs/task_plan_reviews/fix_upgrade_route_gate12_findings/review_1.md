## Should Fix

1. **`task_5_plan.md` — `git switch <branch>` can land on a stale local branch** (raised in review 0 and not addressed). If a local branch with that name already exists, `git switch` checks it out as it is, not as `origin/<branch>` carries it. The later `git push origin <branch>` is then rejected as non-fast-forward, or the move commit is built on old history. Use `git switch -C <branch> origin/<branch>` or add a `git pull --ff-only` step, and say why.
2. **`task_4_plan.md` — case (d) inherits the developer's own git configuration** (raised in review 0 and not addressed). `runStep` in `cli/test/workflow-plugin-pin.test.mjs` adds only `GIT_CONFIG_COUNT`/`KEY_0`/`VALUE_0` to the ambient environment. On a machine whose global or system config sets `advice.detachedHead=false`, the fail-before run passes against the unedited template, and the task's own stop instruction then halts the unit. After the fix, the same config would hide a regression. Have case (d) isolate git's configuration, for example with `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`.
