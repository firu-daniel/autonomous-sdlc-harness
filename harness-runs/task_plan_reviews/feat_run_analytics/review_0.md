## Must Fix

1. **`run-analytics.jq`'s two-mode invocation contract does not compile under jq** — `task_1_plan.md` (producer) and `task_3_plan.md` (consumer, restating it).
   Both files make one program, `cli/templates/scripts/lib/run-analytics.jq`, serve mode `sessions` and mode `overlay`, and each mode's invocation passes only its own variables. Mode `sessions` passes `--argjson idle_threshold_s`, `--argjson known` and `--argjson redact`. Mode `overlay` passes `--argjson suspend` and `--arg suspend_source`. jq resolves every `$name` the program references when it compiles the program, not when the branch holding the reference runs. So the `overlay` call aborts with `$known is not defined`, and the `sessions` call aborts with `$suspend is not defined`. Reproduced here: `jq -n --arg mode a 'if $mode == "a" then 1 else $known end'` exits 3 with `jq: error: $known is not defined … 1 compile error`. The usual workaround, `$ARGS.named`, does not exist in jq 1.5, and the story index's `## Context` sets 1.5 as the floor. Task 3's merge would therefore fail on every run, and Task 5's best-effort hook would log a failure after every session without ever recording one.
   **Fix:** In `task_1_plan.md` → **Contract, header and parsing.** and **Time and idle gaps.** → **Mode `overlay`**, make every invocation pass the full variable set. `sessions` also passes `--argjson suspend '[]' --arg suspend_source none`. `overlay` also passes `--argjson idle_threshold_s <int> --argjson known '[]' --argjson redact '[]'`. State in the header that both modes take every variable. The alternative is to split `overlay` into its own program, which adds a fourth file that Task 4 would ship and Task 9 would mirror. Restate the corrected invocations byte for byte in `task_3_plan.md` → `**Depends on:**`. Also add a `**Verification:**` bullet to `task_1_plan.md` that runs both modes and checks that neither reports a compile error.
