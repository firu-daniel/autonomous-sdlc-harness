## Must Fix

1. **The corpus-snapshot stamp has a producer (Task 3) and four consumers (Tasks 5, 9, 10, 14), and the file in the middle states none of it — `task_4_plan.md`** — `task_4_plan.md`, its `**Depends on:**` line, its `results.mjs` bullet and its `run.mjs` bullet.

   Iteration 4's fix made the stamp the mechanism that keeps two `self-docs` figures from being misread as a before/after pair. `task_3_plan.md`'s `index-build.mjs` bullet now exports `buildIndex({ repoRoot, config })` returning `{ store, embedder, reranker, refresh, chunkKeys, warnings, snapshot, close }` and says in the same bullet: *"Hand that field's name and shape over in this task's commit body: Task 4 renders it into the results file's provenance and Tasks 5, 9 and 10 quote it."* `task_4_plan.md` is that renderer, and it does not carry the field at all — `git grep -n snapshot` over the task files returns nothing in it.

   Three concrete breaks follow, all of them at the seam this round's fix created:

   (a) **The consumer's restatement of the producer's contract is now wrong.** `task_4_plan.md`'s `**Depends on:**` restates the hand-over as `buildIndex({ repoRoot, config }) → { store, embedder, reranker, refresh, chunkKeys, warnings, close }` — the pre-revision shape, `snapshot` absent. Its implementer reads only this file, so the field it is told to render is one its own contract restatement says does not exist.

   (b) **A cited claim about this file does not resolve.** `task_5_plan.md`'s second `**Verification:**` bullet drives `recheck-arm-e.mjs` *"without `--out`, so it writes nothing and prints the table and the run's `snapshot: { files, chunks }` stamp to stdout (`task_4_plan.md`'s `run.mjs` bullet specifies exactly that behaviour for the no-`--out` case…)"*. That bullet says only *"with no `--out` it writes nothing and prints the table to stdout."* The stamp Task 5 must read off stdout — and must confirm is identical across its two runs, which is the whole of the before/after guard — is not in the behaviour Task 4 ships.

   (c) **Task 9 is left to discover it, and hedges in its own Targets.** `task_9_plan.md`'s `### Targets` lists `evals/docs-retrieval/results.mjs` *"**only if** its provenance section does not already print the threshold in force and the run's corpus `snapshot: { files, chunks }` stamp"*, and its `**Depends on:**` restates `runEval(options)` as returning the per-corpus, per-arm result object with no `snapshot` on it. Task 9 calls `runEval`, never `buildIndex`, so the route from Task 3's returned field to the provenance Task 9 must read is defined in no file. `task_10_plan.md`'s adopter warning (*"reads each run's corpus `snapshot` (file and chunk counts) out of the provenance"*) and `task_14_plan.md`'s *"Write the corpus `snapshot` stamp Task 5 recorded beside the pair"* rest on the same undefined route.

   **Fix:** carry the stamp through `task_4_plan.md`, in three places, and correct the one citation that points at it:
   - `**Depends on:**` — restate Task 3's hand-over with the field: `buildIndex({ repoRoot, config }) → { store, embedder, reranker, refresh, chunkKeys, warnings, snapshot, close }`, and add one clause saying `snapshot` is `{ files, chunks }` copied from `refreshIndex`'s `RefreshResult` and never counted by hand.
   - the `results.mjs` bullet — bind the provenance line that currently reads *"the corpus file and chunk counts"* to that field: the counts are rendered **from `buildIndex`'s returned `snapshot`, per corpus**, never counted in this module, and the provenance names the corpus id beside them so a later reader can tell two stamps apart. Add the threshold field here too if it is to be rendered at all, so `task_9_plan.md` stops conditioning its own target list on what this file did.
   - the `run.mjs` bullet — state that `runEval` carries `snapshot` per corpus on the result object it returns, and that with no `--out` it prints that stamp alongside the table, which is what `task_5_plan.md`'s and `task_9_plan.md`'s no-`--out` launchers read.
   - `task_5_plan.md`, second `**Verification:**` bullet — the parenthetical citation of `task_4_plan.md`'s `run.mjs` bullet becomes true once the bullet above is written; leave the citation, but if the writer chooses to expose the stamp only on the returned result object rather than on stdout, reword this parenthetical to match rather than leaving it asserting a behaviour the cited bullet does not specify.
