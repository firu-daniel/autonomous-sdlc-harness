## Must Fix

1. **`modelFilesPresent(...)` is used as a boolean in five places; it returns an object, so every one of those checks is dead** — `task_3_plan.md` (the `index-build.mjs` `**Work:**` bullet and the three-refusals verification bullet), `task_7_plan.md` (second verification bullet), `task_8_plan.md` (second verification bullet), `task_9_plan.md` (the `check-floor.mjs` `**Work:**` bullet and the "Which corpus the gate enforces" / blocked-path text), and the story index's `Manual setup required:` paragraph.
   `cli/src/retrieval/models.ts` declares `export function modelFilesPresent(cacheDir: string): { present: boolean; missing: readonly string[] }`. The plan writes the call as a predicate throughout: *"`modelFilesPresent(retrievalModelCacheDir())` is false (name the missing files)"* (`task_3_plan.md`), *"check `modelFilesPresent(retrievalModelCacheDir())`; when it is false, exit with a distinct status"* (`task_9_plan.md`), *"confirm `modelFilesPresent(retrievalModelCacheDir())` and `retrievalRuntimeState().installed` are both true"* (`task_7_plan.md`, `task_8_plan.md`), and *"verifies that with `retrievalRuntimeState()` and `modelFilesPresent(retrievalModelCacheDir())` and **stops and says so** if either comes back false"* (story index). A returned object literal is always truthy, so an implementer following the text writes `if (!modelFilesPresent(dir))` — a refusal and a gate-blocked branch that can never fire, which is precisely the provisioning gap these checks exist to catch. The sibling in the same sentences is written correctly as `retrievalRuntimeState().installed`, which is what makes the omission on this one invisible rather than obvious, and the task prompt itself is precise about it (*"`modelFilesPresent()` → `present: true`, `missing: []`"*). Note that the two members are the pair the plan already wants: `.present` is the branch condition and `.missing` is the list every one of those messages promises to name.
   **Fix:** in all five places, write the predicate as `modelFilesPresent(retrievalModelCacheDir()).present` and the message source as that same call's `.missing`, e.g. *"`modelFilesPresent(retrievalModelCacheDir()).present` is false — name the paths its `.missing` array holds"*. Keep `retrievalRuntimeState().installed` as written.

2. **Gate 11's BLOCKED path fails `scripts/run-gates.sh`, which is the opposite of what the plan says it does** — `task_9_plan.md` (the `scripts/run-gates.sh` `**Work:**` bullet and the `check-floor.mjs` bullet's blocked branch) and the story index's `Top risks:` third entry.
   `task_9_plan.md` instructs: *"Handle the blocked case the way the script already handles a missing `claude`: not silently skipped, but reported as `BLOCKED` and counted among the failures"*, and the story index's third top risk says Task 9 *"reports it BLOCKED the way the script already reports a missing `claude`, rather than silently skipping it or failing on a provisioning gap."* Those two sentences contradict each other, and the script settles it against the second: `scripts/run-gates.sh`'s gate 1 branch does `failed+=("1 manifests (BLOCKED: claude is not on PATH)")`, and the script's tail is `if [ ${#failed[@]} -eq 0 ]; then … exit 0; fi; … exit 1`. Anything counted among the failures **is** a failing script. So gate 11 as planned makes `bash scripts/run-gates.sh` exit 1 on every machine whose retrieval model cache is empty — and `commands.test` in `harness.config.json` points at that script through the allow-listed `bash scripts/test.sh`, so the harness's own verification command goes red for every contributor and for every future branch run in a checkout without the hand-provisioned cache. "Failing on a provisioning gap" is exactly the outcome, not the one avoided. This also collides with `task_9_plan.md`'s own verification (*"`bash scripts/run-gates.sh` passes on the clean tree, with gate 11 green"*) and with the same line in Tasks 5, 8, 10, 11, 12, 13 and 14, none of which holds on a machine without the models. The plan must choose the behaviour rather than assert an outcome the mechanism does not deliver — and the choice is a real one, because `docs/development.md` §5 already puts real-model retrieval in gate 10 precisely as the gate a process cannot run unattended.
   **Fix:** in `task_9_plan.md`, state which of the two the gate does and say why, and make the story index's third top risk say the same thing. Either (a) the models-absent case is **reported and not counted among the failures** — printed alongside the script's `== gates this script cannot run` block, which already exists for exactly this class, with `check-floor.mjs`'s distinct exit status special-cased in the script rather than handed to the `gate` helper, whose only grading is zero-versus-non-zero; or (b) it is counted among the failures, in which case the top risk must say plainly that `run-gates.sh` requires the provisioned model cache from this branch on, and the task must also update the §5 paragraph and every affected task's *"`run-gates.sh` passes"* verification line to state that precondition. Do not leave both readings on the page.

3. **`task_2_plan.md` says `docs/` holds six files this branch does not create; it holds nine** — `task_2_plan.md`, the third `**Verification:**` bullet.
   The bullet reads *"Every `ref` in `self-docs.jsonl` names a path that exists — the six files under `docs/` this branch does not create, plus the three conventions documents"*. `docs/` carries nine `.md` files today (`analyze.md`, `cli.md`, `config.md`, `development.md`, `guard-verification.md`, `outer-loop-verification.md`, `retrieval.md`, `typecheck-key-decision.md`, `watcher.md`), and this branch creates neither of the two it adds (`retrieval-eval.md`, `retrieval-eval-results.md`) in Task 2 — so nine, not six, are available to label. Nine plus the three conventions documents is also the **twelve** corpus files the provisioning pre-step recorded and that `task_3_plan.md`'s own verification bullet asserts (*"twelve corpus files and a chunk count in the neighbourhood of 166"*), so the plan contradicts itself across two files. An implementer taking the count literally must treat three of the nine documents as off-limits with nothing to tell them which three, and the twenty-record query set would then be written against a corpus two-thirds of its actual size.
   **Fix:** replace *"the six files under `docs/`"* with *"the nine files under `docs/` that exist today"* (or state the count as a property — *"every `*.md` under `docs/` that this branch does not add"* — which is what the next document added to `docs/` will not falsify), and keep the following sentence forbidding labels on headings Tasks 10 and 12 have yet to write.
