## Must Fix

1. **Task 5's own verification re-runs the launcher whose stated contract writes `docs/retrieval-eval-results.md` with `--out`, which would destroy the pre-move `json` fence before Task 14 reads it — the one loss the iteration-2 fix exists to prevent** — `task_5_plan.md`, the second `**Verification:**` bullet.
   That bullet says: *"Re-run arm E on both corpora through `bash scripts/scratch-run.sh harness-runs/scratch/run-eval.mjs` after the change…"*. `harness-runs/scratch/run-eval.mjs` is not a neutral name in this plan: `task_4_plan.md`'s first `**Verification:**` bullet defines that exact path as *"a launcher that imports `runEval` and calls it once per corpus with `--out docs/retrieval-eval-results.md`"*. So the launcher Task 5 names rewrites the generated region, post-move, at entry 5 — three things break at once.
   (a) It contradicts Task 5's own fences in the same file: *"Where this task stops. It changes **one file under `cli/`** and nothing else. It does not edit `docs/retrieval-eval-results.md`"*, and the fourth `**Verification:**` bullet *"`git diff --stat` shows one file changed"*.
   (b) It destroys the evidence the plan's whole ordering argument rests on. Task 14 (entry 6, immediately after Task 5) must *"quote the pre-move per-query distributions into this section … copied verbatim out of the generated region's `json` fence as it stands now"*, and its first `**Verification:**` bullet requires *"every **pre-move** figure … matches the `json` fence in this file's generated region byte for byte"*. Task 5's own hand-off paragraph relies on the same fact: *"The pre-move evidence is re-checkable in the `json` fence as it stands at this commit"*. If Task 5's verification ran that launcher, the fence at that commit is already a post-move generation — and per `task_5_plan.md` and `task_9_plan.md` alike, a post-move generation *"cannot carry `bestScoreOnPositive` for the queries the new threshold abstains on"*. Task 14 then has no source for the pre-move figures it is required to quote, and the calibration evidence is gone for good.
   (c) It also breaks Task 9's guard rather than being caught by it: Task 9 only checks that Task 14's quotation exists before regenerating; nothing checks that the fence Task 14 quoted from was the pre-move one.
   **Fix:** in `task_5_plan.md`'s second `**Verification:**` bullet, state that the re-run is driven with **no `--out`** — a scratch launcher of its own (name it something other than `run-eval.mjs`, e.g. `harness-runs/scratch/recheck-arm-e.mjs`) that imports `runEval`, calls it per corpus without `--out`, and prints to stdout, which is the behaviour `task_4_plan.md`'s `run.mjs` bullet already specifies for that case (*"with no `--out` it writes nothing and prints the table to stdout"*) and the same shape `task_9_plan.md`'s `check-floor.mjs` bullet uses (*"and with no `--out`"*). Add the one-clause reason in that bullet — the pre-move fence must survive until Task 14 has quoted it, and Task 9 is the only task that regenerates the region — so a later reader cannot reintroduce the `--out` form.
