   The task prompt's `## Done when` requires that *"No code path accepts a linked worktree as a run copy."* The index's `## Context` says this is made structural because *"Every run-copy consumer goes through"* `hr_run_copy_check_var`, and that *"The wrappers call `hr_wrapper_target_check_var` directly and are unaffected."* That second sentence is only safe for the three git wrappers that clarification park 1 (Option A) keeps for a hand-made worktree. So a linked worktree can reach this path only through a leftover legacy record's `run_profile`. That is a legacy-run path, not the hand-made worktree Option A keeps: the gate launcher is the `<gate_launcher>` of the autonomous flow only, and the clarification names only `commit-on-branch.sh`, `push-branch.sh` and `refresh-branch.sh`.

It still accepts a linked worktree through `hr_wrapper_target_check_var` and keeps a worktree arm for it: `hooks_config_write`'s `elif [ "$target_mode" -eq 1 ]` branch writes `<record>/config.worktree` through the main checkout, and the `elif [ "$target_kind" != clone ]` sparse-file arm. That is the bootstrap the legacy run copy took.
   **Fix:** Add a `cli`-layer task. Task 1 is already at 20 points and 5 bullets, so do not grow it. Order the new task after Task 1 and before Task 5, linked by `**Depends on:**`. In it:
   - `launch-sandboxed-gates.sh` refuses a target `hr_wrapper_target_check_var` classifies as `worktree`, before step 7, with one sentence naming a linked worktree. Add a case to `cli/test/launch-sandboxed-gates.test.mjs` whose target is a linked worktree made with `git worktree add` and recorded with a `run_profile`. Reword the header's *"or a run copy it lists"*.
   - For `setup-worktree.sh --target`, either refuse a linked-worktree target too, removing the worktree arms of `hooks_config_write` and the sparse-file list and rewriting the cases in `cli/test/setup-worktree-clone-target.test.mjs` / `cli/test/setup-worktree-checkout-sparse.test.mjs` that pass a linked worktree to `--target`, or record in the index, with its reason, why `--target` on a linked worktree is a hand-made-worktree use the clarification keeps.
