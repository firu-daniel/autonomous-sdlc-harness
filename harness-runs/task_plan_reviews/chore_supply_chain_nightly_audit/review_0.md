3. **Task 10's publish-route check cannot pass, because the file it checks is untracked** — `task_10_plan.md` → `**Verification:**`, the "**The publish route.**" bullet.
   The bullet expects `git ls-files -- ':(literal).github/workflows/supply-chain.yml'` to print the path. Plain `git ls-files` lists only paths in the index. At verification time the implementer has just created the file, and the committer stages and commits it only later (`.claude/context/conventions.md` → `## Shell assets`: staging is the commit wrapper's job, and never `git add -A`). So the command prints nothing, and the first half of the check fails. The second command is empty for the same reason, whether or not the file sits under a removed path, so it proves nothing. This is the step that meets the task prompt's acceptance line "is shown to reach `main` through the publish route", so as written that acceptance line is not met.
   **Fix:** Make both commands see untracked files: `git ls-files --cached --others --exclude-standard -- ':(literal).github/workflows/supply-chain.yml'` must print the path, and the same flags over the seven `removed_paths` pathspecs must print no line naming `.github/workflows/supply-chain.yml`. Alternatively, keep the check index-free: read `scripts/publish-main.sh` → `removed_paths` and confirm that no entry is `.github`, `.github/workflows` or the new file's path. Whichever you choose, state that the invariant is independent of whether the file is staged.
