   The scope predicate names *"the docs sections that describe delivery and its precedence"*, and the register's own closure invariant promises *"A file with more than one narrating section gets one row per section"*. The only derivation entry that reaches corpus files is `git grep -l …`, which works at **file** level. So it cannot reach a section inside a file it has already listed, and the rows for `docs/cli.md` were picked by hand. Row 10 even says it was *"not reached by the command"*. I re-ran the command entry verbatim and it lists exactly the 14 files the rows cover, so disposition (i) does not fire. But nothing on the page reaches these two sections of `docs/cli.md`, both of which fall under the predicate:
   - `docs/cli.md` → §7, the **`notifications` never fails** bullet. It states the settings-file precedence (*"machine-local first, the repository's configured `pushEnvPath` second, the first that exists winning"*) and the credential rule (*"because a push URL is a bearer credential"*). This branch changes `doctor`'s advice in that same check (Task 2) and makes the topic a credential too.
   - `docs/cli.md` → §7, the **`--test-notification`** paragraph (*"one credential precedence, one pair of delivery arms"*).
   Neither contains `ntfy`, `push-url`, `--notifications`, `HARNESS_PUSH_URL` or `push.env`, so no entry on the page reaches them.
   **Fix:** Keep the command entry and add a third derivation entry in procedure form.
   - **Artifact:** every file under `docs/` that the command entry lists.
   - **Traversal:** its `## ` sections in file order, then within each section every bold-led paragraph, bullet and table row.
   - **Decision rule:** a block is reached when it describes where notifications are delivered, the settings-file precedence, the form of the stored destination, or the push value's credential status.
   Add a row for each site above with its disposition. `no-change` fits both if the reason is stated: the precedence is unchanged, and the stored value is still a URL. Amend the closure invariant to name the new entry.

## Should Fix

1. **Answers like `no`, `y`, `skip` or `test` become public ntfy topics** — `task_1_plan.md`, `task_3_plan.md`. The grammar accepts any `[-_A-Za-z0-9]{1,64}`. So an adopter who answers the endpoint question with `no` or `skip`, having changed their mind, ends up with `HARNESS_PUSH_URL=https://ntfy.sh/no`: a valid, public, guessable topic that anyone can read branch names from. The plan settles that a topic is a credential, but this path writes a trivially guessable one without saying so. It sits close to the prompt's rule that *an answer that is neither must not silently produce a broken configuration*. Decide explicitly how to handle it: a small reserved-word set (`y`, `n`, `yes`, `no`, `none`, `skip`) re-asked or refused as unrecognised, a minimum length, or a written reason for accepting it. Put the decision in the story index's decisions list.

2. **The lessons-ledger naming rule is quoted without its alias clause** — story index `## Context`, second decision bullet. The ledger rule is *"rename the prose and add an alias for the flag, and never the configuration key…"*. The plan restates it as *"changes the prose and the placeholder, never a wire identifier"*, which drops the alias half. Whether a flag alias is owed here (for example `--ntfy-topic`) is arguable: an alias that also accepts a URL would itself be a second wording. State the decision and its reason, so a reviewer does not read it as a silent omission of a ledger rule.

3. **Tests assert against the generator's own constants instead of the literal contract** — `task_1_plan.md` (the template case imports `NTFY_PUBLIC_ORIGIN`, and the lines case imports `PUSH_DESTINATION_FORMS`) and `task_3_plan.md` (case 7 imports `PUSH_DESTINATION_FORMS` from `dist`). `.claude/context/conventions.md` → `## The testing bar`: *"Assert against the contract stated literally, not against what generated the output"*. The one sanctioned inversion argues its exception in its own header. Either write the literals (`https://ntfy.sh`, and the key phrases of the sentence), or, where identity of wording across surfaces is the contract, have each suite header argue the inversion the way `cli/test/outer-loop-scripts.test.mjs` does. Task 2 already follows the literal rule; apply the same rule to the other two tasks.

4. **The shared sentence has to read correctly in five different grammatical frames, and none is specified** — `task_1_plan.md`. `PUSH_DESTINATION_FORMS` is interpolated as the object of *"Type …"*, of *"--push-url takes …"*, of *"is neither of …"* and into two notes. A sentence that opens *"install the free ntfy app…"* reads badly after *"takes"*. Specify its form (for example a noun phrase such as *"an ntfy topic name — install the free ntfy app …, create a topic, and type its name; it works like a password … — or the full http:// or https:// URL of any other endpoint that accepts a POST"*), and check it against each frame named in Tasks 1 and 3.

5. **Two more places describe the accepted forms outside `PUSH_DESTINATION_FORMS`** — story index `## Context` (*"`PUSH_DESTINATION_FORMS` … is the only text that describes the accepted answers"*) and `task_3_plan.md`. The `--help` summary (*"an ntfy topic name, or the full URL of any endpoint that accepts a POST"*) and the terminal re-ask line (*"neither an ntfy topic name nor a full http:// or https:// URL"*) are both separate wordings. Either interpolate a short shared form owned by Task 1, or list these two as sanctioned short restatements in the story's decision bullet, so the claim of a single source matches the plan.

6. **An existing test depends on `ntfy.sh` appearing in the guided note** — `task_1_plan.md`. The `the opt-in without an endpoint writes nothing and prints the guided setup` subtest in `cli/test/init.test.mjs` asserts that stdout includes `'ntfy.sh'`. Task 1 says `PUSH_DESTINATION_FORMS` *"may quote"* `GUIDED_ENDPOINT_EXAMPLE`, and also claims the existing cases pass unchanged. That claim holds only if the guided note still contains `ntfy.sh`. Make it "must", or name the assertion as one Task 1 updates.
