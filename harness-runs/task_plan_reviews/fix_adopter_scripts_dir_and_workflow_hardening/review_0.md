# Task plan review — iteration 0

## Must Fix
1. **Task 10's upload-path assertion contradicts the resume template it pins** — `task_10_plan.md`.
   The third `**Work:**` bullet ("Add one test per file for the credential shape") requires: *"No `upload-artifact` `path:` in any file points inside the workspace: every one starts with `${{ runner.temp }}` or `${{ env.` whose value the file sets under `runner.temp`."* The resume template sets that env value inside the workspace. `cli/templates/github/workflows/harness-resume.yml`, in the step that reads the configuration, writes `echo "POLL_STATE_DIR=${state_dir%/}/autonomous_logs/poll_state/current"` into `$GITHUB_ENV`, where `state_dir` is `jq -r '.stateDir // "sdlc-harness"'` (a repo-relative path inside the checkout). The `Upload the poller state` step then uploads `path: ${{ env.POLL_STATE_DIR }}`. Under the plan as written, the test cannot pass. Task 8 also keeps every `run:` body byte-stable, so no task moves `POLL_STATE_DIR` under `runner.temp`, and Task 10's targets cannot fix the template. The implementer would have to either write a failing test or weaken the assertion without a rule for doing so. The claim the test means to protect still holds for the persisted-credential jobs: `harness-run.yml`'s only upload is `${{ runner.temp }}/harness-state`, and `harness-trigger.yml` and `harness-control.yml` upload nothing. The resume job is protected another way: Task 8 sets `persist-credentials: false` on `poll`'s checkout.
   **Fix:** Rewrite the upload-path bullet in `task_10_plan.md` so that it holds against the real templates. Scope the "outside the workspace" assertion to the files whose checkout keeps its credential. Every `upload-artifact` `path:` in `harness-run.yml` starts with `${{ runner.temp }}`, and `harness-trigger.yml` and `harness-control.yml` carry no `upload-artifact` step. For `harness-resume.yml`, assert instead that its one checkout carries `persist-credentials: false`, the reason its workspace-relative `POLL_STATE_DIR` upload cannot carry a credential. Restate `POLL_STATE_DIR`'s real definition (`<stateDir>/autonomous_logs/poll_state/current`, set in the configuration-reading step) in the `**Depends on:**` block so the implementer does not have to infer it.

## Should Fix

   **Fix:** Either resolve both tools from `PATH` only, exit `4` (SKIPPED) otherwise as 14c does, and give the `uvx` form as the hand-run install route in Task 17. Or keep the fallback, and have Task 17 amend the "without … a network" sentence to name 6f and 14d as the legs that may fetch their tool, and why.
