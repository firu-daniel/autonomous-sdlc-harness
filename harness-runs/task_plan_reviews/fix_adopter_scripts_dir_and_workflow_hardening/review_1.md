# Task plan review — iteration 1

## Must Fix
1. **Task 8's `persist-credentials: false` on the poller weakens what the poller does on a private repository, against a false premise** — `task_8_plan.md` (and the decisions that restate it: the story index's `artipacked` decision in `## Context`, plus `task_10_plan.md`, `task_14_plan.md`, `task_16_plan.md` and `task_17_plan.md`).
   Task 8's third Work bullet says the change is safe because *"`poll` reaches GitHub only through `gh` with the token in `env:`, never through `git push`"*. The first half of that is false. `cli/templates/scripts/remote-run.sh` → `verb_poll` → `poll_pass` → `poll_branch` calls `remote_branch_exists "$branch"` for every run it examines, and that function runs `git -C "$root" ls-remote --exit-code --heads origin "refs/heads/$1"` inside the checkout. That call authenticates through the credential `actions/checkout` persists, and Task 8 removes it.
   On a public repository, `ls-remote` works anonymously. On a private repository, it fails without that credential. `poll_branch` then takes its `2)` arm, *"whether $branch exists on origin could not be checked (…); proceeding"*, on every tick. As a result, the `1)` arm — *"$branch no longer exists on origin; skipped"*, which also drops the branch's poll state — can never fire. A deleted run branch stays in the poller's view and can be re-dispatched.
   That breaks the prompt's constraint: *"do not loosen behaviour: every job must still do what `docs/remote-execution.md` … say[s] it does"*. Task 8 also keeps every `run:` body byte-stable, so nothing in the plan restores the check. The bullet's own instruction, *"Confirm that against `cli/templates/scripts/remote-run.sh` → `verb_poll`"*, would turn this up at implementation time, but the plan says nothing about what to do then. The implementer would have to choose between a regression and an unplanned residual.
   **Fix:** In `task_8_plan.md`, replace the "only through `gh`" premise with the real reach of `verb_poll`, naming `poll_branch` → `remote_branch_exists` → `git ls-remote … origin`. Then pick one option and record it:
   - **(a) Keep the poller's persisted credential.** Then `artipacked` stands on `harness-resume.yml`'s `poll` checkout. Justify it in the header, as the other residuals are: the job needs the credential for `ls-remote` on a private repository. The `harness-poll-state` upload's `path:` is `<stateDir>/autonomous_logs/poll_state/current`, which does not reach `.git/`. Carry the change through every file that restates the decision:
     - the story index's `artipacked` bullet and the residual set (`artipacked` ×5);
     - `task_10_plan.md`'s credential test, where `persist-credentials: false` is on `warm` only and the resume upload is asserted on its path rather than on the unpersisted checkout;
     - `task_14_plan.md`'s 14d residual table, which gains a `harness-resume.yml` / `artipacked` / `poll` row;
     - `task_16_plan.md`'s Depends-on facts and its §11 list;
     - `task_17_plan.md`'s restated residual set.
   - **(b) Keep `persist-credentials: false` on `poll`.** Then add a `cli`-layer task, ordered before Task 8, that moves `remote_branch_exists`'s existence check onto `gh` (the job's `GH_TOKEN`) in `cli/templates/scripts/remote-run.sh`, with its own test-file coverage. Make Task 8 depend on that task.
