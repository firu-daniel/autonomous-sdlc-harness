   `cli/templates/scripts/autonomous-watcher.sh` → `process_inbox_file` rejects a drop for a branch whose record is `parked` or `paused` and keeps that record's status (`if [ "$existing_status" = "parked" ] || [ "$existing_status" = "paused" ]`, and the comment "A PARKED run owns this branch's working copy and its clarification state. That silently throws away the guard's hold and the outstanding clarification state. The plan already accepts this reasoning for `cleanup-merged-worktrees.sh` (scope register row 29: "a `park_loop` run owns a working copy the watcher comes back to once cleared"), but not for the watcher's own inbox pass. The header REPRO `a guard` entry ("with a `parked` (or `paused`) record for that branch it is archived as rejected_<ts>_…") has the same gap.
   **Fix:** In `task_2_plan.md`, add `process_inbox_file` and the REPRO `a guard` entry to `### Targets`, and add a `**Work:**` item. That item must make a `park_loop` record reject a drop through `reject_preserving_status`, with a log line and a rejection detail that name the clear action (`<clar_dir>/PARK_LOOP_CLEAR`) rather than "answer it". Fold it into an existing bullet so the task stays within 5 bullets.
