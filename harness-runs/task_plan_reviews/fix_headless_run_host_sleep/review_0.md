4. **`hr_on_mains_power` reads a peripheral's `online` as mains power, so a battery-powered laptop keeps the logind lock** — `task_2_plan.md` (and the restated contract in `task_3_plan.md`).
   Task 2 returns 0 (mains) for *"any readable `online` file whose trimmed content is `1`"*, and says *"No other file is consulted."* Under `/sys/class/power_supply/`, device-scope supplies expose `online` too. For example, the `hid-logitech-hidpp` driver's `hidpp_battery_*` entries report `online` = `1` while a wireless mouse or keyboard is connected, and carry `scope` = `Device`. A laptop on battery with such a peripheral would then read as on mains. The watcher would take or keep the `sleep:handle-lid-switch` block lock, and a closed laptop in a bag would stay awake. That is exactly what goal 2 rules out: *"Take the lock only while `/sys/class/power_supply/*/online` reports mains power."*
   **Fix:**
   - `task_2_plan.md` → the `hr_on_mains_power` Work bullet: count an entry only when its `type` is a mains-class supply (`Mains`, plus the `USB` family if intended), and skip any entry whose `scope` is `Device`. State that rule in the doc comment. An entry with no `type` file is skipped. The no-entry-at-all case still counts as AC.
   - `task_3_plan.md` → the **Probe and power cases.** bullet: restate the contract and add cases for a `hidpp_battery_0/{online=1,scope=Device,type=Battery}` entry beside `AC/{online=0,type=Mains}` → 1, and a `type`-less `online=1` entry → ignored.

## Should Fix

1. **The accepted test cost covers only macOS** — story index, `## Context` → **Accepted test cost**. The unedited suites that drive the watcher through their own pass scripts (`watcher-stall-reset-payloads` → `localStall`, among others) run the real `hr_keep_awake_probe_var`. On a Linux developer host with `systemd-inhibit`, each launch then runs the real `timeout 10 systemd-inhibit … true` probe and takes a real logind block lock. On WSL2, or on Linux without the tool, each launch adds a non-quiet `keep-awake: not holding …` line to `watcher.log`, which a suite asserting that log's exact content would see. Either state those costs, or give those arms the same silencing the driver's default probe gives.
2. **A long pass reads as a host wake** — `task_4_plan.md`. `host_wake_pass` writes `.host_last_tick` only at the start of a pass, so the gap it measures includes the previous pass's own duration. The watch loop sleeps `POLL_INTERVAL_SECS` after `tick` returns, so a slow pass inflates the gap. Examples are a worktree setup or a `doctor` run under `npx` in a job-surface check. Anything over `STALL_WAKE_GAP_SECS` defers a hung run's kill by one window. Also write `now` to `.host_last_tick` at the end of `tick`, on every return path including the kill-switch one, so the gap measures only the time between passes.
3. **A released holder's pid stays in the record** — `task_4_plan.md` → `keep_awake_pass`. The battery-release arm records `battery` but does not say that `keep_awake_pid` is cleared. The `off` arm then kills whatever `keep_awake_pid` names if that pid is alive, so a reused pid could get an unrelated process killed. Clear `keep_awake_pid` whenever the holder is killed or found dead.
4. **`GITHUB_ACTIONS` is read as a bare literal** — `task_8_plan.md` → `probeKeepAwakeHost` reads `process.env['GITHUB_ACTIONS']`. `.claude/context/conventions.md` says an environment-variable name is *"read through its constant and never retyped as a literal"*. Declare the name once, for example in `cli/src/doctor/keepAwake.ts` (Task 7), and read it through that constant.
