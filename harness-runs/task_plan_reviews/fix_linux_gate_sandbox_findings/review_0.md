2. **F14's tree guard is narrower than the gate 6a match it exists to stand in for** — `task_14_plan.md`
   Inside the container, gate 6a is `grep -rn "$HOME"`, a bare substring match on the home directory. Task 14's guard counts a hit only when the needle is "followed by `/` or end of line, so a longer user name sharing the prefix is not a hit". So the guard passes spellings that gate 6a fails in the container: the directory in Markdown backticks (`` `<the literal>` ``), in quotes (`"<the literal>"`), or followed by `:`, `)`, `.` or `,`. The stated reason is also backwards: gate 6a does hit a longer name sharing the prefix. Goal 1 asks for a fixture for F14. The index's second `Top risks:` entry and Task 14's own Goal rely on this guard to make "a reintroduction fail on any machine" rather than only inside the container. As specified, it does not do that for the commonest Markdown spelling.
   **Fix:** In `task_14_plan.md`, make the guard count every line that contains the needle as a plain substring, which is exactly what gate 6a matches. Drop the "followed by `/` or end of line" clause and its rationale. Add to the Verification list that the needle is matched as a bare substring, as gate 6a's `grep` matches `$HOME`.
