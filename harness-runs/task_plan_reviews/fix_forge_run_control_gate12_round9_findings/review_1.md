## Should Fix

1. **Task 1 still misstates how a new branch reaches its first push** — `task_1_plan.md` (the **Check** step 1 and the last **Verification** bullet) and the story index's `## Context` / `Top risks:`. This was raised in iteration 0. It is not fixed and is not recorded under `## Rejected findings`. `cli/templates/scripts/create-worktree.sh` cuts a branch with `git -C "$main_repo" worktree add -b "$branch" "$worktree_dir" "origin/$default_branch"`. Under git's default `branch.autoSetupMerge`, that sets `branch.<b>.merge` to `refs/heads/<default>`. The script then pushes with its own `git -C "$worktree_dir" push -u origin "$branch"`, not through `push-branch.sh`. So "A new branch has neither, so `start` and a first push are unchanged" is wrong. So is "A first push is the route `remote-run.sh start` takes for a newly cut branch". In practice the check would ask `ls-remote` about the default branch, find it, and push as before, so the behaviour is harmless. The plan's account of it is not. Correct both statements. Then either add a positive-control case for a branch cut from `origin/<default>` and not yet pushed (expected: no skip line), or say why that case is not needed.
