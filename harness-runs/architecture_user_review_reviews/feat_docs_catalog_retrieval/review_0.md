The three Must Fix items below are all placement gaps inside Findings 2 and 3.

## Must Fix

1. **Finding 2's `--rag` alias has no stated home, and the only home it can take is the `INIT_OPTIONS` table** — offending file: `harness-runs/user_reviews/feat_docs_catalog_retrieval_fix_plan/finding_2.md`, the `**Fix — the `--rag` alias.**` block. Cites `.claude/context/conventions.md` → `## Registries and dispatch tables` and `.claude/context/cli.md` → `## How a module in this layer is written` (*"One string, one producer … The shipped tables are single declarations of their sets and are read rather than copied"*).

   The sub-step says only *"Add `--rag` as an accepted alias for `--docs-retrieval` in `cli/src/commands/init.ts` … the alias is an additional accepted token that sets the same `docsRetrieval` key."* It never says **where** the alias is declared, and `init.ts` has exactly one place it may be: `INIT_OPTIONS`, frozen by `initOptions()` with a compile-time exhaustiveness check, is the single source that three separate consumers read — the parser (`parseInitFlags` → `INIT_OPTIONS.find((candidate) => candidate.flag === name)`), the `Options:` renderer (*"The command's own `Options:` rows … derived from {@link INIT_OPTIONS}"*), and the discarded-flag / re-invocation derivation (*"Derived from {@link INIT_OPTIONS} … rather than from a list of its own"*). An implementer taking the sub-step at its word adds a second accepted token at the parse site, which is a second list beside the registry: `--rag` would then parse but appear in no `--help` row and in no re-invocation line, and the type-level completeness check that makes the table *"an enforced table rather than a convention"* would not see it. The registry rule forbids exactly that second list.

   **Fix:** Rewrite the alias sub-step in `finding_2.md` to state the placement: the alias is carried **as a field on the `docsRetrieval` row of `INIT_OPTIONS`** (e.g. a `readonly aliases?: readonly string[]` member added to both arms of the `InitOption` union), and every consumer that reads the table — `parseInitFlags`'s lookup, the `Options:` row renderer, and the discarded-flag derivation — reads the alias from that same row. Name the three consumers explicitly, and state that no accepted flag token is matched anywhere outside `INIT_OPTIONS`.

2. **Finding 2 plans a new flag spelling as a bare literal, with no constant owner** — offending file: `harness-runs/user_reviews/feat_docs_catalog_retrieval_fix_plan/finding_2.md`, same `**Fix — the `--rag` alias.**` block. Cites `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time`, the *"The shared constants have owners, and a value is imported from its owner rather than retyped"* paragraph and the bullet that follows it (*"each read through its constant and never retyped as a literal — **including in the message that names it to a reader**"*).

   The sub-step keeps `DOCS_RETRIEVAL_FLAG = '--docs-retrieval'` as a constant but writes `--rag` only as prose, and then requires the refusal at `init: --docs-retrieval needs --docs` to *"name the flag the operator actually typed rather than always the canonical one"* — which puts the new spelling into a user-facing message as well as into the table. Under the rule above that spelling is a shared constant with an owner, exactly as `DOCS_RETRIEVAL_FLAG`, `GIT_INIT_FLAG`, `QA_DRIVER_FLAG` and their siblings already are in that module; a literal `'--rag'` typed at the row and again at the message is two copies of one wire.

   **Fix:** Add a sub-step to `finding_2.md` requiring a named module-level constant beside `DOCS_RETRIEVAL_FLAG` in `cli/src/commands/init.ts` (e.g. `DOCS_RETRIEVAL_ALIAS_FLAG = '--rag'`), used by the `INIT_OPTIONS` row, by the parser lookup and by the refusal message, with no literal `--rag` anywhere else in `cli/src`. The doc-table row in `docs/cli.md` §3 is prose and is unaffected.

3. **Finding 3 inlines a new responsibility — and a new persisted artifact — into `cli/src/retrieval/server.ts` instead of giving it its own module** — offending file: `harness-runs/user_reviews/feat_docs_catalog_retrieval_fix_plan/finding_3.md`, the `**The seam.**`, `**What one line carries.**`, `**Where it goes in `answer`.**` and `**Failing to log never fails a call.**` sub-steps. Cites `.claude/context/cli.md` → `## Naming and file layout` (*"A new responsibility gets its own module with its own header rather than widening a neighbour where the boundary is what makes it correct"*), `.claude/context/conventions.md` → `### Where a new responsibility goes` (*"A responsibility that already has a home does not get a second one"*), and `## What accompanies a new unit of each kind`, row *A persisted machine-state key* (*"Its constant in the module that owns that artifact"*).

   `cli/src/retrieval/` is already one module per responsibility — `chunk.ts`, `corpus.ts`, `models.ts`, `refresh.ts`, `runtime.ts`, `search.ts`, `server.ts`, `session.ts`, `setup.ts`, `store.ts`. The finding adds a whole new one — resolve an environment variable to a path, decide whether logging is on, shape and serialize a JSONL record, append it, and degrade to a warning on an unwritable path — and places all of it inside `answer` and around it in `server.ts`, whose own header declares a narrower rule (*"The rule this module exists to enforce: the server's name, its tool's name and the permission string built from them are a wire"*). The plan also says the environment constant is *"declared as an exported constant beside the code that reads it"*, which under the accompanying-set row above means: beside the module that **owns the artifact**, which is the module that does not yet exist. This matters beyond tidiness — the JSONL field list is the input contract the `feat_docs_retrieval_eval` branch will read, and a contract inlined into its first caller has no owner file a later reader can find. (`server.ts` already takes `report: Reporter` on `answer`, so the plan's `report.warn` degradation is correct and is not at issue; `.claude/context/conventions.md` → `## Output, logging and errors` is satisfied.)

   **Fix:** Amend `finding_3.md` to place the seam in its own module — `cli/src/retrieval/queryLog.ts` — carrying: the module header stating what it owns; the exported environment-variable constant (the `RETRIEVAL_STUB_ENV` shape the finding already copies); the record type holding the eight fields the finding enumerates; and one exported function that takes the record plus a `Reporter` and appends or no-ops. `server.ts` then calls that function from `answer`'s exits and holds no logging logic, no field list and no `fs` call of its own. Keep the finding's existing sub-steps on *where* in `answer` the call sites are, on stdout being untouchable and on the serialization comment; they become statements about the call site rather than about the implementation.

4. **Finding 3 adds a file the CLI writes and names neither of the two enumerations it must join** — offending file: `harness-runs/user_reviews/feat_docs_catalog_retrieval_fix_plan/finding_3.md`. Cites `.claude/context/cli.md` → `## How a module in this layer is written`, the *"Machine-scoped state is not an adopter's file"* paragraph (*"What this layer writes outside the repository it was aimed at is **enumerated** and each piece has one owner"*), and `.claude/context/conventions.md` → `## Documents of record`.

   The log path comes from an operator-set environment variable, so it may land inside the target repository or outside it, and the layer keeps a closed list for each case. `docs/cli.md` carries the outside-the-repository one verbatim — *"**Nothing is written outside the repository** except the machine-local artifacts named individually below, each of which lives outside it by that artifact's own definition rather than by this CLI's choice, and each of which is written by a request that says so explicitly"* — and that same paragraph already had to be extended once for this feature, for the retrieval runtime directory, the model cache and the `<stateDir>/docs_index/` cache. A new write surface that joins neither list leaves that sentence false the moment the fix lands. The finding's only documentation sub-step routes the description to `docs/retrieval.md` → `## How it fits together`, which is the feature's own design document and not the enumeration.

   **Fix:** Add a sub-step to `finding_3.md` requiring the enumeration in `docs/cli.md` (the *"Nothing is written outside the repository"* paragraph) to be amended in the same change: one clause naming the query log, stating that its path is the operator's own by the environment variable rather than this CLI's choice, that nothing is created when the variable is unset, and that it is written by no `init` request and carries no write-engine policy. Keep the existing `docs/retrieval.md` sub-step as well — the two documents own different halves. The finding's `_(layer: cli, general)_` tag already covers this edit and does not change.
