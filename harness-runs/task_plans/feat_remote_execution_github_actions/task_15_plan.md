### Task 15 — Write the `harness-run.yml` workflow template, with its self-pause point measured

**Goal:** Write the one workflow that runs a harness run on a GitHub-hosted or a self-hosted runner, chosen by one repository variable, and size its hosted self-pause point from a measurement of how long one sub-agent dispatch really takes.

**Depends on:** Tasks 5–10 and 14, whose interfaces this file calls and restates here so its implementer need not open them:

- `bash "$SCRIPTS_DIR/remote-run.sh" restore "$HARNESS_INPUT_BRANCH" --resume <none|answer|pause>` (Task 7; reads `HARNESS_INPUT_ANSWERS`, `HARNESS_INPUT_PARK_LOOP_CLEAR`), `save <branch> <out_dir>` (Task 7), `continue <branch> <bundle_dir>` (Task 8; reads `HARNESS_MAX_CHAIN`, `HARNESS_REMOTE_STOP`, and takes `chain` from the bundle's `status.json` only — never from `HARNESS_INPUT_CHAIN`).
- `HARNESS_JOB_MODE=1 bash "$SCRIPTS_DIR/autonomous-watcher.sh" job <branch> <engine> <resume>` (Task 9; exit 2 on a protected branch or a malformed `HARNESS_INPUT_CHAIN`), which reads `HARNESS_INPUT_CHAIN` (recorded as the job's `chain`; `0` resets the auto-resume count), `GITHUB_RUN_ID` (the remote-pause lower bound, through `remote-run.sh run-created-at`), `HARNESS_JOB_STARTED_EPOCH`, `HARNESS_JOB_DEADLINE_EPOCH`, `RUNNER_ENVIRONMENT`, `REMOTE_SELF_PAUSE_AFTER_SECS` (hosted only), `HARNESS_REMOTE_SLUG` and every watcher tunable from the environment (Task 10).
- `npx --yes autonomous-sdlc-harness@{{cliVersion}} init --plugin-root-entries` (Task 14), then `doctor`.
- The input contract is Task 5's, restated: `action` (`run` | `pause` | `warm` | `stop`; `stop` is the marker `remote-run.sh stop` always sends, titled `harness stop <branch>`, which Task 8's `continue` and `poll` read so a stopped usage-paused run is never resumed), `branch`, `engine` (`task` | `user_review` | `docs`), `resume` (`none` | `answer` | `pause`), `answers` (JSON object), `park_loop_clear` (`true` | `false`), `chain` (integer); `run-name: harness ${{ inputs.action }} ${{ inputs.branch }}` — Task 10's pause poll matches that title, so it is a wire.
- The names are Task 2's: `HARNESS_RUNNER`, `HARNESS_REMOTE_STOP`, `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`, `HARNESS_PUSH_URL`, `HARNESS_GIT_TOKEN`, the artifact `harness-state`; the header declares this file a mirror of `cli/src/remote/githubActions.ts`.

**The shape, and the rule each part keeps.**

- `on: workflow_dispatch` with the seven inputs; `permissions: contents: write, actions: write`, nothing else.
- **`run` job**, `if: inputs.action == 'run'`, `runs-on: ${{ vars.HARNESS_RUNNER || 'ubuntu-latest' }}`, `concurrency: group: harness-run-${{ inputs.branch }}`, `cancel-in-progress: false` (a continuation queues behind the job that dispatched it). A `pause` dispatch therefore runs **no** job at all — no runner, no billed minute — and exists only as the titled run Task 10 polls for. A `stop` dispatch likewise runs no job and exists only as the titled run `harness stop <branch>` that Task 8 tests for; no job's `if:` may match `stop`.
- Steps, in order: capture `HARNESS_JOB_STARTED_EPOCH`; `actions/checkout` at `ref: ${{ inputs.branch }}`, `fetch-depth: 0`, `token: ${{ secrets.HARNESS_GIT_TOKEN || github.token }}` (a personal or App token here is how the pushed branch triggers the adopter's own CI, which `GITHUB_TOKEN` pushes never do); read `scriptsDir`, `stateDir` and whether retrieval applies from `harness.config.json` with `jq` **at run time** — no configured value is frozen into this file (`.claude/context/conventions.md` → `## Configuration is the source of truth`); stop cleanly when `HARNESS_REMOTE_STOP` is set; Node, the `claude` CLI when absent, and a `jq` / `gh` presence check that names what a self-hosted runner lacks; export only the non-empty credential secrets and fail before launch naming both when neither is set; a git identity for the job's commits; the pinned plugin install; `actions/cache` restore of the retrieval directory keyed on the OS and `{{cliVersion}}`, only when retrieval applies; `init --plugin-root-entries`, then fail when `git status --porcelain` shows any tracked change (naming the remedy: re-run `init` with that CLI version locally and commit), then `doctor`; `setup-worktree.sh`; `restore`; the harness step with `timeout-minutes` computed from `runner.environment`; then `push-branch.sh` under `always()`; `save` and `actions/upload-artifact` of `harness-state` under `always()`; `continue` under `!cancelled()`; a best-effort `failed` notification under `cancelled()`.
- **Every input and variable reaches a shell line through `env:`, never through `${{ }}` inside `run:`** — script injection. The job-level `env:` carries, at least: `HARNESS_JOB_MODE: '1'`; `HARNESS_REMOTE_SLUG: ${{ github.repository }}`; `HARNESS_INPUT_BRANCH`, `HARNESS_INPUT_ENGINE`, `HARNESS_INPUT_RESUME`, `HARNESS_INPUT_ANSWERS`, `HARNESS_INPUT_PARK_LOOP_CLEAR`, `HARNESS_INPUT_CHAIN` from the inputs; `HARNESS_REMOTE_STOP`, `HARNESS_MAX_CHAIN` and the watcher tunables (`STALL_WARN_SECS`, `STALL_KILL_SECS`, `STALL_MAX_RESTARTS`, `USAGE_PAUSE_TRIGGER`, `USAGE_WARNING_DEBOUNCE`, `USAGE_RESUME_MARGIN_SECS`, `USAGE_SEVEN_DAY_PAUSE_PCT`, `PARK_LOOP_MAX_CYCLES`, `PARK_LOOP_WINDOW_SECS`, `REMOTE_WAIT_MAX_SECS`, `REMOTE_AUTO_RESUME_MAX`, `REMOTE_AUTO_RESUME_DELAY_SECS`, `REMOTE_CONTROL_POLL_SECS`) from repository variables of the same names — an unset variable arrives empty, and the watcher's `${VAR:-default}` then applies its own default; `HARNESS_PUSH_URL` from its secret; `GH_TOKEN: ${{ github.token }}` for `gh`.
- **Every GitHub expression is written with a space after `${{`**, so the CLI's `{{token}}` renderer (`cli/src/core/templating.ts`, whose token must start with a letter straight after the braces) never mistakes one for a token; the file's only token is `{{cliVersion}}`, which Task 17 renders.
- **`warm` job**, `if: inputs.action == 'warm'`: checkout the dispatched ref, restore the retrieval cache, run `init` (which installs only what is missing), and let `actions/cache` save it — this is what seeds a cache every branch can read, because a cache saved on a feature branch is invisible to its siblings.
- **The self-pause point and the timeouts.** On a hosted runner the harness step's timeout is `HARNESS_STEP_TIMEOUT_MINUTES` (repository variable) or a default leaving room inside the hosted job limit for the steps around it, and `REMOTE_SELF_PAUSE_AFTER_SECS` is `HARNESS_SELF_PAUSE_AFTER_MINUTES` or the measured default below; on a self-hosted runner the self-pause variable is left **unset** and the step timeout defaults to the self-hosted job limit minus the same allowance. `HARNESS_JOB_DEADLINE_EPOCH` is the start plus the step timeout. The job-level `timeout-minutes` is set to the self-hosted limit, since GitHub-hosted jobs are stopped at their own limit whatever it says. Verify against GitHub's workflow-syntax documentation that `timeout-minutes` accepts an expression at the step level and that `runner.environment` is available there; if either is not, use a step that computes the values into `GITHUB_ENV` and a single variable-driven timeout, and say which in the header.
