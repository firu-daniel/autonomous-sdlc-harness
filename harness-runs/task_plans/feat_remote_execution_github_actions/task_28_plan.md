### Task 28 — Write `docs/remote-execution.md`: the design and the job's lifecycle

**Goal:** Write the document of record for remote execution's design: what happens between a drop and a pushed branch when a run executes on GitHub Actions, every decision the task prompt left open with its reason, and what is still unverified. Task 29 adds the adopter's setup, costs, billing and security to the same file.

**Depends on:** every CLI and plugin task of this branch (Tasks 1–24); the behaviours to describe are restated here so this file can be written from this plan and the code:

- **The key**: `execution.target`, `local` (default) | `github-actions`; readers `init`, the watcher, `doctor` (Tasks 1, 11, 17–19). `forge` gains no reader (the story index's `## Context` states why).
- **Local side**: the watcher prepares a drop as today and dispatches it with `remote-run.sh dispatch` (Task 11); a remote review drop is fast-forwarded, committed as `chore: add user review for <branch>` and pushed first; answers, resumes and pauses written into the run's local mirror are relayed as dispatches (Task 12); the reconcile pass, the cap, the stall watchdog, the usage gate and the machine lane skip remote records; `restart-watcher.sh` does not count them (Task 13). `remote-run.sh` verbs: `dispatch`, `pause`, `warm`, `stop`, `sync`, `status` locally; `restore`, `save`, `continue`, `poll`, `pause-requested` in a job (Tasks 5–8, 10).
- **The job** (Task 15): runner `${{ vars.HARNESS_RUNNER || 'ubuntu-latest' }}`; checkout; config read at run time; remote stop; toolchain; credentials; pinned plugin; retrieval cache; `init --plugin-root-entries` + tracked-clean check + `doctor`; `setup-worktree.sh`; `restore`; `autonomous-watcher.sh job` (Tasks 9–10); final push, `save` + upload of `harness-state`, `continue`, a best-effort cancel notice. A `pause` dispatch runs no job; a `warm` dispatch seeds the retrieval cache on GitHub's default branch.
- **Job mode's policies** (Task 10): remote pause by a polled `harness pause <branch>` run; hosted self-pause at the measured point, disabled on self-hosted; usage wait in-job when cheap or on self-hosted, otherwise the poller; bounded auto-resume of `failed` and overload pauses; the decisions `continue` | `wait-poller` | `stop`; which notifications are sent and which (budget continuations) are not.
- **The bundle** (Task 4): layout and `status.json` keys; walker state stored without its dot; `sync` maps a job that ended mid-run to `paused` / `killed` so `/autonomous-sdlc-harness:branch-resume` resumes it (Task 6).
- **The poller** (Tasks 8, 16): a 30-minute `schedule`, enabled by a pausing job, self-disabling; the unverified `GITHUB_TOKEN` enable/disable and its degradable path.
- **The measurement** Task 15 recorded in `cli/templates/github/workflows/harness-run.yml`'s header: its command, date, figures and derived default.
