### Task 10 — Give job mode its remote pause, hosted time budget, in-job waits and bounded auto-resume

**Goal:** Add to job mode the policies only a remote job needs: honouring a pause the user sent from their machine, pausing itself before a hosted runner's job limit, waiting in the job when a wait is cheap, and resuming a failed or overload-paused run a bounded number of times — then telling the post-steps what to do through the `decision` it writes.

**Depends on:** Task 9, which created `autonomous-watcher.sh job` (refused unless `HARNESS_JOB_MODE=1`), its per-`POLL_INTERVAL_SECS` loop (`reconcile_stale_runs`, `check_stalled_runs`, `usage_gate`), its start record (`decision: continue`) and its exit record (`decision: stop` for every terminal status), its `JOB_MODE` notification variants, and `cli/test/watcher-remote-job.test.mjs`. And Task 8, which last extended `cli/templates/scripts/remote-run.sh` (exit map: 0 done, 1 usage/config, 2 refused, 3 `gh` failed); this task adds the two read verbs job mode calls. Task 4's `status.json` carries `pause_reason`, `auto_resumes` and `control_polled_at` (*"the epoch second up to which the job has checked for a `harness pause <branch>` run — the lower bound the next job's remote-pause poll starts from, or empty"*), which this task writes; `hr_remote_status_write` copies each from the job's registry record. Task 9 sets the record's `chain` from `HARNESS_INPUT_CHAIN` at start, seeds `auto_resumes` from the restored `remote_status.json` **only when `HARNESS_INPUT_CHAIN` is greater than `0`** (else `0`), and leaves `control_polled_at` to the rule below.

**The contract, stated once for every consumer** (Task 15 sets the environment; Task 8's `continue` acts on the decision; Task 28 documents it):

Environment the workflow provides: `HARNESS_JOB_STARTED_EPOCH` (captured in the job's first step), `HARNESS_JOB_DEADLINE_EPOCH` (when the harness step's `timeout-minutes` ends), `RUNNER_ENVIRONMENT` (`github-hosted` | `self-hosted`, from `runner.environment`), `REMOTE_SELF_PAUSE_AFTER_SECS` (set **only** on a hosted runner), `HARNESS_INPUT_CHAIN` (Task 9 reads it), and GitHub's own `GITHUB_RUN_ID`. Tunables with defaults, overridable like every watcher tunable: `REMOTE_CONTROL_POLL_SECS=60`, `REMOTE_WAIT_MAX_SECS=600`, `REMOTE_AUTO_RESUME_MAX=2`, `REMOTE_AUTO_RESUME_DELAY_SECS=300`.

**The remote-pause lower bound — never the job's own start.** A pause the user sends while this job is still **queued**, or between the previous job's last control poll and this job's start (a chained continuation after a budget self-pause), has a `createdAt` earlier than `HARNESS_JOB_STARTED_EPOCH`; bounding the poll by the job's start would lose it while Task 12's relay has already removed the mirror's `PAUSE`. So the poll's lower bound is the record's `control_polled_at`, set at start:

- `HARNESS_INPUT_CHAIN` greater than `0` (an automatic continuation) **and** the restored `remote_status.json` carries a `control_polled_at` → that restored value: the previous job had checked up to there, and anything later is unseen;
- otherwise (a user's dispatch — drop, answer, resume — or no bundle) → **this job's own run's `createdAt`**, read through `remote-run.sh run-created-at "$GITHUB_RUN_ID"`: the moment the dispatch that created this run was made, which precedes any pause sent while it queued, and follows every pause the user's own new dispatch supersedes. If that read fails, fall back to `HARNESS_JOB_STARTED_EPOCH` and log one line naming the fallback.

Each **successful** control poll (`pause-requested` exit 0 or 1) takes the epoch just **before** its query, and after the query sets the record's `control_polled_at` to it and rewrites `remote_status.json` (decision `continue`, as at start), so a bundle saved after a kill still carries a current bound; a failed poll (exit 3) advances nothing. Every later status write carries the field through `hr_remote_status_write`.

| While `running` | Action |
|---|---|
| a run titled `harness pause <branch>` was created after the record's `control_polled_at` (`remote-run.sh pause-requested <branch> <control_polled_at>`, checked every `REMOTE_CONTROL_POLL_SECS`, the first check at the first loop pass) | drop `<state_dir>/PAUSE` once; record `pause_reason: user` |
| `REMOTE_SELF_PAUSE_AFTER_SECS` is set and that long has passed since `HARNESS_JOB_STARTED_EPOCH` | drop `PAUSE` once; record `pause_reason: budget` |

| When the run leaves `running` | Decision written |
|---|---|
| `paused`, `pause_reason: budget` | `continue` — the next job resumes from the ledger. **No `paused` notification**, and the next job sends no `resumed` for a resume whose previous `pause_reason` was `budget`: a chained continuation is not an event the user acts on |
| `paused`, `pause_reason: user` | `stop`; the `paused` notification names `/autonomous-sdlc-harness:branch-resume <branch>` |
| `paused` by the usage gate (`paused_by: usage`; recorded as `pause_reason: usage`) | **wait in the job** — keep looping; the gate's own auto-resume drops `RESUME` at `usage_resume_at` and `resume_paused_runs` relaunches — when the reset falls before `HARNESS_JOB_DEADLINE_EPOCH` **and** either `RUNNER_ENVIRONMENT` is `self-hosted` or the wait is at most `REMOTE_WAIT_MAX_SECS`; otherwise `wait-poller`, with the `paused` notification naming the reset time |

| `completed`, `parked`, `park_loop` | `stop` |

**Auto-resume:** the count is carried across automatic continuations only and **reset by any user action** (story index `## Context` → **API errors**): a job whose `HARNESS_INPUT_CHAIN` is `0` — a user's drop, answer or resume — starts with `auto_resumes` at `0` (Task 9's seeding rule), so a run that exhausted its automatic resumes and was later resumed by hand gets its full allowance again. Then, while `auto_resumes < REMOTE_AUTO_RESUME_MAX` and `now + REMOTE_AUTO_RESUME_DELAY_SECS` is before the deadline, sleep the delay, increment `auto_resumes`, clear `PAUSE` / `RESUME` / `PAUSE_ACK`, set `status: running` and `resume_kind: pause`, and relaunch with `spawn_engine … "" 1` — a resume from the committed ledger, the same path the pause resume takes. Local runs gain none of this: every rule in this task runs only in job mode.
