### Task 12 — Relay answers, resumes and pauses for remote records, and keep the local-only passes off them

**Goal:** Make the files the user's commands write into a remote run's local mirror — an `answer_<n>.md`, a `RESUME`, a `PAUSE`, a `PARK_LOOP_CLEAR` — reach the remote run as dispatches, and make sure nothing local watches, gates, restarts or resumes a remote run on its own.

**Depends on:** Task 11, which created remote records (`execution: github-actions`, no `pid`, `status: running` once dispatched), `launch_remote_run` and the `REMOTE_RUN` sibling path in `cli/templates/scripts/autonomous-watcher.sh`, and `cli/test/watcher-remote-dispatch.test.mjs`. Task 5's `remote-run.sh dispatch <branch> --engine <kind> --resume answer --answers-from <clar_dir> --indexes "<n> …" [--park-loop-clear]`, `dispatch … --resume pause`, and `remote-run.sh pause <branch>` (exit 0 sent, 2 refused, 3 `gh` failed). The mirror's statuses are the ones Task 6's `sync` writes; the user's commands sync before they write (Tasks 22–23).

**The contract, stated once for every consumer** (Tasks 22, 23, 24, 30 describe it):

- **Skipped for every record whose `execution` is `github-actions`:** `reconcile_stale_runs` (it has no local process to vanish), `running_count` (a remote run holds no local slot), `check_stalled_runs`, both halves of `usage_gate` (the pause side and the auto-resume side — the job gates itself), and `lane_release_if_idle`'s liveness input. Each skip is one test of the record's field at the top of the per-record loop, with a comment saying why.
- **Parked relay** (`resume_parked_run`): for a remote record, the answered-set computation over the mirror's clarification directory is unchanged; the kill switch still defers; the cap and the lane are skipped. It sends `dispatch <branch> --engine <engine> --resume answer --answers-from <clar_dir> --indexes "<set>"`, adding `--park-loop-clear` when the record carries `park_loop_clear_pending: 1`. On exit 0: `status: running`, `resumed_at`, `resume_kind: answer`, clear `park_loop_clear_pending`, notify `resumed` with `answered clarification(s) #<set>, dispatched`. The pairs stay in the mirror; the next `sync` replaces the directory with the job's. On a refusal or a `gh` failure the record stays `parked`, the files stay where they are, and one log line names the cause — so the next pass or the user can retry.
- **Park-loop clear:** `clear_park_loops` is unchanged for local records; for a remote record it additionally sets `park_loop_clear_pending: 1`, because the count that matters lives in the job's bundle.
- **Paused relay** (`resume_paused_run`): for a remote record with `RESUME` in the mirror, send `dispatch <branch> --engine <engine> --resume pause`; on exit 0 remove `PAUSE`, `RESUME` and `PAUSE_ACK` from the mirror (keeping `PAUSE_PROGRESS.md`), set `status: running`, `resume_kind: pause`, notify `resumed` with `after pause, dispatched`. A deferral or failure removes nothing.
- **Pause relay** (a new pass, `relay_remote_pauses`): for a remote record whose status is `running` and whose mirror holds `<state_dir>/PAUSE`, send `remote-run.sh pause <branch>`; on exit 0 remove the mirror's `PAUSE` and record `pause_relayed_at`. The kill switch does not block a pause — it stops starts, and a pause is not one. **Placement, exactly one call site:** in `tick()`, immediately after `hr_config_load "$MAIN_REPO" || :` and **before** the `if kill_switch_active; then … return 0; fi` block, so it runs on every pass whether or not `AUTONOMOUS_STOP` is present. It is not called anywhere else, and not again after the kill-switch check. It consults neither the lane nor the cap, and it launches, resumes and dispatches nothing but a `pause` (whose `run` job is skipped). With that placement the planned `AUTONOMOUS_STOP` case passes as written.
- **The kill-switch prose, qualified in place.** Because the relay runs ahead of the brake, three passages are amended in the same edit (`.claude/context/cli.md` → `## What "done" means here`). Each says that relaying a remote run's pause is the one action that still runs under the brake, because it starts nothing, and each points at `REMOTE DISPATCH`:
  - the `tick()` block comment *"One pass. The kill switch first, so an operator's brake beats everything else, …"*: the relay of a remote pause comes first, then the kill switch;
  - the `kill_switch_active` doc comment *"checked before every launch and at the top of every pass"*: at the top of every pass, after the remote-pause relay, which starts nothing;
  - the header paragraph `THE KILL SWITCH IS THE OPERATOR'S, AND THIS SCRIPT NEVER DELETES IT.`: its *"stops the watcher from launching or resuming ANY run"* stays true, and the paragraph adds that relaying a remote run's pause still runs under the brake.
- `print_status` shows `execution=` for a remote record.
