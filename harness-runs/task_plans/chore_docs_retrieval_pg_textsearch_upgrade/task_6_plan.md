### Task 6 — Move the compose image to `pg_textsearch` `v1.5.1` and record what it does to a database 1.3.1 built

**Goal:** Build the compose Postgres's `pg_textsearch` from the upstream tag `v1.5.1`, update both records of why that tag was chosen, and show that the rebuilt server reports `pg_textsearch.library_version` `1.5.1` and installs `1.5.1`. Before rebuilding, leave a database that the **1.3.1** server built. Afterwards, record what the 1.5.1 server does with that database before any store opens it. Task 7 then opens it with the Python store.

**Depends on:** Task 3, which moved PGlite to `pg_textsearch` 1.5.1. The compose engine follows it here, so that both engines carry the same `pg_textsearch` version from this commit on. (Task 4 changed only the TypeScript store, and this task does not depend on it.)

**Where this task stops.**

- The Python store's handling of the old database is **Task 7's**. This task leaves the database untouched after the rebuild: no `ALTER EXTENSION`, no store open, no refresh. Task 7 opens it, records the outcome, and drops it.
- The image's base, `pgvector/pgvector:0.8.1-pg18`, **stays**. The story index's `## Context` records that decision. This task records the divergence it leaves (PGlite now bundles `vector` 0.8.7) and changes nothing about it.
- `docs/retrieval.md` is Task 12's.

**Deviations from plan:**

- **Old database built, with `--docs-root docs`.** `index --repo ..` alone warned `docs.root is not set, so no documentation directory is indexed` and indexed `3 files, 44 chunks`. A second run, `index --repo .. --docs-root docs`, printed `index: 71 files, 825 chunks; embedded 781, unchanged 44, deleted 0`. On the 1.3.1 server (`SHOW pg_textsearch.library_version` = `1.3.1`), `pg_textsearch_upgrade_old` reads `pg_textsearch` `1.3.1`, `vector` `0.8.1`, `count(*)` = `825`; `bm25_summarize_index('chunks_bm25')`: `total_docs: 825`, `docs_persisted: 768`, memtable `documents: 57`, three L0 segments (`docs=373`, `163`, `232`), `on-disk: 3465216 bytes`.
- **Blocked at the rebuild: the 1.5.1 library does not load on the base image's server.** With `ARG PG_TEXTSEARCH_TAG=v1.5.1`, `docker compose -f docs-retrieval-service/compose.yaml build postgres` succeeded, and `up -d --wait postgres` ended `container harness-docs-retrieval-postgres-1 exited (1)`. The log: `FATAL:  could not load library "/usr/lib/postgresql/18/lib/pg_textsearch.so": /usr/lib/postgresql/18/lib/pg_textsearch.so: undefined symbol: palloc_mul`.
  - Cause, measured: `pgvector/pgvector:0.8.1-pg18` carries `postgres (PostgreSQL) 18.2 (Debian 18.2-1.pgdg12+1)`, locally and at the registry's current arm64 digest `sha256:fb00e2858f3c…` (pulled by digest, tag not moved). The build stage installs the newest `postgresql-server-dev-18` apt offers (`apt-cache madison`: `18.6-1.pgdg12+2`, `18.4-1.pgdg12+1`, `18.3-1.pgdg12+1`; no `18.2`). From `18.4` on, `utils/palloc.h` declares `extern void *palloc_mul(Size s1, Size s2);` and `#define palloc_array(type, count) ((type *) palloc_mul(sizeof(type), count))`; `18.3`'s still reads `palloc(sizeof(type) * (count))`. `pg_textsearch` 1.5.1 uses `palloc_array` (`src/access/boolean.c`, `src/segment/graph_snapshot.c`, `src/segment/scan.c`); 1.3.1 uses none of the `palloc_array` family, which is why the 1.3.1 build loaded on 18.2.
  - The story's decision that the base stays `pgvector/pgvector:0.8.1-pg18` therefore cannot hold with a 1.5.1 build as the Dockerfile stands. The routes, each the maintainer's: move the base to a pgvector tag whose server is 18.4 or newer; pin `postgresql-server-dev-18` in the build stage to a minor without `palloc_mul` (`18.3` is the oldest apt still serves, and it can be withdrawn); or upgrade the final stage's server packages to the headers' minor.
  - **State left:** the Dockerfile edit was reverted (`git checkout -- docs-retrieval-service/postgres/Dockerfile`), the 1.3.1 image rebuilt and the default project restarted healthy. `SHOW pg_textsearch.library_version` reads `1.3.1`; `pg_textsearch_upgrade_old` survived both recreations (`psql -l`), still reads `pg_textsearch` `1.3.1`, `vector` `0.8.1`, `count(*)` `825`, and no 1.5.1 server ever opened it. It is still the 1.3.1-built database this task and Task 7 need.
  - Verified from the bundles, for whichever route is taken: `@electric-sql/pglite-pg_textsearch` 0.0.12's `pg_textsearch.control` reads `default_version = '1.5.1'` with `pg_textsearch--1.5.1.sql` as the only install script; `@electric-sql/pglite-pgvector` 0.0.11's `vector.control` reads `default_version = '0.8.7'`; `@electric-sql/pglite` 0.5.10's `dist` carries `PostgreSQL 18.6` (record 2 still says `18.3`).
