### Task 9 — The `docs-search-server.sh` launcher and `hr_cache_dir`

**Goal:** Ship the repository-side program that `.mcp.json` starts: an outer-loop script, copied verbatim into `scriptsDir`. It finds the machine-shared retrieval runtime and `exec`s that installation's `docs serve` for the checkout it sits in. The committed `.mcp.json` then names only `<scriptsDir>/docs-search-server.sh` and never a machine path. The script is always written, so no condition is threaded through the outer-loop writer.

**Depends on:**

- **Task 2:** `machineCacheDir()` (`cli/src/machine/paths.ts`), which is `${XDG_CACHE_HOME:-$HOME/.cache}/autonomous-sdlc-harness`, resolved by `resolveMachineDir` (variable when non-empty, else `$HOME/.cache`, one trailing slash stripped, then `/autonomous-sdlc-harness`), plus, from `cli/src/retrieval/runtime.ts`, `RETRIEVAL_CACHE_DIRNAME = 'retrieval'`, `RETRIEVAL_RUNTIME_DIRNAME = 'runtime'` (joined by `retrievalRuntimeDir()` into `<machineCacheDir>/retrieval/runtime`) and `RUNTIME_CLI_RELATIVE = 'node_modules/autonomous-sdlc-harness/dist/cli.js'`. This script mirrors all of them literally. Task 2 declares the mirror in both owners' headers: `cli/src/machine/paths.ts` choice 2 for `machineCacheDir()` (mirrored by `hr_cache_dir`), and `cli/src/retrieval/runtime.ts`'s header for the three literals, naming this script as their one mirror.
- **Task 6:** the test helper `plantRetrievalRuntime(cacheHome, options?)` (`cli/test/helpers/fixture.mjs`), which plants the runtime CLI entry, its `package.json` at this package's version, and each optional peer's `package.json` under `<cacheHome>/autonomous-sdlc-harness/retrieval/runtime/`.
- **Task 8:** the sub-verb `docs serve`, which takes the global `--cwd <root>` and writes nothing to stdout but the MCP transport.

**Where this task stops.** This task writes the script, the exported name constant `DOCS_SEARCH_SERVER_SCRIPT_NAME` and the row built from it. The `.mcp.json` entry that names it, and the permission fragment, are Task 10's. The runtime it `exec`s is installed by Task 12.

**The runtime is the only thing this script runs, deliberately, with no fallback to any other installation.** A committed `.mcp.json` cannot know where an adopter's own CLI lives, and a second branch here would need a second answer from setup and `doctor`. Instead Task 12 skips the install, and Task 13's `retrieval-dependencies` passes, only on `retrievalRuntimeState().installed` (Task 2), whose first file test is this script's `entry`. So a repository `doctor` passes always has an entry this script finds.
