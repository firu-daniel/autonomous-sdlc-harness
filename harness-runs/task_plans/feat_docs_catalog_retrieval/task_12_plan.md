### Task 12 — Setup-time runtime install and model download, and `docs fetch-models`

**Goal:** When the config in effect has retrieval on, have `init` do every download at setup time, so an unattended run never needs the network. First it installs this CLI, at its own version, together with the retrieval peers into the machine-shared runtime directory. Then it downloads both models into the shared model cache. A re-run with both already present does neither.

**Depends on:**

- **Task 2** (`cli/src/retrieval/runtime.ts`): `retrievalPeers(): readonly { name: string; range: string }[]` (read from this package's own `peerDependencies`), `retrievalRuntimeState(): { installed: boolean; version: string | undefined; missing: readonly string[] }` (the one "is the runtime installed?" predicate: the CLI entry exists, its `package.json` version equals this package's, every peer's `package.json` exists), `retrievalRuntimeDir()`, `retrievalModelCacheDir()`, `RUNTIME_CLI_RELATIVE`, and `retrievalCliEntry(): { entry: string; source: 'this-installation' | 'runtime' } | undefined`.
- **Task 3** (`cli/src/retrieval/models.ts`): `fetchModels(): Promise<void>`, the only call made with `allowRemote: true`; `modelFilesPresent(cacheDir): { present: boolean; missing: readonly string[] }`; and `RETRIEVAL_STUB_ENV`.
- **Task 5:** the `cli/src/core/writer.ts` header paragraph on writes outside the engine, which Task 5 extended with the per-checkout `<stateDir>/docs_index/` clause. This task adds the machine-state clause beside it and owns no other part of that paragraph.
- **Task 6:** `cli/src/commands/docs.ts`, which this task extends with `fetch-models`, and the helpers `retrievalEnv(cacheHome)`, `plantModelFiles(cacheHome)` and `plantRetrievalRuntime(cacheHome, options?: { version?: string }): string[]` (plants the CLI entry, its `package.json` at this package's version or `options.version`, and each optional peer's `package.json` under the runtime directory; returns the sorted planted paths) in `cli/test/helpers/fixture.mjs`.
- **Task 9:** `docs-search-server.sh` `exec`s `<retrievalRuntimeDir()>/<RUNTIME_CLI_RELATIVE>` and nothing else, which is why the install skips only on `retrievalRuntimeState().installed`.
- **Task 11:** `init --docs --docs-retrieval` writes `docs.retrieval: true`. Its case (a), and Task 10's wiring cases, already run with `retrievalEnv`, planted model files and a planted runtime, so the step added here finds both satisfied and must not reach the network in them.

**Where this task stops.** `doctor`'s grading of what this step left behind is Task 13's. The runtime directory and model cache are **machine state written outside the write engine**: `npm` and Transformers.js write them. This task records that in `cli/src/core/writer.ts`'s header beside the registry exception and Task 5's index clause, rather than routing it through a `WritePlan`.

**Work:**

- [ ] `setup.ts`, with the header rule *"The rule this module exists to enforce: every download retrieval needs happens here, at setup time, and never on a run."* Export `setUpRetrieval(options: { dryRun: boolean }): { notes: string[]; warnings: string[] }`. It is synchronous, so `init`'s flow stays linear.
  - **(1) Runtime.** Skip **only** when `retrievalRuntimeState().installed` is `true`, noting that the runtime is already installed (naming its `version` and the directory). Whether this installation could load its peers is **not** consulted: the `.mcp.json` launcher (Task 9) runs the runtime and nothing else, so an adopter whose own CLI resolves its peers, including a self-adopted checkout running its own `cli/dist/cli.js`, still needs the runtime. This module does **not** re-spell the three file tests; they live in Task 2's export alone, the same predicate `doctor`'s `retrieval-dependencies` check passes on, so `init` never skips an install `doctor` then fails and the launcher then cannot find. When the runtime is not installed and `RETRIEVAL_STUB_ENV` is set, run nothing and push a warning that a stub run never installs the runtime (the install's counterpart of `docs fetch-models`' stub refusal, so a test that forgets `plantRetrievalRuntime` stays offline and fails visibly instead of reaching the network). Otherwise `mkdirSync(runtimeDir, { recursive: true })` and run `execFileSync('npm', ['install', '--prefix', runtimeDir, '--no-audit', '--no-fund', `autonomous-sdlc-harness@${ownVersion}`, ...peers.map((p) => `${p.name}@${p.range}`)], { stdio: ['ignore', 'ignore', 'pipe'], timeout: 900000 })`. That is a fixed argument vector with no shell (`.claude/context/cli.md` → *"Every child process is spawned with a fixed argument vector"*).
  - **(2) Models.** When `RETRIEVAL_STUB_ENV` is set, note that stub models need no download and skip. When `modelFilesPresent(retrievalModelCacheDir()).present`, note that the models are cached and skip. Otherwise run `execFileSync(process.execPath, [entry, 'docs', 'fetch-models'], { stdio: ['ignore', 'ignore', 'pipe'], timeout: 900000 })` with the entry `retrievalCliEntry()` now answers.
  - **Failure.** A failed step becomes a **warning** naming the command, its exit status and the last stderr line, with the remedy *re-run `npx autonomous-sdlc-harness init`; `npx autonomous-sdlc-harness doctor` reports what is missing*. The wiring is already written and stays valid, and Task 13's checks fail until the step succeeds.
  - **Dry run.** Under `dryRun`, run nothing and emit one note per step naming exactly what would run. For the runtime step, the `installed` skip is decided first, then `dryRun`, then the stub warning, so a dry run with no runtime names the install whether or not the stub is set.
