### Task 4 — Extend the query-set format with optional `situation`, `intent`, `origin` and `negativeKind`, and mark the committed sets' negatives by meaning

**Goal:** Give a query record the four fields the real catalog's set must carry — the situation that would issue the query, its intent, whether it was written or harvested, and whether a negative is a `far` or a `near` miss — as **optional** fields the loader validates by name, state them in the one statement of the format, and class the two committed sets' negatives `far` / `near` **now**, while their reranker scores are still unobservable, so the pooled calibration's `near` class is a judgement about meaning made before any score exists.

**Why the marks land before Task 5.** Task 5 makes every negative's `bestRerankScore` observable in any eval run. The calibration method Task 3 commits pools the committed corpora's negatives with the real catalog's, and its overlapping case reads the `near` class — so a mark written after the scores were visible would be a mark fitted to them. This task runs **no eval arm**: the only code it executes loads the sets.

### Targets

- `evals/docs-retrieval/queries.mjs` — validation of the four fields, and carrying them on each loaded record.
- `docs/retrieval-eval.md` → `## The query-set format` — the four fields, and the query-wording disclosure.
- `evals/docs-retrieval/queries/fixture-catalog.jsonl` and `evals/docs-retrieval/queries/self-docs.jsonl` — `negativeKind` on every negative, nothing else.
- `docs/retrieval-eval-results.md` → `## Threshold calibration` → `### The re-calibration method, fixed before the real-catalog run` — one appended paragraph recording the eight marks and their reasons.

**Depends on:** Task 3, which creates that sub-heading below the `<!-- eval:generated:end -->` marker and states there that the committed sets' negatives are classed `far` / `near` by meaning before their scores become observable — the rule this task carries out.

**The record contract this task produces, which Tasks 6, 11, 12–14 and 20 consume:**

- `situation` — optional non-empty string: one line of the task prompt, plan step or review finding that would issue the query.
- `intent` — optional, one of `surroundings` (feature surroundings and ripples), `convention` (convention and placement rules), `contract` (backend or contract lookups).
- `origin` — optional, one of `written`, `harvested`.
- `negativeKind` — optional, one of `far`, `near`; **legal only on a negative** (empty `labels`), refused by name on a positive.
- `loadQueries` returns each record as `{ id, query, labels, line, source, situation, intent, origin, negativeKind }`, the four new members `undefined` when absent. No existing field changes meaning; a record carrying none of the four loads exactly as today.
- **`export const NEGATIVE_KINDS = Object.freeze({ far: 'far', near: 'near' })`** in `evals/docs-retrieval/queries.mjs` — the **one declaration** of `negativeKind`'s closed value set. The loader's legal-value list is derived from it (`Object.values(NEGATIVE_KINDS)`), never typed beside it. Every consumer that tests or keys on a class imports it — `calibrate.mjs` (Task 6) as `import { NEGATIVE_KINDS } from './queries.mjs'` for the `N` membership test (`negativeKind === NEGATIVE_KINDS.near`) and the `far` / `near` members of `points[].kind`; `arm-a/spread.mjs` (Task 11) as `import { NEGATIVE_KINDS } from '../queries.mjs'` for the `far` / `near` split — so no `'far'` / `'near'` literal is written anywhere else in the eval (`.claude/context/conventions.md` → *"a value is imported from its owner rather than retyped"*). The JSONL values in the committed sets are data, not a second declaration.
