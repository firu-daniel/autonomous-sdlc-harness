### Task 1 — Build each fixture repository by copying a seeded template the test process builds once

**Goal:** Cut the git processes every fixture repository costs from about fourteen to none, by seeding one template repository per variant once per test process and giving every test its own **copy** of it, so every file that calls `createFixture` gets cheaper at every core count without any test changing what it observes.

**Why this task exists (measured by the planner, 2026-09-25, this worktree, 10 cores, Node v20.19.5).** One `createFixture({ files })` with the default remote costs about **108 ms** wall and **~190 ms of CPU**, and it is about fourteen git processes: `init`, two `config`, `init --bare`, `remote add`, `symbolic-ref`, `hash-object`, `commit-tree`, `push`, plus the `receive-pack` / `pack-objects` / `unpack-objects` / `maintenance run --auto` that `push` sets off. A `GIT_TRACE` run of the whole suite counted **21,604** git processes, of which **640** were origin-seeded fixtures — about **9,000 git processes (≈42%) spent building fixtures**, not testing the CLI. The work is CPU-bound (a serial chain of fixtures ran at 97% CPU), so on a 2- or 4-core runner that CPU is wall time. The seeded state is identical for every test: an unborn `HEAD`, the fixture's `user.email` / `user.name`, and an `origin` whose branch points at a commit over the empty tree. Copying that state in-process gives the same repository without re-deriving it.

**Where this task stops.** It changes **how** a fixture is produced and nothing a test sees. It does not touch any `*.test.mjs` file except the new equivalence test below, and it does not make any case run concurrently — that is Tasks 2–4. The helper's exported signatures stay byte-identical: `createFixture({ files = {}, dirs = [], git = true, remote = true } = {})` still returns `Promise<{ dir: string, cleanup: () => Promise<void> }>`, `runGit(cwd, args)` is unchanged, and every existing caller works unmodified.

### Targets

- `cli/test/helpers/fixture.mjs` — the template, the copy path, the exported seeding function, and the header.
- `cli/test/fixture-template.test.mjs` (new) — proves a copied fixture answers every git query a freshly seeded one answers.

**Work:**

- [ ] `fixture.mjs`: move the existing seeding sequence — `git init --quiet`, the two `config` calls, then `seedOrigin(dir)` when `remote` is true — **unchanged, in the same order**, into an exported `seedRepository(dir, { remote })` that returns the origin path (or `undefined`). It is the one place that sequence is written, used both to build the template and by the equivalence test.
- [ ] `fixture.mjs`: add a module-private, lazily built, **memoized promise per variant** (`remote: true` and `remote: false`): the first `createFixture` that needs a variant creates `realpath(mkdtemp(join(tmpdir(), 'harness-fixture-template-')))`, seeds a `repo/` inside it with `seedRepository` (its origin lands at the sibling `repo-origin.git`, by the existing `ORIGIN_SUFFIX` rule), and every later caller — concurrent ones included — awaits the same promise. **Nothing runs at import time** (the header's standing rule: this file is also loaded as a test file of its own). The template root is removed with `rmSync(root, { recursive: true, force: true })` in a `process.once('exit', …)` handler — in-process, never a shelled-out removal (header choice 2).
- [ ] `fixture.mjs`, `createFixture` with `git: true`: after its own `mkdtemp` + `realpath` (unchanged), copy the variant's `repo/` contents into `dir` with `fs/promises` `cp(…, { recursive: true })`; with `remote` also copy `repo-origin.git` to `` `${dir}${ORIGIN_SUFFIX}` `` and rewrite the one absolute path git stored — `remote.origin.url` in `dir/.git/config` — from the template's origin path to the fixture's own, **in-process**, asserting the old path occurred exactly once in that file (throw a `fixture setup:` error otherwise, so a git version that stores the path somewhere new fails loudly instead of pointing two fixtures at one origin). `git: false` and the `files` / `dirs` seeding are unchanged; the returned `cleanup` still removes `dir` and the origin, one path at a time.
- [ ] `fixture.mjs` header: amend the rule paragraph so it stays true — the template is **never handed to a test**; every test still receives its own repository, now a copy — and add a fifth numbered choice, *"The seeded repository is copied, not rebuilt"*, stating the measured cost above (fourteen git processes and ~100 ms per fixture, ~42% of the suite's git processes) and the one path the copy must rewrite.
- [ ] `cli/test/fixture-template.test.mjs` (new; header opens with the rule it enforces: *a copied fixture is indistinguishable, to git, from a freshly seeded one*): for each variant, build one fixture through `createFixture` and one by calling `seedRepository` on a fresh `mkdtemp` directory, then assert equal answers for `git symbolic-ref HEAD`, `git config --get user.email` / `user.name`, `git for-each-ref --format=%(refname)` (**ref names only** — see the object-id note below), an unborn `HEAD` (`rev-parse --verify --quiet HEAD` fails in both), and — for the remote variant — that `git remote get-url origin` names **that fixture's own** sibling `-origin.git` and `git ls-remote origin` lists the same **ref names** in both. **Never compare object ids across the two repositories:** `seedOrigin` makes its commit with `commit-tree -m 'origin seed'` and `ISOLATED_ENV` pins no `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE`, so the commit's id carries the wall-clock second it was made, and the template and the fresh repository are seeded at different moments — a cross-repository id comparison fails whenever the two seedings straddle a second boundary, the exact intermittent failure the story's first top risk rules out. Assert instead, **within each repository separately** (the copy and the freshly seeded one alike): the local `refs/remotes/origin/<branch>` and the origin's `refs/heads/<branch>` name the **same** object; that object's tree (`git rev-parse <ref>^{tree}`) equals the empty tree (`git hash-object -t tree /dev/null`); and its subject (`git log -1 --format=%s <ref>`) is `origin seed`. Pinning the commit dates in `seedRepository` is deliberately **not** the fix — it would change the environment every fixture's seed runs under. Also assert two copies never share an origin path. Tear everything down in-process via `t.after`.
