### Task 4 — Run `init.test.mjs`'s cases concurrently, keeping its one timing-sensitive case outside the suite

**Goal:** Remove the single largest floor on the suite's wall time: `cli/test/init.test.mjs` runs 111 top-level cases (285 counting subtests) one after another — 123 s in the task prompt's measurement, 95 s alone in the planner's — so on a machine with cores to spare the whole of `npm test` waits for this one file. Its longest single case measured 5.2 s, so with its cases in flight together the file's floor drops to its CPU share.

**Depends on:** Task 2, which creates `cli/test/helpers/concurrency.mjs` exporting exactly:

- `CONCURRENCY_VARIABLE` — the string `'HARNESS_TEST_CONCURRENCY'`;
- `CASE_CONCURRENCY` — a positive integer: the variable's value when set to one (`1` = every case in series), otherwise `Math.max(2, os.availableParallelism())`;
- `concurrentSuite(name, fn)` — exactly `describe(name, { concurrency: CASE_CONCURRENCY }, fn)`.

This task imports those and defines no bound of its own.

**Isolation, established rather than assumed (planner's audit, 2026-09-25 — re-check it, do not inherit it).** The header's own choice 1 already states the property this relies on — *"Every test builds its own fixture and tears it down. No directory is shared and none is reused across tests"* — and the code bears it out: every fixture comes from `fixtureFor` → `createFixture`; every other directory a case makes is its own `mkdtemp` (`harness-retrieval-cache-`, `harness-unresolved-`, the push-notification `XDG_CONFIG_HOME`, the plugin-root `CLAUDE_CONFIG_DIR`); every environment override — `COMMIT_IDENTITY`, `NO_COMMIT_IDENTITY`, `HARNESS_SELF_ADOPT`, `XDG_CONFIG_HOME`, `CLAUDE_CONFIG_DIR`, `retrievalEnv(…)` — travels on one subprocess through `runCli`'s `env` argument, and `grep -nE "process\.env(\.[A-Z_]+|\[[^]]+\]) *=[^=]|delete process\.env" cli/test/init.test.mjs` prints nothing. The one case that copies `cli/dist/` copies it into its own temp root and only reads the package (`runCliFrom`). Module-level values (`GIT_TOO_OLD`, the constant tables) are computed once and never written. Worktrees sit at `` `${dir}-feature_x` ``, keyed on the fixture's unique name.

**The one exception, and why it stays serial.** *"the dev-server wrapper starts the server detached and prints a live pid and a readable log"* asserts wall-clock bounds — the wrapper must return within `RETURNS_PROMPTLY_MS` (3000 ms) while its stub sleeps `DEV_SERVER_STUB_SECONDS`, and `eventually` polls a pid for two seconds. Those bounds are about the wrapper, not about how loaded the machine is, and under a file-wide burst of subprocesses on a 2-core runner they would start measuring the load. It is the only case in the file matching `grep -nE "Date\.now|eventually\(|process\.kill"`.
