### Task 9 — The regression gate: the recorded floor, `run-gates.sh`, gate 11 in `docs/development.md` §5, and the post-move regeneration of the results file's generated region

**Goal:** Make arms B–E a standing regression check where this repository's other gates live, against a recorded floor, so a change that quietly degrades retrieval fails a gate instead of being noticed later — write that gate into §5, which is the definition of done for a change in this tree — and, from the same post-move run, regenerate `docs/retrieval-eval-results.md`'s generated region so the file of record describes the threshold the branch actually ships.

**Depends on:** Task 3, whose `evals/docs-retrieval/args.mjs` accepts `--corpus`, `--arms`, `--k` and `--floor`. Task 4, whose `evals/docs-retrieval/run.mjs` exports `runEval(options)` returning the per-corpus, per-arm result object (`recall@1/3/5`, `MRR`, strict variants, `p50`/`p95`, per-query records), writes nothing when no `--out` is given, and rewrites **only** the region between `<!-- eval:generated:start -->` and `<!-- eval:generated:end -->` when one is. Task 5, which moved `ABSTAIN_SCORE_THRESHOLD` — **the floor is taken after that move**, because abstention changes arm E's hit set and a floor recorded before it would describe a threshold that no longer ships. Task 14, which has already quoted the **pre-move** per-query `bestScoreOnPositive` / `bestScoreOnNegative` distributions into `docs/retrieval-eval-results.md` → `## Threshold calibration`, a hand-written section below the end marker — which is what makes the regeneration below safe to perform: the calibration evidence is no longer only in the generated region.

**Why this task regenerates the results file, and why it is the task that does.** Task 4 generated the region **before** the threshold moved, so the shipped file otherwise records arm E under a retired threshold. This task is the last writer of that region on the branch — Tasks 10–13 do not touch it, and Tasks 6, 7, 8 and 14 write only hand-written sections below the end marker — and it is already running both arms post-move. Regeneration is lossy in one direction: on an abstaining query `searchDocs` returns `{ abstained: true, hits: [] }`, so the post-move `json` fence has no `bestScoreOnPositive` for the queries the new threshold abstains on. That is acceptable **only because** Task 14 has already quoted those pre-move distributions into `## Threshold calibration`, which the runner never rewrites. Verify that quotation is present in the file **before** regenerating; if it is not, stop and say so rather than running with `--out`.

**What the gate does when the models are absent, settled here.** It is **reported and not counted among the failures**, so `bash scripts/run-gates.sh` still exits 0 on a machine whose retrieval model cache is empty. The mechanism is the `failed` array: the script's tail is `if [ ${#failed[@]} -eq 0 ]; then … exit 0; fi; … exit 1`, so *counted among the failures* and *fails the script* are the same statement, and `commands.test` reaches that script through the allow-listed `bash scripts/test.sh` — counting it would make this repository's verification command red for every contributor and every future branch worktree without the hand-provisioned cache. The missing-`claude` branch in gate 1 is therefore **not** the model to copy here: that tool is a stated prerequisite of working in this tree, while the model weights are a several-hundred-megabyte download `docs/development.md` §5 already sorts into gate 10 as the gate a process cannot run unattended. The blocked report goes where §5 already puts that class — the script's `== gates this script cannot run` block — and it is reached by a distinct exit status special-cased in the script rather than by the `gate` helper, whose only grading is zero-versus-non-zero. A **shortfall against the floor still fails the script**; only the cache-absent status is exempt. Every *"`run-gates.sh` passes"* verification line in this plan is therefore true unconditionally, with or without the cache.

**Which corpus the gate enforces, and why only one.** The gate runs **`fixture-catalog` only**. That corpus is committed and changes only when this eval changes, so its numbers are a property of the retrieval code. `self-docs` is this repository's own documentation and moves whenever any branch edits a document — a floor over it would fail on unrelated work and be disabled within a month. `self-docs` numbers stay recorded in `docs/retrieval-eval-results.md` and are re-taken deliberately, not enforced. **That reasoning is written down once, and not here:** `docs/retrieval-eval.md`'s regression-floor section is the record of the floor policy, and it is Task 10's to write. This paragraph is context for the implementer of this task; what ships from this task cites that section rather than restating it.

**A pointer this task writes and the next task fills.** `floor.json`'s `see` field and §5's gate 11 pointer both name `docs/retrieval-eval.md` → the regression-floor section, which **Task 10 creates**, immediately after this one. The pointer is therefore unresolved for exactly one commit, deliberately: the alternative is a second copy of the policy that outlives the branch. Task 10's verification is where both pointers are read back and confirmed to resolve. Hand the two exact pointer strings over in this task's commit body so that task quotes them rather than guessing the heading.

**Why `run-gates.sh` and not a bare invocation.** `commands.test` points at that script and the allow-listed `bash scripts/test.sh` wraps it; commands inside it run as a bash subprocess with no per-command permission check, which is how it already runs `npm run build`, `node cli/dist/cli.js` and `claude plugin validate`. A runner invoked as a bare `node …` from a tool call matches no entry in `.claude/settings.autonomous.json` and **stalls** the run rather than failing it. `AUTONOMOUS_SDLC_HARNESS_RETRIEVAL_STUB` is set nowhere on that path, so the gate runs the real models by default, which is what the eval requires. **Add no entry to `.claude/settings.autonomous.json`.**
