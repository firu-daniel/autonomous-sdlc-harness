### Task 11 — The arm A hand-run procedure, written for an operator at a terminal

**Goal:** Write the procedure an operator follows to run arm A by hand — the exact command, the read-only tool set it runs under, how it is kept off the network, how its token cost is read out of the run's output, and how many repetitions to take for the spread — and run none of it.

**Depends on:** Task 6, which committed arm A's harness: `evals/docs-retrieval/arm-a/agent-task.md` (the task text, with a single `{{query}}` token — named `agent-task.md` rather than `prompt.md` so it stays off the native eval runner's `evals/**/prompt.md` case-discovery glob, and the procedure spells the name exactly as committed), `evals/docs-retrieval/arm-a/run-arm-a.sh` (the hand-run invocation, taking the corpus root, the query-set file and an output path, and reading the agent binary from `${HARNESS_AGENT_CLI:-claude}`), `evals/docs-retrieval/arm-a/score-transcript.mjs` (exporting `scoreTranscript({ transcript, queries })`) and `evals/docs-retrieval/arm-a/sample-transcript.json` (the record shape: `id`, `query`, the returned refs in order, the wall time and the usage block verbatim). Task 4, whose `evals/docs-retrieval/run.mjs` reads `--transcript <path>` through `scoreTranscript` and is the **sole writer** of arm A's row in `docs/retrieval-eval-results.md`'s generated region. Task 10, which created `docs/retrieval-eval.md`, documented `--transcript` in the argument surface, and left a `## Running arm A by hand` heading with one line reserving it for this task.

**This task writes the procedure and does not execute it.** No `claude -p` call is made on this branch, for the reason Task 6's file states and `docs/retrieval-eval-results.md` → `## Arm A — awaiting a hand run` records: the permission profile carries no `claude` grant, an unmatched tool call stalls an unattended run in print mode rather than refusing, and the `scratch-run.sh` route is declined on purpose rather than unavailable. Say that in the procedure too, in one sentence, so the operator knows why they are the one running it.

### Targets

**Work:**

- [x] **The exact command**, in a fenced block, one command per line, with every argument spelled out rather than described: the working directory (the fixture corpus root, so the agent cannot read past it), the agent-task file (`agent-task.md`), the query-set file, the output path, and the binary indirection `${HARNESS_AGENT_CLI:-claude}`. Give the invocation of `run-arm-a.sh` as the operator runs it, and say that the script's own argument paths are **relative to the base the script documents** rather than to a checkout root.
- [x] **The tool set, stated as a property and not as a flag list alone**: read-only over the corpus — `Read`, `Grep` and `Glob` granted; `Bash`, `Write`, `Edit` and every web tool withheld. Say what each withheld tool would have let the arm do that would invalidate the measurement: a web tool makes the arm something other than index-first navigation over the corpus, and a shell makes the tool fence meaningless. **How it is kept off the network:** the withheld web tools are the whole of it on the tool side, and the operator additionally confirms the run reached no network by checking the run's own output for any web tool call. The session's own model traffic is not "the network" in this sense, and the procedure says so rather than leaving a reader to wonder.
- [x] **How the token cost is read out of the run's output**: name the output format the script requests, the field that carries the token counts and the field that carries the cost, and show one worked record with invented numbers, taken from the committed `sample-transcript.json`'s shape. State that the figure recorded for arm A is the **sum over the query set** for one repetition, and that a per-query figure is kept as well, because arm A's cost is the column arms B–E cannot have.
- [x] **How many repetitions, and how the record is shaped**: take **five** repetitions of the whole query set, and record every one — the median and the p95 across repetitions for latency and for token cost, plus the per-repetition recall@5 and MRR, because an agent arm is not deterministic and a single run has no spread to report. Say that a repetition whose returned refs differ from the others is kept and reported rather than discarded, and that the spread itself is a result: an arm whose answers move between runs is a different proposition from one that does not, whatever its mean.
- [x] **What to do with the result**: score each repetition through `scoreTranscript({ transcript, queries })`, which hands the records to the same metric code arms B–E use, then **re-run the eval** — `--out docs/retrieval-eval-results.md --transcript <path>`, through the execution route `docs/retrieval-eval.md` names — and let `results.mjs` regenerate arm A's row from those records in the same walk it renders every other row. State plainly that the row is **never hand-edited**: it sits inside the `<!-- eval:generated:start -->` / `<!-- eval:generated:end -->` region, which has one writer, so a hand edit there is destroyed by the next `--out` run. The **spread** is hand-written, and goes under `## Arm A — awaiting a hand run`, **below the end marker** — hand-written territory — renaming that heading once a number exists. Point at `docs/retrieval-eval.md`'s own decision rule as what the filled row is then read against, and say that this is the step that, together with the private-catalog numbers, closes the roadmap row — not this branch.
