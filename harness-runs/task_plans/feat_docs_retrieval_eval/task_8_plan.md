### Task 8 — Cold-build wall time and index size on disk, through `scratch-run.sh`

**Goal:** Measure the **real-model cold build** of a persisted index on the larger committed corpus and the **size on disk** of the resulting index directory, report both **per chunk and in total**, state the extrapolation to roughly 1,500 chunks, and apply the standing 60-second rule to it.

**Depends on:** Task 3, whose `evals/docs-retrieval/corpora.mjs` exports `corpusConfig({ repoRoot, corpus, docsRoot, conventions }) → { id, config }` and whose `evals/docs-retrieval/index-build.mjs` exports `buildIndex({ repoRoot, config })`, honouring a `--data-dir` so the store persists instead of running in memory. Task 4, whose `docs/retrieval-eval-results.md` carries an empty `## Cold build and index size` section below its `<!-- eval:generated:end -->` marker.

**The standing decision rule this task applies.** **If the cold build exceeds 60 seconds, the build moves into `setup-worktree.sh`.** Sixty seconds is the line because the agent runner's MCP tool-call timeout defaults to 60 s and an adopter may lower their Bash timeouts further. Apply it to the extrapolated figure here; the hand run of `docs/development.md` §5 gate 10 against a real catalog is what settles it on a measured number rather than an extrapolated one. **Plan on the rule tripping:** the provisioning pre-step's in-memory, warm-cache build ran 166 chunks in 9,747 ms — 58.7 ms/chunk, which extrapolates to about 88 s at 1,500 chunks and crosses 60 s at roughly 1,020. Do **not** quote those pre-step numbers as this task's result: that build was in memory, on a warm model cache, and measured no size on disk. Re-measure all of it.

**Why this goes through `scratch-run.sh`.** Clearing an index directory to force a cold build wants a recursive removal, which is a **`deny` floor** entry in `.claude/settings.autonomous.json` — evaluated before `allow` and not overridable, so no grant can reach it — and measuring a directory's size wants `du`, which has no entry at all and therefore **stalls** an unattended run. Both are reached by running a **file** under `harness-runs/scratch/` with `bash scripts/scratch-run.sh`, which executes a file rather than a command string. Inside that file, do both **in process** — `fs.rmSync(dir, { recursive: true, force: true })` and a `fs.statSync` walk that sums `size` and, separately, `blocks * 512` — never by shelling out; `.claude/context/conventions.md` → `## Shell assets` already requires the in-process form of the first. **Add no entry to `.claude/settings.autonomous.json`.**

**Where the index is built, and why not under `stateDir`.** This repository has no ignore rule for `harness-runs/docs_index/` — `init` writes one only when retrieval applies, and it does not here — so building there risks committing a derived cache. Build into `harness-runs/scratch/docs_index/` instead, which `.gitignore` excludes by contents. It is the same store, opened the same way, so the size figure is the one `<stateDir>/docs_index/` would have; say that in the recorded result rather than leaving it to be inferred.
