### Task 4 — Arms B–E, the metrics, and the results file of record

**Goal:** Run the four library arms on the same queries through the retrieval code's own `searchDocs`, compute recall@k, MRR, p50/p95 latency and cost per arm, and write the results file of record — human-readable tables above a machine-readable fenced block, with arm A's row present and empty.

**Depends on:** Task 3, which exports `corpusConfig({ repoRoot, corpus, docsRoot, conventions }) → { id, config }`, `loadQueries(path)`, `assertLabelsResolve(queries, chunkKeys)`, `buildIndex({ repoRoot, config }) → { store, embedder, reranker, refresh, chunkKeys, warnings, snapshot, close }` and `parseArgs(argv)`. **`snapshot` is `{ files, chunks }`**, copied by Task 3 straight off `refreshIndex`'s returned `RefreshResult.files` / `.chunks` — the corpus stamp of the run that just built the index. **It is never counted by hand and never recomputed in this task**: this task's only job with it is to carry it through `runEval`'s result object and render it into the provenance, because `self-docs` is a moving corpus (the story index's snapshot rule) and every figure taken over it is read with its stamp beside it. Tasks 5, 9, 10 and 14 quote what this task renders. Task 2 committed the two query sets; a record carries `id`, `query` and `labels` of `{ ref, grade }`, and **an empty `labels` array is a negative query** — excluded from recall and MRR, and the other half of the abstention calibration.

**The five arms, and the one table that declares them.** (A) index-first navigation — **not run here**; its harness is Task 6's and its row is written empty by this task; it has no `SearchMode`. B–E are the `SearchMode` values of `cli/dist/retrieval/search.js` → `searchDocs({ store, embedder, reranker, query, k, mode })`, called directly, never reimplemented. That module already declares the set **and its order** as an exported single source:

```
export type SearchMode = 'lexical' | 'vector' | 'fused' | 'fused-rerank';
/** Every {@link SearchMode}, in the order a refusal lists them. */
export const SEARCH_MODES: readonly SearchMode[] = ['lexical', 'vector', 'fused', 'fused-rerank'];
```

`.claude/context/conventions.md` → `## Registries and dispatch tables` makes that a single source *"with no second list beside it"*, so **no file on this branch retypes the letters or the modes**: `arms.mjs` below is the one declared arm table, built by pairing letters onto `SEARCH_MODES` imported from the very module `searchDocs` comes from, and every other reader on the branch — `args.mjs`'s `--arms` default and refusal (Task 3), `check-floor.mjs` and `floor.json`'s arm keys (Task 9), `results.mjs`'s columns and `metrics.mjs`'s abstention branch below — reads that table.

**Work:**

- [ ] `arms.mjs` — two things, the table and the runner over it:
  - **The single declared arm table.** Export one ordered array of `{ letter, mode }` — `ARMS` — built by pairing the letters `B`, `C`, `D`, `E` **onto `SEARCH_MODES` imported from `cli/dist/retrieval/search.js`**, index by index, plus the arm A entry whose `mode` is `null`. Build it by mapping over `SEARCH_MODES` rather than by writing four rows, so a fifth `SearchMode` added there produces a **letter-supply failure here** — refuse by name at module load when the letters run out — rather than a silently missing row. Export with it the helpers every other reader uses instead of restating a letter: the default letter set (every entry with a `mode`), a lookup from letter to entry, and a by-name refusal listing the table's own letters. `args.mjs` (Task 3) returns raw `--arms` letters and defers both the default and that refusal to here.
  - **The arm runner.** Export `runArm({ session, arm, queries, k, repeat })`, taking `arm` as a table entry and reading its `mode` from there rather than from a letter test, returning one record per query — `id`, `arm`, the ordered `hits` as `{ ref, score }`, `abstained`, and `durationMs` for each repetition. Time each call with `performance.now()` around `searchDocs` alone. With `repeat > 1`, run every query once per repetition in query order and keep every duration; the hits of the first repetition are the ones scored, and a repetition whose hit refs differ from the first is a **non-determinism warning on the record**, not a silent average. Record `embedCalls` and `rerankCalls` per arm by counting calls through the embedder and reranker the session hands over.
- [ ] `metrics.mjs`: export `scoreArm(records, queries, { kValues: [1, 3, 5] })`. For each positive query, a hit is relevant when its `ref` is a label with `grade >= 1`; **recall@k** is the share of positive queries with at least one relevant ref in the top k, and **MRR** is the mean of `1 / rank` of the first relevant ref (0 when none). Compute the same pair again over `grade == 3` labels only and report it as the strict column. Latency is `p50` and `p95` over every recorded duration of that arm, by nearest-rank. Negative queries do not enter either metric; they produce `abstainedOnNegative` — **computed for every arm with no branch at all**, as the count of that arm's negative-query records whose `abstained` is true. `search.js`'s header says only the reranking mode ever abstains, so the arms that cannot will report `0` as a measured fact rather than as a letter test; there is no `arm === 'E'` anywhere in this module, and a mode added to `SEARCH_MODES` needs no edit here — and `bestScoreOnNegative`, beside `bestScoreOnPositive` for every positive query. **Those two distributions are what Task 5 calibrates the threshold on, so they are per-query values in the machine half and not only summarised.**
- [ ] `results.mjs`: render, from one in-memory result object, both halves of the file so they cannot disagree — a per-corpus table whose rows are **generated by walking `arms.mjs`'s table in its declared order**, one row per entry, with the `Arm` and `Mode` cells read off the entry rather than written out (a new `SearchMode` therefore gains a row here for free), carrying (`Arm`, `Mode`, `recall@1`, `recall@3`, `recall@5`, `MRR`, `strict recall@5`, `strict MRR`, `p50 ms`, `p95 ms`, `cost`), a provenance section, and a trailing fenced ```json block carrying every per-query record. **Arm A's row is present** with every metric cell `—` and its `cost` cell reading `awaiting hand run`; the table's footnote names Task 11's procedure as what fills it.
