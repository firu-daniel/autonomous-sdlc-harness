### Task 3 — Runner core: runner-owned config, index build, label hygiene, argument surface

**Goal:** Build the half of the eval runner that is not an arm: compose the `HarnessConfig` the corpus is read through, build the index for a named corpus, load the query set, **fail loudly on a label that no longer resolves to a real heading**, and parse the argument surface — including `--repo <path>`, so the eval can be pointed at any adopter's checkout.

**Depends on:** Task 2, which committed `evals/docs-retrieval/queries/fixture-catalog.jsonl` and `evals/docs-retrieval/queries/self-docs.jsonl` and the `fixture-catalog` documents under `evals/docs-retrieval/corpora/fixture-catalog/docs/`. The record shape those files carry is restated below so this file is self-contained.

**Why the runner owns the gate, and only the gate.** `cli/src/retrieval/session.ts` refuses to open a session unless `retrievalApplies(config)` — `phases.docs` **and** `docs.retrieval` both true — and this repository's `harness.config.json` has `phases.docs: false` and no `docs` key. **Leave that file alone.** `cli/src/retrieval/corpus.ts`'s own header states the gate "is its callers' to check, not this module's", so this runner supplies `docs` and `phases` itself and drives `corpusFiles` → `refreshIndex` → `searchDocs` directly, never `openRetrieval`. `retrievalApplies` reads `phases.docs` and `docs.retrieval` **and nothing else**, so owning the gate does not extend to owning `layers[]`: that list is read out of the real `harness.config.json`, because the same header's **first** sentence forbids a copy of it anywhere. The two halves are separable and the runner takes only the first. It imports the compiled retrieval modules under `cli/dist/retrieval/` — the real interfaces, never a copy of them — so `npm run build` is its precondition, which is already true inside `scripts/run-gates.sh`, where gate 2a builds before anything downstream runs.

**The query-set record shape.** One JSON object per line: `id` (unique, stable), `query` (the text handed to the arm), `labels` (an array of `{ ref, grade }`). `ref` is `path#anchor` exactly as `SearchHit.ref` renders it — repo-relative path, GitHub-style slug, `path` alone for a preamble chunk. `grade` is an integer `1`–`3`. **An empty `labels` array is a negative query**: nothing in the corpus answers it, it is excluded from recall and MRR, and its best score is what the abstention calibration reads.

### Targets

- `evals/docs-retrieval/corpora.mjs` (new) — corpus resolution.
- `evals/docs-retrieval/queries.mjs` (new) — query-set loading and label hygiene.
- `evals/docs-retrieval/index-build.mjs` (new) — models, store and refresh.
- `evals/docs-retrieval/args.mjs` (new) — the argument surface.

**Work:**

- [ ] `corpora.mjs`: export `corpusConfig({ repoRoot, corpus, docsRoot, conventions })` returning `{ id, config }`, where `config` is a plain `HarnessConfig`-shaped object carrying `stateDir`, `docs: { root }` and `layers: [{ name, path, conventions }]` and nothing else. Two built-in ids:
  - `self-docs` → **read the `harness.config.json` at the resolved `--repo` root and take `layers[]` and `stateDir` from it verbatim**, then override **only** `docs: { root: 'docs' }`. That override is the whole of what the runner owns: `corpus.ts`'s header states that the corpus is *"every Markdown file under `docs.root` plus every conventions document `layers[]` names — nothing else, and no copy of that list elsewhere"*, so **the layer list is never retyped here** — not as a literal, not as a default, not as a fallback when a layer is missing. A layer added to `harness.config.json` is covered by the next run with no edit to this file. If the file is absent or carries no `layers`, **refuse by name** rather than substituting a list.

    **The rule this corpus is pinned by — stated here once, because it binds Tasks 5, 9 and 10.** `docs.root: 'docs'` means `self-docs` holds **every** `*.md` under `docs/`, including the documents this branch itself adds there: from the moment Task 4 creates `docs/retrieval-eval-results.md`, the eval's own file of record is inside the corpus it measures, and Tasks 10 and 12 move it again. The corpus is **not** filtered to pin it: `refreshIndex` calls `corpusFiles` itself (`cli/src/retrieval/refresh.ts`), so excluding two files would mean editing `cli/` code this branch has no reason to touch, and this runner never edits `corpus.ts` or `refresh.ts`. The chosen rule is the other one: **`self-docs` is a moving corpus and every figure taken over it is stamped.** So the runner makes the stamp available to every caller rather than leaving each one to count files: `buildIndex` returns `snapshot: { files, chunks }` taken straight off `refreshIndex`'s own result (`RefreshResult.files` / `.chunks`), and that object is what every task quoting a `self-docs` number stamps with. Both numbers are **derived from that run's refresh result, never typed as a literal**. The consequence every later task obeys: two `self-docs` figures carrying different stamps are not a before/after pair, and a comparison meant to isolate one variable takes both of its numbers in one pass over one tree. `fixture-catalog` needs no stamp — it is committed and moves only when this eval changes — but it is stamped the same way so the provenance has one shape.
  - `fixture-catalog` → `docs.root` `evals/docs-retrieval/corpora/fixture-catalog/docs` with **no** `layers` entries. This one is composed outright and mirrors nothing: its config is a fixture with no layer list to copy.
  - An **ad-hoc** corpus is composed from `--docs-root` plus zero or more `--conventions` paths, which is how the eval runs against an adopter's checkout; those paths are an operator's argument, not a copy of anything. Export the built-in ids as one array so every message that lists them reads it.
- [ ] `queries.mjs`: export `loadQueries(path)` — parse one JSON object per line, refusing a duplicate `id`, a missing `query`, a non-integer or out-of-range `grade`, and a malformed line, each refusal naming the file, the line number and the field. Export `assertLabelsResolve(queries, chunkKeys)`: every `ref` of every label must be a member of `chunkKeys` — the `key` set of the chunks the index just built, which is `path#anchor` or `path` alone, the same string `SearchHit.ref` renders. On a miss, **throw, naming the label**, in exactly this shape so the failure is greppable and Task 10 can quote it: `eval: label <ref> (query <id>, <query-file>) resolves to no chunk in corpus <corpus-id>`. A negative query has no labels and is skipped by this check rather than exempted from it by a flag.
- [ ] `index-build.mjs`: export `buildIndex({ repoRoot, config })` returning `{ store, embedder, reranker, refresh, chunkKeys, warnings, snapshot, close }` — `snapshot` being the `{ files, chunks }` corpus stamp the first bullet settles, copied from `refreshIndex`'s returned `RefreshResult.files` and `.chunks` and from nowhere else. Hand that field's name and shape over in this task's commit body: Task 4 renders it into the results file's provenance and Tasks 5, 9 and 10 quote it. It **refuses before loading anything** in three cases, each naming what to do: the stub variable is set (*"the eval records real-model numbers only; unset it"*), `modelFilesPresent(retrievalModelCacheDir()).present` is false — name the paths that same call's `.missing` array holds — or `retrievalRuntimeState().installed` is false. **`modelFilesPresent` returns an object, not a boolean** (`cli/src/retrieval/models.ts`: `modelFilesPresent(cacheDir: string): { present: boolean; missing: readonly string[] }`), so the branch condition is `.present` and the message's file list is `.missing`; a bare `if (!modelFilesPresent(dir))` is always false and the refusal would never fire. **These names come from two compiled modules, not one — import each from its own:** `RETRIEVAL_STUB_ENV`, `modelFilesPresent` and `resolveModels` are `cli/dist/retrieval/models.js`'s exports; `retrievalModelCacheDir` and `retrievalRuntimeState` are `cli/dist/retrieval/runtime.js`'s. A single import line naming all five fails at module load. **The stub variable's name is never retyped as a literal — not in the check and not in the message.** Import `RETRIEVAL_STUB_ENV` from `cli/dist/retrieval/models.js` — the same module this bullet already imports `resolveModels` and `modelFilesPresent` from, and the constant's only home — read the value as `process.env[RETRIEVAL_STUB_ENV]`, and interpolate the same constant into the refusal text, because `.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time` binds the printed name as well as the read (*"including in the message that names it to a reader"*). The runner is the first consumer of this variable outside the package that owns it, so a rename must break the build rather than the message. Then `resolveModels({ allowRemote: false })`, `openPgliteStore({ dataDir, dimensions })` — `dataDir: undefined` unless `--data-dir` names one, so the default run writes nothing into any tree — and `refreshIndex({ repoRoot, config, store, embedder })`. Surface `corpusFiles`' warnings rather than swallowing them, and derive `chunkKeys` from the same chunking the refresh used so the hygiene check cannot drift from the index.
- [ ] `args.mjs`: export `parseArgs(argv)` for `--repo <path>` (default: the checkout the runner file sits in, resolved from a bare `git rev-parse --show-toplevel`), `--corpus <id>`, `--docs-root <path>`, `--conventions <path>` (repeatable), `--queries <path>` (defaulting to `evals/docs-retrieval/queries/<corpus-id>.jsonl` for a built-in id), `--arms <letters>` (**no letter is spelled in this module — no default list and no legal-letter check here**: `parseArgs` returns the raw letters as given, or `undefined` when the flag is absent, and the default set and the by-name refusal are Task 4's `arms.mjs`, which owns the single declared arm table. Say so in this module's header and in the `--arms` line of the refusal that lists the legal flags, so the boundary is drawn here rather than inferred), `--k <n>` (default 5), `--repeat <n>` (default 1), `--out <path>` (absent means **nothing is written**), `--data-dir <path>`, `--floor <path>` and `--transcript <path>` (an arm A hand-run transcript; **its one reader is Task 4's `run.mjs`**, which scores it through `scoreTranscript` and renders arm A's row from it — this module parses the path and resolves it against `--repo`, and does nothing else with it). An unknown flag is refused by name with the legal set listed. Every path is resolved against `--repo` unless absolute.
- [ ] Give each of the four modules a header comment stating what it owns, in the shape `cli/src` modules use — these files are read by an operator running the eval on their own checkout, and the header is where the rule each holds is written down. `corpora.mjs`'s header states **both halves of the boundary**: that the runner supplies `docs` and `phases` itself because `retrievalApplies` is false in this repository, `harness.config.json` is deliberately not changed, and `corpus.ts`'s header says the gate is its caller's; **and** that the runner does **not** own `layers[]`, because that same header forbids any copy of the conventions list, so `self-docs` reads the list out of the real configuration and overrides `docs.root` alone. Both sentences cite `cli/src/retrieval/corpus.ts`'s header by name, so a reader of either module finds the other.
