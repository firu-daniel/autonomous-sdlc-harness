### Task 11 — Record the credential design, its hygiene limits and the upgrade note in `docs/remote-execution.md`

**Goal:** `docs/remote-execution.md` becomes the one place the job's credential design is decided and argued (goal 6). Every other document cites it. It records:

- what the session can no longer read, and that this is hygiene unless the sandbox's measured PID namespace and no-new-privileges hold;
- the chosen push-credential route, the candidates weighed and rejected, and what each assumes;
- the CI-trigger change;
- the push scan's visible channel;
- the five-checkout paragraph re-counted;
- the upgrade note an adopter must act on.

**Depends on:**

- **Task 6** (`harness-run.yml`):
  - **No `HARNESS_GIT_TOKEN` in `run`.** It is referenced only by the agent-free `open` job (before `run`, `chain` 0, `remote-run.sh open`) and the agent-free `deliver` job (after `run`, `remote-run.sh deliver` on the downloaded `harness-state` bundle). Each checks out and runs the **default branch's** scripts.
  - **`run`'s own credential.** The `run` checkout sets `persist-credentials: false`. `push-credential store` (Task 5) writes `github.token` as one path-scoped entry in `~/.git-credentials`, resolved at store time to an absolute `<store_file>`, and then sets three keys in the checkout's local config, in this order: `credential.https://<host>.useHttpPath true`, `credential.https://<host>/<path>.helper "store --file <store_file>"` — the helper names the file by **absolute path**, never a plain `store` — and last the job push-credential marker `harness.pushCredential job-token` (owned by `lib/harness-run-lib.sh` → `HR_PUSH_CREDENTIAL_KEY` / `HR_PUSH_CREDENTIAL_JOB_TOKEN`, Task 2). `push-credential erase` is `run`'s last step and `--unset`s all three.
  - **Why the path is fixed in `.git/config`.** That checkout is the watcher's main checkout, whose `.git/` the profile write-protects from the session, so its `.git/config` is a record the session cannot write. `push-branch.sh`'s scan (Task 3, through Task 2's `hr_credential_values_var`) reads the job token's file from the `store --file <absolute path>` value there, never from `HOME`; in a job that is the only route by which the job token reaches the scan, because Task 4 strips `GH_TOKEN` from the session. A plain `store` helper value adds nothing to the scan. The marker, read from the same record, is how `push-branch.sh` knows it is in a job and refuses a workflow-file change.
  - **Ordering.** `collect` needs `[run, deliver]`.
  - **Persisted checkouts.** `open`, `deliver` and `collect` persist `github.token`, and `warm` and `run` do not.
- **Task 5.** `deliver` flips the draft ready with `HARNESS_GIT_TOKEN` when set (retrying once with the job's token) and logs which token made the flip. When the secret is set and the pull request is already ready, it first converts it back to a draft with the job's token (`gh pr ready --undo`, the same `pull-requests: write` grant), so `ready_for_review` fires on every run's final tip. A refused conversion — a plan without drafts — is one `::warning::` line, and that tip gets no `ready_for_review`.
- **Task 4.** The watcher strips every `sandbox.credentials.envVars` name but `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN`, plus `HARNESS_PUSH_URL` and `HARNESS_GIT_TOKEN`, from the agent's environment, and stops a run on a push-refusal record, whatever its reason (`failed` with detail `push refused: <reason>`, `::error title=Push refused::`, decision `stop`). It writes nothing to the job summary: `remote-run.sh save`'s `### harness run <branch>` row carries that `failed` detail.
- **Task 3.** `push-branch.sh` refuses commits that carry the job token, `HARNESS_GIT_TOKEN`, an extraheader or a stored git credential, raw or in base64. While the job push-credential marker `remote-run.sh push-credential store` sets is present, that is in a GitHub job, it also refuses, at the first push, commits that change a file under `.github/workflows/` (a merge counted against its first parent). It records either refusal under `<main>/.git/harness-push-refusals/` and exits 0.
