### Task 1 — Scaffold the `harness-docs-retrieval` package, its lockfile and the `scripts/python-service.sh` toolchain wrapper

**Goal:** Give the repository a Python package laid out as a peer of `cli/`: `pyproject.toml`, a src layout, a pinned `uv.lock` and one console entry point whose sub-command table later tasks fill. Add one wrapper through which every Python toolchain command runs as a literal an unattended run can issue.

**Precondition (manual):** `uv` is installed on the machine (story index → `Manual setup required:`). If `uv` is absent or PyPI is unreachable when you run `lock` / `sync`, stop and return a blocker naming which. Never install `uv` or a Python interpreter yourself, and never fall back to `pip` or the system `python3` (3.9, which the MCP SDK does not support).

**Where this task stops.** This task creates the empty frame and no retrieval behaviour. The sub-command table ships with **no rows**: `serve-mcp` is Task 11's, `serve-http` Task 12's, and `index`, `self-check` and `fetch-models` Task 13's. Each of those tasks appends its row to the literal list below. Wiring the wrapper into `scripts/run-gates.sh` is Task 16's. The wrapper's `container-test` sub-command is Task 15's, and this task only reserves its name and its exit status in the header.

**Work:**

- [ ] `scripts/python-service.sh`: `#!/usr/bin/env bash`, `set -uo pipefail`, and a header comment stating what it is, its sub-commands and its exit contract. It resolves the repository root from `${BASH_SOURCE[0]}` through `git -C`, exactly as `scripts/run-gates.sh` does, then works in `docs-retrieval-service/`. Sub-commands: `lock` (`uv lock`), `sync [--with-models]` (`uv sync --frozen` with the dev group, **without** the `models` extra by default; `--with-models` adds `--extra models` for an operator's real-model use, and a plain `sync` afterwards removes it again), `lint` (`ruff check` then `ruff format --check`), `typecheck` (`mypy`), `test [path…]` (`pytest`, with the paths forwarded verbatim, default the whole suite), and `run [args…]` (the `harness-docs-retrieval` console script with the arguments forwarded verbatim, which is how an operator reaches the entry point inside the environment this wrapper keeps; Task 17's README documents it). `lint`, `typecheck`, `test` and `run` run through `uv run --frozen --no-sync`, so a gate never reaches the network. **Exit contract:** `0` pass, `1` the tool reported failure, `2` usage (unknown or missing sub-command), `3` not provisioned (`uv` not on `PATH`, or no synced environment), with a stderr line naming `bash scripts/python-service.sh sync`. The header reserves `container-test` and status `4` for Task 15. **Nothing lands inside the checkout:** the script exports `UV_PROJECT_ENVIRONMENT` to a per-checkout directory under `${XDG_CACHE_HOME:-$HOME/.cache}/harness-docs-retrieval/venvs/` (keyed on the repository root, e.g. by `cksum` of the path), sets `PYTHONDONTWRITEBYTECODE=1`, and points `RUFF_CACHE_DIR` and `MYPY_CACHE_DIR` under the same cache. That way gate 6a's `$HOME` grep gains no hit. Every invocation is spellable as a literal (`bash scripts/python-service.sh test tests/test_cli.py`). The basename is not on the script-allowlist guard's deny list, so an unattended run may call it.
- [ ] `pyproject.toml`: `name = "harness-docs-retrieval"`, `requires-python = ">=3.11"`, a hatchling build backend over `src/harness_docs_retrieval`, and `[project.scripts] harness-docs-retrieval = "harness_docs_retrieval.cli:main"`. **Base dependencies:** `fastapi`, `uvicorn`, `mcp`, `psycopg[binary]>=3.2` (3.2 is where `AsyncRawCursor` arrives, and Task 7 needs it), `huggingface_hub`. **`[project.optional-dependencies] models`:** `sentence-transformers`, `torch`, with `torch` sourced on Linux from the PyTorch CPU index through `[tool.uv.sources]` / an explicit `[[tool.uv.index]]`, so Task 14's image never pulls CUDA wheels. **`[dependency-groups] dev`:** `ruff`, `mypy`, `pytest`, `httpx`. Async tests use anyio's pytest plugin, which ships with the base set. **Tool config:** `[tool.mypy] strict = true` over `src` and `tests`, with an override setting `ignore_missing_imports` for `sentence_transformers.*` and `torch.*` only, because the gate environment never installs the extra. `[tool.ruff]` targets py311. `[tool.pytest.ini_options]` sets `testpaths = ["tests"]`, `addopts = "-p no:cacheprovider -rs"` (so every skip prints its reason, loudly) and registers the marker `container`. Then run `bash scripts/python-service.sh lock` and `bash scripts/python-service.sh sync`, and commit `uv.lock`.
- [ ] `errors.py` and `cli.py`: `errors.py` declares `class ServiceError(Exception)`, the one type for an anticipated failure: a refusal, a missing cache, an unreachable database. `cli.py` declares `@dataclass(frozen=True) class SubCommand(name: str, summary: str, configure: Callable[[argparse.ArgumentParser], None], run: Callable[[argparse.Namespace], int])`, the literal list `SUB_COMMANDS: list[SubCommand] = []`, and `main(argv: Sequence[str] | None = None) -> int`. `main` builds one argparse sub-parser per row, takes the usage text from the same list, exits `2` on a missing or unknown sub-command, and is **the only place an anticipated failure becomes an exit status**: a `ServiceError` prints exactly one line, `harness-docs-retrieval: <message>`, on stderr and exits `1`, with no traceback. Anything else propagates. Each module opens with a docstring stating what it owns, in the style of `cli/src/`'s headers (*"The rule this module exists to enforce: …"*).
- [ ] `tests/conftest.py`: declares `TEST_DATABASE_URL_ENV = "HARNESS_DOCS_RETRIEVAL_TEST_DATABASE_URL"`. A `pytest_collection_modifyitems` hook marks every `container` item skipped when that variable is unset, with the reason `container gate: HARNESS_DOCS_RETRIEVAL_TEST_DATABASE_URL is unset; run bash scripts/python-service.sh container-test on a machine with Docker`. A function-scoped fixture `fresh_database_url` connects to that URL, creates a uniquely named database whose name is composed with `psycopg.sql.Identifier` and never spliced, yields its connection string, and drops it with `WITH (FORCE)` in a `finally`, so a failing test still removes what it created (the lessons ledger's every-exit-path rule). Tasks 7 and 15 consume `fresh_database_url`. No fixture is ever created inside this checkout.
- [ ] `.gitignore` and `tests/test_cli.py`: as a backstop for a contributor who runs `uv` directly, add `docs-retrieval-service/.venv/`, `__pycache__/`, `.mypy_cache/`, `.pytest_cache/` and `.ruff_cache/` **above** the managed block, never inside it. `test_cli.py` opens with the rule it enforces and asserts four things: `main([])` exits `2` and prints usage; `main(["no-such-command"])` exits `2`; a temporary row whose `run` raises `ServiceError("x")`, inserted with `monkeypatch` into `SUB_COMMANDS`, exits `1` with stderr exactly `harness-docs-retrieval: x\n` and no `Traceback`; and `SUB_COMMANDS` is empty at this task's end (Tasks 11–13 update that assertion to the rows they add).
