### Task 4 — Add the TypeScript bridge and the chunk-key and hash parity case over both eval corpora

**Goal:** Give the Python suite one way to ask the **running** TypeScript retrieval code a question. Then use it for the cheapest insurance in the three-branch sequence: over both corpora the eval commits, both backends enumerate the same files and produce the same chunk keys, anchors, embedded text and hashes (Acceptance 1).

**Depends on:** Task 2 (`corpus.py`: `corpus_files(repo_root: str, config: Mapping[str, Any]) -> CorpusFiles`, `read_corpus_file(repo_root: str, path: str) -> str`) and Task 3 (`chunk.py`: `chunk_markdown(path: str, markdown: str) -> list[DocChunk]`, where `DocChunk` has the fields `key, path, anchor, heading, text, body, hash`).

**Why a bridge, and its boundary.** Comparing against a copy of the TypeScript behaviour would only compare two ports. This bridge imports the compiled modules under `cli/dist/retrieval/`, the eval's corpus composer `evals/docs-retrieval/corpora.mjs`, and the suite's fixture helpers `cli/test/helpers/fixture.mjs`, the same way `evals/docs-retrieval/index-build.mjs` imports `cli/dist`. It **reads** the TypeScript side and changes nothing in it. Its precondition is `npm run build`, which `scripts/run-gates.sh` satisfies at gate 2a before Task 16's gate 13 runs. **This task delivers the whole bridge**, every sub-command below, because later tasks consume it unchanged: `constants` is read by Tasks 6, 7, 8 and 10, `render` by Task 8, `stub-models` by Task 6, and `prepare-ts-fixture` by Tasks 11 and 15. They never edit the bridge.

### Targets

- `docs-retrieval-service/tests/ts_bridge.mjs` (new)
- `docs-retrieval-service/tests/ts_bridge.py` (new) — the Python side of the bridge.
- `docs-retrieval-service/tests/test_chunk_parity.py` (new)

**Work:**

- [ ] `ts_bridge.mjs`: an ES module that opens with a header stating its rule (*it answers from the running TypeScript code and never from a copy of it*) and its precondition. It resolves the checkout root from `import.meta.dirname` (`../..`). Sub-commands come from `process.argv[2]`. JSON input is read from stdin where noted, and exactly one JSON document is written to stdout:
  - `corpus <fixture-catalog|self-docs>`: takes `{ id, config, repoRoot }` from `corpusConfig({ repoRoot: <checkout>, corpus })` and then `corpusFiles(repoRoot, config)`. For each file it runs `chunkMarkdown(path, readFileSync(join(repoRoot, path), 'utf8'))`. Prints `{ repoRoot, config, files, warnings, chunks: [{ key, path, anchor, heading, text, body, hash }] }`.
  - `constants`: prints `{ search: { RRF_K, ARM_CANDIDATES, RERANK_CANDIDATES, DEFAULT_RESULTS, MAX_RESULTS, ABSTAIN_SCORE_THRESHOLD, ABSTAIN_MESSAGE, SEARCH_MODES }, store: { CHUNKS_TABLE, BM25_INDEX, BM25_INDEX_DEFINITION, BM25_ORDER_CLAUSE, CHUNK_TEXT_COLUMN, EMBEDDER_META_KEY, embeddingColumn384: chunkEmbeddingColumn(384) }, server: { DOCS_SERVER_NAME, SEARCH_TOOL_NAME, SEARCH_TOOL_PERMISSION }, models: { RETRIEVAL_STUB_ENV } }`. Every value is read from its exported owner and none is typed.
  - `render` (stdin: a `SearchResult` as `{ abstained, hits, bestRerankScore }`): prints `{ text: renderResults(result) }`.
  - `stub-models` (stdin: `{ version, documents, query, passages }`): sets `process.env[RETRIEVAL_STUB_ENV] = version`, calls `resolveModels({ allowRemote: false })`, and prints `{ embedderId, rerankerId, dimensions, documentVectors, queryVector, scores }`.
  - `prepare-ts-fixture <dir> <cacheHome>` (stdin: `{ files: { <relpath>: <content> } }`): writes the files into the existing empty `dir`, then runs `seedRepository(dir, { remote: false })`, `writeRetrievalConfig(dir)` and `plantModelFiles(cacheHome)`. Prints `{ env: retrievalEnv(cacheHome), cliEntry: CLI_ENTRY }`. It creates nothing outside `dir` and `cacheHome`.
- [ ] `ts_bridge.py`: declares `CHECKOUT_ROOT` (two levels above `docs-retrieval-service/tests/`) and `run_bridge(sub_command: str, *args: str, stdin: object | None = None) -> Any`. That function spawns `["node", <ts_bridge.mjs>, sub_command, *args]` as a fixed argument vector with no shell and returns the parsed stdout. It fails the test, rather than skipping it, naming `npm run build` when `cli/dist/cli.js` is absent, and naming the bridge's stderr on a non-zero exit. It also declares `@contextmanager ts_fixture(files: Mapping[str, str]) -> Iterator[TsFixture]`, where `TsFixture` is a frozen dataclass of `dir: Path`, `env: dict[str, str]` and `cli_entry: str`. It makes the fixture directory and the cache home with `tempfile.TemporaryDirectory()` under the system temp directory, calls `prepare-ts-fixture`, and removes both on every exit path (the lessons ledger's every-exit-path rule). Tasks 11 and 15 spawn `node <cli_entry> docs serve` with `cwd=dir` and `env={**os.environ, **env}`.
- [ ] `test_chunk_parity.py`: opens with the rule it enforces and why this is the sequence's cheapest insurance. For each of `fixture-catalog` and `self-docs`, it takes the bridge's `corpus` answer and calls `corpus_files(answer["repoRoot"], answer["config"])` with **that same config**, so the corpus composition has one source, the eval's. It asserts equal `files` and equal `warnings`. It then chunks every file through `read_corpus_file` + `chunk_markdown`. It asserts the key sets are equal and reports keys only on one side by name, and then that each key's whole record (`path, anchor, heading, text, body, hash`) is equal, reporting the first differing field. `self-docs` reads this checkout's live `docs/` and conventions documents, and both sides read the same bytes in the same run, so a moving corpus moves both sides together.

**Verification:**

- `tests/test_chunk_parity.py` passes (subject to the story index's test-run note). If it fails on a real chunking difference, fix it in `chunk.py` or `jscompat.py`. If the difference traces to a Unicode-version disagreement between Node's `\p{L}` / `\p{N}` and Python's `unicodedata`, return a blocker naming the character and the file. Never filter the corpus or relax the comparison.
- `grep -rn "cli/src" docs-retrieval-service/tests/ts_bridge.mjs` finds nothing. The bridge imports compiled `cli/dist` and the two named `.mjs` helpers only.
- The bridge's `constants` output contains no value that is typed in `ts_bridge.mjs` as a literal.
