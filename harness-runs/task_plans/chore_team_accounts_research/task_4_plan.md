### The repository facts §5 rests on

Read each from the file named, by its quoted anchor, before writing it; cite it the same way in the document. None of these is an external source.

- **Only the run job holds a Claude credential.** `harness-run.yml` → the steps named `Check the credentials` and `Run the harness` read `secrets.CLAUDE_CODE_OAUTH_TOKEN` and `secrets.ANTHROPIC_API_KEY` into `IN_OAUTH` / `IN_API`, fail before launch when both are empty, and export each only when non-empty. `harness-trigger.yml` says *"The job reads no repository secret"*; `harness-control.yml` reads no `secrets.` at all (grep it). The secret names are constants in `cli/src/remote/githubActions.ts` (`OAUTH_TOKEN_SECRET`, `API_KEY_SECRET`), mirrored by `harness-run.yml`'s `DECLARED MIRRORS` header.
- **The run job's permissions carry no `id-token`.** `harness-run.yml` → the workflow-level `permissions:` block grants `contents`, `actions`, `issues` and `pull-requests` write, and its header's `THE PERMISSIONS` paragraph says every permission it does not list is `none`.
- **Every run is dispatched by a token that is not the person who asked for it.** `harness-trigger.yml` and `harness-control.yml` run with `GH_TOKEN: ${{ github.token }}`, and `remote-run.sh` is *"the one place a `gh workflow run` of the run workflow is composed"* (its line 3 comment). Chained continuations are dispatched from the run job itself, and `harness-resume.yml`'s scheduled poller dispatches `resume: pause` with `GH_TOKEN: ${{ github.token }}`. A run dispatched by the local watcher with `execution.target` set to `github-actions` uses the maintainer's own `gh` login (`docs/remote-execution.md` → the opening summary).
- **The run's inputs name no person.** `harness-run.yml` → `THE INPUT CONTRACT` lists `action`, `branch`, `engine`, `resume`, `answers`, `park_loop_clear`, `chain`; none records who started the run, and any writer can dispatch `workflow_dispatch` with any inputs (`G7`).
- **The run job is dispatched on the run's own branch**, not the default branch: `remote-run.sh`'s worked examples show `workflow run harness-run.yml --ref feat_x`. An environment rule limited to the default branch would therefore refuse the run job itself (`G3`, `G7`).
- **One actor check gates both the trigger and the commands.** `remote-run.sh` → `authorise_actor`: a person passes with `admin` or `write` from `repos/<repo>/collaborators/<login>/permission`; a bot only when listed in `HARNESS_TRIGGER_ALLOWED_BOTS`; `ghost` and a non-login never. `docs/github-run-control.md` → `## 6. Who can act, and pull requests from forks` describes it.
- **`doctor` reads secret names, never values.** `cli/src/doctor/checks.ts` → the remote check's header: *"Secret **values** are never read: `gh secret list` returns names only"*; it fails when neither credential secret is set and notes when both are (*"billing follows `ANTHROPIC_API_KEY`"*).
- **The job limits.** `harness-run.yml` → `HARNESS_HOSTED_JOB_LIMIT_MINUTES: '360'` and `HARNESS_SELF_HOSTED_JOB_LIMIT_MINUTES: '7200'`: a run job can outlast a federated token's maximum lifetime of 86,400 seconds only on a self-hosted runner, and outlasts the default of 3,600 seconds on either (`R6`).
