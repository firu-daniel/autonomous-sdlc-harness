### Task 10 — Add the shared module `plugin/instructions/plan_review_rounds.md`

**Goal:** State once, for both plan loops and all five plan agents, what a plan-review round is: the round file every gate writes, the Must Fix entry, converging mode, incidental findings, the one exception a precedence rejection makes to the recorded-rejection rule, and how a writer revises — so each agent and core cites a section instead of carrying a copy (`harness-runs/lessons.md` → *"State a new behaviour once, in the section that decides it, and cite it from everywhere else"*; `.claude/context/plugin.md` → `## Writing agent prose`).

**Where this task stops.** This module states contracts and is activated only by pointer. Wiring each citer is its own task: the task-plan core **Task 11**, the fix-plan core **Task 12**, the writers **Tasks 13–14**, the reviewers **Tasks 15–17**, the end-of-branch reviewers **Task 22**. Each citer's dispatch keys (`review_mode:`, `revision_note:`) and paths are its core's; this module names what the keys mean, never a `<state_dir>` expansion a core owns.

### Targets

- `plugin/instructions/plan_review_rounds.md` (new)

**Work:**

- [ ] Open on its own H1, `# Plan-review rounds`, **no frontmatter** (an instruction file; `.claude/context/conventions.md` → `## The stack, in the words the rules below use`), then `## Resolved values` (`<state_dir>` as the sibling modules declare it; `<findings_folder>`, `<iteration>`, `<review_mode>`, `<revision_note>`, `<branch>`, `<N>` and `<k>` named as dispatch values resolved where they appear), then **`## Who may cite this`**: the roster — `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_core.md`, `…/user_review_fix_plan_writing_instructions_core.md`, `…/task_plan_writing_instructions_autonomous.md`, `…/user_review_fix_plan_writing_instructions_autonomous.md`, `${CLAUDE_PLUGIN_ROOT}/agents/task-plan-reviewer.md`, `…/architecture-reviewer.md`, `…/business-parity-reviewer.md`, `…/task-plan-writer.md`, `…/user-review-fix-plan-writer.md`, `…/branch-reviewer.md`, `…/skeptic-reviewer.md` — with the *"a citer points and never restates … an edit that rewords or moves a heading updates every roster member"* rule `plugin/instructions/untrusted_input.md` → `## Who may cite this` words. The roster covers plugin assets; a document outside the plugin (Task 30's `docs/converging-plan-reviews.md`) cites this file by repo-relative path and is not a roster member, the boundary `.claude/context/plugin.md` → `## Citation` draws.
- [ ] **`## The round file`** — `<findings_folder>/review_<iteration>.md`, the reviewer creating the folder itself on its first file; first line `# <title> — round <iteration>` (the reviewer's existing title: `Task plan review`, `Architecture review`, `Business parity review`); then exactly one line `verdict: PASS` or `verdict: FAIL` and exactly one line `review_mode: full` or `review_mode: converging`, before any section; written on **`PASS` too**, then holding only those lines plus any `## Should Fix`, `## Nice to Have` and `## Incidental findings (not gating)`; on `PASS` the return is `verdict: PASS` then `findings_file: <full_path>`, on `FAIL` the existing three lines. A reviewer that finds `review_<iteration>.md` already present replaces it: it is from an interrupted round, and the reviewer reviews again in the mode its dispatch names. **`## The Must Fix entry`** — each Must Fix keeps its title naming the target file and its `**Fix:**` line, and gains two lines: `**Raised against:**` a short verbatim quote of the text the finding was raised against, and `**Must hold:**` the defect stated as the property the target file must satisfy, never as a text replacement.
- [ ] **`## Converging mode`** — what `review_mode: converging` means for a reviewer: read, in order, (1) its own `review_<iteration − 1>.md` and the revision note at `revision_note:`; (2) where the branch history carries the previous round's commit — the most recent commit whose subject is `chore: Plan round <iteration − 1> for <branch>` (task plan) or `chore: Fix plan <N> round <iteration − 1> for <branch>` (fix plan), found with one plain `git log -1 --format=%H -F --grep="<subject>"` — the plan's diff since it (`git diff <sha> -- <story_path> <task_files_dir>`) plus `git status --porcelain -- <task_files_dir>` for new files; (3) the current plan at the files those point to; (4) another reviewer's findings file **only** for a finding the revision note says changed text inside this reviewer's own lens, at the path the note gives. Check only: its own previous Must Fix items are resolved; every change the writer made is sound within its own lens, including text that references or is referenced by the changed text; and the `## Rejected findings` entries under the recorded-rejection rule. It does not re-review the rest of the plan. A rule of the reviewer's own that assumes a whole-plan sweep applies to the text the round's changes reach — each reviewer's definition names that variant. Fallback: when its own previous file or the revision note is absent, it reviews `full` this round and writes `review_mode: full`.
- [ ] **`## Incidental findings — where they go and who reads them`** — anything a converging reviewer notices outside that scope goes under a heading spelled exactly `## Incidental findings (not gating)`; it never counts toward the verdict, the reviewer does not go looking for it, and a round whose only findings are incidental is a `PASS`. The end-of-branch reviewers read every such section in the planning rounds' files — the three task-plan gate folders and the two user-review gate folders, as their own definitions list them — and treat each entry as a **lead to verify against the diff**, never as a finding in itself. **`## A rejection recorded under precedence`** — a writer that resolves two incompatible findings by precedence (task plan: business parity, then architecture, then plan structure; fix plan: business parity, then architecture) records the losing one as `- **<reviewer> <n>** (rejected round <i> — precedence: <winning reviewer> <m>) — <why the two cannot both hold>`. This is the named exception to *"`call stands` is unavailable for a Must Fix"*: the losing reviewer tests only whether the two findings are genuinely incompatible and whether the winning one still stands in the current plan; when both hold, the entry is closed; otherwise it re-raises once, engaging the reason.
- [ ] **`## The writer's revision`** — the round's prompt names every findings file of the round and the revision note path. Group the round's Must Fix items by target file across every findings file, and read every finding on a file against that file's **unchanged** text before the first edit to it; resolve incompatible findings by `## A rejection recorded under precedence`; apply or record each Should Fix of the round — stated as this module's own rule, in plugin prose: *each Should Fix of the round is applied, or recorded under `## Rejected findings` with its reason; none is held for a go-ahead the loop does not relay* — with no citation of any adopter's ledger and no `<state_dir>`-expanded or literal run-artifact path in the shipped text (`.claude/context/conventions.md` → `## Configuration is the source of truth, and it is read at run time`; `.claude/context/plugin.md` → `## What this layer is`; an adopter's `lessons.md` starts as the `init` template and does not carry this repository's rule, so the module must state it itself); never act on an `## Incidental findings (not gating)` entry. Write the revision note **last**, at the path the prompt names: `# Revision note — round <iteration>`, then one line per finding — `- <reviewer> <n> (<findings file path>) — files: <files changed> — <resolved | resolved by <reviewer> <m> | rejected — see ## Rejected findings>` — then `Unrequested changes:` naming every file changed that no finding asked for, or `none`. A user-feedback revision writes one line per feedback item, its reviewer field `user`.
