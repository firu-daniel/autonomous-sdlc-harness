### Task 3 — Walk round nodes in `flow-walker.sh`: every gate every round, round-numbered arguments, review mode, cap payload and the round number on `start`

**Goal:** Make `cli/templates/scripts/flow-walker.sh` walk the format-2 graph: record each gate's verdict and findings file for the round, close the round at the `round` node, print the round-numbered arguments and the review mode the reviewers and the writer need, name every open gate at the cap, and on `start` continue the branch's round numbering from the round files while the loop counter starts at 0, exactly as it does today.

**Depends on:** Task 1, whose gate library this walker sources: `fw_review_verdict <file>` (prints `PASS`/`FAIL`, return 1 when not exactly one verdict line), `fw_fail_count <folder>` (count of `FAIL` round files; it replaces `fw_round_count`), and `fw_round_evidence <root> <note_template> <plan_path>... -- <node>=<folder>...`, which prints `round: <R>|none`, one `gate: <node> <PASS|FAIL|missing|unreadable> <file>` per pair in argument order, `note: present|absent` (the `{round}` = `R+1` note) and `plan: not-newer|newer|unknown`. Task 2, whose graph this walker reads: `formatVersion` 2; the `round` node `plan_round` with `gates` (ordered), `writer`, `counter`, `convergingFrom`, `plan` (names of `paths` entries), `revisionNote` (a `paths` entry carrying `{round}`) and `outcomes` `PASS` / `FAIL`; the cap `summary`'s `{open_gates}` token.

**Two numbers, kept apart — the user's ruling on this branch's cap park, restated in the task prompt (commit `2ea4301c`).** The **loop counter** (`iteration`, the heartbeat's `iter`) drives the cap and the review mode, and is never derived from round files: every `start` sets it to 0, as today, and it carries over only when a saved walk is continued (`cli/test/flow-walker-resume.test.mjs` cases `(1)` and `(5)`). So a proceed-fresh write, an **extend** from answers and an **extend** after an answered cap park — all three `start --entry plan_writer` under `plugin/instructions/task_plan_writing_instructions_core.md` → `## Setup (once per session)` step 7 — each start at counter 0 with a full five-round cap budget and two `full` rounds before `converging`, because a finished walk (a cap park, a convergence) is never continued and there is no other carrier of the counter. The **round number** names the round files: it is the same index in every gate's folder and carries on across the branch's whole planning history, read off the files on `start`, so a new walk never overwrites an earlier walk's round files. In a walk started with no round file on disk the two are equal.

**Where this task stops.** The walker prints values and binding names; which dispatch key each value fills is the core's (**Task 11**), and committing on a `round:` line is the autonomous fork's (**Task 19**). Its tests are **Tasks 4–6**; this checkout's self-adopted copy is **Task 27**.
