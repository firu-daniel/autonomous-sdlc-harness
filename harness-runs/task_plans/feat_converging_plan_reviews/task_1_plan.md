### Task 1 — Report a plan-review round's evidence from the gate library: verdicts, FAIL counts and `fw_round_evidence`

**Goal:** Give `cli/templates/scripts/lib/flow-walker-gates.sh` the mechanical answers round routing needs — a round file's verdict, a folder's count of `FAIL` files, and one call that reports everything a resume has to decide from — so the walker (Task 3) decides and this library only answers, as its header requires (*"IT ANSWERS AND NEVER DECIDES"*).

**Where this task stops.** Nothing here chooses a node, a counter value or an entry: Task 3 owns every decision taken from these answers. This library still writes nothing. It now **opens** a round file to read its verdict line, so the header's *"the findings-folder functions list names only and open no file"* is restated to name the two functions that read a file's verdict line and nothing else from it.

**Forward citation, by design.** The header comment this task writes cites `plugin/instructions/plan_review_rounds.md` → `## The round file`, which **Task 10** creates later in ship order (the `cli` layer ships before `plugin`). Until Task 10 lands the citation points at nothing; it is a comment, and nothing reads it at run time. Task 10's module is the anchor's single home; this task restates only the one-line `verdict:` contract it parses.

### Targets

- `cli/templates/scripts/lib/flow-walker-gates.sh` — three new functions, header restated. `fw_round_count` stays: the shipped walker still calls it, and Task 3 removes it together with that call.
- `cli/test/flow-walker-gates.test.mjs` (new) — the accompanying test the cross-layer testing bar requires of new shell behaviour.

**Work:**

- [ ] `fw_review_verdict <file>` — prints `PASS` or `FAIL` and returns 0 when `<file>` exists and carries **exactly one** line that is byte-exactly `verdict: PASS` or `verdict: FAIL` (a trailing CR tolerated, as `fw_run_mode_skipped` tolerates one); prints nothing and returns 1 otherwise — absent, no such line, or more than one. The line contract is `plugin/instructions/plan_review_rounds.md` → `## The round file` (Task 10): `verdict: PASS` / `verdict: FAIL`, one line.
- [ ] `fw_fail_count <folder>` — prints how many `review_<n>.md` entries (the same name test `fw_next_review_index` applies) `fw_review_verdict` reads as `FAIL`; `0` for an absent folder. It is added **beside** `fw_round_count`, whose "a file is a failed round" premise no longer holds once a `PASS` writes a file. Leave `fw_round_count` and its REPRO line in place: `cli/templates/scripts/flow-walker.sh` → `take_binding` still calls it (`count="$(fw_round_count "$ROOT/$SUBST")"`). Task 3 moves that call to `fw_fail_count` and deletes `fw_round_count` in the same commit, so every intermediate state of the branch stays coherent (contract before consumer).
- [ ] `fw_round_evidence <root> <note_template> <plan_path>... -- <node>=<folder>...` — every path absolute; `<note_template>` carries the literal token `{round}`; the `<node>=<folder>` pairs are the gates the caller names, in gate order (the caller filters skips: Task 3 passes the non-skipped gates for a gate entry and every gate of the round for a writer entry, whose only use is the `round:` line). It prints, in this order, and returns 0 (2 when `git` cannot be run in `<root>`):
  - `round: <R>` — the highest `<n>` among every listed folder's `review_<n>.md`, or `round: none` (then nothing else but the `note:` and `plan:` lines below, `note: absent`, `plan: unknown`);
  - one `gate: <node> <PASS|FAIL|missing|unreadable> <folder>/review_<R>.md` per pair, in argument order — `missing` when that file does not exist, `unreadable` when `fw_review_verdict` returns 1 for an existing file;
  - `note: present` or `note: absent` — whether `<note_template>` with `{round}` replaced by `R+1` exists;
  - `plan: not-newer`, `plan: newer` or `plan: unknown`, judged against the **earliest present** gate file of round `R` (the first pair, in argument order, whose file exists): `not-newer` when that file is committed and neither a later commit (`git rev-list <that commit>..HEAD -- <plan_path>...`) nor an uncommitted or untracked change (`git status --porcelain -- <plan_path>...`) touches a plan path; `newer` when it is committed and one of those does; `unknown` when it is not committed or no gate file exists. Every `git` call is a fixed argument vector run with `-C <root>`, no pipeline into a decision, bash 3.2 and `jq`-free as the header's floors require.
- [ ] Restate the header: the opening sentence's list of answers, *"IT ANSWERS AND NEVER DECIDES"* (round evidence is an answer; the round decision is the walker's), the no-file-opened sentence as stated under **Where this task stops**, and a REPRO block line for each new function against the throwaway fixture the header already builds — a `git init`ed root with a committed `review_0.md` carrying `verdict: FAIL`.
