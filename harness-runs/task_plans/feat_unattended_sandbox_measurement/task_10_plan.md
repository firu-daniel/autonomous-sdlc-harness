### Task 10 — Add the write-protection and git-in-the-clone legs

**Goal:** Measure that each protected path the per-run profile names for the clone, and each base path, is refused to a sandboxed `dd`, to a sandboxed rename staged from a writable spot (CL6's indirect form), and to `Edit` and `Write`. Also measure that sandboxed ordinary git works in the clone under the real per-run profile, while a sandboxed `git config` in it is refused. Every refusal row's session carries a positive control.

**Depends on:**
- **Task 3** — `sp_judge_call`, `sp_judge_tool`.
- **Task 4** — `sp_session`, the prompt builders, `sp_track`, and `SP_CLONE`, `SP_RUN_PROFILE`, `SP_MAIN`.
- **Task 19** — `sp_ctl_prepare <tag>`, `sp_ctl_add <prompt file> written <exact command> <path>` / `sp_ctl_add <prompt file> ran <exact command>`, `sp_ctl_held <stream>`, and `sp_row_result <leg> <row> <verdict> <evidence> <departure>`, which prints `not run` with evidence `control did not succeed: …` when the session's control did not hold. These rows need no control clone, so this task never calls `sp_ctl_clone`. Without a control clone, `sp_ctl_prepare` only clears the session's control list (Task 19 states this).

**The protected set is read from the profile the session runs on, never re-derived and never a literal list.** `SP_RUN_PROFILE` is the base profile's entries plus the per-run appends (`scripts/autonomous-watcher.sh` → `run_profile_render`, which appends `run_profile_entries`' paths to `.sandbox.filesystem.denyWrite` and their `Edit(…)` rules to `.permissions.deny`, and `run_profile_check`, which refuses any other difference from the base). `run_profile_entries` alone prints only the appends. The base's own entries are in `.sandbox.filesystem.denyWrite` only: the main checkout's wrappers and other `scripts/*.sh`, `scripts/lib`, `githooks`, `.mcp.json`, the `.claude/settings*.json` files, `<main>/.git`, `harness.config.json`, the run registry and `scripts/.git`. Reading the one file gets every entry the profile carries. The two targets it does not carry, the per-run profile file and the plugin root, are added explicitly below.

### Targets

- `scripts/lib/sandbox-probe/legs-protection.sh` (new) — `sp_leg_write_protection`, `sp_leg_git`, and the reader `sp_protected_set`. It opens with `#!/usr/bin/env bash` and a `# legs-protection.sh — …` header, and sets no shell option (no `set`, no `shopt`): the entry point owns `set -u` (Task 1; `.claude/context/conventions.md` → `## Shell assets`, *"A sourced library sets no shell options at all"*).

**Work:**

- [ ] **`sp_protected_set` — the set, from `SP_RUN_PROFILE`.**
  - **The `dd` and rename half:** `jq -r '.sandbox.filesystem.denyWrite[]' "$SP_RUN_PROFILE"`. Each line is one entry.
  - **The `Edit` / `Write` half (W6):** `jq -r '.permissions.deny[] | select(startswith("Edit("))' "$SP_RUN_PROFILE"`. Strip `Edit(` and the closing `)`, and read the leading `//` as the absolute root (the rule syntax). An entry ending `/**` is a directory entry.
  - **Glob entries:** an entry carrying `*` names the sibling run copies, in the form `<work_root>/<project>-*/…`. Expand it to the probe clone by replacing the path prefix up to and including the `*` segment with `SP_CLONE`. Before replacing, check that `SP_CLONE` matches that glob (bash `[[ $SP_CLONE == $prefix ]]`). An entry the clone does not match is printed as `not run` evidence for CS1, never silently dropped.
  - **The per-run profile file itself:** `SP_RUN_PROFILE` is added to the set. It is CS7's target, and is not one of its own entries.
  - **The plugin root — added explicitly, because the profile may not carry it.** The prompt's write-protection leg names *"the plugin root"*. The profile carries a plugin root only through `permissions.additionalDirectories` (`cli/src/generators/writeProtection.ts` → `protectedPaths`, the loop that skips the state directory and pushes every other entry with *"the plugin guard hooks run from it, outside the sandbox"*). On this repository that list holds only the state directory, so the profile carries **no** plugin-root entry, and reading the profile alone would never probe it.
    - **Resolving it.** The probe resolves the installed `autonomous-sdlc-harness` plugin root before the session from the plugin install record, `"$HOME/.claude/plugins/installed_plugins.json"`, reading that plugin's install path with `jq`. After the session it cross-checks that path against the session's own `init` event (the stream's first `system`/`init` line, its `plugins[]` entry for the plugin) and names any disagreement in the evidence.
    - **Probing it.** It is added to the set as a directory target, probed at the new file name `<plugin root>/sbx_cs1_plugin_new`, passed to `sp_track`, with the same `dd` and rename calls as every other entry. It maps to **CS1**.
    - **Recording which layer.** CS1's evidence carries one clause for the plugin root: whether `SP_RUN_PROFILE`'s `.sandbox.filesystem.denyWrite[]` names it (`listed by the profile`), or not (`additionalDirectories holds no plugin root on this repository; refused only by the runtime's write roots` when refused). A write that lands at `<plugin root>/sbx_cs1_plugin_new` makes CS1 `fail`.
    - **Unresolvable.** When the install record is absent or names no path for the plugin, CS1 prints `not run` with evidence `plugin root unresolved: <reason>`, never `pass`: the prompt names the plugin root as part of the set, so CS1 without it is not the measurement owed.
  - **Each entry is mapped to one row.** `<main>/.git` (the entry that equals `"$SP_MAIN/.git"`) is **CS2**. `SP_RUN_PROFILE` is **CS7**. Every other entry, the clone's own paths and the base `<main>` paths alike, is **CS1**. CS1's evidence names how many entries it covered, which were under the clone, and which were base paths.
  - **The `dd` target per entry.** An existing regular file is its own target. A directory entry, or a path that is a directory on disk, is probed at a new file name inside it: `<dir>/sbx_cs1_new` (CS1's recorded form, `<clone>/.git/hooks/sbx_cs1_new`), or, for `<main>/.git`, CS2's three recorded names (`sbx_cs2_new`, `refs/heads/sbx_cs2_probe`, `objects/sbx_cs2_probe`). A file entry that does not exist (`commondir`, `config.worktree`, `http-alternates` on a clean clone) is probed at its own path. Every new name is passed to `sp_track`, so a write that lands is removed.
- [ ] **`sp_leg_write_protection` (CS1, CS2, CS7, W6, W8).** One session, launched with `--allowedTools "Bash(dd:*)"`, the rename helper rule and `--debug-file`. For each `dd` target:
  - a `dd if=/dev/null of=<target> conv=notrunc`. Expect the `sandbox` layer, `Operation not permitted`.
  - an indirect rename (CL6 (b)'s form): one `bash <helper>` call, allowed as exactly that command. Its script stages a sibling where CL5 measured new files writable, as a `cp -p` byte copy of an existing target, then `mv`s it onto `<target>`. A rename that lands therefore leaves the content unchanged. Expect the `sandbox` layer refusal and the inode unchanged.
  - an `Edit` (after `Read`) of each `Edit`-half path that exists, and a `Write` of each that does not (W6), judged by `sp_judge_tool`. Expect the file-tool denied-directory message.
  - **Reading a `.git` refusal:** per §4's note, for the clone's own `.git/config`, `.git/hooks/` and `objects/info/alternates`, a file-tool refusal grades the per-run profile only when its message is the denied-directory one. A permission-layer `… don't ask mode` on those paths is the runtime's, not the profile's. Record which layer in the evidence.
- [ ] **The write-protection session's controls, its rows and W8.**
  - **Controls, issued last in the same session**, after `sp_ctl_prepare wp`:
    - `sp_ctl_add <prompt> written "dd if=/dev/null of=<clone>/.git/sbx_wp_ctl conv=notrunc" <clone>/.git/sbx_wp_ctl` — the new file directly in `<clone>/.git`, which CL5 measured writable;
    - `sp_ctl_add <prompt> ran "dd if=/dev/null of=<clone>/<tracked file> conv=notrunc"` — a `dd` on a tracked clone file;
    - `sp_ctl_add <prompt> tool Write <clone>/sbx_wp_tool_ctl.txt` — the file-tool control for W6, a `Write` creating a new file in the clone's working tree. Task 19 passes it to `sp_track`.
  - **The rows.** After `sp_ctl_held`, CS1, CS2, CS7 (judged by the `dd` and the rename) and W6 (by the file tools) are printed through `sp_row_result`.
  - **W8.** Assert the `--debug-file` log carries no `is not matched by file permission checks` line and no `mixes * with the trailing :* prefix syntax` line for any rule the per-run profile carries. `sp_track` the debug file. W8 reads a log, not a refusal, so it is printed through `sp_result_line`.
- [ ] **`sp_leg_git` (CS3, CL5).** One session, cwd `SP_CLONE` on its run branch, under the real `SP_RUN_PROFILE`:
  - CS3: CL4's calls, one each, through `--allowedTools` where the profile refuses one (`git switch` among them): `git add <file>`; `git commit -m "<subject>"`; `git fetch origin`; `git stash push`; `git stash pop`; `git switch -c <x>`. Expect each succeeds. They are judged by the ref moving (commit), the stash restoring, and `git rev-parse --abbrev-ref HEAD` printing `<x>` after the switch. Edit a tracked file before the session, so the add/commit has a change. `<x>` needs no `sp_track_branch`: it is a local branch in the clone, removed with the clone.
  - CL5: `git config sbx.probe true` in the clone. Expect it refused (`could not lock config file .git/config`), at the `sandbox` layer.
  - **CL5's control:** CS3's calls in the same session are its positive control. Before the session, `sp_ctl_prepare git`. After the CS3 calls, `sp_ctl_add <prompt> ran "git status --porcelain"`, which runs in the same sandboxed clone. After `sp_ctl_held`, CL5 is printed through `sp_row_result`. CS3 is not a refusal row and is printed through `sp_result_line`.
