### Task 1 — Make the run-copy check refuse a linked worktree, and reframe the library's worktree prose as a hand-made checkout

**Goal:** the rule "a linked worktree is not a run copy" gets one home in the run library: a new `hr_run_target_check_var`, which `hr_run_copy_check_var` — the check every run-copy consumer goes through — calls, so that check accepts the main checkout and a registered clone only and refuses a linked worktree. Tasks 11 and 12 call the same function. The library's prose stops calling a linked worktree a run copy, and the wrappers' hand-made-worktree arm stays exactly as it is.

**The interface this task produces (consumed by Tasks 11 and 12).** `hr_run_target_check_var <main> <dir>` — calls `hr_wrapper_target_check_var "$1" "$2"` and returns 1 with that check's own `HR_TARGET_REFUSAL` when it fails; when it succeeds with `HR_TARGET_KIND=worktree`, returns 1 with `HR_TARGET_REFUSAL` set to exactly one sentence, `'<dir>' is a linked worktree of <main>, and a run copy is a clone the run registry records` (`<dir>` and `<main>` as passed); otherwise returns 0 with `HR_TARGET_KIND` (`main` or `clone`), `HR_TARGET_GITDIR` and `HR_TARGET_BRANCH` exactly as `hr_wrapper_target_check_var` set them. It reads no run registry and no tip, prints nothing, and sets no new `HR_` variable. Call it directly, never inside `$(…)`.

**Where this task stops.** It changes `cli/templates/scripts/lib/harness-run-lib.sh` and the three test files below. It does **not** touch `hr_wrapper_target_check_var`, `hr_wrapper_branch_var`'s `worktrees/<name>/HEAD` read, `hr_copy_kind`'s `worktree` answer or `hr_worktree_config_check_var` — the wrappers keep accepting a linked worktree a person made by hand (clarification park 1, Option A). It does not switch `launch-sandboxed-gates.sh` (Task 11) or `setup-worktree.sh --target` (Task 12) to the new function. The watcher's own changes are Task 2's, the sweep's Task 4's, and the wrapper and `remote-run.sh` header prose Task 5's.
