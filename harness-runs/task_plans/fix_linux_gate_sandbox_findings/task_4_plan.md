### Task 4 — PD28: add CL5's `File exists` lock refusal to the judge's Linux table, and grade CL5 on it plus the placeholder readings

**Goal:** Grade CL5's `git config sbx.probe true` on Linux from the refusal shape *and* the `.git/config.lock` readings the git leg already takes, now that the third Linux run has decided what `File exists` means.

**The finding (docs/sandbox-verification.md §5 PD28).** On 2026-11-03 CL5 printed `not run`: `no refusal string this judge knows on Linux, so not graded: Exit code 255: error: could not lock config file .git/config: File exists; .git/config.lock read: before the session absent, inside the session crw-rw-rw- 1 nobody nogroup 1, 3 Nov  3 19:07 .git/config.lock, after it absent`. Inside the session the lock path was a character device `1, 3`, which is `/dev/null`, and it was absent before and after the session. That is the placeholder bubblewrap mounts at an absent `denyWrite` path (§5 F9). git creates `.git/config.lock` exclusively, so `File exists` there is the sandbox's refusal.

**The decision this task implements.**

- **The table entry is the whole line shape, never a bare `File exists`:** `could not lock config file .git/config: File exists`. A bare `File exists` would let any `mkdir` or `ln` collision on any Linux row read as a sandbox refusal.
- **CL5 passes on that shape only when the readings show the placeholder:** before the session `absent`, inside it a reading whose first character is `c` and which carries `1, 3`, and after it `absent`. With the shape and any other readings, CL5's `git config` result is `not run`, and its evidence says the `File exists` refusal is the sandbox's only where the lock path read as its `/dev/null` placeholder inside the session, followed by the three readings. A lock that was there before the session (a leftover) is therefore never a pass.
- **Nothing changes on macOS:** the Linux table applies only under `SP_PLATFORM=linux`, and the readings are taken only on Linux.

**The interface Task 8 tests.** `scripts/lib/sandbox-probe/judge.sh` → `SP__LINUX_SANDBOX_STRINGS` gains, as its fourth and last member, the exact string `could not lock config file .git/config: File exists`. `sp__linux_refusal_names` therefore prints `Read-only file system, Permission denied, Device or resource busy, could not lock config file .git/config: File exists`. `scripts/lib/sandbox-probe/legs-protection.sh` → `sp__git_cl5_grade <stream> <exact command> [<lock before> <lock inside> <lock after>]` keeps its signature. On Linux with the shape matched, it sets `SP_VERDICT` to `pass` when the three readings fit as above, and to `not run` when they do not. The evidence always carries `; .git/config.lock read: before the session <b>, inside the session <i>, after it <a>`, as today.
