### Task 6 — Add `doctor`'s `profile-sandbox` check

**Goal:** `doctor` reports a permission profile whose sandbox block is not what the configuration says it should be: sandbox on, strict mode, exactly the two named unsandboxed wrappers, the configured domains, and the opt-out when, and only when, it is taken. The check is read-only and repairs nothing (`.claude/context/cli.md` → *"`doctor` asks, grades and repairs nothing"*).

**Depends on:**

- Task 1 — `cli/src/config/model.ts`:

  ```ts
  sandboxOptedOut(config: HarnessConfig): boolean
  sandboxAllowedDomains(config: HarnessConfig): readonly HarnessSandboxDomain[]
  ```

- Task 2 — `cli/src/generators/sandboxProfile.ts`. Every expected value comes from these exports and never from a copy in `checks.ts`:

  ```ts
  SANDBOX_KEY                     // 'sandbox'
  SANDBOX_OPT_OUT_MARKER          // the _README line prefix an opted-out profile carries
  expectedSandbox({ repoRoot, config }): {
    optedOut: boolean; optOutReason?: string;
    excludedCommands: readonly string[];   // the two main-checkout wrapper rules
    allowedDomains: readonly string[];     // configured, plus 127.0.0.1 when browser wiring applies
  }
  shippedSandboxSettings(): readonly { path: string; value: boolean }[]  // read from the shipped template
  ```

The citation is a comment only, so this task ships independently, and the number resolves once Task 25 lands (`.claude/context/conventions.md` → `## Documents of record`: *"A deferral cites a numbered roadmap item, and the number owes a row"*).
