### Task 5 — Keep planners out of the guard list and have reviewers police registration

**Goal:** The task-plan writer never lists a tree guard and never writes a sentence that would cancel the loop's guard run, and pairs every task that adds a tree-reading test with a catch-all-layer task that adds its `treeGuards` entry; the task-plan reviewer flags a plan that breaks either; the branch reviewer flags a tree-reading test the branch adds with no `treeGuards` entry anywhere in the branch diff; and the layer reviewer flags such a test only when neither the unit's own diff nor its `<task_file>` accounts for the registration (task prompt, Proposal items 3 and 4); and the flow document's Phase G sentence that restates the old one-file rule becomes a pointer to `## The test-run rule`.

**Why registration is graded where it is.** A tree-reading test lives under a layer's own path (here `cli/test/`), while its `treeGuards` entry lives in the root `harness.config.json`, which belongs to the catch-all layer (`.claude/context/conventions.md` → `## The layers`). A correctly layered plan therefore registers the test in a **separate, later, catch-all task** (this branch's own case: Task 8 registers `cli` tests), and the layer reviewer, which grades only the unit's uncommitted set (`plugin/agents/layer-reviewer.md` → `## Process` step 2), can never see both halves in one diff. So the full check sits at the two levels that see both layers — the plan (task-plan writer and reviewer) and the branch (branch reviewer) — and the layer reviewer's trigger never requires the entry in the unit's own diff.
