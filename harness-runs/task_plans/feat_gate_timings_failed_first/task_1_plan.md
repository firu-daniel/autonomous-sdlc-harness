### Task 1 — `run-test-suite.sh` tells its gates the label and log directory, records the commit a clean run used, and reuses a finished verdict on that commit

**Goal:** Change the shipped Run gates wrapper `cli/templates/scripts/run-test-suite.sh` in three ways. It hands both gate commands the round's label and lane directory. Its worker records the commit it ran against, beside `.verdict`, when nothing outside `<state_dir>` was dirty at its start or its finish. Its run form and its `--no-detach` form collect a finished verdict of the label, as `--wait` would, when HEAD is still that commit and the tree is still clean outside `<state_dir>`. Otherwise they run as today.

**Where this task stops.** This task changes the template and one comment block of the template run library. It writes no test: Task 2 pins every behaviour below in `cli/test/run-test-suite.test.mjs`. It does not touch this repository's copies under `scripts/`, which Task 6 brings in line byte-for-byte. It does not touch `scripts/run-gates.sh`, the consumer of the two environment variables, which is Tasks 8 and 9. Nor does it touch the READMEs and plugin prose that describe the wrapper, which are Tasks 3, 4 and 5. Every one of those tasks cites the header paragraphs this task writes, so keep their opening words exactly as named below.

### Targets

- `cli/templates/scripts/run-test-suite.sh`: the gate environment, the commit record, the reuse in both forms, and the header comments.
- `cli/templates/scripts/lib/harness-run-lib.sh`: the `THE RUN GATES LANE:` comment above `HR_TEST_RUN_LABEL_PATTERN` only. No code changes.

**Work:**

- [ ] **Tell both gates the round.** In `run_gate`, inside the subshell that `eval`s the command, export `RUN_TEST_SUITE_LABEL=<label>` and `RUN_TEST_SUITE_LOG_DIR=<log_dir>`. `<log_dir>` is the value the script already computes through `hr_test_run_lane_dir`, repo-relative because `hr_state_dir` yields `stateDir` as configured. Both gates (typecheck and test) receive them. `RUN_TEST_SUITE_WORKER` stays unset before any gate, as today. Add a header paragraph opening `WHAT A GATE IS TOLD.` with three statements. The two names and their values. That a gate command may write its own per-round records beside the log, named `<label>.<suffix>`, and that this script reads none of them. And that a gate run by hand gets neither variable.
- [ ] **Record the commit of a clean run.** Add one function, for example `clean_tree_commit_var`, used by every reader and writer below. It sets a variable to `git rev-parse --verify -q HEAD`'s output only when that call exits 0 **and** `git --no-optional-locks status --porcelain --untracked-files=all -- . ":(exclude)$state_dir"` exits 0 with empty output. Otherwise it sets the variable empty. When `$state_dir` is empty or normalizes to the repository root (`.`), it always sets it empty. `--no-optional-locks` keeps the call from writing `.git/index.lock` under the launcher's read-only `.git` bind. The worker calls it right after claiming `.running` and again after the test gate's `exited` marker, once `finish_signalled` has passed. It writes `<label>.commit` holding that one line, through `<label>.commit.tmp` and `mv -f`, **before** `.verdict` is renamed into place. It writes it only when both answers are non-empty and equal. A signalled worker writes no `.commit`, just as it writes no verdict.
- [ ] **Reuse a finished verdict, in both forms.** In the run form, after the existing `if run_alive; then wait_for_verdict; fi`, and before the `rm -f` of the verdict: when `.verdict` and `.commit` both exist and `.commit`'s one line equals a non-empty `clean_tree_commit_var` answer, call `emit_verdict`. It prints `pass` (exit 0) or `fail <log>` (exit 1), as `--wait` does. Start nothing and leave the log, `.verdict` and `.commit` untouched. Apply the same test in the `--no-detach` branch after its own `run_alive` check. On reuse there, rewrite `.verdict` with its own content through `.verdict.tmp` and `mv -f`, so its mtime is the current second (the launcher's `started()` test in `launch-sandboxed-gates.sh` accepts only a verdict stamped at or after its call), then `emit_verdict`. When either form does not reuse, it removes `.verdict`, `.verdict.tmp`, `.commit` and `.commit.tmp` before starting, so a stale `.commit` never outlives its verdict. The `--wait` form is unchanged.
- [ ] **Say it in the header.** Rewrite these header paragraphs, keeping each opening phrase byte-for-byte because Tasks 3, 4 and 5 cite them:
  - **`ONE RUN PER LABEL.`** The run form never starts a second run of a live label. It also reuses a finished verdict on the same commit. State what "nothing the gates read has changed" means: HEAD equal to `.commit`, and the `status` query above empty at the worker's start, its finish and at reuse time. Say why `<state_dir>` is excluded (the session writes run artifacts there during and between rounds, and the gates do not test them) and why ignored files do not count. Name the residual, worded generically because every adopter receives this header and none has this repository's gates: a gate that scans the state directory's committable files does not re-scan a change made there after the run. Name no gate, script or file of this repository in it — Task 6 copies this template byte-for-byte to `scripts/run-test-suite.sh`, so the repository's copy cannot carry a different wording. Note that a session can write `.commit` as it can write `.verdict`, so reuse adds no trust surface.
  - **`THE LOG IS VERSIONED PER ROUND`.** A re-run of the same label truncates its log *unless* the run form reuses that label's finished verdict.
  - **`THE NO-DETACH FORM`.** The reuse, and the verdict rewrite that the launcher's `started()` needs.
  - **`OUTPUT CONTRACT`.** The run form may answer a verdict at once.
  - **`BESIDE THE LOG`.** Add a `<label>.commit` entry.
  - **The `Usage:` / `Exit map:` lines.** Exit 0 and 1 now also cover "run form reusing a finished verdict of its label".
