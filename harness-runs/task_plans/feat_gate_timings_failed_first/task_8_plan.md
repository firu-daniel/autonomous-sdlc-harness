### Task 8 — Add `scripts/lib/gate-round-lib.sh`: gate lines with durations, the round record, the previous round's failures and the focused-then-full driver

**Goal:** One sourced library holding everything about a Run gates round that is not a particular gate: where its records go, how a gate line prints its duration, how a row is recorded, which units failed in the previous round, the focused-then-full driver that runs them first and stops early when they still fail, and the slowest-files section. It is what `cli/test/gate-round-lib.test.mjs` (Task 11) exercises, because `scripts/run-gates.sh` itself runs every real gate and cannot be run from a test.

**Depends on:** Task 1, whose `run-test-suite.sh` exports into each gate command `RUN_TEST_SUITE_LABEL=<label>` and `RUN_TEST_SUITE_LOG_DIR=<state_dir>/test_run_logs/<sanitized branch>` (repo-relative); Task 6, which leaves `scripts/lib/harness-run-lib.sh` byte-identical to its template, whose `THE RUN GATES LANE:` block owns `HR_TEST_RUN_LABEL_PATTERN` (the labels the lane accepts) and `HR_TEST_RUN_LOG_SUBDIR` (the lane's directory name) — this library reads both from there and retypes neither (`.claude/context/conventions.md` → *"The shared constants have owners, and a value is imported from its owner rather than retyped"*); and Task 7, whose reporter writes `<file>` records shaped `file\tstatus\tseconds\ttests\tfailed`, one row per test file (`file` relative to the runner's cwd, `status` `pass`|`fail`, `seconds` one decimal), last line `end`. **Where this library stops:** it runs no gate and knows none by name — `scripts/run-gates.sh` (Task 9) supplies the unit function, the ordered unit ids and the four configuration variables below, and owns every gate's command, grading and its `passed` / `failed` arrays and closing summary.

### Targets

- `scripts/lib/gate-round-lib.sh` (new).

**Work:**

- [ ] **The library's shape and its seam.** `#!/usr/bin/env bash`, a `# gate-round-lib.sh — …` header stating what it owns, who sources it (`scripts/run-gates.sh` and `cli/test/gate-round-lib.test.mjs` only), its **prerequisite** — the sourcing script sources `scripts/lib/harness-run-lib.sh` first, because `gr_init` validates against that library's `HR_TEST_RUN_LABEL_PATTERN` and `HR_TEST_RUN_LOG_SUBDIR` and this library defines no label pattern and no lane-directory name of its own (the header names the two constants, never their values) — and that it **sets no shell options** (`.claude/context/conventions.md` → *"A sourced library sets no shell options at all"*). Bash 3.2; every name prefixed `gr_` / `GR_`; durations from `$SECONDS`, no `date`. Configuration the caller sets before use: `GR_PREREQUISITES` (space-separated `<prereq>:<dep>,<dep>,…` entries), `GR_NARROWED_IDS` (ids whose focused run takes test files), `GR_TEST_FILE_PATTERN` (an ERE every recorded file must match), `GR_TEST_ROOT` (the repo-relative directory recorded files are relative to). `gr_init <repo_root> <tmp_dir>` validates the two `RUN_TEST_SUITE_*` values — the label matches `$HR_TEST_RUN_LABEL_PATTERN`; the directory is non-empty, does not start with `/`, has no `.` or `..` segment, its second-to-last segment equals `$HR_TEST_RUN_LOG_SUBDIR`, and `<repo_root>/<dir>` is an existing directory — and sets `GR_LABEL` and the absolute `GR_LANE`, or leaves both empty (no record; the round still runs, unfocused, with its test record under `<tmp_dir>`). Both constants are read with the `${NAME-}` form (the sourcing script may run under `set -u`); when either is unset or empty — the run library was not sourced — `gr_init` leaves `GR_LABEL` and `GR_LANE` empty: the no-record outcome, never a guessed pattern or directory name. It resets `GR_PHASE=full` and the per-round state.
- [ ] **Lines, rows, destinations.** `gr_gate_line <ok|FAIL|BLOCKED|SKIPPED> <name> <seconds> [<detail>]` prints exactly `  ok    <name> (<s> s)`, `  FAIL  <name> (<detail>, <s> s)`, `  BLOCKED <name> — <detail> (<s> s)`, `  SKIPPED <name> — <detail> (<s> s)`. `gr_record <id> <status> <seconds>` appends the tab-separated row `<GR_PHASE>\t<id>\t<status>\t<seconds>` to `<GR_LANE>/<GR_LABEL>.gates.tsv` when there is a lane, and always tracks, for the current phase, whether any row was `FAIL` and which ids were `ok`. `gr_tests_destination` prints the absolute record path for the current phase — `<GR_LANE>/<GR_LABEL>.<GR_PHASE>.tests.tsv`, or `<tmp_dir>/<GR_PHASE>.tests.tsv` with no lane. `gr_slowest <tests_tsv> <phase>` prints `== slowest test files (<phase> run of gate 4), by the sum of each file's top-level test durations ==` and up to ten rows `  <seconds> s  <file>  (<tests> tests, <failed> failed)`, slowest first, from a readable record; otherwise the one line `== slowest test files: no per-file record (<reason>) ==`.
- [ ] **The previous round's failures.** `gr_previous_focus_var <id>…` (the caller's ordered unit ids) picks the newest `<GR_LANE>/*.gates.tsv` other than `<GR_LABEL>.gates.tsv`, compared with `-nt` (no `stat`, no `ls` parse); none, or no lane, returns 1. The record is **unreadable** — return 1 — unless its first line is exactly `phase\tgate\tstatus\tseconds`, its last line is `end\tcomplete` or `end\tstopped`, and every row between has four fields with phase `focused`|`full`, an id among the given ids, status `ok`|`FAIL`|`BLOCKED`|`SKIPPED` and digits for seconds. It takes the rows of the record's last phase (`full` if any, else `focused`) and their `FAIL` ids. For a failed id in `GR_NARROWED_IDS` it reads `<prev label>.<that phase>.tests.tsv` on the same terms (exact header, last line `end`, five fields, `file` matching `GR_TEST_FILE_PATTERN`, status `pass`|`fail`): unreadable, or no `fail` row, returns 1; rows whose file no longer exists under `<repo_root>/<GR_TEST_ROOT>` are dropped, and a narrowed id left with no file leaves the focus set. Each prerequisite whose dependant is in the set is added. It sets `GR_PREV_LABEL`, `GR_FOCUS_IDS` (in the caller's order), `GR_FOCUS_FILES` (space-separated), and returns 0 only when `GR_FOCUS_IDS` is non-empty; a previous record with no `FAIL` returns 1.
- [ ] **The driver.** `gr_run_round <unit_fn> <id>…` writes this label's record header (truncating an earlier attempt of the same label). When `gr_previous_focus_var` answers 0: `GR_PHASE=focused`, print `run-gates: running first what failed in <prev label>: gates <ids>; test files <files or none>`, call `<unit_fn> <id>` for each focus id; on any `FAIL` print `run-gates: stopped early: ran only gates <ids> and test files <files or none>, which failed in <prev label>; every other gate and test file did not run, so this round cannot pass`, append `end\tstopped`, return 1. Otherwise print `run-gates: everything that failed in <prev label> passed; running every other gate and the whole suite`, set `GR_PHASE=full` and call `<unit_fn>` for every id whose focused row is not `ok`, plus every narrowed id, in the caller's order. With no focus set, `GR_PHASE=full` and every id runs once. Append `end\tcomplete`, return 0. Lists are joined with `, `. The unit-function contract, stated in the header: called as `<unit_fn> <id>`, reads `GR_PHASE` and, for a narrowed id in the focused phase, `GR_FOCUS_FILES`; prints its own lines; calls `gr_record <id> …` exactly once; its exit status is ignored.
- [ ] **What the library never does.** It never writes outside `GR_LANE` or `<tmp_dir>`, never writes an absolute path into a record, never reads a record of its own label as "previous", and never lets a focused phase end a round any way but `fail`: the only `return 0` path is one where every id the caller passed has run in the `full` phase or passed (`ok`) in the focused one, with every narrowed id run whole in `full`. State that invariant in the header as the rule it exists to enforce.
