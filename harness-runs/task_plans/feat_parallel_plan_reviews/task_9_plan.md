### Task 9 — Attribute overlapping sub-agents correctly in run analytics, with a union wall time

**Goal:** Verify that `run-analytics.sh` attributes sub-agents that run at the same time correctly — each dispatch's own wall time, the session's wall time shorter than the sum of its dispatches, and each dispatch's tokens on the right agent — and fix what assumes one sub-agent at a time: the report's claim that the summed `Agent` time is how long the orchestrator was blocked, which overlap makes false.

**Where this task stops.** The analytics programs and their own suite only. Nothing here reads the walker or the planning graph: a plan round's set is simply several `Agent` calls in one assistant message, and the record describes any such message, whichever phase sent it. `run-analytics.sh` itself is unchanged, because both computations live in the two `jq` programs it calls (its header, `THREE FILES, ONE DRIVER.`). The self-adopted copies are **Task 21**'s.

### Targets

- `cli/templates/scripts/lib/run-analytics.jq` → mode `sessions` (`finalize`) and the header's session-record description.
- `cli/templates/scripts/lib/run-analytics-report.jq` → `session_md`'s `### Time` table, the `Agent` / `Task` note and the `### Sub-agents` table's note, and the header's mode `markdown` description.
- `cli/test/fixtures/run-analytics-overlap.jsonl` (new) and `cli/test/fixtures/run-analytics-overlap-transcripts/agent-<id>.jsonl` (new, one per overlapping dispatch).
- `cli/test/run-analytics-overlap.test.mjs` (new) — the accompanying test.
