### Task 3 — Walk a round as a set in `flow-walker.sh`: fan-out, any-order recording under a lock, wait, held binding, join, resume

**Goal:** Make the walker own every rule of a parallel round — which gates are due, which outcomes are still missing, when the round closes, when a binding fires, and what a resume dispatches — so a driver that only reads the walker's output and calls the walker can run a round's gates at once.

**Depends on:** Task 1, whose `fw_round_evidence` prints `plan: not-newer | newer | unknown` judged against **every** present round file (the round's earliest), with its output order and exit codes unchanged; Task 2, whose graph is `formatVersion` 3 — `plan_round` carries `"parallel": true`, every gate's `PASS` / `FAIL` / `skip[].to` and `plan_writer`'s `returned` name `plan_round`, and `entries` names `plan_round` in place of `business_parity_review`.

**Where this task stops.** The walker prints and records; it never dispatches, never decides an outcome, and states no safety contract (its header's `THE SAFETY CONTRACT IS DELIBERATELY NOT THE WALKER'S` stands). Its suites are **Tasks 4–8**: none is edited here, so the old suites fail against this walker until those tasks land. The orchestrator's prose for the new output is **Task 12**'s; the decision record is **Task 22**'s.
