### Task 26 — Classify an idle gap during overlapping dispatches by the context still working, not the orchestrator

**Goal:** Fix the second place run analytics assumes one sub-agent at a time: `run-analytics.jq` → `on_user` marks the orchestrator's context `awaiting` on **every** user event, so when two `Agent` calls go out in one assistant event and their results come back in separate user events, the first result makes the idle-gap classifier read the orchestrator as having a request in flight while it is still blocked on the second dispatch. An idle gap in that window is then labelled `in_flight_request` / `orchestrator` when the remaining reviewer is running a tool or has its own request in flight. Record, with the reason, every other attribution in the two `jq` programs that was checked under overlap and still holds.
