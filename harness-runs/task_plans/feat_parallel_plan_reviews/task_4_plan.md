### Task 4 — Give the walker test driver `--node` and concurrent calls, and re-pin `flow-walker.test.mjs` to the set

**Goal:** Carry the walker's main suite onto the fan-out — each of its sixteen cases asserting the set, the `wait` lines and the join's result instead of one reviewer after another — and give every walker suite the driver it needs to record a gate's outcome by name and to issue simultaneous calls.

**Depends on:** Task 3, whose walker prints, after the writer's `returned`, one dispatch block per due gate in `gates` order — `action: dispatch` / `node:` / `agent:` / `arg.iteration: <round>` / `arg.review_mode:` / the passed-through `skip:` / `round:` / `ledger:` lines **in the first block only** / `heartbeat:` — and records an outcome with `next … --node <gate> --outcome <o> [--findings <path>]`, printing `action: wait` / `node: plan_round` / `recorded: <gate> <outcome>` / one `pending: <gate>` per gate still out, until the set's last outcome prints the round's result exactly as a closing round did before (writer revision with `round: <n> FAIL`, UI-test writer with `round: <n> PASS` and `ledger: P1`, the hand-off, or the cap escalation from `plan_round`). A set holds every due gate: three with parity on, **two** where parity is skipped at the fan-out (its `skip: business_parity_review <skipped|passed-by-exclusion>` line then rides in the first block). A gate's `error` or `blocker` is recorded like a verdict and **held**: it prints `wait` while other gates are out, and once every gate of the set has recorded an outcome the join prints, instead of the round's result, `action: binding` / `binding: <escalate>` / `node: <the first held gate in gates order>` / `agent: <its agent>` / `reason: <error|blocker>` / one `held: <gate> <error|blocker>` line per held gate in `gates` order — no `round:` line, and the counter does not move. While a set is pending, a `next` without `--node` is refused (exit 1) before its outcome is read.

**Where this task stops.** This task owns `cli/test/helpers/walker.mjs`; **Tasks 5–8** consume its two additions and edit no line of it. New fan-out cases beyond re-pinning are **Task 5**'s, concurrency is **Task 6**'s.
