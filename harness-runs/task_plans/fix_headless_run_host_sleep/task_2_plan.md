### Task 2 — The run library's keep-awake primitives: the key's reader, the shared host classifier, the mode decision, the mains-power probe and the holder

**Goal:** `cli/templates/scripts/lib/harness-run-lib.sh` gains every primitive the watcher's hold needs, as pure functions that set variables and log nothing. They are: the `execution.keepAwake` reader, a host classifier extracted from the sandbox judge so both share one WSL detection, a probe a test can override, the decision of which hold applies, a mains-power probe, and a function that starts a holder for one pid.

**Depends on:** Task 1, which declares `execution.keepAwake` (boolean, absent = `true`) in `cli/src/config/model.ts`. The shell reader below is that key's mirror, with the same absent-is-true rule.

**Where this task stops.** This task edits only the library **template**. It never calls `log`, never touches the registry, and spawns nothing at source time. **Task 4** calls these functions from `autonomous-watcher.sh` and owns every log line, registry field and pass. **Task 3** tests them. **Task 9** copies this file into this repository's own `scripts/lib/` byte for byte. Its contract is the function list below, and Tasks 3, 4 and 7 restate it, so carry every name, variable and reason string byte for byte. The library still sets no shell option (`.claude/context/conventions.md` → `## Shell assets`). Bash 3.2 forbids `$BASHPID`, `${v,,}`, associative arrays and `wait -n`.

**The contract.**

| Function | Sets / answers |
|---|---|
| `HR_KEEP_AWAKE_WHO='autonomous-sdlc-harness'`, `HR_KEEP_AWAKE_WHAT='sleep:handle-lid-switch'` | Plain assignments at source time. Declared mirrors of Task 7's `KEEP_AWAKE_WHO` / `KEEP_AWAKE_WHAT` |
| `hr_keep_awake <repo_root>` | Status only, like `hr_progress_comments`: `0` = `true` or absent, `1` = `false`, `2` = unresolvable or not a boolean |
| `hr_host_kind_var <uname_s> <uname_r>` | `HR_HOST_KIND` ∈ `macos` \| `linux` \| `wsl2` \| `wsl1` \| `unsupported`. Always returns 0 |
| `hr_keep_awake_probe_var` | `HR_KEEP_AWAKE_HOST` (a `HR_HOST_KIND` value, `unsupported` when `uname` fails) and `HR_KEEP_AWAKE_TOOL` ∈ `caffeinate` \| `systemd-inhibit` \| empty. Always returns 0. **This is the seam tests override**, as they override `hr_sandbox_prereq_probe_var` |
| `hr_keep_awake_mode_var <repo_root> <job_mode>` | `HR_KEEP_AWAKE_MODE` ∈ `caffeinate` \| `logind` \| `off`, `HR_KEEP_AWAKE_REASON` (empty when holding), and `HR_KEEP_AWAKE_QUIET` (`1` when an `off` needs no per-launch line, else empty). Always returns 0 |
| `hr_on_mains_power` | Status only: `0` = a counted mains-class entry is online, or no entry is counted; `1` = battery. Counts only an entry whose `type` is `Mains` or the `USB` family, whose `scope` is not `Device`, and which has an `online` file |
| `hr_keep_awake_hold_var <mode> <pid> <branch>` | `HR_KEEP_AWAKE_STATE` ∈ `held` \| `battery` \| `refused` \| `failed`, `HR_KEEP_AWAKE_PID` (the holder's pid when `held`, else empty) and `HR_KEEP_AWAKE_DETAIL` (one line when not `held`). Returns 0 only when `held` |

### Targets

- `cli/templates/scripts/lib/harness-run-lib.sh` — the functions above, the config-load emission, the sandbox judge's extraction and a **KEEP AWAKE** header block.

**Work:**

- [ ] **The key's reader.** In `hr_config_load`'s single `jq` program, emit `execution.keepAwake` beside `execution.progressComments`, under the same `if type == "boolean" or . == null then . else "invalid" end` screen. Extend the comment that lists those keys to name it. Add `hr_keep_awake` directly after `hr_progress_comments`, built the same way: `hr_config_load "$root" || return 2`, an absent key returns 0, `true` → 0, `false` → 1, anything else → 2. Its doc comment says it is *"THE ONE READER OF THE KEY IN THIS FAMILY"*, that its TS mirror is `cli/src/config/model.ts` → `keepAwakeEnabled`, and that the watcher passes the **main** checkout, never a run copy.
- [ ] **One host classifier, two users.** Move the `case "$uname_s" … "$uname_r"` classification out of `hr_sandbox_prereq_judge_var` into `hr_host_kind_var`, unchanged. Have the judge call it and set `HR_SANDBOX_HOST="$HR_HOST_KIND"`, so the judge's every output is byte-identical to today's. Its doc comment declares it the shell mirror of `cli/src/doctor/sandboxPrerequisites.ts` → `sandboxHostKind`. Then add `hr_keep_awake_probe_var`. It runs `uname -s` and `uname -r`, and when either fails it sets host `unsupported` and tool empty. Otherwise it classifies through `hr_host_kind_var`, then sets the tool to `caffeinate` on `macos` when `command -v caffeinate` resolves, to `systemd-inhibit` on `linux` when `command -v systemd-inhibit` resolves, and to empty otherwise. `wsl2` gets no tool, on purpose: nothing inside WSL can hold Windows awake.
- [ ] **`hr_keep_awake_mode_var <repo_root> <job_mode>`** decides in this order. The first match wins, and the reason strings are a wire Tasks 3 and 5 match byte for byte:
  1. `<job_mode>` is `1` → `off`, quiet, reason `job mode — a GitHub Actions runner does not sleep`.
  2. `${GITHUB_ACTIONS:-}` is `true` → `off`, quiet, `GITHUB_ACTIONS is true — a GitHub Actions runner does not sleep`.
  3. `hr_keep_awake "$root"`: `1` → `off`, quiet, `execution.keepAwake is false`. `2` → `off`, **not** quiet, `execution.keepAwake is not a boolean`.
  4. `hr_keep_awake_probe_var`, then by host: `macos` with tool `caffeinate` → `caffeinate`, reason empty. `macos` without it → `off`, not quiet, `caffeinate does not resolve on PATH`. `linux` with tool `systemd-inhibit` → `logind`. `linux` without it → `off`, not quiet, `systemd-inhibit does not resolve on PATH`. `wsl2` → `off`, not quiet, `WSL2 — nothing inside WSL can keep Windows awake; set the Windows power plan's lid action to Do nothing on AC (#160 feat_wsl2_support)`. `wsl1`, `unsupported` or anything else → `off`, quiet, `no sleep hold on this platform`.
- [ ] **`hr_on_mains_power`.** Walk the entries of `${HR_POWER_SUPPLY_DIR:-/sys/class/power_supply}/*/`. `HR_POWER_SUPPLY_DIR` is the test seam, and its doc comment says so and says nothing in a shipped script sets it. An entry is **counted** only when all three hold: its `type` file reads, trimmed, `Mains` or a `USB`-family value (`USB` or any value beginning `USB_`, which older kernels report for USB chargers); its `scope` file is absent or does not read `Device`; and its `online` file is readable. An entry with no `type` file is skipped. So is any `scope` = `Device` supply, such as a wireless mouse's `hidpp_battery_*`, which reports `online` = `1` while connected and must never read as mains on a laptop on battery. Any counted entry whose trimmed `online` is `1` → 0. At least one counted entry with none reading `1` → 1. No counted entry at all → 0, because a desktop or server with no mains-class entry counts as AC. A literal unmatched glob is skipped, never read. The doc comment states this rule, the `scope` = `Device` reason included, and that no other file is consulted.
- [ ] **`hr_keep_awake_hold_var <mode> <pid> <branch>`** plus the **KEEP AWAKE** header block. Start with all three outputs empty, then handle the mode:
  - `caffeinate`: run `caffeinate -s -i -w "$pid" </dev/null >/dev/null 2>&1 &`. Set `HR_KEEP_AWAKE_PID=$!` and state `held`.
  - `logind`: when `hr_on_mains_power` fails, set state `battery`, detail `on battery power`, and return 1. Otherwise run the probe `systemd-inhibit --what="$HR_KEEP_AWAKE_WHAT" --mode=block --who="$HR_KEEP_AWAKE_WHO" --why="run $branch" true </dev/null >/dev/null 2>&1`. Prefix it with `timeout 10` when `command -v timeout` resolves, so a logind that never answers cannot hang a launch. On a non-zero status `rc`, set state `refused`, detail `systemd-inhibit exited <rc> — logind did not answer, or polkit refused the lock`, and return 1. Otherwise start the holder `systemd-inhibit` with the same four flags followed by `sh -c 'while kill -0 "$1" 2>/dev/null; do sleep 1; done' keep-awake-wait "$pid"`, also `</dev/null >/dev/null 2>&1 &`. Set `HR_KEEP_AWAKE_PID=$!` and state `held`.
  - Any other mode, or an empty or non-numeric `<pid>`: state `failed`, detail `no hold for mode '<mode>'` or `no engine pid`, return 1.

  The header block states each rule the code relies on. The hold waits on one pid and ends with it, so it can never outlive the run. Every holder's stdio is detached, so it can never hold the launch pipe open. `-s` is AC-only by `man caffeinate`. Both logind lock kinds are needed because `LidSwitchIgnoreInhibited=yes` makes a closed lid ignore a plain `sleep` lock (`man logind.conf`). The waiter is a POSIX loop rather than GNU `tail --pid`, because the same code runs under macOS's BSD userland in tests. A refused lock is never retried here. Add the new functions to the header's function index wherever the existing ones are listed.
