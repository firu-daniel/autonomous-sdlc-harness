### Task 3 — Wire the carry-forward to self-adopt runs in `init`, report it, and name every `.bak` left in a contents-ignored state-dir folder

**Goal:** Make `init` turn on Task 1's carry-forward exactly when it is wiring the harness's own repository through `HARNESS_SELF_ADOPT=1`, and never otherwise. Make its `commands` report say that a carried line was carried. After the plan is applied, name in the run's notes every `.bak` that landed inside a state-dir directory git ignores by its contents, where `git status` never shows it.

**Depends on:** Task 1 and Task 2.

- **Task 1** produces the contract this task calls, in `cli/src/generators/scripts.ts`:
  - `WrapperScriptsOptions.carryOnDiskCommandLines?: boolean`;
  - `WrittenWrapper.carried: boolean`, true exactly when the body was taken from the wrapper on disk;
  - `readWrapperBody(path: string): WrapperBody | undefined`, which returns `undefined` when the file is absent and `{ kind: 'unrecognised' }` when the read throws.
- **Task 2** makes a state-dir README with template-identical bytes come back `kept` under `--force`. So the only state-dir `.bak` files left for this task to name are those of READMEs whose bytes differed.
- This task owns every edit to `cli/src/commands/init.ts` on the branch. It changes nothing in `scripts.ts`, `stateDir.ts` or `repoRoot.ts`.

**Source:** `cli/src/commands/init.ts` → `assertNotHarnessOwnRepository`, `SELF_ADOPT_ENV`, `run`, `keptWrapperBody`, `wrappedRowLine`, `commandReportLines`; `cli/src/generators/repoRoot.ts` → `contentsIgnoredDirectories`.
