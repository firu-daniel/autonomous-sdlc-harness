### Task 1 — Make the `run-test-suite.sh` template's run form detach the gate run and print `pending` at once

**Goal:** Give adopters a run form that starts both gates as a process detached from the calling shell and returns `pending` at once, so every round is collected through `--wait`. The Bash tool's backgrounding, and its background time limit, then never touch a gate run. The wire stays exactly as it is.

**Where this layer stops.** This task changes the template `cli/templates/scripts/run-test-suite.sh` only. **Task 2** proves it in `cli/test/run-test-suite.test.mjs`. **Task 3** corrects `cli/templates/scripts/README.md`. **Task 9** copies the result to this checkout's `scripts/run-test-suite.sh`. The flow prose that calls the wrapper belongs to Tasks 4–8. This task changes no `plugin/` file and no document under `docs/`.

**What must not change (the wire).**
- The stdout lines `pass`, `fail <log path>` and `pending`, and the exit map 0/1/2/3 with each code's meaning.
- Every refusal text, including `no run in flight for <label>` and `cannot read the heartbeat of '<path>'`.
- The label pattern.
- The paths `<state_dir>/test_run_logs/<sanitized branch>/<label>.log`, `.running` and `.verdict`, and the transient `.running.stop.<pid>`.
- The five log marker lines, byte-exact.
- `.running` holding the PID of the process running the gates, as an ownership token, with its mtime as the heartbeat.
- One run per label: a run form that finds a live run of its label collects it through `wait_for_verdict` and starts nothing.

No second liveness signal is added, no `kill -0` / `ps` / `pgrep` is introduced, and no wall-clock constant decides survival.

**Work:**

- [ ] **Split the run form from the worker.** Name the environment marker, for example `RUN_TEST_SUITE_WORKER`, beside the existing `RUN_TEST_SUITE_WAIT_SLICE` / `RUN_TEST_SUITE_STALE` seams. Its value is the label. The script acts as the **worker** only when the marker equals the label it was given. A worker unsets the marker before anything else runs, so no gate ever inherits it: this repository's own suite spawns the wrapper with the label `task_round_1`. Argument parsing, configuration resolution and every refusal stay in front of the split, so a refusal still exits 2 with its one stderr line and writes nothing. The worker's body is today's run body unchanged: `.running` ← `$$`, the traps, the fd-3 heartbeat, `run_gate` for both gates, the verdict rename, the `.running` removal, and the final `echo` of the verdict, which now goes to `/dev/null`.
- [ ] **Run form, after `run_alive` says no run is live:**
  1. `mkdir -p` the log directory.
  2. Remove a stale `.verdict` / `.verdict.tmp`.
  3. Start the worker exactly in probe A2's shape: `RUN_TEST_SUITE_WORKER=<label> nohup bash <the script's own resolved path> <label> </dev/null >/dev/null 2>&1 &`, then `disown`. Stdin, stdout and stderr all point away from the calling shell, so the Bash call returns. Invoke `nohup` **by name, resolved on `PATH`** — never an absolute path or `command -p`. Task 2's start-up-refusal case relies on this: it shadows `nohup` with a stub that starts nothing.
  4. Poll once a second until **either** `.running` holds the worker's PID (`$!`) **or** `.verdict` exists. Either one ends the poll successfully: print `pending` and exit 3. The `.verdict` branch is required, not an optimisation. The worker body removes `.running` as soon as it has renamed `.verdict` into place (`printf '%s\n' "$verdict" > "$verdict_file.tmp" && mv -f …`, then `if [ "$(cat "$running_file" …)" = "$$" ]; then rm -f "$running_file"; fi`), so a worker whose gates finish between two polls is never seen holding `.running`. Step 2 has just removed any stale `.verdict` / `.verdict.tmp`, so a `.verdict` seen after it can only be this worker's. The run form still prints `pending`, not the verdict, so its normal answer stays `pending` and the wire is unchanged; the next `--wait` reads the verdict from `.verdict` without re-running anything.
  5. Bound that poll by `STALE_SECONDS`. Only a poll that sees **neither** `.running` holding `$!` **nor** `.verdict` within it is a refusal, exit 2, with one new stderr line in the existing `run-test-suite.sh: <reason>` form, for example `the detached run of <label> did not start`. Add it to the exit map's refusal list.

  The poll is a start-up bound on a process that has not begun, not a gate time limit.
