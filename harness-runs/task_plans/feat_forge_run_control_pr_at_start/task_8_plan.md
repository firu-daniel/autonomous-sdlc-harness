### Task 8 — `deliver`: reply to and resolve the review threads a round implemented

**Goal:** Item 13. At a user-review round's `completed`, every inline review thread whose comment the round collected is handled, according to the fix plan's verdict for that comment. A comment that became an **implemented** finding gets a reply naming the fix commit (*Addressed in `<sha>`.*), and its thread is resolved. A comment that became an **invalid or out-of-scope** observation gets a reply with the reason, and its thread stays open. The reviewer's *Changes requested* review is never dismissed. This task also defines the fix-plan line that carries the comment ids, which `deliver` reads.

**Depends on:** Task 7, the previous editor of `cli/templates/scripts/remote-run.sh`. Through Task 6, `verb_deliver` reads the bundle's engine (`user_review` is a round), marks the pull request ready, and leaves a marked point after the flip and before the `completed` comments. This task's call goes at that point, so the replies land before `completed` is posted.

**Where this task stops, and who writes what it reads.** This task **owns the wire**: the header of `remote-run.sh` (the `deliver` paragraph) defines the `**Review comments:**` line below, in the same way the header's `control` paragraph already owns the round file's shape. **Task 12** makes `plugin/agents/user-review-fix-plan-writer.md` write that line and cites this header for its shape. Until Task 12 lands, no fix plan carries the line, so this code finds no verdict and replies to nothing. The documentation is **Task 16's** (§2, §8).

**The wire, stated exactly; Task 12 writes it to this form:**

- In a per-finding file `<state_dir>/user_reviews/<branch>_fix_plan[_<n>]/finding_<K>.md`, one line whose text begins `**Review comments:** ` followed by one or more comment ids separated by `, `. Example: `**Review comments:** 2735551234, 2735551240`.
- In the fix-plan index's `## Out of scope / verified-OK` section, a bullet (a line beginning `- `) ending with ` **Review comments:** <id>[, <id>…]`. The bullet's text before that suffix is the reason the reply quotes.
- The ids are the inline-comment ids the round's marker line records (`comments=<id,…>`), which are GitHub's review-comment `id`s. An observation that came from no inline comment carries no such line.
- A finding is **implemented** when the fix-plan index carries the literal `[x] **Finding <K>**`. Its **fix commit** is the oldest commit on `origin/<branch>` that introduced that literal into the index, because the committer flips the entry in the fix's own commit (`plugin/agents/committer.md` → `mode: review_item`).
