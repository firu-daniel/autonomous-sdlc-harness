### Task 4 — Add the `open` verb: open the draft pull request at the run's start and name it on the source issue

**Goal:** Item 4 and item 8. A new job-side verb, `remote-run.sh open <branch> [--repo <root>]`, opens the run's draft pull request from the branch to `defaultBranch`, using the token rules and the single ready-pull-request retry that `deliver` uses today. When it opens one and the run has a source issue, it posts one short comment on that issue naming the pull request, so the issue links the pull request from the moment it exists.

**Depends on:** Task 3, the previous editor of `cli/templates/scripts/remote-run.sh`. Its `forge_pr_var` sets `FORGE_PR` and `FORGE_PR_DRAFT` (`true`/`false`/empty), which this verb reads to decide whether one is already open.

**Where this task stops.** This task adds the verb and the shared opening function. It does **not** run the verb anywhere: the `harness-run.yml` step that calls it is **Task 5's**. It does not change what `deliver` posts or flip any draft state: that is **Task 6's**. It refactors `deliver` to call the shared function, with `deliver`'s behaviour unchanged. The documentation is **Tasks 15 and 17's**.

### Targets

- `cli/templates/scripts/remote-run.sh` — the verb plumbing (the verb `case`, `usage`, the root resolution, the self-gated group, `setup_fail`, the final dispatch `case`), a new `forge_open_pr`, `deliver_pr_body`, a new `verb_open`, `verb_deliver`'s create section, and the header.
- `cli/test/remote-open.test.mjs` (new).
- `cli/test/remote-deliver.test.mjs` — only where an assertion quotes the body sentence this task rewrites.

**The interfaces later tasks rely on:**

- `forge_open_pr <branch>`. The caller has already run `forge_repo_var`, `forge_fetch_branch <branch>` and `forge_issue_var <branch>`, so `FORGE_REPO`, `FORGE_SERVER` and `FORGE_ISSUE` are set. It returns **0** when a pull request was opened, setting `FORGE_PR` (the number), `FORGE_PR_URL` (`$FORGE_SERVER/$FORGE_REPO/pull/<n>`) and `FORGE_PR_DRAFT` (`true` when the `--draft` create succeeded, `false` when the ready retry did). It returns **1** when none was opened, setting `OPEN_ERR` (one line naming why) and `OPEN_FORBIDDEN` (`1` when GitHub refused with `PR_CREATE_FORBIDDEN`, else `0`). It always sets `OPEN_BASE` (the configured `defaultBranch`, empty when unreadable) for the caller's compare link. It never posts and never exits. **Task 6's** `deliver` calls it as its fallback.
- The `opened` comment's marker is `forge_marker opened <branch>`, that is `<!-- sdlc-harness event=opened branch=<branch> -->`. `opened` is a new event name. `forge_dispatch_engine_var` and `control_issue_branch_var` match only `started`, `round` and `reply` markers, so neither reads it.
