### Task 6 — `deliver`: post `completed` on the pull request and the issue, and mark the pull request ready

**Goal:** Item 4's `completed` transition. When a run or a round completes, `deliver` reuses the open pull request and marks it ready for review if it is a draft. It posts `completed` on the pull request always, and also on the source issue when there is one. Both get `sdlc-harness: done`. A refused flip is one warning line and never a failure.

**Depends on:** Task 4, the previous editor of `cli/templates/scripts/remote-run.sh`. It provides `forge_open_pr <branch>` (returns 0 opened / 1 not; sets `FORGE_PR`, `FORGE_PR_URL`, `FORGE_PR_DRAFT`, `OPEN_ERR`, `OPEN_FORBIDDEN`, `OPEN_BASE`), which `verb_deliver` already calls after that task's refactor. Through Task 3, `forge_pr_var` sets `FORGE_PR_DRAFT` (`true`/`false`/empty).

**Where this task stops.** This task owns `completed` and the flip to ready. The flip back to draft when a round starts, and the `failed`/`stopped` texts, are **Task 7's**. Resolving review threads at a round's `completed` is **Task 8's**: this task leaves a clearly marked point in `verb_deliver`, after the flip and before the comments, where Task 8 adds its call. The documentation is **Task 15's** (§4 and the §5 `completed` row).
