### Task 1 — Per-run profile: `Edit`-only file-tool deny map, and the run copy's exact wrapper twins

**Goal:** Make the pinned pair, `writeProtection.ts` → `fileToolDenyRules` and the watcher's `run_profile_render` kind → rule map, emit `Edit` rules only. Then have the watcher's per-run profile grant the run copy's own wrappers by their exact absolute path. That replaces the inert `Bash(bash <work_root>/<project_name>-*/scripts/<x>.sh:*)` glob. The two changes share one file, and the map half must change in both places at once because `cli/test/watcher-run-profile.test.mjs` holds them equal.

**Where this task stops.** It does not touch the template `cli/templates/claude/settings.autonomous.json` or `cli/src/generators/permissionProfile.ts`. Dropping the base profile's `Write` allow pair and its sibling-glob wrapper rows is **Task 3**'s. It does not touch `doctor`, which **Task 2** owns. When this task lands, `cli/test/doctor-profile-sandbox.test.mjs` (fixed by Task 2) and the write-protection cases of `cli/test/profile.test.mjs` (fixed by Task 3) still expect `Write` rules and go red. The story index's `## Context` states this, and this task does not edit those files.

### Targets

- `cli/src/generators/writeProtection.ts`: `fileToolDenyRules`, the module header, and `applyWriteProtection`'s `_README` line.
- `cli/templates/scripts/autonomous-watcher.sh`: `run_profile_entries`, `run_profile_render`, `run_profile_check`, `spawn_engine` and their header comments.
- `cli/test/watcher-run-profile.test.mjs`.

**Work:**

- [ ] **`writeProtection.ts`.** `fileToolDenyRules(entry)` returns `Edit` rules only: `file` → `[Edit(/<p>)]`, `directory` → `[Edit(/<p>/**)]`, `entry` → `[Edit(/<p>), Edit(/<p>/**)]`. Keep the `//` spelling, which is the one-slash prefix plus the path's own leading slash. Rewrite the module header so the rule reads *"an `Edit` deny rule for Claude's file tools"*. State why there is no `Write` rule: `Edit(path)` rules cover every file-editing tool, `Write` included, and a `Write(path)` rule is accepted, never consulted, and warned about at startup (`docs/sandbox-verification.md` → F4). Update the header's mirror bullet for `run_profile_render` to the new map. Update `fileToolDenyRules`' doc comment to match. In `applyWriteProtection`'s `_README` line, *"has an `Edit` and a `Write` rule in `deny`"* becomes *"has an `Edit` rule in `deny`"*. Keep the rest of that line byte-identical.
- [ ] **Watcher map.** In `run_profile_render`'s jq `def rules:`, make the three arms `Edit` only, matching the bullet above exactly. Update the comment block above the function (the *"kind → rule map … declared mirror"* paragraph and *"its Edit / Write rules"*) and the `spawn_engine` comment *"through Edit/Write/Read rules"*, which becomes *"through Edit/Read rules"*.
- [ ] **Watcher wrapper twins: one helper, used by render and check.** Add `run_profile_wrapper_prefixes <copy>`. It sets two globals, `RUN_PROFILE_MAIN_PREFIX` = `Bash(bash <MAIN_REPO>/<scripts_dir>/` and `RUN_PROFILE_COPY_PREFIX` = `Bash(bash <copy>/<scripts_dir>/`. Read `<scripts_dir>` with `hr_scripts_dir "$MAIN_REPO"`. A `.` scripts directory collapses to the root, as the generator's `join(repoRoot, scriptsDir)` does, so the prefix is then `Bash(bash <MAIN_REPO>/`. The function's header comment declares it a mirror, in the form of the existing `run_profile_render` mirror comment: *"The main prefix is a declared mirror of cli/src/generators/permissionProfile.ts → the `{{repoRoot}}` wrapper rows of `WRAPPER_ROW_TOKENS`, `OUTER_LOOP_ROW_TOKENS` and `DEPLOY_ROW_TOKENS` (`Bash(bash <repoRoot>/<scriptsDir>/`, a `.` scripts directory collapsing to the root), held equal by cli/test/watcher-run-profile.test.mjs. A change to that row spelling is an edit here in the same change."* The owner's header declares this mirror in turn (**Task 3**). In `run_profile_render`, for each of `.permissions.allow` and `.permissions.ask`, append the twin of every base entry in that list that starts with the main prefix: the same entry with the main prefix replaced by the copy prefix, in base order, each only when absent. The `ask` twins are what keep a run copy's `deploy.sh` asked about rather than allowed. Never twin any other entry. A `Bash(bash <plugin root>/…)` entry or a repo-relative one keeps its single spelling. Extend `run_profile_entries`' existing exit-3 refusal so a copy path carrying `$`, a backquote, `&`, `;`, `|`, `<` or `>` is refused, as a quote, `*` or tab already is. These are the command-entry shapes `cli/src/generators/profileEntries.ts` → `FORBIDDEN_IN_ENTRY` never lets the generator emit. Update the refusal sentence to name them. Update the function header: *"nothing else changes"* becomes *"and the run copy's twins of the base's main-checkout wrapper rules appended to `.permissions.allow` and `.permissions.ask`"*.
