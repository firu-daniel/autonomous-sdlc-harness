### Task 3 — Drive the two programs from `run-analytics.sh`: paths, suspend intervals, idempotent merge, byte-stable write

**Goal:** Ship `run-analytics.sh`, the outer-loop script that, given a stream file and a branch, records every not-yet-recorded headless session of that stream into `<state_dir>/run_analytics/<branch>/run-analytics.json` and regenerates `run-analytics.md` beside it — idempotent per `session_id`, best-effort, and silent about everything but its one result line.

**Depends on:** Task 1 and Task 2, whose invocations this script makes exactly as they define them:
- Task 1, `lib/run-analytics.jq`: `jq -n -R -c -S -f <lib>/run-analytics.jq --arg mode sessions --argjson idle_threshold_s <int> --argjson known '<json array of session_id strings>' --argjson redact '<json array of [from, to] pairs>' --argjson suspend '[]' --arg suspend_source none < <stream>` → a JSON array of new session records, oldest first, each with `session_id`, `first_at`, `last_at` and `time.host_suspended_ms` / `time.idle_gaps`; and `jq -c -S -f <lib>/run-analytics.jq --arg mode overlay --argjson idle_threshold_s <int> --argjson known '[]' --argjson redact '[]' --argjson suspend '<json array of [start_ms, end_ms]>' --arg suspend_source <pmset|journalctl|file|none>` over that array on stdin. **Both calls pass all six variables** — `jq` resolves every `$name` the program references at compile time, so a call that omits one aborts with `$<name> is not defined` in either mode (Task 1's header states the rule); the neutral values above are the ones each mode ignores, and `idle_threshold_s` is the same `RUN_ANALYTICS_IDLE_SECS` value in both.
- Task 2, `lib/run-analytics-report.jq`: `--arg mode rollup` (document → document with `.run`) and `--arg mode markdown` (document → text, read with `-r`), over the document `{schema: 1, branch, sessions, run}`.

**Where this script stops.** It writes the two files in the given checkout and nothing else: it commits nothing, pushes nothing, notifies nothing and never touches the stream. Committing the result after each session is **Task 5's** (the watcher), and shipping this file through `init` is **Task 4's**.

### Targets

- `cli/templates/scripts/run-analytics.sh` (new, mode `0755` once Task 4 ships it) — the driver. This repository's own `scripts/` copy is Task 9's.

**Work:**

- [ ] **Header, usage and exit contract.** `#!/usr/bin/env bash`, a `# run-analytics.sh — <what it is and what it decides>` header (per `.claude/context/conventions.md` → `## Shell assets` and the sibling outer-loop scripts' shape), `set -uo pipefail` as `cli/templates/scripts/scratch-run.sh` sets it, and a `REPRO` block reproducing each outcome by hand against a throwaway `git init` fixture. Usage: `run-analytics.sh <stream_file> <branch> [--repo <checkout>] [--main-repo <main_checkout>]`; `<checkout>` defaults to the top of the checkout the current directory is in (a bare `git rev-parse --show-toplevel`); `<main_checkout>` is the main checkout whose path is redacted to `<main_repo>` (see **Paths through the run library.**) — the watcher passes it (Task 5), and a hand run may omit it. Exit `0` with one stdout line — `recorded <n> session(s) for <branch>`, `unchanged: no new session for <branch>`, or `no session in <stream_file>`; exit `1` with one `run-analytics: <reason>` line on stderr for any failure; exit `2` on bad usage. Tunables, read from the environment like the watcher's and stated in the header: `RUN_ANALYTICS_IDLE_SECS` (default `120`, a positive integer, else exit 2) and `RUN_ANALYTICS_SUSPEND_SOURCE` (unset = read the host; `none` = read nothing; any other value = a file of `<start ISO-8601 UTC> <end ISO-8601 UTC>` lines, one interval per line — the seam Task 6 drives).
- [ ] **Paths through the run library.** Source `lib/harness-run-lib.sh` from `${BASH_SOURCE[0]}`'s directory with the `dirname` idiom its header prescribes, and resolve the output directory as `hr_state_path <checkout> run_analytics/<branch>` — the state directory is read from the checkout's `harness.config.json`, never assumed; the two jq programs are resolved beside this script under `lib/`. The redaction pairs passed to Task 1, in this order: the checkout's top → `<repo_root>`; the main checkout → `<main_repo>`, when it differs from the checkout's top; `$HOME` (when set and non-empty) → `~`. **Where the main checkout comes from:** the `--main-repo` argument when it is given and non-empty, and `hr_main_repo`'s answer for the checkout only otherwise. `hr_main_repo` alone is not enough. Its header says *"Inside a clone it answers the clone itself"*, and every run copy `create-worktree.sh` makes is a clone. On a real run it would therefore return the copy's own top, the pair would be skipped, and the main checkout's path — present in the stream through every `<MAIN_REPO>/scripts/…` wrapper call and the `--add-dir <MAIN_REPO>/<state_dir>` grant — would reach the committed files as a home-relative `~/…` path. The script reads no `HARNESS_MAIN_REPO`: `cli/templates/scripts/autonomous-watcher.sh`'s header above `spawn_engine` states that *"no outer-loop script reads it, because an assignment prefix on an excluded call could set it"*. The watcher passes the same `$MAIN_REPO` value explicitly as an argument instead (Task 5). The header's tunables paragraph states this source and its fallback. The pair order matters: a clone sits at `<main>-<branch>`, so the main checkout's path is a string prefix of the copy's, and the copy's pair must be applied first. It writes only under `run_analytics/<branch>/` — never another branch's directory (`harness-runs/lessons.md` → *A command scoped to one branch reads and writes that branch's state only*).
- [ ] **Idempotent merge.** When `run-analytics.json` exists it must parse and carry `schema` `1`; otherwise exit 1 naming the file and leave it byte-for-byte untouched — an unreadable record is never overwritten, because it is the only copy of earlier sessions. `known` = its sessions' `session_id`s. Run Task 1's `sessions` mode once over the stream. Append the new records (possibly none) to the existing `sessions` array in stream order — a recorded entry is never rewritten, reordered or re-derived — then run Task 2's `rollup` and `markdown` **every time**, so the `.md` is always regenerated from the `.json` (the task prompt's rule) and a hand-deleted `.md` comes back. `unchanged…` is printed when neither file's bytes changed; no stream session and no existing file → `no session…`, writing nothing.
- [ ] **Host suspend intervals, only when they can matter.** Read the host only when a new session has `host_suspended_ms > 0` and at least one idle gap; bound every read to the new sessions' overall `[first_at, last_at]`. macOS (`uname -s` is `Darwin`, `pmset` on `PATH`): `pmset -g log` lines whose event column is `Sleep` / `Wake` (`YYYY-MM-DD HH:MM:SS ±HHMM` local times converted to UTC epoch milliseconds inside `jq` by subtracting the offset), paired Sleep → next Wake; Linux (`journalctl` on `PATH`): `journalctl -k -o short-iso --no-pager` over the same window, `PM: suspend entry` → `PM: suspend exit`; either reader failing or absent → `suspend_source` `none` and only the `wall − duration_ms` total stands. Pass the intervals to Task 1's `overlay` mode with the matching `suspend_source`. Every reader is a fixed argument vector with no network access.
- [ ] **Byte-stable write, temporary files removed on every exit path.** Write both outputs into `mktemp` files inside the output directory, compare each with `cmp -s` against the existing file, and `mv` into place only a file whose bytes differ (JSON written `jq -S` with a trailing newline, so a re-run over the same stream produces identical bytes and the watcher's commit sees an identical blob); a `trap` removes every temporary file on success, failure and signal alike (`harness-runs/lessons.md` → *A script that creates a temporary working copy or branch removes it on every exit path*). Create the output directory with `mkdir -p` only after the inputs parsed. No wall-clock value is written into either file.

**Verification:**

- A probe under `<state_dir>/scratch/` run through `bash <scripts_dir>/scratch-run.sh` builds a throwaway `git init` repository with a `harness.config.json` naming a `stateDir`, runs the template script over a hand-written two-session stream with `RUN_ANALYTICS_SUSPEND_SOURCE=none`, and shows the two files under `<stateDir>/run_analytics/<branch>/`; a second run prints `unchanged…` and `cmp` finds both files identical.
- Appending a third session to the stream and re-running leaves the first two entries of `.sessions` identical (`jq -S '.sessions[0:2]'` before and after compare equal).
- The same probe, re-run with `--main-repo` naming a second throwaway directory (not the checkout) over a stream whose `Bash` `input.command` names `<that directory>/scripts/x.sh`, writes neither that directory's path nor the checkout's into either file. `jq` on the `.json` shows the command as `<main_repo>/scripts/x.sh`, and `grep -F` for each of the two paths finds nothing in either file.
- A corrupt `run-analytics.json` makes the script exit 1 with one `run-analytics:` line and leaves the file's bytes unchanged; no `tmp` file is left in the directory after any of these runs.

**Deviations from plan:**

- **Redaction pairs are sorted longest `from` first, not applied in a fixed order.** Each anchor contributes both its physical spelling and its logical one: `git rev-parse --show-toplevel` returns `/private/tmp/…` where `$TMPDIR` reads `/tmp/…`. A fixed order cannot place two spellings of two anchors correctly. Sorting by length still puts a clone at `<main>-<branch>` ahead of its main checkout, which is the reason the plan gives. `$HOME` → `~` stays last. The probe's `clone prefix order` case shows `<repo_root>/scripts/a.sh && <main_repo>/scripts/b.sh`.
- **`recorded 0 session(s) for <branch>` covers a regeneration with no new session.** This is the case where a hand-deleted `.md` comes back. The plan's three lines do not cover it, and `unchanged…` would be false there.
- **A `RUN_ANALYTICS_SUSPEND_SOURCE` file is read under the same "can it matter" gate as the host.** An unreadable or malformed file is an exit 1, because it is an operator's input. A failing host reader still degrades to `none`, as the plan says.
- **Intermediates go in a private `mktemp -d` under `$TMPDIR`.** The plan creates the output directory only after the inputs have parsed, so intermediates cannot go there. The trap removes this directory with `rm -f` and `rmdir`, never a recursive removal. The two final temporaries are `mktemp` files inside the output directory, as the plan says.
- **`journalctl` is bounded by `--since @<s> --until @<s>`** (epoch seconds, which avoids any local-time conversion). `pmset -g log` takes no window, so its lines are filtered to the span inside `jq`.
- **The branch must pass `git check-ref-format refs/heads/<branch>` and must not start with `-`; anything else is an exit 2.** The branch names a directory under `run_analytics/`, so `..` or a leading `/` would let the write escape it.
- **Evidence downgrade: the real host readers were not run.** A direct `pmset -g log` was refused by the tool layer ("Permission to use Bash has been denied because Claude Code is running in don't ask mode"). Both parsers were exercised only against stand-in `pmset` / `journalctl` (and a stand-in `uname` answering `Linux`) placed first on `PATH`, printing the documented line formats. Both re-classed the overlapping gap as `host_asleep` with the matching `suspend_source`. A stand-in that exits 1 left `none`. A direct `bash -n` was refused in the same way, so it ran inside the probe instead.
- **Evidence downgrade: the jq 1.5 floor is reasoned, not executed.** The only `jq` here is 1.8.2. The script's own programs use only `--slurpfile`, `try`/`catch`, `unique_by`, `all/2`, `fromdateiso8601` and string slicing, all of which exist in 1.5.
- **Probe evidence.** `harness-runs/scratch/run_analytics_sh_probe.mjs` was run as `bash scripts/scratch-run.sh harness-runs/scratch/run_analytics_sh_probe.mjs <repo_root>` and printed `ALL PASS`. It covers every **Verification** bullet. The byte checks use `Buffer.compare` instead of `cmp`. The no-path check is a substring test, standing in for `grep -F`, over both files, for both throwaway directories in both spellings. The probe also covers usage exit 2, the missing stream, the `no session…` case writing nothing, the default checkout from a subdirectory, and no work directory left in `$TMPDIR`.
