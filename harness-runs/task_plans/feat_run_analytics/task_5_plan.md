### Task 5 — Record and commit run analytics after every session in `autonomous-watcher.sh` → `spawn_engine`

**Goal:** After every headless session ends — the launch, every park or pause resume, and every job-mode auto-resume, locally and inside a GitHub Actions job — run `run-analytics.sh` over that run's stream and commit the two output files on the run's branch, best-effort: a failure is one line in the watcher log and never changes the classification, the exit code or any notification.

**Depends on:** Task 3 and Task 4. Task 3's `run-analytics.sh` contract, restated: `run-analytics.sh <stream_file> <branch> --repo <checkout> --main-repo <main_checkout>` (the main checkout's path is redacted to `<main_repo>`; the script never reads `HARNESS_MAIN_REPO`, so this argument is how it learns that path) writes `<checkout>/<state_dir>/run_analytics/<branch>/run-analytics.json` and `run-analytics.md`, prints one result line on stdout, exits `0` on success (including *unchanged* and *no session*), `1` with one `run-analytics: <reason>` line on stderr on failure, `2` on bad usage, and commits nothing. Task 4 is what makes `init` write it beside this watcher as `<scripts_dir>/run-analytics.sh`.

**Where this task stops.** It decides when the script runs and commits what it wrote; it computes nothing. The suite that drives this hook through a real watcher pass is **Task 7's**; this repository's own `scripts/autonomous-watcher.sh` copy is **Task 9's**.

- [ ] New function `record_run_analytics <branch> <worktree> <log_path>`, documented in a comment block like `classify_run_exit`'s, which **always returns 0** and never reads or writes the caller's `rc`: return at once when the registry's `stall_killing` is `1` (the watchdog owns this run's teardown, exactly as `classify_run_exit`'s first test); when `$RUN_ANALYTICS` is not executable, `log` one line naming it and the `init --force` route, and return; resolve `state_rel` through `run_state_dir "$worktree"` (unresolvable → one `log` line, return); run `"$RUN_ANALYTICS" "${log_path%.log}.stream.jsonl" "$branch" --repo "$worktree" --main-repo "$MAIN_REPO" >>"$log_path" 2>&1`. `$MAIN_REPO` is the same value `spawn_engine` exports as `HARNESS_MAIN_REPO`, passed as an argument because no outer-loop script reads that variable. The script's own output goes to the run's log. On a non-zero exit, `log` one line `run analytics: '<branch>' not recorded (exit <n>) — see <log_path>` and return. Every line this function writes through `log` lands in the **watcher log**, `<state_dir>/autonomous_logs/watcher.log`, because `log()` tees to `$WATCHER_LOG`. That includes the not-executable line and the unresolvable-state line. The run's log holds only what the script and `watcher_commit` print. Task 7 asserts the lines in the watcher log.

No push here: locally the commit rides the run's next push, and in a job the workflow's `Push the branch` step pushes it (`## Context` of the story index states why — no network calls). `watcher_commit` → `hr_commit_placed` commits only that path, runs no hook, refuses a protected branch and leaves the copy's index synced, so the copy reads clean for the next resume.
