### Task 6 — Pin the script's metrics and idempotence in `cli/test/run-analytics.test.mjs` over a two-session fixture stream

**Goal:** A `cli/test` suite that runs the `run-analytics.sh` `init` writes over a small two-session fixture stream and pins the task prompt's six cases — a stalled request, an `api_retry`, a sub-agent dispatch, a tool call, a `result` whose `duration_ms` is shorter than the wall span, and a re-run that changes nothing — plus the per-request latency rule, the suspended-time arithmetic, and the no-machine-path rule.

**Depends on:** Task 4, which makes `init` write `scripts/run-analytics.sh`, `scripts/lib/run-analytics.jq` and `scripts/lib/run-analytics-report.jq` into a fixture. The contract under test, restated from Tasks 1–3: `bash scripts/run-analytics.sh <stream_file> <branch> [--repo <checkout>] [--main-repo <main_checkout>]` (the main checkout's path is redacted to `<main_repo>`; it falls back to `hr_main_repo` when the argument is absent) writes `<stateDir>/run_analytics/<branch>/run-analytics.json` = `{schema: 1, branch, sessions, run}` and `run-analytics.md`; exit `0` with `recorded <n> session(s) for <branch>` / `unchanged: no new session for <branch>` / `no session in <stream_file>`, `1` with one `run-analytics: <reason>` stderr line, `2` on bad usage; `RUN_ANALYTICS_SUSPEND_SOURCE` = `none` or a file of `<start> <end>` ISO-8601 UTC lines; `RUN_ANALYTICS_IDLE_SECS` defaults to `120`. Session keys: `session_id, complete, first_at, last_at, time{wall_ms, duration_ms, duration_api_ms, host_suspended_ms, idle_ms, active_ms, idle_threshold_s, suspend_source, idle_gaps[{start_at, length_ms, context, class}]}, requests{items[{started_at, context, latency_ms, output_tokens, input_tokens, cache_read_tokens, cache_write_tokens, after_retry}], overall, by_context}, tools{items[{tool, context, started_at, duration_ms, result_bytes, is_error, permission_denied}], by_tool, slowest, polling}, subagents[{type, description, started_at, duration_ms, requests, …, wall_share}], cost{…, cache_hit_ratio}, reliability{api_retries, api_retry_errors, …}`; gap classes `host_asleep`, `in_flight_request`, `tool_running`, `unknown`; `.run` keys including `wall_ms, active_ms, host_suspended_ms, idle_ms, sessions, total_cost_usd, slowest_subagent`.

**Where this task stops.** It tests the script alone, run by hand against a fixture; the watcher calling it after a session is **Task 7's** suite. It changes no shipped file.

### Targets

- `cli/test/run-analytics.test.mjs` (new) — the suite.
- `cli/test/fixtures/run-analytics-two-sessions.jsonl` (new) — the fixture stream, carrying no machine path: where a path is needed it holds the literal `@FIXTURE_ROOT@` or `@MAIN_REPO@`. When the suite copies the file in, it replaces the first with the throwaway repository's root and the second with a second throwaway directory that stands in for the main checkout.

**Work:**

- [ ] The fixture: two sessions, each opening with a `system`/`init` carrying its own `session_id`, with hand-chosen timestamps so every expected number is computable by hand and stated in a comment in the suite: session 1 holds one orchestrator request that stalls 300 s before its assistant event, one `system`/`api_retry` (`error_status` `529`) before a request in the same context, one `Bash` tool call whose `input.command` names `@FIXTURE_ROOT@/scripts/x.sh` and whose `tool_result` text carries a multi-byte character, issued three times (a polling loop), one `Bash` tool call whose `input.command` names `@MAIN_REPO@/scripts/y.sh` (a wrapper call through the main checkout), and a `result` whose `duration_ms` is 600 000 ms below the wall span; session 2 holds one `Agent` dispatch (`subagent_type`, `description`) whose sub-agent events carry its `parent_tool_use_id` and make two requests, then its `tool_result`, then a `result`. Plus untimestamped `tool_progress` and `system`/`thinking_tokens` events, and one non-JSON line.
- [ ] Suite scaffolding: header stating the rule it enforces (the script's record is right, idempotent per `session_id`, and machine-path-free) and what it deliberately leaves out — the real `pmset` / `journalctl` readers (host-dependent; the suite sets `RUN_ANALYTICS_SUSPEND_SOURCE` on every run) and the 10 MB timing (a hand-run step, `<state_dir>/lessons.md` → *Evidence and measurement*). Build the repository with `createFixture` and `runCli(dir, ['init'])` from `cli/test/helpers/fixture.mjs`, place the fixture stream under its `<stateDir>/autonomous_logs/`, and run the script with `runBash` from the fixture root, never against this checkout.
- [ ] Metric cases, asserting exact values: the stalled request's `latency_ms` is the gap from the last timestamped event of its context to its first assistant event (the per-request rule) and it is counted in `requests.overall.over_threshold` and as an idle gap of class `in_flight_request`, context `orchestrator`; the request after the retry has `after_retry: true` and `reliability.api_retry_errors` holds `529`; the dispatch's `type`, `description`, `duration_ms` (its `tool_use` to its `tool_result`), `requests: 2` and `wall_share`, and those two requests carry its `subagent_type` as `context`; the tool call's `duration_ms`, `result_bytes` (the UTF-8 byte count, not the character count) and one `polling` entry with `count: 3`; `time.host_suspended_ms` equals `wall_ms − duration_ms` = 600 000 exactly.
- [ ] Suspend overlay and incomplete sessions: with a `RUN_ANALYTICS_SUSPEND_SOURCE` file whose one interval overlaps the stalled gap, that gap's class is `host_asleep` and `suspend_source` is `file`; with `none` it stays `in_flight_request`. A stream whose last session has no `result` records only the earlier sessions; appending a later session then records it with `complete: false`.
- [ ] Idempotence, refusal and redaction: a second run over the same stream exits 0 with `unchanged…` and both files are byte-identical to the first run's; appending a third session and re-running leaves `.sessions[0]` and `.sessions[1]` deep-equal to before; `run-analytics.md` contains `## Whole run` before `## Session 1` before `## Session 2`; a corrupt `run-analytics.json` makes the script exit 1 with one `run-analytics:` stderr line and leaves the file's bytes unchanged; neither output file contains the fixture repository's absolute root, `/Users/` or `/home/`, and the polled command shows `<repo_root>/scripts/x.sh`. Main-checkout case: every run in the suite passes `--main-repo <the second throwaway directory>`, which is not the fixture root, as the watcher does. That directory's path appears in neither output, and the wrapper call's command shows `<main_repo>/scripts/y.sh`. This is the case the plain-checkout fixture would otherwise hide, because there `hr_main_repo` answers the checkout itself.

**Verification:**

- `npm test --workspace cli -- test/run-analytics.test.mjs`, as one plain foreground command from the repository root, passes, and its captured counts show every case ran (`# fail 0`, a non-zero `# pass`).
- `grep -nE '/(Users|home|private|tmp|var)/' cli/test/fixtures/run-analytics-two-sessions.jsonl` finds nothing.

**Deviations from plan:**

- **The main-checkout `Bash` call is issued three times, not once.** A session record carries a Bash command only in `tools.polling` (`lib/run-analytics.jq` → `finalize`: `tools.items` has no `command` key), and the Markdown renders commands only from `polling` (`lib/run-analytics-report.jq`, the polling table). A single `@MAIN_REPO@/scripts/y.sh` call would therefore appear in neither output, and the plan's assertion that it shows as `<main_repo>/scripts/y.sh` could not be made. With three calls it forms a second polling entry (`count: 3`, `total_ms: 3000`), and the suite asserts it in both files.
- **The `api_retry` event carries no timestamp**, as no `system` event does in the measured streams (Task 1's deviation note). This keeps the next request's `latency_ms` measured from the last timestamped event (00:05:11 → 00:05:15 = 4 000 ms) rather than from the retry.
- **Session 1's result is at 00:20:00**, so its wall span (1 200 000 ms) can exceed `duration_ms` by 600 000. That makes a second idle gap (00:05:22, 878 000 ms, class `unknown`). The suite asserts it, and also asserts that the suspend interval leaves it as `unknown`.
