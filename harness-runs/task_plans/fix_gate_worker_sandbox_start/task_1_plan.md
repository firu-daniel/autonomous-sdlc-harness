### Task 1 — Add `scripts/gate-worker-start-probe.sh`, an in-session probe of the gate worker's start with `nohup` and detach controls

**Goal:** Give this repository a probe that an unattended session can run in its own sandbox. It measures whether the Run gates worker starts, captures the worker's own stderr, and separates `nohup` from detaching by controls that each remove one candidate. Every reading is printed whole, so Task 2 can gate its fix on it and Task 6 can record it.

**Where this layer stops.** This task writes the probe and runs it once to show it works. It changes no file under `cli/`: the run form's template is Task 2's, and the probe only **copies** it into a fixture. It writes nothing in `docs/`, because the record is Task 6's. The probe's test is Task 4's.

### Targets

- `scripts/gate-worker-start-probe.sh` (new) — hand-written for this repository, like `scripts/sandbox-probe.sh` and `scripts/probe-plugin-cli.sh`. It is not in the set `init --force` regenerates and not a `cli/templates/` file, and its header says so in those words.

**The interface later tasks rely on — spelled out here, restated in Tasks 2, 4 and 6.**

- **Invocation:** `bash scripts/gate-worker-start-probe.sh [--work <base>]`, from the checkout root, as one plain foreground command with no `$` in it. That keeps it inside what the script-allowlist guard permits (`scripts` is this repository's `scriptsDir`, and the basename is not deny-listed). Also `bash scripts/gate-worker-start-probe.sh judge <leg> <records dir>` and `--help`.
- **Work area:** `<base>` defaults to `<root>/<state_dir>/scratch`. `<root>` is placed by `hr_script_root` and `<state_dir>` by `hr_state_dir`, both from `scripts/lib/harness-run-lib.sh`, never by git discovery from the scripts directory. The probe creates one fresh `gwsp.XXXXXX` directory under `<base>` with `mktemp -d "<base>/gwsp.XXXXXX"`. That directory, and nothing else, is removed on every exit path (an `EXIT` trap, plus `INT`, `TERM` and `HUP`). A `<base>` that is absent or cannot hold the directory is a refusal: exit 2, nothing created.
- **Legs, in this order, and the one summary line each prints:** `gwsp: <leg>: <verdict> — <evidence>`. Each leg first prints its full readings under a `== gwsp: <leg> ==` header, never truncated (lessons ledger: *"A measurement script stores and reports every reading in full"*).
  - `env` — verdict `info`. Readings: `claude --version` (stdout, stderr and status, or `not found`), `uname -sr`, `sw_vers -productVersion` where it exists, `$BASH_VERSION`, and the date.
  - `sandbox` — verdict `sandboxed` | `unsandboxed` | `not run`. It writes `$HOME/.gwsp-sandbox-check.<pid>` and grades on disk. Present means `unsandboxed`, and the file is removed at once. Absent means `sandboxed`, with the write's message whole. The header records the residual: a sandbox profile that grants `$HOME` would read as `unsandboxed`.
  - `nohup` — verdict `pass` | `fail` | `not run`. In the call, not detached, it runs `nohup true </dev/null >/dev/null 2><rec>` and the control `( trap '' HUP; exec true ) </dev/null >/dev/null 2><rec>`, recording each status and stderr whole. `fail`: `nohup` exits non-zero while the control exits 0. `pass`: both exit 0. Anything else is `not run`.
  - `detach` — verdict `pass` | `fail` | `not run`. Two arms, each detached with `&` plus `disown` and each writing one marker file, with stderr captured to its own record. The `nohup` arm is `nohup bash -c '<write marker>'`. The trap arm is `( trap '' HUP; exec bash -c '<write marker>' )`. It waits at most 10 s for the markers and grades on disk. `fail`: the `nohup` arm wrote nothing and the trap arm wrote its marker. `pass`: both wrote. Anything else is `not run`, and the evidence names each arm `started` / `not started`.
  - `launch-line` — verdict `pass` | `fail` | `not run`. The leg stands in for the run form's launch, so it first does the setup the run form does before its launch line, because the worker path creates no directory (it starts at `printf '%s\n' "$$" > "$running_file"`; only the run form runs `mkdir -p "$log_dir"`):
    - **Lane setup.** From the fixture root, in a subshell that sources the fixture's **copied** `scripts/lib/harness-run-lib.sh`, compute the lane directory as the worker computes it: `hr_state_dir <fixture>`, `hr_current_branch <fixture>`, then `hr_test_run_lane_dir` on those two (with this fixture, `devscene/test_run_logs/gwsp-probe`, relative to the fixture root). Never retype the path. Then `mkdir -p` it and `rm -f` its `gwsp_launch.verdict`, `.verdict.tmp`, `.commit`, `.commit.tmp`, `.running` and `.start`, as the run form's own `rm -f` does (plus `.running`, since no run of this label is live in a fresh fixture). Any setup command that fails grades the leg `not run`, quoting that command and its message whole. A setup fault is never `fail`.
    - **The launch.** From the fixture root, it issues the run form's **pre-fix** worker launch line verbatim, with stderr redirected to a record instead of `/dev/null`: `RUN_TEST_SUITE_WORKER=gwsp_launch nohup bash <fixture>/scripts/run-test-suite.sh gwsp_launch </dev/null >/dev/null 2><rec> &`, then `disown`. It waits at most 15 s for `gwsp_launch.verdict` in that lane.
    - **Grading and evidence.** `pass`: the verdict is on disk. `fail`: none is. Either way, the readings and the evidence quote what reached the lane on disk — the lane directory's listing and whether `gwsp_launch.running` and `gwsp_launch.verdict` are present — together with the stderr record whole. A `fail` is thus told apart from a setup fault: the lane exists and is listed, and nothing of the worker's reached it.
    - **Expected unsandboxed.** Where `nohup` works — the unsandboxed control, `bash scripts/gate-worker-start-probe.sh` from a terminal — this leg reads `pass`.
  - `run-form` — verdict `pass` | `fail` | `not run`. It issues the fixture's run form as shipped, `bash <fixture>/scripts/run-test-suite.sh gwsp_run`, and records stdout, stderr and status. On `pending`, it issues `--wait gwsp_run` with `RUN_TEST_SUITE_WAIT_SLICE=10` at most 3 times, a stated departure. `pass`: `pending` and then `pass`. `fail`: exit 2 with `the detached run of gwsp_run did not start`. It also records the lane directory's listing and, when present, `gwsp_run.start` whole: that file exists only once Task 2 has landed.
  - `tmpdir` — verdict `pass` | `fail`. Readings: `$TMPDIR`, its canonical form (`cd -P` / `pwd -P`, the symlink candidate), and `mktemp "${TMPDIR:-/tmp}/gwsp.XXXXXX"` and a bare `mktemp -d`, each graded on disk, with what each created removed. `fail`: either created nothing.
- **The fixture** (`<work>/repo`): `git init -q`, then `git symbolic-ref HEAD refs/heads/gwsp-probe`, with no commit needed. A `devscene.config.json` with `version` 1, `defaultBranch` `main`, `stateDir` `devscene`, `scriptsDir` `scripts`, one catch-all `general` layer, `commands.typecheck` `<none>` and `commands.test` `true`. Copies of this checkout's `cli/templates/scripts/run-test-suite.sh` and `cli/templates/scripts/lib/harness-run-lib.sh` under `scripts/`. Nothing from this checkout's own `scripts/run-test-suite.sh` runs.
- **`judge <leg> <records dir>`** re-grades one leg from its records alone and prints its summary line. It reads only that directory, so Task 4 can plant every verdict class. Each leg's record file names are fixed in the header (`<leg>.<reading>.status` / `.stderr` / `.stdout`, plus the leg's on-disk marker names). For `launch-line` those include the lane setup's status and message (a non-zero setup status grades `not run`), the lane listing, and the presence of `.running` and `.verdict`.
- **Exit map:** 0 when every leg printed a summary line, whatever the verdicts. 1 for usage. 2 for a refusal before any leg ran, with nothing created. 5 when teardown could not remove something, named on stderr.

**Work:**

Argument parsing, the `--work` refusal, the one fresh `gwsp.XXXXXX` directory and the teardown trap that removes it and nothing else.

**Verification:**

- The one in-session run prints a `== gwsp: <leg> ==` block and one `gwsp: <leg>: <verdict> — …` line for each of the seven legs, in order, and exits 0. Its verdicts are a measurement, not this task's pass criterion. Task 2 acts on them. A `launch-line` reading whose block shows no lane directory, or a `No such file or directory` on a lane path in its stderr record, is a fixture defect in this task, not a measurement.
