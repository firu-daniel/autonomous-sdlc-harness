### Task 7 — Add the optional matched-precision ONNX fp32 leg to `vector-agreement.mjs`

**Goal:** Separate the two divergence sources the task prompt orders first and second: **quantization**, and **ONNX-exported weights against their PyTorch originals at matched precision**. When the operator has supplied the fp32 ONNX export, `vector-agreement.mjs` also embeds every chunk with it. It then reports two more cosines per chunk: TypeScript q8 against TypeScript fp32, which is quantization alone over the same ONNX graph, and TypeScript fp32 against Python fp32, which is the export and the runtime alone at matched precision. When the export is absent the leg reports itself **not arranged** and the module behaves exactly as Task 6 left it.

**Depends on:** Task 6, which produces `measureVectorAgreement({ checkout, corpus })` → `{ corpus, snapshot, ids: { typescript, python }, pairs: [{ key, cosine, textMatches }], summary, lowest, textMismatches, legs: { quantizationAndExport: true } }` and `renderVectorAgreement(result)`. This task extends both. Existing fields keep their names and meaning, and new fields are added beside them. It also depends on **Task 13**, which exports `EMBEDDING_EXTRACT_OPTIONS` (`{ pooling: 'cls', normalize: true }`, read-only) from `cli/src/retrieval/models.ts`, compiled to `cli/dist/retrieval/models.js`. `loadModels` reads that constant itself, so the leg extracts exactly as the TypeScript backend does.

**Where this task stops.** It does not download anything and never writes into the machine-shared Xenova cache: the task prompt says *"stop and say so rather than improvising an install"*, and `docs/retrieval.md` → `## Measured, and how` records that cache's state as something no tooling here moves. The export is the operator's optional manual step, placed under `harness-runs/scratch/backend-comparison/onnx-fp32/` (story index → **Manual setup required**). Whether the leg ran, and what it shows, is **Task 10's** to write up.
