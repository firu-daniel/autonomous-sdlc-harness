### Task 3 — Drive the Python package's `serve-http` as an eval session in `python-backend.mjs`

**Goal:** Give the eval a Python-backend **session**: an object the runner can query arm by arm exactly as it queries the in-process TypeScript index. It is built by running the Python package's own entry points over a mirror of the corpus, re-implements none of its search, and leaves no process, port or directory behind on any exit path.

**Depends on:** Task 1, which provides `mirror-fixture.mjs` → `buildMirrorFixture(repoRoot, resolved)` → `{ dir, config, files, warnings }` and `removeMirrorFixture(dir)`. This task calls both and builds no fixture of its own. It also depends on Task 2 for `evals/docs-retrieval/README.md` only: Task 2 added the `backends.mjs` row, and this task's row follows it.

**Where this task stops.** It exposes a session and does nothing with it. **Task 4** wires it into `run.mjs` / `arms.mjs` behind `--backend python`, and is the only caller that queries it per arm. **Task 5** reuses `indexPythonCorpus` for the MCP pass, and **Task 6** reuses it to have the Python vectors in the database. Nothing here touches `docs-retrieval-service/`: the task prompt forbids any change to the Python backend's behaviour on this branch.

### Targets

- `evals/docs-retrieval/python-backend.mjs` (new).
- `evals/docs-retrieval/README.md` → `## The modules` — a new `python-backend.mjs` row (scope register row 27).

**The interface this task produces — Tasks 4, 5 and 6 restate it verbatim:**

```
indexPythonCorpus({ checkout, fixtureDir })
  -> Promise<{ files: number, chunks: number, embedded: number, unchanged: number, deleted: number, warnings: string[] }>

openPythonSession({ checkout, resolved })
  -> Promise<{
       backend: 'python',
       snapshot: { files: number, chunks: number },
       chunkKeys: Set<string>,
       warnings: string[],
       embedder: { id: string },
       reranker: { id: string },
       packageVersion: string,
       search({ query, k, mode }) -> Promise<{ hits: { ref: string, score: number }[], abstained: boolean, bestRerankScore: number | null, searchMs: number }>,
       close() -> Promise<void>
     }>
```

`checkout` is the absolute root of this checkout, which `args.mjs` → `parseArgs` returns as `checkout`. `resolved` is `corpora.mjs` → `corpusConfig`'s `{ id, config, repoRoot }`.

**Work:**

- [ ] **Header and preconditions.** The module header states *"The rule this module exists to enforce"*: the eval reaches the Python backend only through the package's own entry points, `bash scripts/python-service.sh run <sub-command>` (the wrapper `docs-retrieval-service/README.md` → `## Standing it up` makes the one route), and every figure is scored by the eval's own `metrics.mjs`. Import every name the CLI already owns from `cli/dist/retrieval/pythonBackend.js`: `PYTHON_DATABASE_URL_VARIABLE`, `PYTHON_SELF_CHECK_SUB_COMMAND`, `parseSelfCheck`, `pythonDatabaseUrl`. Import `RETRIEVAL_STUB_ENV` from `cli/dist/retrieval/models.js`. The names the CLI does not own are spelled once, as module constants, and the header names each one's owner: the sub-commands `index` and `serve-http` (`docs-retrieval-service/src/harness_docs_retrieval/cli.py` → `SUB_COMMANDS`), the paths `/search` and `/health` and the response keys `hits`, `abstained`, `best_rerank_score`, `search_ms` (`http_app.py` → `create_app`), and the `index:` summary line (`cli.py` → `_run_index`). An `assertPythonBackendAvailable()` refuses, each by name and before anything is spawned: `RETRIEVAL_STUB_ENV` set (real models only, as `index-build.mjs` → `assertRealModelsAreAvailable` refuses); the wrapper exiting `3` (not provisioned; quote its stderr line); and any `FAIL` line of `self-check --repo <fixture>` as `parseSelfCheck` reads it (quote that line, which names the missing weights or the unreachable database). The database URL is `pythonDatabaseUrl(process.env)`, imported: `cli/src/retrieval/pythonBackend.ts` → `pythonDatabaseUrl` is the one place the launcher's default is decided (`cli/src/doctor/checks.ts` already consumes it), so this module neither restates the rule nor imports `PYTHON_DEFAULT_DATABASE_URL`. The child environment sets `PYTHON_DATABASE_URL_VARIABLE` to that value. It is passed in the child environment and **never** written into any message or return value.
- [ ] **`indexPythonCorpus`.** Run `index --repo <fixtureDir>` through the wrapper with `execFileSync('bash', [<checkout>/scripts/python-service.sh, 'run', 'index', '--repo', fixtureDir], { cwd: checkout, env })`, a fixed argument vector with no shell (`.claude/context/cli.md` → *"Every child process is spawned with a fixed argument vector"*, applied here by analogy). Parse the one stdout line `index: <files> files, <chunks> chunks; embedded <n>, unchanged <n>, deleted <n>`, with an optional `; rebuilt for a new embedder`, into the return object. Collect `harness-docs-retrieval: warning: <text>` stderr lines into `warnings`. On a non-zero exit, refuse with the child's `harness-docs-retrieval: <message>` line. On an unparseable stdout, refuse quoting it.
- [ ] **`openPythonSession`, start.** `buildMirrorFixture(checkout, resolved)`. **Everything after it sits inside one `try`**: on any throw, the `catch` calls `close()` when the child has been spawned, and `removeMirrorFixture(dir)` otherwise, then rethrows — so every refusal **after the fixture is built** (the stub refusal, the wrapper's exit `3`, a `self-check` `FAIL`, an `index` failure or unparseable `index:` line, a `/health` refusal) removes the fixture it created, and nothing else. Inside the `try`: `assertPythonBackendAvailable`. Then `indexPythonCorpus`, whose `{ files, chunks }` become `snapshot`, so every figure is stamped the way `index-build.mjs` stamps the TypeScript side. Compute `chunkKeys` with the TypeScript `chunkMarkdown` over the fixture's files, which is exactly `index-build.mjs` → `buildIndex`'s computation. The header records that the two chunkers' keys are byte-identical by `docs-retrieval-service/tests/test_chunk_parity.py`. Pick a free loopback port by listening on port `0` at `127.0.0.1` and closing. Spawn `serve-http --repo <fixtureDir> --host 127.0.0.1 --port <port>` through the wrapper with `spawn(…, { detached: true, stdio: ['ignore', 'pipe', 'pipe'] })`. `detached` puts the bash wrapper, `uv` and the Python server in one process group, so `close()` can stop all three. Poll `GET /health` until `200`, the child exits (refuse with its last stderr line), or a named deadline constant (`HEALTH_DEADLINE_MS`, generous because the first start loads both models; refuse naming the constant). That bounds the retry, per `harness-runs/lessons.md` → *"Every automatic retry in an unattended path is bounded by a count or a deadline."* `embedder.id` and `reranker.id` are `/health`'s `embedder` and `reranker`. `packageVersion` is read from `docs-retrieval-service/pyproject.toml`'s `version = "…"`.
- [ ] **`search` and `close`.** `search({ query, k, mode })` sends `POST /search` with the JSON body `{ query, k, mode }`. On a non-`200`, it refuses with the response's `error` text and the query. It maps the response to `{ hits: hits.map(({ ref, score }) => ({ ref, score })), abstained, bestRerankScore: best_rerank_score ?? null, searchMs: search_ms }`, refusing by name when any of those four keys is absent. That turns a renamed key into a stop rather than a silent `undefined` figure. `close()` sends `SIGTERM` to the process group (`process.kill(-child.pid, 'SIGTERM')`), awaits the child's exit, and calls `removeMirrorFixture` in a `finally`, so a refusal after the fixture was built still removes it. That follows `harness-runs/lessons.md` → *"A script that creates a temporary working copy or branch removes it on every exit path"*. Every refusal inside `openPythonSession` after the fixture is built goes through the start bullet's `catch` — `close()` once the child is spawned, `removeMirrorFixture(dir)` before — and then rethrows.
- [ ] **`README.md`**: add the `python-backend.mjs` row: *the Python backend as an eval session — the package's `index` and `serve-http` run through `scripts/python-service.sh` over a mirror of the corpus, queried per arm with `POST /search`; latency is the server's own `search_ms`.*
