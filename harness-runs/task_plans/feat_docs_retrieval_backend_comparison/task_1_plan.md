### Task 1 — Lift the mirror fixture into `mirror-fixture.mjs`, and read the query-log pass's compared arm through `readCorpusMachineHalf`

**Goal:** Give the eval one owner for the throwaway mirror repository that both backends' servers read a corpus through. Then stop the query-log pass picking its compared arm by a scan, which a second `self-docs` block from a later task could fool. This task changes no figure and no output of the query-log pass.

**Why this task exists.** The Python service refuses a `--repo` that carries no `harness.config.json` (`docs-retrieval-service/src/harness_docs_retrieval/service.py` → `load_service_config`). The `fixture-catalog` root, `evals/docs-retrieval/corpora/fixture-catalog`, carries none, and the task prompt forbids changing the corpus. `evals/docs-retrieval/query-log-pass.mjs` → `buildFixture` already builds exactly the repository the Python service needs. It sits under the system temp directory and holds every corpus file at its own repo-relative path, so every rendered `ref` is unchanged, plus a `harness.config.json` carrying the resolved `docs.root` and `layers[]`. Tasks 3 and 5 need it too. `.claude/context/conventions.md` → `### Where a new responsibility goes`: *"A responsibility that already has a home does not get a second one"* and *"Before adding a copy of anything, grep for it."* So it moves to its own module rather than being copied.

**Where this task stops.** It adds no backend, no flag and no block id. The `@<backend>` block keys are **Task 2's**. This task only makes the query-log pass read its block by marker, so that Task 2's blocks cannot be mistaken for the one it compares against.

### Targets

- `evals/docs-retrieval/mirror-fixture.mjs` (new) — the mirror fixture's one owner.
- `evals/docs-retrieval/query-log-pass.mjs` — imports the fixture from the new module; `comparedArm` reads through `results.mjs` → `readCorpusMachineHalf`.
- `evals/docs-retrieval/README.md` → `## The modules` — a new `mirror-fixture.mjs` row (scope register row 24).
