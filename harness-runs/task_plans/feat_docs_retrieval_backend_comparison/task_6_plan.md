### Task 6 — Measure per-chunk vector agreement between the two embedders in `vector-agreement.mjs`

**Goal:** Measure directly how far apart the two embedders' vectors are for the same chunks: the cosine between the TypeScript embedder's vector (`Xenova/bge-small-en-v1.5`, q8 ONNX) and the Python embedder's (`BAAI/bge-small-en-v1.5`, fp32 PyTorch) for every chunk key of a corpus. That number is the evidence the write-up's embedder-id decision rests on (task prompt item 3: *"Measure vector agreement directly … That number decides whether the embedder `id` the first branch namespaced may ever be shared"*).

**Depends on:** Task 1, for `mirror-fixture.mjs` → `buildMirrorFixture(repoRoot, resolved)` and `removeMirrorFixture(dir)`. Also Task 3, for `python-backend.mjs` → `indexPythonCorpus({ checkout, fixtureDir })` → `Promise<{ files, chunks, embedded, unchanged, deleted, warnings }>`, which leaves the Python vectors of exactly this corpus in the `chunks` table of the compose database. For `evals/docs-retrieval/README.md` only, it also depends on Task 5, the last task to edit that file before this one.

**Where this task stops.** It measures the q8-ONNX-against-fp32-PyTorch pair only. The matched-precision leg, ONNX fp32 against PyTorch fp32, is **Task 7's** extension of this module. Without that leg, this figure carries quantization and export together, and the rendered output says so. This task decides nothing about the embedder id: **Task 10** records the decision from this figure and arm C's agreement.

**The interface this task produces — Tasks 7, 9 and 10 restate it:**

```
measureVectorAgreement({ checkout, corpus })     // the eval's parseArgs surface
  -> Promise<{ corpus, snapshot: { files, chunks }, ids: { typescript, python },
               pairs: [{ key, cosine, textMatches: boolean }],
               summary: { count, min, p5, p50, mean, max }, lowest: [{ key, cosine }],

renderVectorAgreement(result) -> string
```

**Work:**

- [ ] **Header.** *"The rule this module exists to enforce"*: the two vectors compared for a chunk are the ones each backend's **index actually stores** for that chunk key. The TypeScript side is embedded from the same `chunk.text` that `refreshIndex` embeds (`cli/src/retrieval/refresh.ts` → `embedder.embedDocuments(batch.map((chunk) => chunk.text))`). The Python side is read out of the Python index, never recomputed here. A chunk whose stored text differs between the two sides is reported as a text mismatch and kept out of the cosine summary, because its cosine would measure the chunker rather than the embedder. The header states that the summary covers document vectors only, not query vectors with bge's instruction prefix, and that the write-up must say so.
- [ ] **TypeScript vectors.** Call `assertRealModelsAreAvailable()` (`index-build.mjs`). Resolve the corpus with `corpusConfig`. List files with `corpusFiles` and chunk them with `chunkMarkdown`, exactly as `index-build.mjs` → `buildIndex` computes `chunkKeys`, to get `{ key, text }` per chunk. Embed every `text` with `resolveModels({ allowRemote: false })`'s `embedder.embedDocuments` (all from `cli/dist/retrieval/`). Record `embedder.id`.
- [ ] **Python vectors.** First, before anything is built or indexed, compute the database the index will be written to as `pythonDatabaseUrl(process.env)`, importing `pythonDatabaseUrl` and `PYTHON_DEFAULT_DATABASE_URL` from `cli/dist/retrieval/pythonBackend.js` — the same call Task 3's `indexPythonCorpus` makes, so the write and the read are decided by the one owner (`cli/src/retrieval/pythonBackend.ts` → `pythonDatabaseUrl`). Unless that value equals `PYTHON_DEFAULT_DATABASE_URL`, refuse by name, **without printing the URL**: the refusal names `PYTHON_DATABASE_URL_VARIABLE` (imported from the same module) and states that the `docker compose exec … psql` read route can reach only the compose database, so a measurement against any other database would read a different index from the one just built. Then `buildMirrorFixture(checkout, resolved)`, then `indexPythonCorpus({ checkout, fixtureDir: dir })`, which also gives `snapshot`. Then read every row with `execFileSync('docker', ['compose', 'exec', '-T', 'postgres', 'psql', '-U', <user>, '-d', <database>, '-At', '-c', "SELECT json_build_object('key', key, 'text', text, 'embedding', embedding::text) FROM chunks ORDER BY key"], { cwd: <checkout>/docs-retrieval-service })`, one JSON object per line. `<user>` and `<database>` are taken from `new URL(PYTHON_DEFAULT_DATABASE_URL)` — its `username`, and its `pathname` without the leading `/` — never retyped as `harness` / `docs_retrieval`. The compose service name `postgres` is the one literal kept, as a module constant, and the header names its owner (`docs-retrieval-service/compose.yaml` → `services.postgres`). Parse each `embedding` (`[v1,v2,…]`). The Python id is read off the `meta` table's `embedder` row through the same `psql` route (`SELECT value FROM meta WHERE key = 'embedder'`), because that row records what the index was built with. Expect `py-st/BAAI/bge-small-en-v1.5:fp32:cls:384:v1`. Refuse by name when `docker` is absent or the container is not running, quoting the stderr line. Remove the fixture in a `finally`.
- [ ] **Pair, summarise, render.** Join the two sides on `key`. A key present on one side only refuses by name: the chunkers are byte-parity-tested (`docs-retrieval-service/tests/test_chunk_parity.py`), so a missing key means the two indexes describe different corpora. `textMatches` is strict string equality. `cosine` is the full cosine (dot over the product of norms), not the dot product, so an unnormalised vector cannot pass. `summary` is over text-matching pairs, with p5 / p50 from `metrics.mjs` → `percentile`. `lowest` is the ten lowest. `renderVectorAgreement` prints the corpus, snapshot, both ids, summary, the lowest ten keys with their cosines, the text-mismatch keys, and the line *"Leg: q8 ONNX (TypeScript) against fp32 PyTorch (Python) — quantization and export measured together; the matched-precision leg is reported separately when arranged."* Add the README row: *the cosine between the two backends' stored document vectors for every chunk key of a corpus.*
