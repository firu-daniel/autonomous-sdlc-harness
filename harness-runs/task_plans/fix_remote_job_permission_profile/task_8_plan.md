### Task 8 — Correct `docs/remote-execution.md` §1, §4, §6 and §7

**Goal:** Make the design of record for remote execution say what the code now does about the permission profile, the committed `.claude/settings.json`, the push of the workflows to the default branch and the token scope that push needs (task prompt → `## What is wrong`, findings 2, 5, 6 and 7; acceptance criterion four; `## Scope register` row 1).

**Depends on:** Tasks 1–7 and Task 11, whose behaviour this task describes and does not change. What each one shipped, as this document must state it:

- **Task 1** — `init` writes `.claude/settings.autonomous.json` into the managed `.gitignore` block for every adopter; a copy an earlier release committed stays tracked until untracked by hand.
- **Task 2** — a `Read` grant is required at the plugin's **runtime root**, including a root that is also the install root (every GitHub-sourced marketplace, the runner's included), whatever `phases.qa` says; it is exempt only at an install root distinct from the runtime root, the `directory`-sourced case measured 2026-08-26.
- **Task 3** — `init --plugin-root-entries` also adds every resolved plugin root to the profile's `permissions.additionalDirectories`, and its `_README` line claims entries only when it wrote some.
- **Tasks 4 and 5** — `doctor --remote-job` fails `profile-paths` when the profile covers no path in the checkout, fails `plugin-permissions` when a required entry or `additionalDirectories` root is missing or no plugin root resolves, and fails the new `profile-tracked` check when the profile is committed at `HEAD`; without the option those stay warnings. Both `profile-paths` (under the option) and `profile-tracked` print the same **untrack route** (`checks.ts` → `profileUntrackRemedy`), in this order and spelling: `git rm --cached .claude/settings.autonomous.json`, `git commit -m "Stop tracking the machine-local permission profile"`, `git push --no-verify origin <defaultBranch>`. It lands on the default branch because every run's branch is cut from `origin/<defaultBranch>`, so an untrack pushed only to a run branch covers one run; and it carries `--no-verify` because the `pre-push` hook `init` installed refuses a push to the default branch — the adopter's deliberate push, which the harness never makes.
- **Task 6** — the job's `Preflight with doctor` step runs `doctor --remote-job`; a workflow rendered before this release reaches it only after `init --force` re-renders it.
- **Task 7** — in job mode the watcher also passes each of the profile's `permissions.additionalDirectories` entries as an `--add-dir` at launch; a local launch is unchanged.
- **Task 11** (ships before this task) — `init`'s remote-execution note prints step 1's commands as, in order, `git add <workflow paths>`, `git commit -m "Add the harness workflows"`, `gh auth refresh -s workflow`, `git push --no-verify origin <defaultBranch>`, and `doctor`'s `remote-execution` warning names the same last two. `cli/test/init.test.mjs` pins those four against `## 7.` step 3, so this document prints exactly them, in that order.
