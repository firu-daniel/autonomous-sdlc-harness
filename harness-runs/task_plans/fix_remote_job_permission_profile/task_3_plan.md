### Task 3 — Make `init --plugin-root-entries` grant shell reads over the plugin roots, and keep its notes true

**Goal:** Under `init --plugin-root-entries` — the switch the remote job's `Generate the job's permission profile` step runs — add every resolved plugin root to the generated profile's `permissions.additionalDirectories`, so a shell read of an instruction file (`cat`, `head`, `ls`) is not refused as outside the allowed working directory; make the profile's `_README` claim plugin-root entries only when some were written; and make **both** of `init`'s closing notes that call the profile committed — `writePermissionProfile`'s and `projectSettings.ts`'s onboarding note — say it is gitignored and that a teammate generates theirs with `init` (task prompt → `## What is wrong`, findings 1 and 2; Run 2's `_comment` that claimed entries the profile did not carry).

**The interface this task produces, consumed by Task 4.** In `cli/src/generators/permissionProfile.ts`, exported:

```ts
/** The directories a plugin-root grant adds to `permissions.additionalDirectories`: every root given, normalized with `normalizedRoot`, de-duplicated, in input order. */
export function pluginRootDirectories(roots: readonly string[]): readonly string[]
```

The generator calls it with `resolvedPluginRoots(repoRoot)`; Task 4's `doctor --remote-job` calls it with the roots `plugin-permissions` grades and requires each result in the profile's `permissions.additionalDirectories`. **Task 7** consumes the *file*, not the function: the watcher reads `.permissions.additionalDirectories[]` out of the written profile in job mode, so every directory this task writes there is one the job's launch will also pass as `--add-dir`.

**Where this task stops.** It changes the profile generator, the one onboarding note in `projectSettings.ts`, and their tests only; `init`'s remote-execution note (`init.ts` → `reportGithubSteps`) is **Task 11's**, and `README.md` **Task 10's**.
