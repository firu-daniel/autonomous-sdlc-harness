## Why it matters

The sandbox's guarantee is that what a run writes stays inside the sandbox. Every unsandboxed git call in a run's working copy is a way out of that. Each of these is a candidate route; *verify each one*:

- **Nested repositories.** `git status` recurses into a populated gitlink, which the agent can create with an allowed `git add`. A `core.fsmonitor` in that nested repository's own config, a file the sandbox can write, then runs. On-demand fetch recursion reads `<main>/.git/modules/<name>/config`.
- **Checkout of run-authored commits.** `reset --hard`, `merge --ff-only` and `worktree add` write committed content over the protected worktree paths: the hooks directory, `.claude/settings.json` and `.mcp.json`. The watcher's next commit runs those hooks, and the resumed session loads that settings file's hooks and those MCP servers, all outside the sandbox. The write protection on those paths holds only until the watcher's next checkout.
- **Hooks.** `post-merge`, `pre-commit`, `commit-msg`, `post-commit` and `reference-transaction` run from the worktree's `core.hooksPath`, which no watcher call pins.
- **Filter and diff drivers.** These are selected by a `.gitattributes` the run wrote (residual 6 covers the drivers themselves).
- **The branch's own bootstrap** run by `create-worktree.sh --existing`, and the branch's own scripts run by the next GitHub job.

None of this needs a sandbox escape. It needs only a planted file and a watcher that later runs git in that copy.

## Constraints

- **The wrappers' shipped behaviour does not change** for any caller that is not the watcher family: `push-branch.sh`, `refresh-branch.sh`, and `commit-on-branch.sh` as dispatched agents call it. The tests named above stay green unchanged.
- **No existing refusal gets weaker**, in the wrappers, the guards, the profile or the watcher. A copy that fails a new check fails the way the watcher already fails a pre-launch problem (`fail_before_launch`, or `reject_preserving_status` where a record must survive). It never falls back to the unhardened call.
- **The watcher's outcomes stay the same on an honest copy.** That covers an identical re-drop's skip, a non-blocking local commit or push failure, the remote arm's blocking ones, and the watchdog's resume from the committed ledger.
- **Scripts stay bash 3.2-compatible**, the macOS system `bash`. Git version floors stay as shipped: 2.23 for the wrappers, 2.38 for the refresh. A new floor is a `doctor` warning and a docs line, not a silent requirement.
- **The design does not rely on the Linux glob entries.** Where a call is safe only because a worktree-glob entry holds, it counts as exposed on Linux.
- `scripts/run-gates.sh` must pass.
