`fix_commit_prefix_policy` settles which prefix every commit in **this repository** carries. It is a change to this repository's own conventions, not to the plugin: the plugin already tells `/autonomous-sdlc-harness:harness-analyze` to derive an adopter's commit policy from that adopter's existing rules and history, and that stays as it is.

Two rules disagree today, and the run trips on that disagreement on almost every branch:

- **This repository's policy** (`.claude/context/conventions.md` → `## Commit-message policy`, unchanged since the self-adoption commit `cba2ac24`) allows one token, `chore`, and only for fixed-form run-artifact subjects. It designates **`none`** for both a story task's commit and a review fix's commit. `harness-analyze` derived it from history that had no prefix convention to find: the pre-adoption subjects on `dev` are unprefixed (`Adopt the harness in its own repository`, `Add a plain roadmap of planned features`).
- **The unit loop's row `A`** (`plugin/instructions/unit_loop_core.md` → `## Substitution table`, the `commit_prefix rule` cell) derives a story task's prefix from the branch name: `feat_` → `feat`, `fix_` → `fix`, `refactor_` → `refactor`, else `chore`.

The committer checks the prefix against this repository's policy, so it refuses the prefix row `A` passes. On `fix_run_gates_sandbox_tmpdir`, dispatch #2 got `error: commit_prefix `fix` is not a legal value` and had to be redone with `none`. 54 of the 63 per-branch intake files under `harness-runs/improvement_observations/` report the same conflict, under headings like *"Row A's branch-derived commit_prefix disagreed with the repository's commit policy for story-task commits"*. The result is a branch history mixing prefixed fixed-form subjects (`chore: Flow progress C2f for <branch>`) with unprefixed task and fix subjects (`Task 1 — Give every bare mktemp …`, `Finding 1 — Stop TD1's verdict …`).

## Where the intended rule comes from

The rule already existed in the `expause` repository (`<home>/Work/expause`) before that repository adopted the harness:

- **Before adoption:** `.claude/agents/committer.md` at `48df2da37`, the `commit_prefix` bullet (line 31). It has a closed vocabulary, `feat`, `fix`, `refactor`, `docs`, `chore`, and each token designates a commit class: new work → `feat`; a fix to existing work → `fix`; a restructuring with no behaviour change → `refactor`; a change confined to documentation prose → `docs`; a flow-artifact, configuration or housekeeping commit → `chore`. Its step 4 rule: *"The first word after the prefix MUST be capitalized (e.g., `feat: Add foo`, not `feat: add foo`)."*
- **At adoption:** `09f1207d8`, `.claude/context/conventions.md` → `## Commit-message policy`. It carries that vocabulary and class table into the conventions document the plugin committer reads, and it states *"No class carries no prefix: `none` never arises for this project."* Diff the two before writing this repository's version.

## The goal

1. **Rewrite this repository's `## Commit-message policy`** in `.claude/context/conventions.md` on the expause model:
   - **Vocabulary, closed:** `feat`, `fix`, `refactor`, `docs`, `chore`, `research`. `research` is for a commit whose content is a research or measurement record under `docs/`, the kind `chore_docs_retrieval_bm25_scoring_diagnosis` and `chore_gate_10_real_catalog_measurement` shipped as `chore`.
   - **Per commit class, as expause has it:** a story task's commit takes the token row `A` derives from the branch name. A **review-fix** commit takes **`fix`** (`fix: Finding 1 — Stop TD1's verdict …`). Restructuring with no behaviour change takes `refactor`, documentation prose takes `docs`, and run artifacts keep their fixed `chore:` forms. **`none` never arises.**
   - **Capitalisation:** the first word after the prefix is **capitalized** (`fix: Add foo`, not `fix: add foo`). That matches the fixed-form subjects most of the flow already emits (`chore: Flow progress C2f for <branch>`, `chore: Add task plan for <branch>`).
   - **Fixed-form subjects stay byte-for-byte as they are**, including the lowercase ones (`chore: add task prompt for <branch>`, `chore: add code review for <branch>`, `chore: add docs checklist for <branch>`, `chore: add user review for <branch>`). They stay exempt from the capitalisation rule and the length cap, because the commit point that owns each passes it verbatim.
   - Keep the 72-character cap, the attribution-trailer ban and the merge-commit carve-out as they are.
   - **Write it as instructions, not prose.** Apply `plugin/agents/layer-implementer.md` → `## Minimal prose — every line carries a rule`: a line stays only if a named reader would do the wrong thing without it, and a conventions document may carry at most the one sentence a reader needs at the point of use. Use the expause section (`09f1207d8`) for its **rules**, not its wording. Its inline `_Source: …_` lines are rationale that belongs in the plan and the commit message, not in the document. Simplify this repository's current section the same way: the vocabulary, a class → prefix table, the capitalisation rule, the cap, the trailer ban and the fixed-form list, each stated once as a rule. The current section's paragraphs explaining *why* (the trailer ban's justification, the probe's provenance and its omission classes) shrink to what a committer or a writer acts on.
2. **Bring the policy's fixed-subject provenance paragraph in line:** add `research` to the probe alternation it names (`docs`/`feat`/`fix`/`refactor`/`chore`/`test`), then re-run the probe and confirm the fixed-form list is unchanged.

## Constraints

- **Scope is this repository's conventions documents only.** No edit under `plugin/` or `cli/templates/`: row `A`'s rule, the committer contract, `/autonomous-sdlc-harness:branch-prompt` and the template's commit-policy guidance stay as they are. The change touches `.claude/context/conventions.md`, plus any other file at this root that quotes the policy. `.claude/context/plugin.md` → `## The commit-message policy` is a pointer, but check it.
- **Known consequence, stated in the policy rather than fixed:** row `A` produces only `feat` / `fix` / `refactor` / `chore`, so a story task on a `docs_` or `research_` branch commits as `chore`. That is the plugin's branch-name rule, and it is a legal token here.
- **No history is rewritten.** The unprefixed task and fix subjects already on `dev` and on open branches stay as they are; the policy governs commits made from this branch on.
- **The `record disposition of ` / `mark … done — ` subject templates are a parsed interface** (`plugin/instructions/improvement_observations_instructions.md` → `## Dispositioned units`). The capitalisation rule must not break their case-insensitive leading-word match.
- **Verify on a real run:** the next autonomous run's story-task commits land with the branch-derived prefix, and its review-fix commits with `fix:`, with no refused committer dispatch.
