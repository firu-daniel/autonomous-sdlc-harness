## The defects

1. **T2's result line is refused.** In `scripts/lib/sandbox-probe/legs-local.sh`, T2's final call reads `sp_result_line gates T2"$verdict" …`, with no space. The row and the verdict fuse into `T2fail`, every later argument shifts, and `sp_result_line` refuses the line (`verdict '<sandbox_violations>' for gates T2fail is not pass, fail or not run`). Add the space, and add a test that catches a result line with a fused row.
2. **T2 cannot finish as one foreground call.** The leg issues `bash scripts/test.sh` once, in the foreground. The Bash tool moved it to the background at 120 s and stopped it at its 10-minute cap while gate 4 was still running. The full gates take longer than that. Real runs take the gates through `scripts/run-test-suite.sh <label>` and its detached run form (`docs/sandbox-verification.md` §7 OR6). Re-design T2 so it measures the gates sandboxed in a form that can complete: the `run-test-suite.sh` route, judged from the lane's verdict and log. Amend T2's row in `docs/sandbox-verification.md` to the call it now names, and say why. That session also showed sandbox denials of outbound `api.anthropic.com:443` and `http-intake.logs.us5.datadoghq.com:443` during gate 4. Keep T2's evidence able to surface such lines; don't treat them as the verdict.
3. **TD2's positive control never runs.** The explicit form is `mktemp "${TMPDIR:-/tmp}/harness-gates.XXXXXX"` (`c_explicit` in `legs-local.sh`). Its `${…}` expansion cannot match `--allowedTools "Bash(mktemp:*)"`, so don't-ask mode refuses it at the permission layer, and the leg grades `fail`. The three refusals it exists to contrast held exactly as expected. Spell the control as a literal the allow rule matches, for example by resolving the session's `TMPDIR` first and passing the literal path. A control refused at the permission layer must grade `not run`, never `fail`.
4. **The file-tool judge misfiles the denied-directory refusal (W6).** `sp__layer` in `scripts/lib/sandbox-probe/judge.sh` checks the session's `permission_denials` before the text `File is in a directory that is denied by your permission settings.`. Claude Code 2.1.311 lists those refusals in `permission_denials`, so all 35 `Edit`/`Write` refusals (22 `Edit`, 13 `Write`) were filed under the permission layer and W6 printed `fail`, though every call was refused with the row's exact message and no file changed. Recognise the denied-directory text before the `permission_denials` check, or treat both as the file-tool layer. Add a fixture under `cli/test/fixtures/sandbox-probe/` whose result lists the denied call in `permission_denials`, as 2.1.311 does.
5. **N5 does not recognise the tool's own refusal.** The call carrying `allowed_domains: ["example.com"]` was refused before it ran: `<tool_use_error>allowed_domains cannot widen network access in this session: the configured sandbox allowlist is the whole allowlist here (…)</tool_use_error>`. `sp_judge_allowed_domains` grades any error without a known refusal string as `not run`, which is right for the unknown case (the skeptic's N5 finding on `feat_unattended_sandbox_measurement`). Add this refusal, matched on its stable prefix `allowed_domains cannot widen network access`, to the strings that grade N5 `pass`. Add a fixture.
6. **N3 and N4 are ambiguous without a listener.** `curl -sS --max-time 5 http://127.0.0.1/` and `http://169.254.169.254/` each ended `Exit code 7` with no refusal string, and the probe judged "not refused, reached the network". With nothing listening on the target, curl's exit 7 cannot tell a refused connect from a reached-but-closed port. Start a listener the probe owns on a loopback port for the session's duration (for example `python3 -m http.server --bind 127.0.0.1 <port>` under `SP_TMP`, or a `nc` equivalent present on stock macOS), aim N3 at it, and grade on whether its response body comes back. For N4, record curl's full error line, not just the exit status. Grade `not run` when that line cannot tell the cases apart. Amend N3/N4's rows to the call they now name.
7. **The credentials leg's session issues no calls.** S1, S2, S4 and S5 printed `not run`: the session made none of its calls, not even the control `cat <clone>/harness.config.json`. The streams were deleted at teardown, so the cause is unrecorded; the likeliest is that the model declined a prompt asking it to read `~/.ssh` and print token variables. Make the leg's prompt one a session follows: state that it is a sandbox measurement whose refusals are the expected result, and that `printenv` of a token variable prints only presence (or use a form that prints a variable's presence, never its value). Never print a real secret. Add a check that grades the whole leg `not run`, with the reason "the session issued no calls", when the control is absent.
8. **The probe deletes the evidence of every row it could not grade.** Teardown removes `SP_TMP`, streams included, so a `not run` or `fail` cannot be examined afterwards. Keep the session streams and prompts of every leg that printed anything but `pass`, by moving them to a directory the probe prints at the end, outside the clone and the main checkout's protected paths. Alternatively add an opt-in `--keep` flag. Document it in Gate 15.
9. **CS3's row expects a call the profile refuses by design.** `git add`, `commit`, `stash push`/`pop` and `switch -c` succeeded in the clone. `git fetch origin` was refused by the network allowlist (`sandbox proxy: github-firu:22: 403 host is not on the allow list`). That refusal is the design: a run copy reaches its remote only through `<main>/scripts/` wrappers (§7 OR2). Either drop `git fetch origin` from CS3's call list or grade it as an expected refusal. Amend the row and its expected column to match, and grade on the remaining calls.
10. **`printf: write error: Broken pipe`, twice.** `sp__wp_tracked` in `legs-protection.sh` pipes `printf '%s\n' "$list"` into `grep -qxF`, which closes the pipe early. Use a form with no pipe into an early-exiting reader.

11. **P1b grades `pass` on a permission-layer refusal.** The assignment-prefixed wrapper call was refused in don't-ask mode, so it never reached the sandbox or the `excludedCommands` match, yet the row printed `pass`. A permission-layer refusal of the call under test must grade `not run` with that reason, and the leg must allow the exact prefixed call through `--allowedTools` so the sandbox half is measured.
12. **Halves the probe does not take.** CS7's `Edit` half (only the `dd` and the rename are taken); R4's `--local` half (only the fetch); W8 reads only the write-protection session's `--debug-file`, and W7's session has none. Take each, or name it in the row as not taken.
13. **CS4's expected column names exits 0 or 4.** The refresh on a clone already containing `origin/dev` exited 3, the wrapper's documented nothing-to-do code. Amend the expected column, and have the leg accept 3 there.
