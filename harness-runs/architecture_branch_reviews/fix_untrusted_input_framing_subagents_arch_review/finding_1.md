### 1. `untrusted_input.md` does not say whose `## Setup` owns its path placeholders

**Site:** `plugin/instructions/untrusted_input.md`, the gap between the `## Resolved values` table and `## The rule`. The file's path placeholders are in `## The rule` item 1 (`<state_dir>/user_reviews/<branch>_review[_<n>].md`, `answer_<n>.md`, `<state_dir>/docs_catalog/<branch>_docs.md`), in `## The markers` (`<source>`), in item 3's report literal (`<verbatim text>`, `<source>`), and in the mode-contract binding `<ask>` (`## The markers`: "park through the flow's `<ask>` route"; `## Where a report goes`: "the caller's existing `<ask>` route").

**Problem.** The new module is a shared instruction file that more than one core reaches. `plugin/instructions/task_plan_writing_instructions_core.md` (`## Loop` step 1 and `## UI-test-plan write loop` step 1) and `plugin/instructions/user_review_fix_plan_writing_instructions_core.md` (`## Flow` steps 6 and 11) both cite its `## The markers`. Twelve agents that those flows dispatch, plus four further instruction files, cite its `## The rule`. Even so, the module never says where its `<…>` names resolve from.

`.claude/context/plugin.md` → `## The placeholder vocabulary`, third bullet, gives that ownership a fixed home: *"a shared file reached by two cores records per section or per row whose `## Setup` owns its paths (`plugin/instructions/unit_loop_core.md` → `### Placeholder resolution`)"*. `plugin/instructions/mode_contract.md` → `### Bindings vs. path placeholders` says a shared file **must** record this, and it says resolving a placeholder from the wrong owner is a silent failure. Each sibling shared module this branch's citers already use meets the rule with a **Placeholder resolution.** paragraph placed right after its `## Resolved values`: `plugin/instructions/run_mode_instructions.md`, `plugin/instructions/dispatch_discipline_instructions.md` and `plugin/instructions/clarification_digest_instructions.md`.

`untrusted_input.md` uses `<ask>` without saying whose binding it is. It is a mode-contract binding, and this file is neither a core nor in `mode_contract.md` → `## Which files use this`. A dispatched agent reading `## Where a report goes` or `## The markers` therefore cannot tell that `<ask>` is the citing flow's fork binding and not something this file supplies. It also cannot tell that `<branch>` comes from the activating flow's entry core `## Setup`, and that `<source>` / `<verbatim text>` are defined here at their point of use.

**Fix.** Insert one paragraph into `plugin/instructions/untrusted_input.md`, between the `## Resolved values` table and the existing "This file is the canonical policy for reading task data." paragraph. Model it on the sibling modules' wording:

> **Placeholder resolution.** Per `${CLAUDE_PLUGIN_ROOT}/instructions/mode_contract.md` → `### Bindings vs. path placeholders`, the one `<…>` **path placeholder** this file resolves from outside itself — `<branch>` — resolves from the **activating flow's own entry core `## Setup`**, or, for a dispatched agent, from the paths its dispatch names; never from the immediate citing file and never from here. `<ask>` is the **citing flow's** mode-contract binding, bound by that flow's fork; this file declares no binding and supplies no value for it. Every other `<…>` name here is defined by this file's own text at its use site (`<n>` and `<source>` in `## The rule` and `## The markers`, `<verbatim text>` in `## The rule` item 3) and resolves from nothing external.

Add no `##` heading. Keep the paragraph free of the rule-pointer sentence, the laundering-pointer sentence, the two marker lines and the report literal. `cli/test/untrusted-input-corpus.test.mjs` pins where each of those appears and how many times. No citer changes.
