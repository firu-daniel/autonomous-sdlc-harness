### 1. The round driver re-derives the Gate 12 configuration read instead of using `harness-run-lib.sh`'s readers

**Site:** `scripts/lib/gate12-sandbox-round/preflight.sh` → `g12_config_dir` (the whole function), and its three callers in `g12_preflight`: `g12_config_dir stateDir sdlc-harness G12_STATE_DIR`, `g12_config_dir scriptsDir scripts G12_SCRIPTS_DIR`, `g12_config_dir defaultBranch "" G12_CONFIG_DEFAULT`, plus the separate `jq -e 'type == "object"'` parse check above them. The header's `THE CONFIGURATION READ.` paragraph describes the same copy.

**Problem.** `.claude/context/conventions.md` → `### Where a new responsibility goes` states: *"A responsibility that already has a home does not get a second one"*, and *"Before adding a copy of anything, grep for it"*. It gives `cli/src/core/repoPaths.ts` as the cost of breaking this: private copies of one normalisation drift apart with no compile error and no test. Reading a repository's `harness.config.json` from a shell script under `scripts/` already has a home. `scripts/lib/harness-run-lib.sh`, the sibling of this driver's own `lib/` directory, has a header calling it *"the one place … [that] reads that repository's `harness.config.json` at run time"*. It derives *"the anchors (… state-dir paths) the scripts would otherwise each re-derive slightly differently"* through `hr_config_load`, `hr_state_dir`, `hr_scripts_dir` and `hr_default_branch`. This branch names `scripts/sandbox-probe.sh` as its model (story plan `## Context` → *"The model is `scripts/sandbox-probe.sh`"*), and the probe sources that library and reads a *target* checkout's `stateDir` through it (`scripts/lib/sandbox-probe/preflight.sh` → `. "$lib"`; `scripts/lib/sandbox-probe/legs-local.sh` → `hr_state_dir "$SP_CLONE"`).

`g12_config_dir` is a second definition of the same read, and it already differs from the owner:
- `hr_config_load` refuses a file holding more than one JSON document and reads each scalar through `tostring`. `g12_config_dir` reads only the first document and refuses any value that is not a string.
- `hr_config_load` treats `null`, `"null"` and `""` as "not set" and falls back to the schema default. `g12_config_dir` refuses an empty string and refuses a `null` value as "a null, not a string".
- `g12_config_dir` refuses `..` and a leading `/`. `hr_config_dir` does not.

So the driver and the Gate 12 repository's own outer-loop scripts, `remote-run.sh` among them (which this driver dispatches through), can resolve `stateDir` or `scriptsDir` differently for the same file. The driver would then plant prompts, write state and look for `remote-run.sh` somewhere other than where the job reads them.

**Fix.** In `scripts/lib/gate12-sandbox-round/preflight.sh`:
1. At the start of `g12_preflight`, before the configuration checks, source this checkout's run library the way the model does. Resolve it from `${BASH_SOURCE[0]}` (`"$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd -P)/lib/harness-run-lib.sh"`). If it cannot be read, refuse with `g12_preflight_refuse "cannot read the run library at '<path>'"`, as `sp_preflight` does.
2. Replace the `jq -e 'type == "object"'` check and the three `g12_config_dir` calls with the library's readers on `G12_ROOT`: `G12_STATE_DIR="$(hr_state_dir "$G12_ROOT")"`, `G12_SCRIPTS_DIR="$(hr_scripts_dir "$G12_ROOT")"`, `G12_CONFIG_DEFAULT="$(hr_default_branch "$G12_ROOT")"`. Map a non-zero status to `g12_preflight_refuse` with a message naming the key and `'$G12_ROOT/harness.config.json'`. Keep the existing "no harness.config.json" refusal (check 3) in front of them, so that refusal's message stays the same.
3. Keep the driver's stricter safety screen as an extra check on the values the library returns: refuse a value that starts with `/` or contains `..`, using the same two `case` arms. Do not keep it as a second reader. Delete `g12_config_dir`.
4. Update the header's `THE CONFIGURATION READ.` paragraph. It should say the values come from `hr_state_dir`, `hr_scripts_dir` and `hr_default_branch` (`scripts/lib/harness-run-lib.sh`), with only the `..` / leading-`/` screen added here.

No `cli/test/` change is expected. `cli/test/gate12-sandbox-round-cli.test.mjs` asserts the "no harness.config.json" refusal on the bytes on disk and makes no assertion on the per-key refusal messages.
