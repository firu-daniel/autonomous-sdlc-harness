### 2. `sp__wp_mv_class` keeps a second copy of the judge's Linux refusal strings, and its header says the copy matches when it does not

**Site.** `scripts/lib/sandbox-probe/legs-protection.sh` → `sp__wp_mv_class`: its header comment (*"its Linux refusal strings are kept to the judge's layer table (judge.sh → sp__layer's Linux `sandbox` arm), `Device or resource busy` among them (PD23)"*) and its Linux arm `*"Read-only file system"* | *"Device or resource busy"*) printf '%s\n' refused ;;`. Compare `scripts/lib/sandbox-probe/judge.sh` → `sp__layer` → `line="$(sp__line_with "$text" "Read-only file system" "Permission denied" "Device or resource busy")"`.

**Problem.** The probe now keeps the Linux sandbox-refusal string set in two places. `judge.sh` → `sp__layer` holds three strings: `Read-only file system`, `Permission denied` and `Device or resource busy`. `legs-protection.sh` → `sp__wp_mv_class` holds its own list of two. This branch extended both lists in parallel (Task 6 and Task 12). The new header comment says the classifier's strings are "kept to the judge's layer table", but `Permission denied` is in the judge and not in the classifier. Either the header is wrong, or the subset is deliberate and the header does not say so.

`.claude/context/conventions.md` → `### Where a new responsibility goes` says *"A responsibility that already has a home does not get a second one"* and *"Before adding a copy of anything, grep for it"*. `judge.sh`'s own header states that a Linux refusal string is added to its table "only from a Linux run's kept evidence". So the judge's table is where that set belongs. `.claude/context/cli.md` → `## What "done" means here` adds that a header a reviewer reads as a guarantee has to stay true. That rule is written for `cli/src` modules, but the same reasoning applies here.

**Fix.** Make `judge.sh` the single owner of the string set:
1. In `scripts/lib/sandbox-probe/judge.sh`, add `sp__linux_refusal_line <text> [<string>...]`. It prints the first line of `<text>` that contains one of the judge's Linux `sandbox` strings and returns 0, or returns 1 when none matches. If string arguments are given, it matches only that subset, and each one must be a member of the judge's set. Change `sp__layer`'s Linux arm to call it with no subset.
2. In `scripts/lib/sandbox-probe/legs-protection.sh` → `sp__wp_mv_class`, replace the literal `case` arm with a call to `sp__linux_refusal_line "$1" …`. Pass the full set, or, if leaving out `Permission denied` for a rename is deliberate, pass `"Read-only file system" "Device or resource busy"`.
3. Rewrite the `sp__wp_mv_class` header comment so it says what the code does: either "the judge's Linux set, through `sp__linux_refusal_line`", or "the rename-shaped subset of the judge's Linux set, `Permission denied` left out because <the reason PD23's evidence gives>".
4. If the full set is chosen, add a case beside the existing `sbx_wp_mv … Device or resource busy` case in `cli/test/sandbox-probe-protection-legs.test.mjs` that pins a `Permission denied` rename line to `refused` on Linux and to `other` on macOS.
