### 1. The owner's DECLARED MIRRORS block lists `bwrapUsernsRestrictRemedy` as mirrored by the shell judge, which carries no remedy

**Site:** `cli/src/doctor/sandboxPrerequisites.ts` → the module header's **DECLARED MIRRORS** block, first bullet, the clause *"the judge also mirrors {@link NestedUsernsAnswer} and the stock-profile half of the refusal ({@link BWRAP_USERNS_RESTRICT_PROFILE_PATH}, {@link bwrapUsernsRestrictRemedy})"*.

**Problem.** The module's stated rule is *"the sandbox's host prerequisites are declared once, here, and every other copy is a declared mirror held equal by a test"*, and its header is the place that rule's mirror set is listed. This branch adds a clause saying that `cli/templates/scripts/lib/harness-run-lib.sh` → `hr_sandbox_prereq_judge_var` mirrors `bwrapUsernsRestrictRemedy`. It does not. The judge's `failed-stock-restrict` arm sets `nested_sentence` to *"`bwrap` cannot create a user namespace inside its sandbox, so every sandboxed command would fail; `/etc/apparmor.d/bwrap-userns-restrict` is present and confines bwrap's children."* That sentence names the stock profile's path but none of the four remedy commands (`mkdir -p` of the disable directory, the `ln -sf`, `apparmor_parser -R`, `apparmor_parser -r`). The judge's own comment says the watcher's message adds the pointer to `doctor`, and that pointer is where the remedy is. `cli/test/sandbox-prerequisites-shell-mirror.test.mjs` checks only that the refusal contains `BWRAP_USERNS_RESTRICT_PROFILE_PATH` (its header names `installCommands`, `WSL1_AGENT_MESSAGE` and `BWRAP_USERNS_RESTRICT_PROFILE_PATH`). Nothing holds a remedy mirror equal, because no such mirror exists.

So the owner now declares a mirror that is not there and that no test holds. A reader who changes `bwrapUsernsRestrictRemedy` will go looking for a shell copy to edit and find none. A reader who trusts the header will believe the watcher's refusal states the remedy. That breaks `.claude/context/cli.md` → `## What "done" means here`: *"A reviewer holds a change to its module's own header. Where the header states a rule, the change either satisfies it or amends the header in the same edit."* It also breaks the module's own rule that every listed mirror is held equal by a test.

**Fix.** In `cli/src/doctor/sandboxPrerequisites.ts`, in that header clause, remove `{@link bwrapUsernsRestrictRemedy}` so it reads: *"the judge also mirrors {@link NestedUsernsAnswer} and, in the stock-profile half of the refusal, {@link BWRAP_USERNS_RESTRICT_PROFILE_PATH}"*. Keep the `cli/templates/github/workflows/harness-run.yml` bullet as it is: that step does apply the remedy, and `cli/test/workflow-sandbox-install.test.mjs` holds it. This is a doc-comment-only edit. It changes no code path and no test, and asks for no test run.
