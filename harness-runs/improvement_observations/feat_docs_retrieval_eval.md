# Improvement observations — feat_docs_retrieval_eval

## An implementer cannot write a commit body, so a plan that hands evidence forward "in the commit body" hands it nowhere
- **category:** agent-contract
- **evidence:** `task_5_plan.md` line 29 required *"Record the before figure, the after figure and the shared stamp in the commit body, where Task 14 reads them back"*, and `task_14_plan.md` line 9 required Task 14 to take them *"from Task 5's commit body and from nowhere else"*. `git log -1 --format='%b' 51ba982` returns a single newline. Only `committer` writes commits, and its commit-message contract composes the subject from the unit title and the staged-path set and emits exactly one body line ever — the `record disposition of <unit token> — <cause>` line; no dispatch argument carries an implementer's measured figures into a commit message. So the hand-off was unsatisfiable by construction rather than skipped by Task 5's implementer, which did take the measurement (`harness-runs/scratch/recheck-arm-e.mjs`, gitignored, stdout only) and had nowhere durable to put it. Task 14's `layer-implementer` returned a `blocker:` and changed no file, which parked the run (`harness-runs/clarifications/feat_docs_retrieval_eval/question_3.md`).
- **cost this run:** one park, and a recovery dispatch pair the flow has no shape for — the user's park-3 answer had to authorise re-entering a unit already `[x]` and re-taking its measurement (commit `25891ee`), plus a one-criterion amendment to `task_14_plan.md`. Two dispatches and one commit spent recovering a figure that was measured once already.
- **hypothesis:** (a guess) a plan-format rule forbidding the commit body as a hand-off channel, and naming the producing task's `**Deviations from plan:**` block instead, would have been cheaper than any agent-side change — the user's answer made exactly that the standing rule for the rest of this branch.

## The unit loop's row-A `commit_prefix` rule derives a value this repository's commit policy does not admit, and every task commit overrode it
- **category:** agent-contract
- **evidence:** `unit_loop_core.md` row `A`'s `commit_prefix rule` cell reads *"from the branch name: `feat_` → `feat`, `fix_` → `fix`, `refactor_` → `refactor`, else `chore`"*, so this branch yields `feat`. `.claude/context/conventions.md` → `## Commit-message policy` puts one token in its vocabulary (`chore`, reserved for the flow's fixed-form run-artifact subjects) and designates **`none`** for the *"Adding new work — a story task's commit"* class. All 8 `mode: task` committer dispatches of this session (#3, #5, #7, #9, #11, #13, #15, #17 — Tasks 14, 6, 7, 8, 9, 10, 11, 12, 13) reported the mismatch unprompted and committed on the policy's designation instead; two of them added that the dispatching caller is where it should be corrected.
- **cost this run:** none to the artifacts — the committer resolved it correctly every time — but eight returns spent restating the same reconciliation, and the orchestrator passed a value it had no basis for eight times.
- **hypothesis:** (a guess) the row's cell states a derivation where the five fix rows state a *class* and defer the token to `committer.md`'s own contract; the asymmetry may be the whole of it.

## `chmod` is refused in the autonomous worktree, so a shipped script lands non-executable beside executable siblings
- **category:** tooling-gap
- **evidence:** Task 6's `layer-implementer` (dispatch #4) reported `chmod` refused and `evals/docs-retrieval/arm-a/run-arm-a.sh` committed at mode `644` while sibling scripts in the tree are `755`; recorded in that task's `**Deviations from plan:**` block, commit `c3a8d58`. Task 11 (#14) then had to write `bash run-arm-a.sh` into the operator procedure rather than invoking the file directly, and recorded that as its own deviation (commit `110680e`).
- **cost this run:** the branch ships a script at the wrong mode and an operator procedure shaped around it; the fix is one hand command, which Task 6's return names for the user.

## `bash -n` on a shell file outside the configured scripts directory obtains no permit, so a new script ships syntax-unverified
- **category:** tooling-gap
- **evidence:** Task 6's implementer (#4) reported `bash -n evals/docs-retrieval/arm-a/run-arm-a.sh` refused — a `.sh` token outside `scriptsDir` gets no automatic permit from the script-allowlist guard — and recorded an explicit evidence downgrade: that script's syntax rests on reading rather than on execution. The same run verified the two new `.mjs` modules with `node --check` without trouble (dispatches #37, #43, #49), so the gap is specific to shell files outside `scriptsDir`.
- **cost this run:** one shipped shell script whose syntax no gate checked, disclosed in its own task's deviations rather than silently.
