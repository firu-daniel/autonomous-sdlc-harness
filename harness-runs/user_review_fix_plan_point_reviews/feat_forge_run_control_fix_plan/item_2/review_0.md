# cli review — 2. A round collects only the submitting reviewer's review and comments, so other reviewers' input and refused reviews are lost — iteration 0

## Should Fix
1. **No case pins that a failed permission call for a second author fails the collection** — `cli/templates/scripts/remote-run.sh` (`round_collect`) — "4)\n        RC_ERR=\"${AUTH_WHY%.}\"\n        return 3 ;;"
   Item 5 of the finding makes this a security property: a failed permission call (arm 4) fails the whole collection, and a missing permission answer never counts as a pass. Nothing in `cli/test/remote-control-review.test.mjs` exercises it. Every new case gives each author an answer in `STUB_PERMISSIONS`. So if a later edit folded arm 4 into the `*)` drop arm, or into the `0)` allow arm, every test would still pass. That change would silently drop, or admit, an author whose permission could not be read. The stub already fails the call for a login it has no answer for (`if (answer === undefined || answer === 'FAIL') fail(...)`), so the case is cheap to add. Confirmation rests on reading `round_collect` and `control_review`'s `3)` arm. No probe was run for this path.
   **Fix:** Add a case to `cli/test/remote-control-review.test.mjs`: `STUB_PR_REVIEWS` carries `review(5, 'bob')`, and `STUB_PERMISSIONS` is `{ alice: 'write', bob: 'FAIL' }`. Assert exit 3 (`EXIT_GH`), one reply naming `the permission check for @bob failed`, no `engine=user_review` dispatch, and origin's refs unchanged (`f.originRefs()` before and after).
