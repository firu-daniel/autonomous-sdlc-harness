## Should Fix
1. **The workflow header's variable list leaves out `HARNESS_TRIGGER_ALLOWED_BOTS`, which the new `collect` job reads** — `cli/templates/github/workflows/harness-run.yml` (header, `WHAT IT READS.` → `Variables:`) — "Variables: HARNESS_RUNNER, HARNESS_REMOTE_STOP (any value stops every job"
   The `collect` job's `env:` maps `HARNESS_TRIGGER_ALLOWED_BOTS: ${{ vars.HARNESS_TRIGGER_ALLOWED_BOTS }}`. `round_collect` uses it to decide which bot-authored reviews count. Before this change, nothing in `harness-run.yml` read it, and the header's `WHAT IT READS` list still says so. An adopter tuning repository variables reads this list to learn what the run workflow honours. That adopter would conclude the allowed-bots variable affects only `harness-control.yml`, when it now also decides whether a bot's review starts a round at the end of a run. Confirmed by `grep -n HARNESS_TRIGGER_ALLOWED_BOTS` over the file: it appears only at the `collect` job's `env:` line.
   **Fix:** Add `HARNESS_TRIGGER_ALLOWED_BOTS` to the `Variables:` sentence of `WHAT IT READS.`, with a short note that the `collect` job reads it to decide which bot-authored reviews are collected, as `harness-control.yml` does.

2. **The default-branch checkout differs from the plan's YAML sketch, but `**Deviations from plan:**` does not record it** — `harness-runs/user_reviews/feat_forge_run_control_fix_plan/finding_3.md` (`**Deviations from plan:**`) — "check out the run's branch (fetch-depth 0)"
   The plan's item 2 sketch says the `collect` job checks out the run's branch. The implementation checks out the default branch. That is the correct behaviour, and it is the fix the iteration-0 review asked for. But the task file's deviation list never mentions it, while it does record every other departure (`continue-on-error`, the reuse of `control_*`, the extra test cases). The branch-level reviewer grades the diff against this file. Reading the sketch, it would see the default-branch `ref:` as an undocumented departure from the plan and could ask for it to be reverted to `inputs.branch`, which reintroduces the `create-worktree.sh` refusal.
   **Fix:** Add a `cli` layer sub-bullet under `**Deviations from plan:**`: "the `collect` job checks out the default branch, not the run's branch, as `harness-control.yml`'s review job does: `review` cuts its own working copy of the branch, which `create-worktree.sh` refuses for a branch already checked out; `collect` fetches the branch itself (`forge_fetch_branch`). `workflow-templates.test.mjs` asserts the `ref:`."
