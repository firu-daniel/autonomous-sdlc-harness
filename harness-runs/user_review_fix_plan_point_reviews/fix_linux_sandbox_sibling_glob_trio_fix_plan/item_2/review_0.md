## Nice to Have
1. **The header gives a reason that is true but not the one the code's safety rests on** — `cli/templates/scripts/autonomous-watcher.sh` (`run_profile_entries` header) — "No line here carries a `*`, so run_profile_edit_drops cannot match its rules."
   `run_profile_edit_drops` reads only `$SETTINGS_PROFILE`'s `.permissions.deny`. It never sees `run_profile_entries`' output. In `run_profile_render`'s jq, the `$edrop` filter is applied to the base's deny list before `add_absent` appends the entries' rules. So an appended sibling rule survives even if it did carry a `*`. The no-`*` property guards something else: a base that already holds the exact sibling rules does not lose them, which is what the new test's `widened` leg pins. A maintainer who reads the sentence as the whole guarantee could relax the `*` skip or the drop's `contains("*")` and think they had preserved it, or could think they had broken it.
   **Fix:** Replace the sentence with: "run_profile_edit_drops reads only the base and the render applies its drops before it appends these lines, and no line here carries a `*`, so a base already holding a sibling's exact rules loses none of them."
