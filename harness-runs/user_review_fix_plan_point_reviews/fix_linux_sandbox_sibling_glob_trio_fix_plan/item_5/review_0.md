# general review — ### 5. The absent-path check cannot take what the owed re-take needs: it truncates its `git status` readings, reads none of Claude Code's built-in paths, has no `dd` row and no control mode — iteration 0

## Should Fix
1. **`written` cannot tell a `dd` write apart from a bubblewrap placeholder** — `scripts/sandbox-absent-path-check.sh` (`write_probe`) — "printf 'verdict\twritten\n'"
   The verdict is `written` whenever the plain shell sees `<clone>/.git/commondir` during the poll. On a bubblewrap host, a session whose profile still yields that path in `denyWrite` (or in an `Edit` deny rule, which Claude Code also enforces inside the sandbox; see `cli/src/generators/writeProtection.ts`, "On Linux Claude Code enforces the `Edit` deny rules inside the sandbox too") plants a 0-byte, read-only placeholder there on the host when its sandbox starts (`cli/templates/scripts/lib/harness-run-lib.sh` → `hr_placeholder_host_probe_var`, "Bubblewrap enforces a `denyWrite` entry for an absent path by planting a placeholder there"). The `before` reading comes before the session starts, and polling starts only after the `dd` tool_use reaches the stream. So in the regression this probe exists to catch, where P still denies the clone's `commondir`, `dd` is refused but the placeholder is already present, and the verdict line reads `written`. A maintainer filling the AP row from the verdict would then record the opposite of what happened. The `stat` mode on the `plain shell` line (`-r--r--r--` against a writable mode) and the `dd` result in `## Write probe` can separate the two cases, but nothing in the verdict tells the reader to check them. Confirmed by reading only: the script is Linux-only and refuses this host, and my scratch probe of the poll was denied by the session's permission mode.
   **Fix:** Before setting the verdict, check P with `hr_profile_deny_paths "$P"` (and `.permissions.deny`) for `$t`. If P yields `$t`, record a `profile denies\tyes` line and set the verdict to `placeholder` (or refuse up front with exit 2, documented in the header's exit line). Otherwise keep `written` only when the file appeared and the `dd` tool_result was not an error, so a 0-byte read-only file seen beside a refused `dd` is not reported as a write.

## Nice to Have
1. **The `before` line has a different shape when the file is present** — `scripts/sandbox-absent-path-check.sh` (`write_probe`) — "printf 'before\t%s\n' \"$(st_of \"$t\")\""
   The absent case writes `before\tabsent\t<path>` and the present case writes `before\t<stat>` with no path, so the `## Write probe` rows differ in column count between the two outcomes.
   **Fix:** Write `printf 'before\t%s\t%s\n' "$(st_of "$t")" "$t"` so both cases use `before\t<state>\t<path>`.
