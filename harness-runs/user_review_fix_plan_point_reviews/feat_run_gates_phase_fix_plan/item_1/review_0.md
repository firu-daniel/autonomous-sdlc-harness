# plugin review — ### 1. A `G.4` unit re-fixes a test an earlier unit's fix already cleared, with no way to close it as already passing — iteration 0

## Should Fix
1. **The `No`-path template list is still two-way, so it contradicts the new `already_passing` template** — `plugin/agents/committer.md` (`## Commit-message policy` → **Subject reconciliation**) — "with a `disposition` argument, `<commit_prefix>: record disposition of <unit token> — <cause>`; without one, `<commit_prefix>: mark <unit token> done — <what the staged set shows>`"
   The test sentence still sends every commit without a `disposition` down the `mark <unit token> done — …` template, and that includes an index-only `already_passing` commit. The new paragraph that starts "**An `already_passing` argument takes the same placement with its own template.**" gives that commit a different subject, `mark <unit token> already passing — <cause>`, but only three paragraphs later. So the file now contains two instructions that disagree. A committer that applies the first sentence literally writes `mark Finding 3 done — …`, and the already-passing fact then appears on neither the subject nor a body line. That breaks the "never in neither" invariant the new paragraph states. The `commit_prefix: none` rendering sentence right after it has the same two-way list.
   **Fix:** Make the `No` branch three-way where it is first stated: "with a `disposition` argument, `…record disposition of <unit token> — <cause>`; with an `already_passing` argument, `…mark <unit token> already passing — <cause>`; with neither, `…mark <unit token> done — <what the staged set shows>`". Add the matching `mark Finding 3 already passing — <cause>` rendering to the `commit_prefix: none` sentence. Then shorten the later paragraph so it covers only the body-line placement, the normalisation and the `record disposition of ` exclusion.

2. **The transient form's definition-by-exclusion still takes in the already-passing close** — `plugin/agents/layer-implementer.md` (`## Output contract`) — "The default, and the form for everything the two disposition paragraphs above exclude."
   This is now one of three named forms. An already-passing close is excluded by both disposition paragraphs, because it is neither a standing prohibition nor an unsatisfiable gate. So this sentence still defines it as a **Transient failure**, which contradicts the third bullet two lines below. Anyone reading the default's scope as written gets it wrong, and a bare `blocker:` `<escalate>`s and halts the loop, which is exactly what this fix exists to prevent.
   **Fix:** Reword it to "The default, and the form for everything the two disposition paragraphs and the row-`G.4` check above do not admit."

## Nice to Have
1. **"Both templates" is now three** — `plugin/agents/committer.md` (**Subject reconciliation**) — "**Both templates are free-form subjects, not fixed-form ones.**"
   The new `mark <unit token> already passing — <cause>` template is also free-form and takes the same capitalisation rule. "Both" now undercounts it.
   **Fix:** Change it to "**All three templates are free-form subjects, not fixed-form ones.**" Alternatively, name the already-passing template in that sentence.
