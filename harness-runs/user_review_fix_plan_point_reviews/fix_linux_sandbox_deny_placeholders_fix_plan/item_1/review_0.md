# cli review — 1. A stall kill inside a job leaves placeholder leftovers that break the rest of that job, because the manifest and the sweep skip job mode — iteration 0

Confirmation note: no test was executed by this review. The run of `node --test` on the edited suites was refused by the permission layer, so the findings below rest on reading `cli/templates/scripts/autonomous-watcher.sh`, `cli/templates/scripts/lib/harness-run-lib.sh` and the three edited suites. The implementer's green counts recorded in the task file were not re-observed.

## Should Fix
1. **The manifest-placement refusal has no case** — `cli/templates/scripts/autonomous-watcher.sh` (`placeholder_manifest_writable_root`; `spawn_engine` — "placeholder manifest: not writing $manifest for '$branch', under the session-writable root $add_root")
   The plan's canonical-path refusal is the guarantee that the sweep never reads a manifest the session itself could have rewritten. Its deviation also widened it (a `~/` root resolves under `HOME`, a relative root under the working copy, and an uncanonicalisable path or a `/` root counts as containing the manifest). No case in `cli/test/watcher-placeholder-host.test.mjs` or `cli/test/watcher-remote-job.test.mjs` drives it. Every `job:` case puts `RUNNER_TEMP` outside every root precisely to avoid it. Suppose a maintainer breaks the `case "$m" in "$r" | "$r"/*)` comparison or the `~/` arm. Every suite stays green, and a job then writes, and later sweeps from, a manifest inside a session-writable `--add-dir` root such as `$RUNNER_TEMP/harness-marketplace`. That reintroduces the attack the refusal exists to close. The plan did not list this case, so this is graded Should Fix rather than as a missing required test.
   **Fix:** Add a `job:` case to `watcher-placeholder-host.test.mjs` that sets `RUNNER_TEMP` to a directory under the checkout, or makes it a profile `additionalDirectories` root. Assert that the log carries `placeholder manifest: not writing`, that no manifest exists under it, and that the session still launched (`f.prompts().length === 1`). Alternatively, add direct library-style cases that source the watcher and call `placeholder_manifest_writable_root` with an absolute root, a `~/` root, a relative root and a `/` root.

## Nice to Have
1. **The probe-and-sweep pair is duplicated across both arms of `spawn_engine`** — `cli/templates/scripts/autonomous-watcher.sh` (`spawn_engine`) — "hr_placeholder_host_probe_var\n    if [ \"$HR_PLACEHOLDER_HOST\" = \"1\" ]; then\n      placeholder_sweep_pass \"$branch\" 0"
   The job arm and the local arm now open with the same three statements. Only the local arm goes on to the clone launch check. Two copies can drift, for example if a later edit changes the exclude argument in one arm only.
   **Fix:** Hoist `hr_placeholder_host_probe_var` and the `placeholder_sweep_pass "$branch" 0` guard above `if [ "$JOB_MODE" = "1" ]`. Keep only the `copy_kind = clone` launch check inside the local arm, and move the "No launch check: …" comment beside the hoisted block.
2. **The refusal log can name the manifest as the "session-writable root"** — `cli/templates/scripts/autonomous-watcher.sh` (`placeholder_manifest_writable_root`) — "m=\"$(hr_canonical_path_nogit \"${1-}\")\" || {\n    printf '%s\\n' \"${1-}\""
   When the manifest itself cannot be made canonical, the function prints the manifest path. `spawn_engine` then logs "under the session-writable root <manifest>", which names no root. Only an operator reading that log line is affected, and no decision turns on it.
   **Fix:** In that branch print a fixed marker such as `(manifest path not canonicalisable)`, or log a separate line in `spawn_engine` for that case.
