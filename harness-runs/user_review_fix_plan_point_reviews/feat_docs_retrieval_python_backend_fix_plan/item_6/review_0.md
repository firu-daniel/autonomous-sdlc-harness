# general review — 6. SIGTERM cancels an in-flight call where `serveDocs` drains the queue before closing the store — iteration 0

## Should Fix
1. **The `transport_scope.cancel()` comment and the `serve_mcp` docstring claim SIGTERM ends a real stdio server. A probe shows it does not.** — `docs-retrieval-service/src/harness_docs_retrieval/mcp_server.py` (`serve_mcp`) — "# The stdin reader is still waiting on a line that may never come."
   The comment says cancelling `transport_scope` releases `stdio_server`'s stdin reader. The docstring says the server "Serves until the client closes stdin or the process gets `SIGTERM`". The fix plan's deviation note repeats the claim ("the transport scope is still cancelled, because `stdio_server`'s stdin reader is blocked on a line that may never come"). The installed SDK (mcp 2.2.0, `mcp/server/stdio.py` → `stdio_server`) reads stdin through `anyio.wrap_file(...)`, so each `readline` is a worker-thread call. Cancelling the scope does not interrupt that call: the scope's exit waits until the thread returns.
   Executed probe: a subprocess ran this tree's `serve_mcp` on real stdio with `open_session` patched to a `FakeSession`. The parent held stdin open, sent `SIGTERM` after 2 s, and waited 5 s. Result: `STILL RUNNING 5s after SIGTERM (stdin held open); after stdin close rc=0`, with stderr `starting` / `store closed` / `exited cleanly`. The same probe over HEAD's `serve_mcp` (the removed lines, with `scope.cancel` as the signal handler) gave the identical result, so this is **pre-existing, not a regression**. The ordering this unit fixes (the in-flight call finishes, then the store closes) holds. Lint, typecheck and the full suite all pass: 192 passed, 9 container-skipped.
   The text this unit wrote is still wrong about the stated mechanism. The new test cannot reveal that, because it swaps `stdio_server` for in-memory streams. Command: `bash scripts/python-service.sh test ../harness-runs/scratch/probe_real_sigterm_test.py ../harness-runs/scratch/probe_head_sigterm_test.py --tb=line -p no:cacheprovider`. The probe files are gitignored scratch.

For example, the comment could read: "Cancelling does not interrupt the thread-backed stdin read; the process exits once stdin delivers a line or closes." Narrow the docstring to match, correct the deviation note, and record the SIGTERM-with-open-stdin hang as a deferred item that cites a roadmap number (`.claude/context/conventions.md` → `## Documents of record`).
   (b) Make SIGTERM actually end the process. For example, pass `stdio_server` your own `stdin` wrapper whose reads can be abandoned on cancel, or stop awaiting the reader's join on the SIGTERM path. Then add a subprocess test that holds stdin open.
