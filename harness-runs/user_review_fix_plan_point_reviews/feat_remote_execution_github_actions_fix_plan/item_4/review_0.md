# plugin review — 4. The interactive-test (QA) phase has no remote path — iteration 0

## Must Fix
1. **The `remote-skipped:` line never says which id vocabulary it takes, so the writer can record a value that no reader matches** — `plugin/instructions/autonomous_pause_and_ledger.md` (`### 1.3 Templates`, both engine templates) — "- remote-skipped: <phase ids this run's execution environment cannot run, comma-separated, or `none`>"
   Every consumer of the line keys on the literal `qa`: §1.4 seeds `E` / `R4` `[-]` when the line "names `qa`", §1.3 item 3 maps `remote-skipped: qa`, and Override K in both autonomous forks fires on `remote-skipped: qa`. Nothing tells the writer to use that id. The creating fork gets it from the launch prompt's remote-job clause (`cli/templates/scripts/autonomous-watcher.sh`, `remote_qa_clause`), which names no id at all ("the interactive-test phase is unsupported: record it on the ledger's remote-skipped line"). The template's placeholder says "phase ids", and this ledger's own vocabulary for phase ids is its entry ids (`E`, `P2`, `R4`). So a fork that follows the template literally can write `remote-skipped: E` or `remote-skipped: interactive-test`. In that case `E` / `R4` is not seeded `[-]`, Override K does not fire, and the Done summary falls back to the core's arms. That is the misreport this finding exists to prevent. The fix plan's own sub-step requires the missing statement ("The only id it can carry today is `qa`"), and `grep -n "only id\|carry today"` finds nothing in the file.
   Confirmation rests on reading the three sites. No flow was executed.
   **Fix:** In `### 1.3`, beside the new template line (or in the block paragraph that starts "All three data lines"), state that the line carries **run-mode directive ids** (`${CLAUDE_PLUGIN_ROOT}/instructions/run_mode_instructions.md`'s vocabulary), never ledger entry ids, and that the only id it can carry today is `qa`. For example, make the template read `- remote-skipped: <run-mode directive ids this run's execution environment cannot run — today only \`qa\` — comma-separated, or \`none\`>`.

## Should Fix
1. **"a local re-run of the same branch is not excluded" overstates things for the task engine, where a resume keeps the recorded line** — `plugin/instructions/autonomous_pause_and_ledger.md` (`### 1.3`, "**Keep the four provenances apart.**") — "holds for **this run only** — a local re-run of the same branch is not excluded"
   §1.4 says a task-engine ledger is never re-seeded and that "a resume, which re-reads the recorded block rather than the prompt, keeps the `remote-skipped:` line". So a remote-created task-engine ledger resumed locally keeps `E` as `[-]`. Only the user-review engine's **re-seed** (a new round) re-evaluates the line. As worded, "re-run" reads as if a local resume of the same branch would run QA. The Done line routes the reader to `/autonomous-sdlc-harness:branch-qa-test` anyway, so no flow step turns on this. The prose is still wrong for the task engine.
   **Fix:** Qualify the clause. For example: "holds for the run (or, in the user-review engine, the round) whose ledger recorded it — a resume keeps it (§1.4), and only a fresh user-review round launched locally, or a local `branch-qa-test`, runs the phase."
