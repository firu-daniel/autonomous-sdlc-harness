# general review — ### 3. Pause, resume, answer and user-review on a remote run need a local copy, an adopt, a sync and a running watcher, though GitHub accepts every one of them directly — iteration 1

Scope: the `general` layer's files in the uncommitted set (`docs/development.md`, `docs/github-issue-trigger.md`, `docs/outer-loop-verification.md`, `docs/remote-execution.md`, `docs/watcher.md`), checked against `cli/templates/scripts/remote-run.sh`, `cli/templates/scripts/create-worktree.sh` and the five `plugin/commands/branch-*.md` files as landed. The `cli` and `plugin` files are reviewed in their own layers. No probe was run. Every finding below comes from reading the cited script source and the plugin commands (a `grep -o "remote-run.sh [a-z-]*"` over `plugin/commands/*.md`, and a read of `verb_pause`, `verb_dispatch` and `verb_review`). Anything left to Finding 1 or Finding 2 (the `adopt` sentences in `docs/github-issue-trigger.md` → `## 4.`, Gate 12 (xiii)(c), and `branch-status`'s `adopt --list` row) is not raised here.

## Should Fix
1. **The `remote-run.sh` row's lists of who writes the registry and which verbs the commands call are now incomplete** — `docs/watcher.md` (`## 2.` table, the `remote-run.sh` row) — "it reads and writes the run registry (`sync`, `stop`, `adopt`)"; "a `branch-*` command, for `adopt`, `fetch`, `pause`, `dispatch` and `review`"
   This unit added two registry writers. `verb_dispatch` writes `status running`, `resumed_at` and `resume_kind` after a chain-0 `--resume answer|pause` ("hr_registry_set \"$reg\" \"$branch\" status running resumed_at"), and `verb_review` writes `status running engine user_review`. The row still names only `sync`, `stop` and `adopt`. The edited "who runs it" cell now lists the commands' verbs one by one but leaves out `sync`, which `branch-answer`, `-pause`, `-resume` and `-user-review` all run ("**Remote records sync first.**"), and `status`, which `branch-status` runs. A maintainer who uses this row to find what touches the registry, or which verbs a command can reach, gets an incomplete answer.
   **Fix:** Change "(`sync`, `stop`, `adopt`)" to "(`sync`, `stop`, `adopt`; `dispatch` after a user's chain-0 `--resume answer|pause`, and `review`, update an existing remote record)". Change the command cell to "a `branch-*` command, for `sync`, `status`, `fetch`, `pause`, `dispatch` and `review`, and `adopt` until Finding 1 removes it".

2. **The `create-worktree.sh` row still describes `--no-bootstrap` as new-branch-only** — `docs/watcher.md` (`## 2.` table, the `create-worktree.sh` row) — "with `--no-bootstrap` it cuts and pushes the new branch without that hand-off, for `remote-run.sh start` in a trigger job, whose copy runs nothing"
   This unit removed the `--existing` / `--no-bootstrap` exclusion. `create-worktree.sh`'s own `Usage:` comment now reads "--no-bootstrap skip the bootstrap: alone, create and push a new branch; with" `--existing`, and `remote-run.sh review` calls `create-worktree.sh --existing --no-bootstrap <branch>`. This row is the docs' only description of the flag, and it still says the flag only cuts a new branch for `start`. A maintainer who reads it would think a `review` copy is bootstrapped, or that the pairing is still refused. The task file's deviation notes list the other `docs/watcher.md` edits this unit made, but not this row.
   **Fix:** "with `--no-bootstrap` it skips that hand-off: alone it cuts and pushes a new branch, for `remote-run.sh start` in a trigger job; with `--existing` it checks out an existing branch and pushes nothing, for `remote-run.sh review`. Neither copy runs anything."

3. **"Each command's dispatch is `chain: 0`" is not true of the pause** — `docs/remote-execution.md` (`## 1. The lifecycle of a remote run`, the paragraph after the command table) — "Each command's dispatch is `chain: 0`, takes no cap slot and consults no lane."
   `verb_pause` sends `-f "action=pause" -f "branch=$branch"` and no `chain` input. Only the `dispatch` sends (`resume: answer|pause`, and `review`'s `user_review`) carry `chain=0`. The rewrite repeats the old relay sentence's wording, and this paragraph is now the only statement of the commands' dispatch inputs. A reader comparing it with a `harness pause` run's inputs on GitHub would find no `chain`.
   **Fix:** "Each command's `dispatch` is `chain: 0`, and its `pause` is a jobless `action: pause` run with no chain. None takes a cap slot or consults a lane."
