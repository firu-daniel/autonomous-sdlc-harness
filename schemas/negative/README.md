# negative/

Every document in this directory exists to be **rejected**. Each one isolates a single constraint — it is otherwise a copy of the worked configuration in `examples/harness.config.json`, so the only thing that can make it fail is the constraint it is named for. The `stateDir` dot prohibition is two independent clauses and takes two documents. `state-dir-leading-dot.json` isolates the character-class `pattern`, whose first character class refuses a leading dot. `state-dir-nested-dot.json` isolates the `not` clause: `sdlc/../.claude` satisfies `pattern` and is rejected only by `"not": { "pattern": "(^|/)\\." }`, so deleting that clause turns this document green and nothing else here notices. Both exist because the artifact tree has to be writable by an unattended run, and a dot-path is where a host reserves directories an unattended run may not write to — so an artifact tree placed under a dot-path, reached directly or through a `..` segment that resolves to one, risks being silently never written. `layers-no-catch-all.json` proves the catch-all requirement — the schema requires **at least one** `layers[]` row whose `path` is `"."` — which exists because that row is where work matching no layer's `path` is routed: a configuration without one leaves that work unroutable and stops a run mid-flight, the most expensive moment at which to discover a one-line configuration mistake. `qa-driver-unknown.json` proves the `qa.driver` enum, which exists because a value outside the declared set selects no interactive-test variant at all — the phase would have nothing to run rather than the wrong thing to run. `agent-effort-unknown.json` proves the `agentEffort` enum, which exists because the runtime does not refuse an out-of-set level: it warns, ignores the flag and falls back to its own per-model default, so a mistyped level costs a run the effort the committed configuration did not choose and nothing reports the substitution. `detection-preset-unknown.json` proves the `detection.preset` enum, which exists because that value is the record of which layer profile the repository was wired against — every later reader, from a `doctor` run to `/harness-analyze`, re-derives what `init` decided by reading it, so a name outside the set describes a profile no release of this tool can reproduce. The script asserts each outcome directly: `npm run validate:config:negative` asserts that **every wired document** is **read and rejected** — it fails both when the schema starts accepting one and when one cannot be loaded. A new document added to this directory is not covered until it is wired into that script as its own assertion. A fixture here that starts validating cleanly is a regression in the schema, not in the fixture — fix the constraint, do not adjust the document to suit it. One mechanical caveat when copying from `examples/harness.config.json`: `$schema` is a directory-relative pointer, so re-base it to `../harness.config.schema.json` for this directory instead of carrying the example's value across.
