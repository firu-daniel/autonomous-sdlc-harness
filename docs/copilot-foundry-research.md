**Who reads this:** the maintainer deciding whether, and how, the harness can be adopted inside a company whose only licensed AI coding product is GitHub Copilot (Business or Enterprise), and the planner of any branch that changes how a run authenticates, which engine it launches, or how it caps spend. It owns the findings below, each with its source, as of 2026-10-16, and the routes and recommendation drawn from them. It does not own any design choice: any change it describes to `cli/templates/github/workflows/harness-run.yml`, `cli/templates/scripts/autonomous-watcher.sh`, `doctor` or anything else is a later branch's to make.

It cites rather than restates [`ARCHITECTURE.md`](../ARCHITECTURE.md) §5–§9 — the engine-axis inventory and the nine-operation adapter contract — and [`team-accounts-research.md`](team-accounts-research.md), which covers credentials for a team that does have Claude accounts. [`github-integration-research.md`](github-integration-research.md) A7 recorded, earlier, that Copilot's cloud agent and third-party agents documented no custom plugin, permission profile or launch line; §3 and §4 below supersede that entry where the two disagree.

## 1. The answer in brief

**Yes, with a route that depends on what else the company has.**

- **If the company has an Azure, AWS or Google Cloud tenant** — common in a Microsoft-centric "Copilot-only" shop — Claude Code runs on Claude models billed to that cloud, with no Anthropic contract. The harness runs unchanged locally; the GitHub Actions path needs a small credential change (§5, §6). **This is the recommended route when the company will not buy from Anthropic.** It bills per token, and a harness run measures at about $55–$86 at Opus 5.5 list rates (§5.4). Where the company can buy from Anthropic, a Team plan's Premium seat is a flat $100–$125 per member per month and is far cheaper for regular use.
- **If it has only Copilot**, Copilot CLI is now close enough to Claude Code — headless `-p`, per-agent tool allowlists, subagents, Claude-format plugin manifests, `.claude/settings.json` hooks with a Claude-compatible `PreToolUse` contract, MCP, an OS sandbox — that it is a realistic **second engine**, but adopting it is the open *Engine / provider abstraction* row of [`ROADMAP.md`](../ROADMAP.md) → *Engines, environments and integrations*, not a configuration change (§4.1).
- **Running Claude Code itself on a Copilot token through a proxy is not recommended**: nothing permits it, and the usage pattern of a daemon is the one GitHub's acceptable-use policy names (§4.5).

## 2. What the harness needs from its engine

[`ARCHITECTURE.md`](../ARCHITECTURE.md) §5–§9 is the inventory of record; this section only ranks it for the Copilot question. The flow logic under `plugin/instructions/`, the agents' role prose, the plan / review / ledger formats, the state directory, the clarification and pause sentinels, `classify_run_exit`, the worktree / commit / push wrappers, the guard policy bodies and the MCP servers are plain markdown, shell and files, and port as they are.

The hard couplings, hardest first:

1. **Containment.** The exhaustive `dontAsk` permission profile (`cli/templates/claude/settings.autonomous.json`, generated by `cli/src/generators/permissionProfile.ts`), Claude Code's OS sandbox block, and the `PreToolUse` interception point the six guards in `plugin/hooks/hooks.json` hang on. [`ARCHITECTURE.md`](../ARCHITECTURE.md) §9 names this the property that disqualifies a candidate engine first.
2. **A sub-agent primitive with an enforced per-agent `tools:` closure** — the only thing keeping browser tools inside `qa-tester` (`.claude/CLAUDE.md` → *Agent authoring rules*).
3. **Plugin packaging and asset resolution** — `${CLAUDE_PLUGIN_ROOT}` across the plugin corpus, slash-command resolution from a headless first message (the `ENGINE_COMMAND_TASK` string in `cli/templates/scripts/autonomous-watcher.sh`), and the marketplace format.
4. **An auto-loaded root context file** (`CLAUDE.md`) in every sub-agent. It fails silently when absent.
5. **The headless event stream** — the `stream-json` schema, and `rate_limit_event` records whose `five_hour` / `seven_day` windows drive the usage gate.
6. **Launch flags and credentials** — `-p`, `--settings`, `--permission-mode`, `--add-dir`, `--model`, `--effort`, and `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`, which `cli/templates/github/workflows/harness-run.yml` requires one of.

## 3. What Copilot offers today

### 3.1 Copilot CLI

- **Headless mode** — `-p/--prompt`, `--agent`, `--model`, `--allow-tool` / `--deny-tool` / `--allow-all-tools`, `--output-format=json` (JSONL), `-s/--silent`, `--no-ask-user`, `-r/--resume`, `--autopilot` with `--max-autopilot-continues`, `--plugin-dir`, `--additional-mcp-config` and `--sandbox`. **Documented:** https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference, https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/run-cli-programmatically.
- **Status** — generally available since 2026-02-25. **Unconfirmed** on github.blog; the date comes from a release aggregator.
- **Session spend cap** — `--max-ai-credits=N`, public preview. **Documented:** https://github.blog/changelog/2026-07-01-set-ai-credit-session-limits-in-copilot-cli-and-sdk/.
- **Automation credentials** — `COPILOT_GITHUB_TOKEN`, then `GH_TOKEN`, then `GITHUB_TOKEN`; a fine-grained PAT carrying the *Copilot Requests* permission, or an OAuth token; classic `ghp_` PATs are refused. GitHub documents an Actions recipe. **Documented:** https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/automate-with-actions. **Inference:** a PAT is a user token, so CI usage bills to that user's seat. Whether an Actions `GITHUB_TOKEN` can carry Copilot usage is **unconfirmed**.
- **Claude models** — Haiku 4.5 and 5.5, Sonnet 4.6, 5 and 5.5, Opus 4.8, 5 and 5.5, Fable 5 and 5.1 are listed as GA. **Documented:** https://docs.github.com/en/copilot/reference/ai-models/supported-models. Per-client availability for every model is **unconfirmed**, because the table was truncated.

### 3.2 Custom agents and subagents

- **Format** — `.github/agents/NAME.agent.md`, with user-level agents in `~/.copilot/agents/` and org-level ones in the `.github` repository. Frontmatter: `name`, `description`, `tools` (all tools when omitted), `mcp-servers`, `target`, `model`. The cloud agent ignores `model`. **Documented:** https://docs.github.com/en/copilot/reference/custom-agents-configuration.
- **CLI subagents** — each custom agent runs as a subagent with its own context window, and subagents can run in parallel. Whether a custom agent can dispatch further agents by name, and how deep, is **unconfirmed**. The harness needs one level: an orchestrator dispatching about fifteen roles.
- **VS Code** reads Claude-format `.claude/agents/*.md` (comma-string `tools`, `disallowedTools`) and maps Claude tool names to its own. An agent dispatches others through the `agent` / `runSubagent` tool and an `agents:` list. **Documented:** https://code.visualstudio.com/docs/agent-customization/custom-agents.
- **Contradiction** — the CLI plugin reference lists `.claude/agents` in its lookup order, while the CLI custom-agents how-to lists only `.github/agents/` and `~/.copilot/agents/` (https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli). **Unconfirmed** which holds.

### 3.3 Plugins, marketplaces and skills

- **Copilot CLI** looks for a plugin manifest in `.plugin/plugin.json`, `plugin.json`, `.github/plugin/plugin.json`, then `.claude-plugin/plugin.json`, and accepts `.claude-plugin/marketplace.json`. Manifest component paths cover `agents`, `skills`, `commands`, `hooks` and `mcpServers`. `${CLAUDE_PLUGIN_ROOT}` is an alias **only in a plugin agent's `mcp-servers` frontmatter**; MCP `args` / `env` / `cwd` document `${PLUGIN_ROOT}`. **Documented:** https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference. Whether the token is substituted in agent bodies and hook commands, as the harness relies on, is **unconfirmed**.
- **VS Code agent plugins** accept `.claude-plugin/plugin.json`, `agents/`, `skills/` and `hooks/hooks.json`, and expand `${CLAUDE_PLUGIN_ROOT}` in hooks and MCP. Enterprise admins control which plugins and marketplaces are allowed. Claude-style `commands/` is **not documented**. **Documented:** https://code.visualstudio.com/docs/agent-customization/agent-plugins.
- **Skills** — Copilot CLI reads `SKILL.md` folders from `.github/skills`, `.claude/skills` and `.agents/skills`. **Documented:** https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills.
- A community fork reports that Copilot's marketplace schema rejects the `git-subdir` source type. **Unconfirmed**, single source.

### 3.4 Hooks

- Copilot CLI reads `.github/hooks/*.json` **and** the inline `hooks` in `.claude/settings.json` and `.claude/settings.local.json`, plus plugin hooks. It supports fourteen events.
- **A PascalCase `PreToolUse` event switches the payload to Claude's snake_case fields** (`tool_name`, `tool_input`) and Claude tool names (`Bash`, `Read`, `Edit`).
- A deny is `permissionDecision: "deny"` with `permissionDecisionReason`, and exit code 2 denies as well — the contract `plugin/hooks/git-commit-branch-guard.sh` already speaks.
- **Timeouts fail open** (30 s by default). Under the cloud agent `ask` is treated as `deny`.
- **Documented:** https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-hooks-reference.
- Whether `CLAUDE_PROJECT_DIR` is set for a hook is **unconfirmed**.
- **VS Code's local harness** reads Claude hooks only with `chat.useClaudeHooks` on (off by default), and **ignores matchers**, so every `Bash`-matched guard would run for every event. **Documented:** https://code.visualstudio.com/docs/copilot/customization/hooks.

### 3.5 Instructions

- Copilot CLI reads `.github/copilot-instructions.md`, `.instructions.md` files and `AGENTS.md`. Whether it reads `CLAUDE.md` is **unconfirmed**. **Documented:** https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/overview.
- The cloud agent reads `CLAUDE.md` alongside `AGENTS.md`. **Documented:** https://github.blog/changelog/2026-06-23-copilot-coding-agent-now-supports-agents-md-custom-instructions/.
- VS Code reads `CLAUDE.md` behind `chat.useClaudeMdFile`. **Documented:** https://code.visualstudio.com/docs/copilot/customization/custom-instructions.

### 3.6 MCP and enterprise policy

- MCP works in the CLI, in VS Code and in the cloud agent.
- Enterprise and org MCP policies, and the CLI on/off policy, apply to the CLI. **Documented:** https://docs.github.com/en/copilot/how-tos/copilot-cli/administer-copilot-cli-for-your-enterprise.
- Registry-based MCP allowlists in the CLI are in public preview, match by name only, and GitHub recommends `managed-settings.json` as the GA control. **Documented:** https://docs.github.com/en/copilot/reference/enterprise-administrators/mcp-allowlist-enforcement.

### 3.7 Copilot cloud agent and SDK

- **Cloud agent** — runs on GitHub-hosted Actions runners and is prepared by `copilot-setup-steps.yml`. A stuck session times out after one hour, and workflows on its pull requests need a human to approve them. It can be started through the agent tasks API (public preview, user tokens only) or by assigning an issue. **Documented:** https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-via-the-api, https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/troubleshoot-cloud-agent.
- **Copilot SDK** — GA on 2026-06-02 for Node/TS, Python, Go, .NET, Rust and Java. It exposes the CLI's runtime: sessions, custom tools, pre/post tool-use and permission hooks, MCP, skills and custom agents. **Documented:** https://github.blog/changelog/2026-06-02-copilot-sdk-is-now-generally-available/.

### 3.8 Billing

- **Since 2026-06-01, usage is metered in GitHub AI Credits** — per input, output and cached token at each model's API rate — replacing premium requests. Business includes 1,900 credits per user per month and Enterprise 3,900. **Documented:** https://github.blog/changelog/2026/04/27/github-copilot-is-moving-to-usage-based-billing/, https://docs.github.com/en/copilot/get-started/plans. The $0.01 credit value and org-wide pooling are **unconfirmed** on docs.github.com.
- Per-request model multipliers found in older pages predate June 2026 and are stale.
- **Inference:** every subagent's tokens count, so at Opus rates a seat's monthly allotment covers few full autonomous runs, and an adopter would need an overage budget and `--max-ai-credits`.

## 4. The routes

### 4.1 Copilot CLI as a second engine

**What maps directly** (§3): the headless launch, Claude-format plugin manifests and marketplaces, `.claude/skills`, `.claude/settings.json` hooks with a Claude-compatible `PreToolUse` contract, per-agent `tools:`, subagents, MCP, `--sandbox`, and an Actions recipe.

**What a port would have to build or settle**, keyed to §2:

- **Containment (§2.1).** Copilot's `--allow-tool` / `--deny-tool` grammar is not the 68 raw-string `Bash(...)` rules under `dontAsk`. The profile generator would need a second output, and whether `--sandbox` offers what `docs/sandbox-verification.md` measures of Claude Code's sandbox would need its own measurement. Hook timeouts fail open, where the harness's guards assume an answer.
- **Sub-agent closure (§2.2).** `tools:` is supported. Dispatch-by-name of plugin agents from an orchestrator session in `-p` mode is **unconfirmed**.
- **Asset resolution (§2.3).** `${CLAUDE_PLUGIN_ROOT}` coverage outside MCP frontmatter is **unconfirmed**, and so is support for `commands/`. A headless first message naming the plan engine's command (the watcher's `ENGINE_COMMAND_TASK`) may need the commands carried as skills instead.
- **Root context (§2.4).** If the CLI does not read `CLAUDE.md`, an `AGENTS.md` written by `init` would carry the same content.
- **Event stream and usage gate (§2.5).** Copilot's JSONL is a different schema, and it has no `rate_limit_event` windows. The usage gate would give way to `--max-ai-credits`, which is the *Budget governor* row of [`ROADMAP.md`](../ROADMAP.md).
- **Launch and credentials (§2.6).** The binary seam already exists (`${HARNESS_AGENT_CLI:-claude}`), but every flag is Claude's spelling, and `agentModel: "opus"` is a Claude Code alias that Copilot would not resolve.

**Inference:** this is the *Engine / provider abstraction* row of [`ROADMAP.md`](../ROADMAP.md) with a concrete first candidate. The adapter contract of [`ARCHITECTURE.md`](../ARCHITECTURE.md) §7 could be tested against it. It is the best long-term route for a Copilot-only company and the most work.

### 4.2 Claude on the company's own cloud (Foundry, Bedrock, Vertex)

Claude Code officially supports Microsoft Foundry, Amazon Bedrock and Google Cloud as providers, selected by environment variables, with billing on that cloud and no Anthropic contract. **Documented:** https://code.claude.com/docs/en/microsoft-foundry. The harness launches `claude -p` exactly as it does today. §5 covers Foundry in detail, since a Copilot customer is most likely to hold an Azure tenant. **This is the recommended route.**

### 4.3 The Claude partner agent on GitHub.com

Anthropic's agent, built on the Claude Agent SDK and offered as a third-party agent in GitHub, is in **public preview** on Pro, Pro+, Business and Enterprise, and "can be powered by your existing Copilot subscription". Business and Pro were added on 2026-02-26. It must be enabled at the enterprise and the organisation level, and enabling it installs the *anthropic code agent* GitHub App. Sessions start from the Agents tab, an issue assignment or `@Claude` in a pull request, and end in a pull request. It consumes Actions minutes and AI Credits. **Documented:** https://docs.github.com/en/copilot/concepts/agents/about-third-party-coding-agents, https://github.blog/changelog/2026-02-26-claude-and-codex-now-available-for-copilot-business-pro-users/.

Whether it loads a repository's `.claude/` plugins, hooks, subagents or MCP servers is **unconfirmed**; GitHub's page does not cover it. **Inference:** it does not fit the outer loop. There is no daemon, no inbox and no worktree, and each session yields one pull request. At best it is a manual entry point for single tasks.

### 4.4 Claude sessions in VS Code

VS Code runs Claude sessions on the Claude Agent SDK. Usage is billed through Copilot when a Copilot model is picked, the sessions "use Claude project configuration" in the workspace, and an organisation may manage the setting `github.copilot.chat.claudeAgent.enabled`. **Documented:** https://code.visualstudio.com/docs/agents/agent-types/third-party-agents. **Inference:** this can carry the supervised `/autonomous-sdlc-harness:branch-*` flows by hand, not unattended runs. VS Code's own local harness ignoring hook matchers (§3.4) is a reason to prefer the Claude session over it.

### 4.5 Not recommended: Claude Code on a Copilot token through a proxy

Claude Code accepts any gateway exposing a supported API format through `ANTHROPIC_BASE_URL`. Anthropic "doesn't endorse, maintain, or audit third-party gateway products", and names no Copilot provider. **Documented:** https://code.claude.com/docs/en/llm-gateway. Proxies such as `copilot-api` and LiteLLM's `github_copilot` provider work technically. `copilot-api`'s own README warns that heavy scripted use can trigger abuse detection and "temporary suspension of Copilot access".

- GitHub's Terms of Service say "Your login may only be used by one person" (B.4) and reserve excessive-use decisions to GitHub's "sole discretion" (H). **Documented:** https://docs.github.com/en/site-policy/github-terms/github-terms-of-service.
- The Acceptable Use Policies ban "excessive automated bulk activity". **Documented:** https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies.
- No page checked grants use of a Copilot token from a non-Copilot client, and none explicitly forbids it. The current Copilot product-specific terms could not be retrieved, so an explicit prohibition is **unconfirmed**.

**Inference:** a 24/7 daemon is the automated-bulk pattern the policy names. The traffic is unsupported and puts a seat at risk. The harness should not document this route as an option.

## 5. Route 4.2 in detail: Microsoft Foundry

### 5.1 Credentials

Every credential belongs to the company's **own Azure Foundry resource**, not to an Anthropic account. An Azure admin creates a Foundry resource and deploys the Claude models into it. Claude Code then accepts one of three credentials. **Documented:** https://code.claude.com/docs/en/microsoft-foundry.

- **API key** — the resource key, copied from the Foundry portal (*Build → Models → deployment → Details → Key*), set as `ANTHROPIC_FOUNDRY_API_KEY`.
- **Microsoft Entra ID** — with no key set, Claude Code uses the Azure SDK default credential chain: an `az login` session, a managed identity, a service principal, or workload-identity OIDC.
- **Bearer token** — an Entra access token obtained by another process, set as `ANTHROPIC_FOUNDRY_AUTH_TOKEN`, which takes precedence over the other two.

Enabling the provider takes `CLAUDE_CODE_USE_FOUNDRY=1` plus `ANTHROPIC_FOUNDRY_RESOURCE` (the resource name alone) or `ANTHROPIC_FOUNDRY_BASE_URL`. The roles *Foundry User* (formerly Azure AI User) and *Cognitive Services User* are enough to call the models. There is no setup wizard, and `/logout` is unavailable.

**Inference:** an unattended daemon is better served by Entra ID through a managed identity or service principal than by a stored key, since there is then no long-lived secret to rotate.

### 5.2 How usage is metered

**Documented:** https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry, https://platform.claude.com/docs/en/about-claude/pricing#claude-in-microsoft-foundry-pricing.

- Usage is billed through the **Azure Marketplace in Claude Consumption Units (CCUs)**. Anthropic rates the token usage in USD at the **standard Claude API per-model, per-feature rates**, applies any negotiated discount, and converts the result to CCUs at a fixed $0.01 per CCU.
- The CCU quantity is reported hourly and invoiced monthly in arrears as a single line on the Azure bill. CCUs are not prepaid: there is no balance and no commitment. Azure Cost Management shows the aggregate.
- US Data Zone Standard deployments carry a 1.1× multiplier; Global Standard is 1×.
- Example list rates: Opus 5.5 is $4 / MTok input and $20 / MTok output, and Sonnet 5.5 is $2 / $10. Cache hits on both are 0.05× the input price.
- Rate limits are Azure per-deployment quotas, surfacing as HTTP 429, and Anthropic's rate-limit headers are not sent. Limits are raised through an Azure quota request.

**Inference:** the difference from a Claude subscription is the cost model, not the price per token. A subscription has flat pricing with five-hour and seven-day windows; Foundry has spend only, and every long Opus run is metered. Prompt caching matters here, because a run re-reads the same instruction and conventions documents.

### 5.3 Model and effort

Model and effort are set the same way as today. The watcher passes `--model "$AGENT_MODEL"` and `--effort "$AGENT_EFFORT"` (`cli/templates/scripts/autonomous-watcher.sh`), and Claude Code forwards both. Effort is not on Foundry's list of unsupported features. On Foundry, the Fable models, Sonnet 5 and later, and Opus 4.7 and later get the 1M-token context window by default, when Claude Code can tell which model a deployment serves. **Documented:** https://code.claude.com/docs/en/microsoft-foundry.

The constraints:

1. **The `opus` alias must be pinned.** Without `ANTHROPIC_DEFAULT_OPUS_MODEL`, the `opus` alias on Foundry resolves to **Opus 4.6**, and Foundry has no startup model check, so requests to a missing deployment simply fail. **Documented** (same page). Opus 4.6 is offered only as *Hosted on Anthropic*, not *Hosted on Azure*. **Documented** (platform page, model table). `agentModel` defaults to `opus` (`schemas/harness.config.schema.json`). So an adopter sets `ANTHROPIC_DEFAULT_OPUS_MODEL` (and the Sonnet and Haiku variables) to a deployed model such as `claude-opus-5-5`, or writes a full model ID into `agentModel`. Deployment names that differ from model IDs also need `modelOverrides` for the 1M window to be detected.
2. **The usage gate does nothing.** It pauses runs on `rate_limit_event` five-hour and seven-day windows (`cli/templates/scripts/autonomous-watcher.sh`, the usage-gate parser), which only a Claude subscription emits. On Foundry it never fires: safe, but uncapped. The spend controls available are an Azure budget alert and Claude Code's `--max-budget-usd`, which today only the mention session in `cli/templates/scripts/remote-run.sh` passes.
3. **Hosting option.** *Hosted on Azure* keeps prompts and completions inside Azure and serves Opus 5.5 and 5, Opus 4.8, Sonnet 5.5 and 5, and Haiku. It does not support server-side code execution, newer web-search and web-fetch tool versions, API Agent Skills, programmatic tool calling, or the Files API. Claude Code detects an Azure-hosted deployment and adapts, and the harness depends on none of those features. Fable 5.1 requires *Hosted on Anthropic*. **Documented** (platform page).
4. **Not supported on Foundry at all:** the Message Batches API, the Models API, the Admin and Compliance APIs, server-side fallback, and the current computer-use and browser-use toolsets. **Documented** (platform page). The harness uses none of them; its QA phase drives a browser through MCP servers, not the API toolset.

### 5.4 What a harness run costs at API rates

Foundry, like the Console API, bills every token, so the cost of one autonomous run is the number that decides the route.

**What was measured, and how.** Every unattended run tees its headless stream to `<state_dir>/autonomous_logs/<branch>.stream.jsonl`. Each session in it ends with a `result` event whose `total_cost_usd` is Claude Code's own figure for that session. A run resumed across sessions writes one `result` per session, so a run's cost is the sum of `total_cost_usd` over every `result` event in its file:

```
grep '"total_cost_usd"' <branch>.stream.jsonl | jq -s 'map(.total_cost_usd) | add'
```

**What the figure is.** Checked on 2026-10-16 against the stream logs, as follows:

- **It includes the subagents.** `modelUsage` lists every model the session used, subagents included, and its per-model `costUSD` values add up exactly to `total_cost_usd`. Its token totals are larger than the main session's own `usage` block.
- **It prices each token type separately.** Uncached input, output (thinking included), cache reads and cache writes each get their own list price.
- **It is an estimate at list prices, not an amount Anthropic billed.** Each model entry carries `"costBasis": "list"`. On a subscription nothing is charged per token; the figure is what the same tokens would cost on the API or on Foundry, where the CCU conversion uses the same list rates (§5.2).

**Results.** These are lower bounds: a session the watcher kills writes no `result` event, so its spend is missing from its file. One of the thirty files in the first set is such a session.

| Set | Runs | Median | Mean | Range | Mean duration |
|---|---|---|---|---|---|
| A private adopter's repository, the last 30 stream logs: product features and harness fixes. **Estimated** at Opus 5.5 list rates from each run's recorded token counts by type. | 29 with a `result` | **$86** | **$84** | $27–$152 (middle half $57–$106) | ~4.7 h |
| This repository's own runs on Opus 5.5, `harness-runs/autonomous_logs/`: smaller branches | 11 | **$55** | **$62** | $21–$114 | ~2.1 h |

**Where the cost comes from**, in the first set: cache reads ~45%, cache writes ~30%, output ~25%, uncached input under 1%. **Inference:** a run is expensive because every turn of every agent re-reads a large instruction, conventions and code context, not because of what it writes. Prompt caching already absorbs most of that, so the context each agent loads is the lever on cost, more than the volume of output.

**What it means for the routes.**

- **Foundry or the Console API.** At $55–$86 per run, one autonomous branch per developer per working day comes to roughly **$1,100–$1,700 per developer per month**.
- **Copilot.** An Enterprise seat's 3,900 included AI Credits (§3.8) cover less than one median run.
- **An Anthropic Team plan.** A Premium seat is a flat **$100–$125 per member per month**, with 6.25× the Pro plan's per-session allowance and a weekly limit; a Standard seat is $20–$25 for 1.25× ([`team-accounts-research.md`](team-accounts-research.md) → P1, retrieved 2026-10-02). Limits are per member and not pooled. Usage past a seat's limit can continue on usage credits, which bill at API rates. **Inference:** for a developer who runs the harness regularly, a Premium seat is far cheaper than per-token billing, as long as the runs fit its five-hour and weekly windows. The usage gate exists to pace runs to exactly those windows. **Not measured:** how many runs fit in one Premium seat's windows. A real Team seat would measure it.
- **The caveat on that inference.** Anthropic announced a separate Agent SDK credit for headless use, then paused it ("For now, nothing has changed"; [`team-accounts-research.md`](team-accounts-research.md) → P5). If it returns, `claude -p` usage could move off the seat allowance onto metered credits.

## 6. What route 4.2 would change in the harness

None of this is decided here. Each item is a later branch's.

- **Local runs need no code change** — only the §5.1 environment variables and the model pin from §5.3.
- **Remote runs on GitHub Actions do not work on Foundry today.** Claude Code reads the Foundry variables on any machine, a runner included, so nothing in the engine blocks it. What blocks it is the workflow:
  - `cli/templates/github/workflows/harness-run.yml`'s *Check the credentials* step fails the job unless the `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` secret is set.
  - Its *Run the harness* step exports only those two before `autonomous-watcher.sh job`.
  - `harness-control.yml` passes the same two to the mention session.

  Supporting Foundry would take three changes:
  1. **Accept a Foundry credential** as a third option, by one of two routes:
     - **Key** — an `ANTHROPIC_FOUNDRY_API_KEY` secret, exported with `CLAUDE_CODE_USE_FOUNDRY=1` and `ANTHROPIC_FOUNDRY_RESOURCE`.
     - **Keyless, preferred** — Azure workload identity federation: `permissions: id-token: write` and an `azure/login` step before the run. Claude Code's default Azure credential chain then picks up the Azure CLI sign-in, and no secret is stored.
  2. **Export the model pins** (`ANTHROPIC_DEFAULT_OPUS_MODEL` and its Sonnet and Haiku siblings) from repository variables, for the reason in §5.3.
  3. **Make the same change in `harness-control.yml`** for the mention session.

  `claude-code-action` already has a provider input for Foundry using OIDC, which shows the shape (https://code.claude.com/docs/en/github-actions). The usage gate is as inert on a runner as it is locally, and per-run cost is §5.4's.
- **`doctor`** could warn when a provider is selected and the `opus` alias is unpinned.
- **The usage-gate documentation** ([`watcher.md`](watcher.md)) would need to state that the gate is inert on a cloud provider. The spend cap is the *Budget governor* row of [`ROADMAP.md`](../ROADMAP.md).
