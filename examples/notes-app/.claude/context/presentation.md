# Presentation layer

> **Read this when:** you are building or reviewing anything under `src/presentation` — the add form, the note list, the filter control, or a new region of the one mounted surface. **Skip when:** the change is a business rule (`src/domain`), a persisted shape (`src/data`), the stylesheet or the mount (`.` — the `general` layer), or a test (`test`).

**Purpose.** What a module in this layer has to do to look and behave like the rest of `src/presentation`, plus the two review contracts the harness itself checks here. The rules every layer shares live in [`.claude/context/conventions.md`](conventions.md) and are not repeated: where one of them decides something here, this file states the consequence and names the owner.

## The stack, in this layer

The language is TypeScript under `strict: true`, and there is no UI framework, no state container and no template language to defer to — adding one is a supervised decision rather than a task's (`.claude/context/conventions.md`, `## The stack, in the words this project uses`). The consequence here: **a module builds its own nodes with `document.createElement` and types them as the concrete DOM interface they are.** The `node:test` suite does not reach this directory; how a change here is verified instead is in `## Registering a new region` below. _(read off: `src/presentation/noteListView.ts` (`renderRow`), `src/presentation/app.ts` (`createApp`))_

## The shape of a module

- **A module opens with a header comment naming the file and what it owns**, including what it deliberately does not do. _(read off: `src/presentation/qaAttrs.ts` (file header), `src/presentation/noteComposer.ts` (file header))_
- **A region module exports exactly one `create<Thing>` factory plus the interfaces describing its handle and, when it has several things to report, its callbacks.** The factory shape itself is owned by `.claude/context/conventions.md` (`## Where a new responsibility goes`); what this layer adds is that **every other function stays inside the factory closure and is not exported** — a repeated element shape becomes a local builder, a render mode becomes a local `render<Mode>`. _(read off: `src/presentation/noteListView.ts` (`createNoteListView`, `button`, `renderViewing`, `renderEditing`), `src/presentation/noteComposer.ts` (`createNoteComposer`))_
- **The handle's `element` is `readonly` and typed as the concrete element**, not `HTMLElement`, so the wiring can reach form or list APIs without a cast. _(read off: `src/presentation/noteComposer.ts` (`NoteComposer`), `src/presentation/noteListView.ts` (`NoteListView`))_
- **The exported factory, each exported interface and each interface member carry a JSDoc block comment.** A callback's comment says which control raises it and what its arguments mean. _(read off: `src/presentation/noteListView.ts` (`NoteListCallbacks`), `src/presentation/qaAttrs.ts` (`QaAttrs`))_
- **A module that redraws from data draws only its container at construction and its content on the first `render`; a module whose content is fixed builds that content at construction and exposes no `render`.** _(read off: `src/presentation/noteListView.ts` (`createNoteListView`), `src/presentation/noteComposer.ts` (`createNoteComposer`))_
- **A region is constructed once, inside `createApp`, and is never unmounted — so nothing in this layer is torn down by hand.** `src/main.ts` mounts `createApp()` into `#app` on `DOMContentLoaded` and the surface lives for the page; a listener attached to a node that `render` replaces is discarded with that node, so it is not removed explicitly. A region that would need a teardown point — a listener or timer reaching outside its own subtree — is a design question rather than a task's; see `## Not determined`. _(read off: `src/main.ts`, `src/presentation/app.ts` (`createApp`), `src/presentation/noteListView.ts` (`render`))_
- **A view module calls no business function.** It is handed values and callbacks, and every callback lands in `src/presentation/app.ts`; only that module may import `../domain/notesService.js` (`.claude/context/conventions.md`, `## The layers, and the direction a dependency may point`). The consequence here: a view module never re-expresses a domain rule — `src/presentation/noteComposer.ts` sets `form.noValidate = true` so the browser cannot apply one either. _(read off: `src/presentation/noteComposer.ts` (`createNoteComposer`), `src/presentation/noteListView.ts` (file header))_
- **A helper used by more than one module in this directory is its own module here**, shaped like `src/presentation/qaAttrs.ts`: named exports, no import from another layer, nothing done at import time (`.claude/context/conventions.md`, `## Where a new responsibility goes`). _(read off: `src/presentation/qaAttrs.ts` (`qa`))_

## Two harness contracts

**Test attributes.** Every element an interactive test drives carries a stable test attribute, applied through one shared helper rather than hand-written per element, because the test agent locates elements by that attribute and by nothing else. A class name or a copy string is not a substitute: both change for reasons that have nothing to do with the test, and a control with no attribute is simply untestable. In this project the attribute is `data-qa-id` and the helper is `qa` in `src/presentation/qaAttrs.ts` — the three attribute names and the ban on a hand-written `setAttribute('data-qa-…')` are owned by `.claude/context/conventions.md` (`## Test attributes, and the helper that writes them`). This layer adds:

- **`qa` wraps the creation expression itself**, and properties are set on what it returns: `const submit = qa(document.createElement('button'), { id: 'note-submit', status: 'idle' });`. _(read off: `src/presentation/noteComposer.ts` (`createNoteComposer`), `src/presentation/app.ts` (`createApp`))_
- **A purely structural container is not published** — a wrapper `div`, the heading, the mount root carry no `data-qa-id`. Publishing what nothing drives creates a hook a test will come to depend on. _(read off: `src/presentation/app.ts` (`createApp`), `src/presentation/noteListView.ts` (`renderViewing`))_
- **An id token is kebab-case and prefixed with its surface** — `note-` for the notes surface, composer, list, empty state and row alike, and `filter-` for the filter control. A new region inside an existing surface takes that surface's prefix rather than coining its own. _(read off: `src/presentation/noteComposer.ts` (`createNoteComposer`), `src/presentation/noteListView.ts` (`renderRow`, `renderEmpty`), `src/presentation/app.ts` (`FILTERS`))_
- **A repeated element keeps the same id in every instance and is told apart by `data-qa-value`**, never by an id generated per instance: a row is `note-row` carrying the note's id as its value. A generated id would make every test selector depend on data. _(read off: `src/presentation/noteListView.ts` (`renderRow`), `src/presentation/qaAttrs.ts` (`setQaValue`))_
- **A status token is written in every state, including the neutral one.** An element with a state publishes it both ways — `selected`/`unselected`, `idle`/`saving`, `idle`/`invalid`, `never-edited`/`edited` — rather than omitting the attribute to mean the default, because a test waits on a token and cannot wait on an absence. _(read off: `src/presentation/app.ts` (`refresh`), `src/presentation/noteComposer.ts` (`showError`, `setSaving`), `src/presentation/noteListView.ts` (`renderViewing`))_
- **A `data-qa-value` is written only where there is a value to read, and is never emptied to stand for absence** — the attribute is passed `undefined`, which `qa` omits, and the status token carries the state instead. The edited stamp publishes epoch milliseconds when there is an instant and no `data-qa-value` at all when there is none, while publishing a status token either way — `never-edited` when there is no instant, `edited` when there is. This is the asymmetry with the rule above: a status token is always written, a value only when one exists. _(read off: `src/presentation/noteListView.ts` (`renderViewing`), `src/presentation/qaAttrs.ts` (`qa`), `styles.css` (`.note__edited[data-qa-status='never-edited']`))_
- **A container that publishes a count publishes the *rendered* count, and refreshes it at the top of `render` before the children are replaced.** The list carries its own `data-qa-value`, so a test asserting on it asserts what the filter drew rather than how much is in storage. _(read off: `src/presentation/noteListView.ts` (`createNoteListView`, `render`))_

**Module size.** A review flags a module that has outgrown one region and splits it; the split line is **one region per module**, where a region is one thing on screen with one handle and one set of callbacks. A module that has acquired a second handle, a second callbacks interface, or a render path no other part of its own region reaches, is past the line and is split into a sibling module wired in `src/presentation/app.ts`. This is a review-severity contract: a reviewer cites the rule rather than arguing taste. The one-region line is the whole of the threshold — no number stands behind it; see `## Not determined`. _(read off: `src/presentation/noteComposer.ts` (`NoteComposer`), `src/presentation/noteListView.ts` (`NoteListView`), `src/presentation/app.ts` (`createApp`))_

## Copy, styling and structure

- **User-visible copy is a literal at the element that shows it, set with `textContent`**; there is no localization accessor and no message catalogue, and introducing one is a supervised decision (`.claude/context/conventions.md`, the `general` layer section). The consequence here: **a toggle's label is the action, its `data-qa-status` token is the state** — the pin control reads `Unpin` while its token reads `pinned`. _(read off: `src/presentation/noteListView.ts` (`renderViewing`))_
- **A module sets `className` and nothing else about appearance**: no inline `style`, no theme accessor, no sizing or spacing token in TypeScript. Every class it sets has a BEM rule in `styles.css`, which the `general` layer owns (`.claude/context/conventions.md`, the `general` layer section). _(read off: `src/presentation/noteListView.ts` (`renderRow`), `styles.css` (`.note__controls`))_
- **A state that is both visual and testable is expressed once — as the `data-qa-status` token — and styled through an attribute selector**, not by also toggling a modifier class. A variant that follows a note's own stored fields is the modifier class instead: `note--pinned`, `note--archived`. _(read off: `src/presentation/app.ts` (`refresh`), `styles.css` (`.filters__control[data-qa-status='selected']`), `src/presentation/noteListView.ts` (`renderRow`))_
- **Accessibility attributes are the only ones a view module writes by hand.** A control with no visible label carries `aria-label` — a `placeholder` is not a label — a region that announces a failure carries `role="alert"`, and a **landmark** element grouping controls carries its own `aria-label`. A plain wrapper `div` grouping controls does not: it is structural, and labelling it would announce a group the page's outline does not have. _(read off: `src/presentation/noteComposer.ts` (`createNoteComposer`), `src/presentation/noteListView.ts` (`renderEditing`) for the labelled controls and the alert region, `src/presentation/app.ts` (`createApp`) for the landmark, `src/presentation/noteListView.ts` (`renderViewing`) for the unlabelled `note__controls` wrapper)_

## State, and the render pass

The source of truth is storage, reached through the `data` layer, and **no module here introduces a store object, an observer or a subscription to mirror it** (`.claude/context/conventions.md`, `## State, and where the truth lives`). What this layer does with that:

- **No view module holds a note.** It is handed `Note` values on each render and hands ids back through its callbacks; it does not know that a click was a write. _(read off: `src/presentation/noteListView.ts` (`NoteListCallbacks`, `render`))_
- **This layer sees entities only.** Nothing here imports from `src/data/`, names a storage key or knows the serialized shape: `NOTES_STORAGE_KEY` and the `<FIELD>_WHEN_ABSENT` constants belong to the `data` layer and `NoteRecord` never reaches a view (`.claude/context/conventions.md`, `## The layers, and the direction a dependency may point`, `## The wire surface`). The consequence here: **a value a test reads is taken off the entity**, not off anything storage-shaped — `note.updatedAt.getTime()`, not a record field. _(read off: `src/presentation/noteListView.ts` (`import type { Note }`, `renderViewing`), `src/presentation/app.ts` (imports))_
- **Which view variables a handler assigns, and whether it ends in `refresh()`, are owned by `.claude/context/conventions.md` (`## State, and where the truth lives`)** — including the licence to clear a variable another handler owns. This layer's own consequences are the two below.
- **A new region that needs remembered state adds its variable in `createApp`, not inside the region module.** A view module's own closure variables hold DOM references only, under the re-pointing rule below. _(read off: `src/presentation/app.ts` (`createApp`), `src/presentation/noteListView.ts` (`createNoteListView`))_
- **A handler that clears a variable it does not own writes the reason in a comment at the assignment**, so the next reader sees why the other region's state stopped meaning anything. _(read off: `src/presentation/app.ts` (the `FILTERS` control click handler))_
- **`refresh()` runs in one order: control tokens first, then the list.** It publishes each filter control's `selected`/`unselected` token, then calls `list.render(listNotes(filter), editingId)` — one read of the domain per pass, and what is drawn is what that read returned. _(read off: `src/presentation/app.ts` (`refresh`))_
- **A DOM reference kept between passes is re-pointed on every render and cleared at its start.** Rendering replaces rather than patches (`.claude/context/conventions.md`, `## State, and where the truth lives`), so a reference held from a previous pass points at a detached node. _(read off: `src/presentation/noteListView.ts` (`render`, `showEditError`))_
- **A view reports a failure through its own error region and never throws, and whether that region is always in the DOM follows the control it belongs to.** A region belonging to a control that is always on screen is built at construction and stays in the DOM with nothing to say, carrying `idle` (`src/presentation/noteComposer.ts` (`showError`)); a region belonging to a transient mode is built with that mode, and its reporter returns without doing anything when the mode is not drawn (`src/presentation/noteListView.ts` (`render`, `showEditError`)). Either way a `null` message returns a region that is on screen to `idle` rather than removing it, and which error is the user's to fix is decided in `src/presentation/app.ts` alone (`.claude/context/conventions.md`, `## Errors and logging`). **No logging call is written here** — there is no logger, and introducing one or the first `console` call under `src/` is a supervised decision (same owner). _(read off: `src/presentation/noteComposer.ts` (`showError`), `src/presentation/noteListView.ts` (`renderEditing`, `render`, `showEditError`), `src/presentation/app.ts` (`createApp`))_
- **A fixed set of view options is a module-scope `ReadonlyArray` beside the module that renders it** (`.claude/context/conventions.md`, `## Where a new responsibility goes`). The consequence here: **adding a filter option is three places, not two** — an entry in `FILTERS`, its member in the `NoteFilter` union, and its arm in the matching expression in `listNotes`, which the `domain` layer owns. A member added without that arm falls into the not-archived branch, draws the wrong notes and still typechecks. _(read off: `src/presentation/app.ts` (`FILTERS`), `src/domain/note.ts` (`NoteFilter`), `src/domain/notesService.ts` (`listNotes`))_

## Registering a new region — every place, in order

The app is one mounted surface: `index.html` holds `#app`, `src/main.ts` mounts `createApp()` into it, and this layer has **no router, no route table, no screen registry and no navigation module** — introducing navigation is a supervised decision, not a task's (`.claude/context/conventions.md`, `## Where a new responsibility goes`). So a new region is reachable only if all of these are done:

1. **The module** — `src/presentation/<camelCase>.ts`, exporting its `create<Thing>` factory and handle interface.
2. **The import and construction** in `src/presentation/app.ts`, inside `createApp`, with its callbacks written there.
3. **The append** — added to the `root.append(…)` call. A region constructed but never appended compiles, typechecks and shows nothing; this is the omission that ships a finished region invisible.
4. **The refresh** — driven from `refresh()` if it displays note data, so it is redrawn from the same single read as everything else.
5. **The style rules** — its BEM classes in `styles.css`, including any `[data-qa-status='…']` selector its states need.
6. **The test surface** — a `data-qa-id` on every element a test drives, a `data-qa-status` token on anything a test must wait for, and a scenario in the run's own UI test plan under `sdlc-harness/ui_test_plans/<branch>/`.

No teardown step follows: a region is built once inside `createApp` and stays for the life of the page, so nothing has to be unregistered.

_(read off: `src/presentation/app.ts` (`createApp`), `src/main.ts`, `index.html` (`<div id="app">`), `styles.css` (`.filters`))_

**What accompanies a new control inside an existing region:** an id, a status token if a test waits on it, the CSS rule for any state it shows, and the UI-test-plan scenario. Not a unit test: this layer is not covered by the `node:test` suite and is verified in the interactive QA phase, which `.claude/context/conventions.md` (`## The testing bar`) owns — as it owns the test-runner and doubles idiom, and the commit-message policy that governs the commit this change lands in.

## One example — the shape a rule takes here

```ts
const archive = button('note-archive', note.archived ? 'Restore' : 'Archive', 'note__control');
// The token is the state the note is *in*, so a test reads a row's condition off it; the
// label is the action, which is the opposite word.
setQaStatus(archive, note.archived ? 'archived' : 'active');
archive.addEventListener('click', () => callbacks.onArchiveToggled(note.id, !note.archived));
```

One control, five of this file's rules at once: built by a local closure helper rather than a repeated block; published through `qaAttrs.ts` with a surface-prefixed id shared by every row; label is the action and token is the state; the boolean handed back is the state the row is asking to move **to**; and the handler calls a callback and does nothing else — no write, no DOM patch, no listener to remove later. _(read off: `src/presentation/noteListView.ts` (`renderViewing`))_

## Not determined

- No numeric size threshold for a module in this layer is fixed anywhere in the tree — no linter or size configuration is committed and no source states one — so the review contract above rests on the one-region rule rather than on a count a reviewer can cite. A number stated here, or a lint rule that enforces one, settles it.
- The vocabulary of `data-qa-id` tokens and `data-qa-status` tokens is not stated anywhere: `QaAttrs.status` is a free `string` and `QaAttrs.id` likewise, so nothing stops a new module coining a synonym for an existing token or suffixing an input id where a sibling does not. This one reason covers both the status-token vocabulary and the id-suffix question. A token and id vocabulary written into this file, or union types on `QaAttrs`, settles both.
- Whether a region other than the list may keep a DOM reference across renders at all: the pattern observed is a reference re-pointed on each render and cleared at the start of the pass, and no source in the tree says whether that is the intended idiom or the one case that needed it. A rule stated here, or a second region adopting or refusing the pattern, settles it.
- Where a listener or timer reaching **outside** a region's own subtree would be released: the pattern observed is that a listener is attached to a node the region itself created, so `render` replacing that node is the whole of its release, and a region handle exposes no teardown method the wiring could call. Nothing in the tree says whether reaching outside the subtree is permitted at all. A teardown method on a region handle, or a rule stated here, settles it.
