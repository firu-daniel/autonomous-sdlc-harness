# Cross-layer conventions

> **Read this when:** you are implementing, reviewing or planning **any** change to notes-app — these rules hold in every layer, and this file is also the `general` layer's own document (`harness.config.json`, the `general` entry, path `.`). **Skip when:** never; every other context file assumes this one has been read.

**Purpose.** The rules a change must satisfy whichever layer it lands in, and the vocabulary the harness uses to talk about this project.

## The stack, in the words this project uses

- **Language and module system.** TypeScript under `strict: true`, targeting `ES2022`, compiled by `tsc` from `src/` to `dist/`; `package.json` declares `"type": "module"` and TypeScript as the only dependency. There is no UI framework, no state-container library, no bundler and no runtime dependency: the surface is hand-written DOM built with `document.createElement`. Adding a framework or a runtime dependency is not a task's to decide: raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as part of the change. _(read off: `package.json` (`devDependencies`), `tsconfig.json` (`compilerOptions.strict`), `src/presentation/app.ts` (`createApp`))_
- **An import specifier carries the extension of the file that is actually resolved at runtime**, never none, because `module`/`moduleResolution` are `NodeNext`. In `.ts` source that is always the compiled `.js`, including for a sibling in the same directory. In an `.mjs` test it is `.js` for anything reached through `dist/` and `.mjs` for a sibling helper under `test/helpers/`, which ships as source and is never compiled — the extension follows the resolved file, not the importing one. A type-only import uses `import type`, or the inline `type` modifier inside a mixed import. _(read off: `tsconfig.json` (`compilerOptions.module`), `src/domain/noteMapper.ts` (`import { PINNED_WHEN_ABSENT, UPDATED_AT_WHEN_ABSENT, type NoteRecord }`), `test/notesService.test.mjs` (`import { installStorageDouble } from './helpers/storageDouble.mjs'`, `await import('../dist/domain/notesService.js')`))_
- **Named exports only.** No module has a default export, and a new one does not introduce the first. _(read off: `src/domain/notesService.ts`, `src/presentation/qaAttrs.ts`)_
- **Test runner.** `node:test` with `node:assert/strict`, run by `npm test` over `test/*.test.mjs`. _(read off: `package.json` (`scripts.test`), `test/notesStore.test.mjs`)_

## The layers, and the direction a dependency may point

The names below are the ones in `harness.config.json`; the orchestrator assigns every task to exactly one of them.

- **`data` — `src/data`.** The persistence shape and the browser-storage gateway. `src/data/noteRecord.ts` owns the persisted `NoteRecord` interface, its runtime guard `isNoteRecord`, and every constant the rest of the project shares about storage: the key it owns (`NOTES_STORAGE_KEY`), and — for each field the record may omit — the constant that names what that absence means, declared beside the field and named `<FIELD>_WHEN_ABSENT` (`PINNED_WHEN_ABSENT`, `UPDATED_AT_WHEN_ABSENT` are the shape to copy). `src/data/notesStore.ts` owns `readAll` and `writeAll` and is the **only** file in the project that touches `localStorage`; a second one is a defect. Nothing under `src/data/` may import from `src/domain/` or `src/presentation/`. _(read off: `src/data/notesStore.ts` (`readAll`, `writeAll`), `src/data/noteRecord.ts` (`NOTES_STORAGE_KEY`, `UPDATED_AT_WHEN_ABSENT`))_
- **`domain` — `src/domain`.** The entities the app talks in and every business rule. `src/domain/note.ts` owns `Note` and `NoteFilter`; `src/domain/noteMapper.ts` owns `toNote`/`toRecord` and is the **only** file that converts between the storage shape and the entity; `src/domain/notesService.ts` owns one exported function per thing a user can do, the error class those functions raise (`ValidationError`), and **the argument types those functions take** — a patch or options type belonging to one action is exported beside the action rather than added to `note.ts`, which holds entities. `NotePatch`, which `editNote` takes, is the shape to copy. It may import from `src/data/` and must not import from `src/presentation/`. _(read off: `src/domain/noteMapper.ts` (`toNote`, `toRecord`), `src/domain/notesService.ts` (`ValidationError`, `NotePatch`, `editNote`))_
- **`presentation` — `src/presentation`.** The DOM. `src/presentation/app.ts` (`createApp`) is the **only** module here that may import `../domain/notesService.js`; the view modules `noteComposer.ts` and `noteListView.ts` are handed data and callbacks and call no business function themselves. A view module may import domain **types** (`../domain/note.js`) — that is the boundary: types cross freely, behaviour crosses at `app.ts`. Nothing here may import from `src/data/`. _(read off: `src/presentation/app.ts` (`createApp`), `src/presentation/noteListView.ts` (`createNoteListView`, `import type { Note }`))_
- **`tests` — `test`.** The `node:test` suite and its helpers. It imports the **compiled** modules from `dist/`, never `src/`. _(read off: `test/notesService.test.mjs` (`await import('../dist/domain/notesService.js')`))_
- **`general` — `.`.** Everything the layers do not own: `src/main.ts`, `index.html`, `styles.css`, `tools/`, and the toolchain manifests. Its rules are in `## The `general` layer` below.

**The direction is inward-only: `presentation` → `domain` → `data`.** An import pointing the other way is a defect however small, because it makes the inner layer unusable without the outer one.

## How a change flows, and the order files are created in

A feature is built inner-first, so a half-built tree still compiles and still tells the truth:

1. **`src/data/noteRecord.ts`** — the field on `NoteRecord` and its clause in `isNoteRecord`. Whether that field is optional, and the constant that names what its absence means, are owned by `.claude/context/data-layer.md` (`## The persisted shape`); this step is where they land.
2. **`src/domain/note.ts`** — the entity's own version of the field, in whatever shape reads best in code.
3. **`src/domain/noteMapper.ts`** — both directions. An optional record field becomes a required entity field here, and the default is resolved here and nowhere else.
4. **`src/domain/notesService.ts`** — the action, as one exported function, with the rule it enforces and any argument type it needs.
5. **`src/presentation/`** — the view module, then its wiring in `app.ts`.
6. **`test/`** — the cases (see `## The testing bar`).

_(read off: the layer headers of `src/data/noteRecord.ts`, `src/domain/noteMapper.ts` and `src/presentation/app.ts`, and the import graph above)_

## Where a new responsibility goes

- **A new thing a user can do** is a new exported function in `src/domain/notesService.ts`, not a branch inside an existing one.
- **A new persisted field** follows the order above; nothing outside `noteMapper.ts` may construct the entity shape from a record.
- **A rule about *when* a persisted field moves belongs to the action that moves it**, not to the read-modify-write helper the actions share: `editNote` stamps `updatedAt` in its own `change` callback because `setArchived` and `setPinned` share `update` and neither is an edit. A rule pushed down into the shared helper silently applies to every action that will ever use it. _(read off: `src/domain/notesService.ts` (`editNote`, `update`))_
- **A new region of the screen** is a new module in `src/presentation/` exporting a `create<Thing>(…)` factory that returns a `<Thing>` interface with a `readonly element` and the methods `app.ts` will call. A region with several things to report takes a **callbacks object**, whose members are named `on<Noun><PastParticiple>` or `on<Noun>Requested` — `onEditSaved`, `onPinToggled`, `onDeleteRequested` — and a boolean argument on a toggle is **the state the caller is asking to move to**, never the current one. A region with one thing to report takes that single callback as a plain parameter instead, named for the event rather than the noun: `createNoteComposer(onSubmit)`. _(read off: `src/presentation/noteListView.ts` (`NoteListCallbacks`, `onArchiveToggled`), `src/presentation/noteComposer.ts` (`createNoteComposer`))_
- **A helper wanted by more than one layer** has nowhere to go: there is no `src/shared/` or `src/util/` directory, and creating one is not a task's to decide — raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as a side effect of a change. **A helper used by more than one module inside `src/presentation/` is its own module in that directory**, and `src/presentation/qaAttrs.ts` is the shape to copy: named exports, no import from another layer, and nothing done at import time. _(read off: the directories under `src/`, `src/presentation/qaAttrs.ts` (`qa`))_
- **A registry** — a fixed set of view options — lives beside the module that renders it, as a module-scope `ReadonlyArray` of objects; `FILTERS` in `src/presentation/app.ts` is the shape to copy. There is no router, no route table and no screen registry: the app is one mounted surface, and introducing navigation is not a task's to decide — raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as part of the change. _(read off: `src/presentation/app.ts` (`FILTERS`), `index.html`)_

## State, and where the truth lives

- **The source of truth for shared state is `localStorage`, reached only through `src/data/notesStore.ts`.** There is no in-memory store, no observer and no subscription: view state lives as closure variables inside `createApp` — the active filter and the id of the row being edited. **A handler assigns every view variable its own action invalidates — the one it owns, and any other whose value that action leaves pointing at nothing — and then calls `refresh()`.** Clearing another handler's variable is the rule, not a trespass, wherever the change removes what that variable referred to; the reason goes in a comment at the assignment. The filter control is the shape: it sets `filter`, then clears `editingId`, because a row being edited under one filter has no row to return to under another. A handler whose action changes nothing about what the surface is showing *itself* — an archive, a pin, a delete — assigns nothing and calls `refresh()` alone. _(read off: `src/presentation/app.ts` (`createApp`, `onEditRequested`, `onArchiveToggled`, the `FILTERS` control click handler, `refresh`))_
- **A handler whose domain call *completed* ends in `refresh()`; a handler whose call raised a `ValidationError` reports it through the view's own error region and does *not* refresh**, so the typed draft or the open edit row survives to be corrected. Refreshing on the rejected path would redraw the list from storage and discard what the user was fixing. _(read off: `src/presentation/app.ts` (`onEditSaved`, the `createNoteComposer` callback))_
- **`refresh()` re-reads the whole list through `listNotes(filter)`, and no handler patches the DOM from what a domain call returned.** What is on screen is what storage returned on the last read; a handler that renders its own return value instead is a defect. _(read off: `src/presentation/app.ts` (`refresh`, `onEditSaved`), `src/domain/notesService.ts` (`listNotes`))_
- **Rendering replaces, it does not patch.** `render` rebuilds every row through `replaceChildren`. _(read off: `src/presentation/noteListView.ts` (`render`))_

## The wire surface

`NoteRecord` (`src/data/noteRecord.ts`) is the serialized shape; `Note` (`src/domain/note.ts`) is the in-language entity. **A serialized field name is identical to the in-language property name** — no renaming, no snake_case, no mapping table — and the difference between the two types is carried by **type**, not by name: `createdAt` is epoch milliseconds on the record and a `Date` on the entity, `pinned` is optional on the record and required on the entity, `updatedAt` is optional epoch milliseconds on the record and a required `Date | null` on the entity. Widening that gap to a name change would put a second thing in the mapper that is not a type change. _(read off: `src/data/noteRecord.ts` (`NoteRecord`), `src/domain/note.ts` (`Note`), `src/domain/noteMapper.ts` (`toNote`))_

**An optional record field is a compatibility surface, and it stays one in both directions.** A record read back is never repaired on the way in: an absent key stays absent in the record, and `toNote` is where the absence becomes the entity's value. On the way out, `toRecord` decides per field which of two things it writes, and the choice is stated with the field — the substituted value, so every rewritten record carries the key explicitly (`pinned`), or `undefined`, which `JSON.stringify` omits, so a note whose state has no instant behind it stays keyless however often it is rewritten (`updatedAt`). The second is required wherever absence is a *meaning* rather than a missing default: inventing a value there records something that never happened. _(read off: `src/data/noteRecord.ts` (`isNoteRecord`, `UPDATED_AT_WHEN_ABSENT`), `src/domain/noteMapper.ts` (`toNote`, `toRecord`))_

**Anything read back out of storage is `unknown` until a type guard says otherwise.** No file uses `any`. Which single type assertion a guard may make, and where, is owned by `.claude/context/data-layer.md` (`## The persisted shape`) — the guards live in that layer — and is not restated here. What the gateway absorbs and what it raises — including what becomes of an element the guard rejects — is owned by `.claude/context/data-layer.md` (`## Failure, as a caller sees it`) and is not restated here. _(read off: `src/data/notesStore.ts` (`readAll`), `src/data/noteRecord.ts` (`isNoteRecord`))_

## Test attributes, and the helper that writes them

The interactive test phase (`harness.config.json`, `qa.driver: web-playwright`) locates elements by **`data-qa-id`**, waits on **`data-qa-status`** and reads **`data-qa-value`**. Three attribute names and no fourth.

**Every one of them is written through `src/presentation/qaAttrs.ts`** — `qa(element, { id, status?, value? })` on a freshly created element, `setQaStatus` and `setQaValue` afterwards — and **never with a hand-written `setAttribute('data-qa-…')`**; that prohibition is a rule in its own right, and it is what keeps the convention checkable. The check is `grep -rn "addEventListener" src/presentation/` against `grep -rn "qa(" src/presentation/`: a listener on an element that never went through the helper is a control nobody can drive. Grepping the literal `data-qa-id` is **not** that check — because every attribute goes through the helper, that literal matches `src/presentation/qaAttrs.ts` and nothing else; the same file's header still states the older comparison, and the helper-call grep is the one to run. The only attributes set directly in a view module are accessibility ones (`aria-label`, `role`). _(read off: `src/presentation/qaAttrs.ts` (`qa`, `setQaStatus`, `setQaValue`), `src/presentation/app.ts` (`qa(document.createElement('button'), { id: entry.id })`), `src/presentation/noteComposer.ts` (`aria-label`))_

Three rules on the tokens themselves:

- **A status token names the state the element is *in*, and the label names the action** — the archive control reads `data-qa-status="active"` while its label says `Archive`. _(read off: `src/presentation/noteListView.ts` (`renderViewing`))_
- **A `data-qa-value` carries the machine form of what is shown, never the rendered one.** The edited stamp publishes epoch milliseconds while its text is a `toLocaleString()` rendering, because only the stored number reads back the same on every machine and in every zone. _(read off: `src/presentation/noteListView.ts` (`renderViewing`), `src/domain/note.ts` (`Note`))_
- **A region a test reads stays in the DOM when it has nothing to say**, carrying the token for that state — `status="idle"` for an error region, `status="never-edited"` for a stamp there is none of — rather than being removed on success: a removed element has no state to wait on. Where that state should not be *seen*, it is hidden in `styles.css` on a selector keyed to the token, never omitted by the view. _(read off: `src/presentation/noteComposer.ts` (`showError`), `styles.css` (`.note__edited[data-qa-status='never-edited']`))_

Per-feature assertions for a run belong in that run's own UI test plan under `sdlc-harness/ui_test_plans/<branch>/`, not in `.claude/qa_test_scenarios.md`, which holds the project's scenario rules and is the operator's.

## Errors and logging

- **A layer that raises an error a caller may distinguish defines its own named class**, extending `Error` and setting `this.name` to the class name in the constructor: `StorageWriteError` for a write that did not land (carrying the underlying failure as `cause`), `ValidationError` for input that breaks a domain rule. **A precondition no caller catches raises a bare `Error`** whose message names the app and the missing thing — the mount guard in `src/main.ts` is the shape; a named class there would add a type nothing ever narrows on. _(read off: `src/data/notesStore.ts` (`StorageWriteError`), `src/domain/notesService.ts` (`ValidationError`), `src/main.ts`)_
- **A validation failure is checked before anything is written**, so a rejected input leaves storage untouched. _(read off: `src/domain/notesService.ts` (`addNote`, `editNote`, `update`))_
- **The surface catches only the error class it can ask the user to fix, and rethrows every other**: `if (!(error instanceof ValidationError)) throw error;`. Swallowing a `StorageWriteError` would tell the user a note was saved that was not. _(read off: `src/presentation/app.ts` (`createApp`))_
- **What the storage gateway absorbs and what it raises is owned by `.claude/context/data-layer.md` (`## Failure, as a caller sees it`)** and is not restated here; the cross-layer half is the two rules above — each layer's own error class, and a surface that catches only what the user can fix.
- **There is no logger and no logging call anywhere under `src/`.** Failures travel as thrown errors or as a `data-qa-status` token the user and the test both read. `console` is used only in `tools/dev-server.mjs`, which is dev tooling and not shipped. Introducing a logger — or the first `console` call in `src/` — is not a task's to decide: raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as part of the change. _(read off: `src/`, `tools/dev-server.mjs`)_

## The testing bar

`npm test` runs `pretest` first, which builds `dist/`, so **a change to `src/` is invisible to a test run that did not rebuild**. Both harness commands must pass before a change counts as done: `bash scripts/typecheck.sh` and `bash scripts/test.sh` (`harness.config.json`, `commands`).

The idiom:

- **A test file is named `test/<module under test>.test.mjs`**, plain ESM, and imports the **compiled** module from `dist/` — Node cannot load the `.ts` source. _(read off: `test/notesStore.test.mjs`)_
- **There is no mocking library.** A collaborator is replaced by a hand-written double in `test/helpers/`, exported as an `install<Thing>Double()` factory that returns a handle, and **installed before the module under test is imported** — which is why the module under test arrives through a dynamic `await import` at the top of the file rather than a static one. A helper does nothing at import time. _(read off: `test/helpers/storageDouble.mjs` (`installStorageDouble`), `test/notesService.test.mjs`)_
- **State is reset between cases** with `beforeEach(() => storage.reset())`. _(read off: `test/notesService.test.mjs`)_
- **A test name is a sentence about behaviour**, subject first: `'addNote rejects a blank title and persists nothing'`. _(read off: `test/notesService.test.mjs`)_
- **An assertion about what was persisted reads the raw stored value**, bypassing the gateway, so the test cannot pass on a gateway that never wrote. _(read off: `test/notesService.test.mjs` (`stored`), `test/helpers/storageDouble.mjs` (`getRaw`))_
- **A case that must distinguish correct code from a plausible wrong version says so in a comment, and is built so that it can.** Two shapes recur: reading a mapped field back through `listNotes` rather than through a mutator, because a mutator's `change` callback overwrites the field after `toNote` ran; and seeding a stamp far in the past rather than one the setup just wrote, because a mis-placed restamp lands in the same millisecond as the edit that set it up. _(read off: `test/notesService.test.mjs` (`seedEditedLongAgo`, `prePinningRecord`))_

What accompanies a new unit:

- **A new exported function in `src/data/` or `src/domain/` ships with cases in the suite file that exercises its module** — the matching `test/<module>.test.mjs` where the module has one, and otherwise the test file of the module that calls it, exercising the new function through that caller. Adding the matching test file instead is always allowed and never required by a rule here; what is required is that the function be reachable from a case in the suite. The cases cover the happy path, the not-found or rejected path **and** what that path left in storage — a no-op must be asserted to have written nothing. _(read off: `test/notesService.test.mjs`, `test/notesStore.test.mjs`, `package.json` (`scripts.test`))_
- **A new field crossing the mapper** ships with cases in both directions, including a record written before the field existed and a rewrite of such a record, asserting what the rewrite left in storage — a field whose absence carries a meaning is asserted still absent afterwards. A case driven through a caller states in a comment why the caller's own return value cannot stand in for the mapper's. _(read off: `test/notesService.test.mjs` (`prePinningRecord`, `preUpdatedAtRecord`))_
- **A new clause in `isNoteRecord` ships with the rejection cases it adds**, one per way the value can fail the clause — the wrong type and, for a number, the non-finite value — each asserting that the offending record is dropped and its siblings survive. _(read off: `test/notesStore.test.mjs`, `src/data/noteRecord.ts` (`isNoteRecord`))_
- **A new presentation control** ships with a `data-qa-id`, a `data-qa-status` token if a test has to wait on it, and a scenario in the run's UI test plan. There is no DOM test harness in this project and `src/presentation/` is not covered by the `node:test` suite — the project installs a compiler alone, and every suite file imports from `dist/data/` and `dist/domain/` only — so a presentation change is verified through the interactive QA phase, and adding a DOM test runner is not a task's to decide: raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as part of the change. _(read off: `package.json` (`devDependencies`, `scripts.test`), `test/notesService.test.mjs`, `test/notesStore.test.mjs`, `harness.config.json` (`phases.qa`))_

## The `general` layer

- **`src/main.ts` stays directly under `src/` and does nothing but mount.** `rootDir: "src"` is what emits it at `dist/main.js`, the path `index.html` loads; moved into a layer directory it emits elsewhere, the page loads nothing, and the build still exits 0. _(read off: `src/main.ts`, `tsconfig.json` (`compilerOptions.rootDir`), `index.html`)_
- **A static asset the page fetches lives at the repository root beside `index.html`, never under `src/`.** `tsc` compiles `.ts` and copies nothing else, and there is no bundler, so an asset under `src/` never reaches `dist/` and 404s under `npm run dev`; the dev server's static root is the repository root, which is what makes `./styles.css` and `./dist/main.js` resolve from the same place. _(read off: `styles.css` (file header), `tools/dev-server.mjs` (`ROOT`), `tsconfig.json` (`include`))_
- **All styling lives in `styles.css`.** A module sets `className` and never an inline `style`, and there is no theme accessor and no design-token module in TypeScript. _(read off: `styles.css`, `src/presentation/noteListView.ts` (`renderRow`))_
- **Shared colours and the base spacing unit are `:root` custom properties in `styles.css`** — `--gap`, `--line`, `--muted`, `--danger` — and a rule that needs one reads it back through `var(…)` rather than re-declaring the value. A value used at one site only is written as a literal instead of becoming a token: `.note--pinned` takes `body`'s own `#1c1c1c`. _(read off: `styles.css` (`:root`, `.note--pinned`))_
- **Class names are BEM**: `block`, `block__element`, `block--modifier`. _(read off: `styles.css` (`.note__title`, `.note--pinned`))_
- **Text is set with `textContent`.** No module assigns `innerHTML` or inserts markup as a string. _(read off: `src/presentation/noteComposer.ts`, `src/presentation/noteListView.ts`)_
- **User-facing strings are literals at their use site.** There is no localization accessor and no message catalogue; the app is single-locale (`index.html`, `lang="en"`). Introducing localization is not a task's to decide: raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as part of the change. _(read off: `index.html`, `src/presentation/app.ts`)_
- **Dev tooling under `tools/` has zero dependencies** and is plain `.mjs`; the project installs a compiler and nothing else. `tools/dev-server.mjs` takes its port from `HARNESS_DEV_SERVER_PORT` and treats a taken port as fatal rather than moving. _(read off: `tools/dev-server.mjs`, `package.json` (`devDependencies`))_
- **`sdlc-harness/`, `scripts/` and `githooks/` are harness-generated and are not this project's source.** No rule here is read off them, and a task does not edit them to make a build pass. _(read off: `harness.config.json` (`stateDir`, `scriptsDir`, `githooksDir`))_
- **This project's own `.gitignore` rules go below the managed block, never inside it.** The generated block covers the harness's own machine-local paths and is extended from above by a re-run; `dist/` and `node_modules/` are this project's to supply. _(read off: `.gitignore`, `tsconfig.json` (`compilerOptions.outDir`))_

## Commit-message policy

This section is the whole of what the committer reads from this document.

- **Prefix vocabulary: `chore` alone, and only where the dispatching flow supplies it.** A subject this project writes for itself — a code commit, a manifest change — carries **no** type prefix: no `feat:`, no `fix:`, no `chore:`. It is a bare imperative sentence: `Ignore this project's build output and dependency tree`. Where a flow commit point passes a `commit_prefix`, the value is `chore` and the committer emits it as given. **The prefix therefore does not tell code from artifact** — a review-fix commit carries `chore:` and touches `src/` or `test/` — so read the staged paths, not the prefix. _(read off: `git log --format='%s'` with `git show --stat` on the prefixed subjects)_
- **The first word after any prefix is capitalized**, and the subject carries no trailing period. _(read off: `git log --format='%s'`)_
- **Subject-length cap: 72 characters.** A subject that will not fit moves its detail into the body. _(read off: `git log --format='%s'`)_
- **Body: optional, and when present it says *why*, not *what*** — the diff already says what. It is separated from the subject by a blank line. _(read off: `git log --format='%b'`)_
- **Attribution trailer: forbidden.** No `Co-Authored-By:`, no agent-naming trailer, on any commit — a code commit or a flow-artifact one. _(read off: `git log --format='%b'`)_
- **Fixed-form subjects — exempt from the capitalisation rule and from the length cap, and passed byte-for-byte.** Each is emitted verbatim by the commit point that owns it, substituting `<branch>`, `<entry-id>` and `K` (the UI test number); a policy that re-cases or truncates one breaks that commit point.

  - `chore: Add task plan for <branch>`
  - `chore: Add UI-test plan for <branch>`
  - `chore: Add flow-progress ledger for <branch>`
  - `chore: Flow progress <entry-id> for <branch>`
  - `chore: Add branch statistics for <branch>`
  - `chore: Update branch statistics for <branch>`
  - `chore: Add user-review fix plan for <branch>`
  - `chore: Log dispatch additions for <branch>`
  - `chore: Log improvement observations for <branch>`
  - `chore: Record clarification digest for <branch>`
  - `chore: add code review for <branch>`
  - `chore: Mark UI test K passing for <branch>`
  - `chore: add task prompt for <branch>`
  - `chore: add docs checklist for <branch>`

  **Three of these are emitted lower-case** — `chore: add code review for <branch>`, `chore: add task prompt for <branch>` and `chore: add docs checklist for <branch>` — and every subject in the list, whatever its casing, is passed byte-for-byte.
