# Tests

> **Read this when:** you are adding, moving or rewriting a file under `test/`, or changing behaviour in `src/data/` or `src/domain/` that a case there protects. **Skip when:** the change touches only `src/presentation/`, `index.html` or `styles.css` — this suite drives no DOM — or only the harness-generated `scripts/`, `githooks/` and `sdlc-harness/` trees.

**Purpose.** How the suite under `test/` is laid out, what a case may reach for, and the in-file shape a new case copies.

The cross-layer testing bar is owned by `.claude/context/conventions.md` (`## The testing bar`) and is not restated here: the rule that a test imports the **compiled** module from `dist/`, the hand-written-double idiom and its `install<Thing>Double()` factory, the reset-between-cases rule, the "a test name is a sentence about behaviour" rule, the raw-read persistence assertion, the rule that a case which must distinguish correct code from a plausible wrong version says so in a comment and is built so that it can, and what a new unit must ship with. The runner and the assertion library themselves are named in `.claude/context/conventions.md` (`## The stack, in the words this project uses`), not in that section. This file is what all of it costs inside `test/`.

## The tree

- **Every automated test is a file directly in `test/`.** `package.json` (`scripts.test`) hands the runner a one-level shell glob, `test/*.test.mjs`; a test file placed in a subdirectory of `test/` is never expanded into that argument list, never runs, and leaves a green run that asserted nothing. _(read off: `package.json` (`scripts.test`))_
- **The tree does not mirror `src/`'s layer directories.** A file is named for the module under test alone, and the layer that module lives in appears in neither the path nor the name — the file-name pattern itself is owned by `.claude/context/conventions.md` (`## The testing bar`). _(read off: `test/notesService.test.mjs`, `test/notesStore.test.mjs`)_
- **No test file lives beside the source it covers.** A test written under `src/` falls outside the runner's `test/*.test.mjs` glob and never runs; and `tsconfig.json` compiles `src/` into `dist/` (`rootDir: "src"`, `outDir: "dist"`, `include: ["src"]`), so a `.ts` one there is emitted into the build output the page loads its module from. _(read off: `package.json` (`scripts.test`), `tsconfig.json` (`include`, `rootDir`, `outDir`), `index.html`)_
- **Machinery shared by more than one test file is its own module under `test/helpers/`, named `<camelCase>.mjs`, and does nothing at import time.** A fixture used by a single file stays in that file. `test/helpers/` is outside the runner's glob, so a case written there does not run. _(read off: `test/helpers/storageDouble.mjs` (`installStorageDouble`), `package.json` (`scripts.test`))_
- **A specifier inside `test/` carries the extension of the file it actually resolves to** — `.js` for a compiled module under `dist/`, `.mjs` for a sibling helper — because nothing compiles this tree and Node resolves the literal path. `.claude/context/conventions.md` (`## The stack, in the words this project uses`) states the `.js` half as the general rule; the helper import is where it reads as the real extension rather than the compiled one. _(read off: `test/notesService.test.mjs` (`'./helpers/storageDouble.mjs'`, `'../dist/domain/notesService.js'`))_
- **The suite is not type-checked.** `npm run typecheck` is `tsc --noEmit` over `include: ["src"]`, so a `.mjs` file's only declared contract is its JSDoc: a helper's returned handle is documented inline on `@returns` rather than left to the call sites. _(read off: `tsconfig.json` (`include`), `package.json` (`scripts.typecheck`), `test/helpers/storageDouble.mjs` (`@returns`))_

## What a case may reach

- **A case runs entirely in-process.** No network, no filesystem, no timers, no environment variables, no real clock control: the only thing a test replaces is browser storage. Reaching outside the process is not a task's to decide — raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as part of the change. _(read off: `test/` — no `node:fs`, `node:http`, `fetch`, `setTimeout` or `process.env` occurrence in the suite)_
- **`globalThis.localStorage` is the only global the suite installs**, and `installStorageDouble` is the only thing that installs it. Patching a second global is not a task's to decide either — raise it for supervised follow-up (a `/harness-analyze` re-run or a hand edit), never as a side effect of a case. _(read off: `test/helpers/storageDouble.mjs` (`globalThis.localStorage`))_
- **A storage key is imported from the compiled module that owns it, never spelled as a string literal in a test** — `const { NOTES_STORAGE_KEY } = await import('../dist/data/noteRecord.js')`. A literal would keep passing after the key is renamed. _(read off: `test/notesService.test.mjs`, `test/notesStore.test.mjs`)_
- **The value an absence resolves to is written as a literal in the assertion, not imported from the constant that names it.** A case pinning what `PINNED_WHEN_ABSENT` or `UPDATED_AT_WHEN_ABSENT` means asserts `false` and `null` outright; importing the constant would make the case agree with whatever the constant is changed to, which is the change the case exists to catch. The rule is the opposite of the storage-key one above because the claim is opposite: the key is an identifier the test does not care about, the default is the behaviour the test is about. _(read off: `test/notesService.test.mjs` (`a record written before updatedAt existed reads back as never edited`, `addNote starts a note unpinned, in the entity and in storage`), `.claude/context/conventions.md` (`## The layers, and the direction a dependency may point`))_
- **A shape the gateway itself would never write is seeded raw**, through the double's `setRaw`, so the case under test is the only code that has to accept it: malformed JSON, a non-array value, a wrong-typed field, a record written before a field existed. _(read off: `test/notesStore.test.mjs` (`readAll returns [] on malformed JSON rather than throwing`), `test/notesService.test.mjs` (`prePinningRecord`))_
- **Where the value under test cannot survive a round trip through `JSON.stringify`, the record is seeded as a hand-written JSON string and a comment says why.** `JSON.stringify(Infinity)` emits `null`, which fails the guard on a different clause than the one the case is aimed at, so the literal `1e999` written into the JSON text is what actually reaches the finiteness check. _(read off: `test/notesStore.test.mjs` (`betaWithInfinity`))_
- **A collaborator failure is injected through the double's handle, never by replacing a method inside a case** — `failWrites(error)` makes every subsequent write throw the error the case constructed, so the case can assert that exact object came back as `cause`. Nothing has to undo it: the file's `beforeEach` reset re-allows writes. _(read off: `test/helpers/storageDouble.mjs` (`failWrites`, `reset`), `test/notesStore.test.mjs` (`writeAll throws StorageWriteError when the write does not land`))_
- **This suite asserts no DOM and no `data-qa-*` attribute.** Those belong to the interactive QA phase and its per-run plan, per `.claude/context/conventions.md` (`## Test attributes, and the helper that writes them`). _(read off: `harness.config.json` (`qa.driver`), `test/`)_

## The shape of a test file

- **The first line is a header comment naming the file and what the suite pins**, in the form `// <filename> — <the claim the file exists to hold>`. _(read off: `test/notesStore.test.mjs` (`the gateway's two error idioms, pinned`), `test/helpers/storageDouble.mjs`)_
- **The prologue runs in one order and nothing precedes it:** the named imports from `node:test`, the default import from `node:assert/strict`, the helper import, the double's installation at module scope, then the `await import` of each compiled module under test. The installation sits above the dynamic imports because that ordering is the whole reason the imports are dynamic. _(read off: `test/notesService.test.mjs`, `test/notesStore.test.mjs`)_
- **Cases are flat `test(...)` calls at module scope, never a `describe` block.** A group of cases is introduced by a comment saying why these cases and not others; the `// --- <what this group pins> ---` banner is the form `test/notesService.test.mjs` uses, and the parentheticals on its existing banners name the change that added the group. _(read off: `test/notesService.test.mjs` (`// --- setPinned and pinned-first listing`), `test/notesStore.test.mjs` (`The three cases below are that decision`))_
- **A fixture reused by several cases is module-scope**: a plain object literal when it is a stored record, and a factory function returning the created entities when the scenario has to be built through the API. _(read off: `test/notesStore.test.mjs` (`alpha`), `test/notesService.test.mjs` (`threeWithMiddlePinned`))_
- **A record that must fail a guard is a spread of a valid fixture with the one offending field replaced** — `{ ...beta, updatedAt: 'yesterday' }` — so the case cannot pass on an unrelated defect, and the sibling it is seeded beside is the untouched fixture. _(read off: `test/notesStore.test.mjs` (`readAll drops a record whose pinned is not a boolean and keeps its siblings`))_
- **An epoch-millisecond literal is written with `_` separators**, and a fixture that a case has to tell apart from another gets its own instant rather than sharing one. _(read off: `test/notesStore.test.mjs` (`alpha`, `beta`), `test/notesService.test.mjs` (`seedEditedLongAgo`))_
- **A derived accessor a file needs repeatedly is one arrow at module scope with a JSDoc line**, so each case reads as its claim rather than as plumbing. _(read off: `test/notesService.test.mjs` (`stored`))_
- **One double per file, shared by every case.** A case never installs its own; it seeds through the handle and relies on the file's `beforeEach` reset (owned by `.claude/context/conventions.md`, `## The testing bar`). _(read off: `test/notesService.test.mjs`, `test/notesStore.test.mjs`)_

## Assertions

- **`assert.equal` and `assert.deepEqual`, from `node:assert/strict`.** The strict module is imported so the plain names *are* the strict comparisons; the `strictEqual`/`deepStrictEqual` spellings are not written, and the loose `node:assert` is not imported. _(read off: `test/notesStore.test.mjs`, `test/notesService.test.mjs`)_
- **`assert.throws` takes the error class when the class is the whole claim, and a predicate when a field of the error is part of it** — `(error) => error instanceof StorageWriteError && error.cause === quota`. _(read off: `test/notesStore.test.mjs` (`writeAll throws StorageWriteError when the write does not land`), `test/notesService.test.mjs` (`addNote rejects a blank title and persists nothing`))_
- **An `assert.ok` over a key-presence check carries a message stating the claim; an `instanceof` one does not.** A failed `'updatedAt' in record` prints the expression and leaves the reader to work out which way it was meant to go, so the message says what the code did wrong — `'readAll invented an updatedAt the stored record did not carry'`. An `instanceof` check names the type in the expression itself and needs nothing added. _(read off: `test/notesStore.test.mjs` (`readAll keeps a record written before updatedAt existed and leaves the key absent`), `test/notesService.test.mjs` (`rewriting a record written before pinning existed gives it the field explicitly`, `addNote persists the record and returns the mapped entity`))_
- **A no-op is asserted against storage, not against the return value alone** — capture the raw value before the call and compare it after. A function that returned `false` and wrote anyway is the failure this catches. _(read off: `test/notesService.test.mjs` (`deleteNote on an unknown id returns false and leaves the store unchanged`))_
- **Where a case exists to pin a boundary rather than a behaviour, the comment says which boundary** — the entity/record split at the mapper, or the filter branch an early return would skip. _(read off: `test/notesService.test.mjs` (`// The boundary:`))_

**Rule that holds whatever the language is:** a test names the behaviour it protects, not the function it calls. A failing run is read by someone who did not write the test and may not know the code, so the name has to carry the claim — a failure should read as a sentence about the product, and a test whose name only repeats a file path leaves that reader with a search instead of an answer.

## One example from this repository

```js
// test/notesService.test.mjs
test('deleteNote on an unknown id returns false and leaves the store unchanged', () => {
  addNote('Alpha', 'first');
  const before = storage.getRaw(NOTES_STORAGE_KEY);

  assert.equal(deleteNote('nope'), false);
  assert.equal(storage.getRaw(NOTES_STORAGE_KEY), before);
});
```

The name is the claim and reads without the code. The no-op is asserted where it would actually go wrong — the raw stored value, reached past the gateway — rather than on the boolean alone. The key is the imported constant, and the setup uses the real `addNote` so the case fails if the two halves of the module stop agreeing.

## Not determined

- Whether behaviour the suite exercises only through a caller — `isNoteRecord` in `src/data/noteRecord.ts`, reached through `readAll`; `toNote` and `toRecord` in `src/domain/noteMapper.ts`, reached through `listNotes` and the service actions — is ever *wanted* to have a matching test file of its own. Where its cases go is not the open part: `.claude/context/conventions.md` (`## The testing bar`) already fixes that — cases go "in the matching `test/<module>.test.mjs` where the module has one, and otherwise the test file of the module that calls it, exercising the new function through that caller", and "Adding the matching test file instead is always allowed and never required by a rule here". What no rule settles is the preference between those two permitted placements for these modules. A rule here stating that preference, or a `test/noteMapper.test.mjs` appearing, settles it.
- Whether the suite is meant to be type-checked or coverage-measured: `tsconfig.json` includes `src` only and sets neither `allowJs` nor `checkJs`, and `package.json` (`scripts.test`) passes the runner no coverage flag; nothing in the tree says whether that is a decision or simply untouched. A `checkJs`/`allowJs` configuration reaching `test/`, a coverage flag or threshold in the test script, or a rule here, settles either half.
- Whether the double's `uninstall()` is meant to be called at the end of a file. `test/helpers/storageDouble.mjs` exports it on the handle and documents it, and no case or teardown calls it; the runner ends the process either way, so the code cannot say whether it is a contract or a leftover. A file calling it in an `after` hook, or a rule here saying the global stays installed for the process lifetime, settles it.
