# Domain layer

> **Read this when:** you are changing anything under `src/domain` — the entities the app talks in (`Note`, `NoteFilter`), the mapper that converts them to and from the stored shape, or a rule about what a note may be and what a user may do to one. **Skip when:** the change is about how notes reach `localStorage` (`src/data`, [`data-layer.md`](data-layer.md)) or how they are shown (`src/presentation`, [`presentation.md`](presentation.md)). Read [`conventions.md`](conventions.md) first either way: it owns every cross-layer rule this file points at.

**Purpose.** Where this project's rules live, what they may know about, and what must never reach them.

## The types this layer owns

- **`src/domain/note.ts` owns the entities the whole app talks in** — `Note` and `NoteFilter` — and imports nothing. A type that names a business concept goes here; a type that shapes one function's arguments stays beside that function (`NotePatch` in `src/domain/notesService.ts`). _(read off: `src/domain/note.ts` (`Note`, `NoteFilter`), `src/domain/notesService.ts` (`NotePatch`))_
- **An entity property is named exactly as the stored field is named, and differs from it only by type.** `createdAt` is a `Date` here and epoch milliseconds on the record; `pinned` is required here and optional there; `updatedAt` is `Date | null` here and optional epoch milliseconds there. A new field that needs a different *name* on the two sides is not a mapping decision this layer may take on its own — the naming rule is owned by `conventions.md` (`## The wire surface`). _(read off: `src/domain/note.ts` (`Note`), `src/domain/noteMapper.ts` (`toNote`))_
- **Optionality is a storage concern that stops at the mapper.** A field the record declares optional is declared required on the entity, and its absent-value meaning is resolved in `toNote` from the constant `src/data/noteRecord.ts` owns for that field (`PINNED_WHEN_ABSENT`, `UPDATED_AT_WHEN_ABSENT`) — never re-declared here and never resolved a second time downstream. _(read off: `src/domain/note.ts` (`Note`), `src/domain/noteMapper.ts` (`toNote`), `src/data/noteRecord.ts` (`PINNED_WHEN_ABSENT`, `UPDATED_AT_WHEN_ABSENT`))_
- **Where a state has no value behind it, the entity says so with a `null` member rather than by leaving the property off.** `updatedAt` is `Date | null` and `null` *is* the answer "never edited", so every note above this layer answers the question and no caller distinguishes a missing key from a real state. An optional property on `Note` would push that distinction into every reader. _(read off: `src/domain/note.ts` (`Note`, file header), `src/presentation/noteListView.ts` (`note.updatedAt === null ? 'never-edited' : 'edited'`))_
- **A closed set of choices is a string-literal union on the entity type**, not a boolean parameter or a free string: `NoteFilter` is `'active' | 'archived' | 'all'`. A new listing option is a new member of that union, and adding one means changing `listNotes`' own match condition: that condition derives the match from `filter === 'archived'` after a single `filter === 'all'` ternary, so a member added without touching it is silently listed as active rather than rejected. _(read off: `src/domain/note.ts` (`NoteFilter`), `src/domain/notesService.ts` (`listNotes`))_

## Where a rule is written

- **Every business rule is a function in `src/domain/notesService.ts`, written once.** The title rule is `requireTitle`, and every path that sets a title calls it — including the patch path, which routes through it rather than re-testing the string. The same rule restated in a view, in the composer's markup or in the mapper is a defect even when the observable behaviour is right: the next surface copies the nearest expression rather than the authoritative one. _(read off: `src/domain/notesService.ts` (`requireTitle`, `editNote`))_
- **A rule that normalizes returns the value to store, and its callers store the return rather than the input they passed in.** `requireTitle` returns the trimmed title, so `addNote` and `editNote` persist what the rule handed back and `"  Alpha  "` and `"Alpha"` are the same note title. Validating in one place and normalizing in another gives the second place a way to disagree. _(read off: `src/domain/notesService.ts` (`requireTitle` doc comment, "Returns the trimmed title to store"; `addNote`, `editNote`))_
- **Inside `src/domain/notesService.ts`, a helper that is not itself a thing a user can do is module-scope and unexported** — `requireTitle`, `pinnedFirst`, `update`. What that module exports is the user actions, plus the error class and the patch types those actions take. **`src/domain/noteMapper.ts` runs the other way round: it exports what `notesService.ts` calls — `toNote` and `toRecord` — and nothing beyond that.** So a second converter or a mapper helper added there for a new persisted field (step 3 of the flow `conventions.md` (`## How a change flows, and the order files are created in`) owns) is exported if the service calls it, and stays module-scope if it does not. _(read off: `src/domain/notesService.ts` (`pinnedFirst`, `update`, `ValidationError`, `NotePatch`, `import { toNote, toRecord } from './noteMapper.js'`), `src/domain/noteMapper.ts` (`toNote`, `toRecord`))_
- **Listing order is decided here, not on screen.** `listNotes` filters and then orders through `pinnedFirst` — a partition that leaves stored order intact inside each group and does not mutate its argument. A view that sorts what it was handed would be the second expression of that rule. _(read off: `src/domain/notesService.ts` (`listNotes`, `pinnedFirst`))_
- **Identity is minted here.** `addNote` sets `id` from `crypto.randomUUID()`; a caller does not supply an id and storage does not invent one. _(read off: `src/domain/notesService.ts` (`addNote`))_
- **A rule that can reject runs before any write.** `requireTitle` throws before `readAll`/`writeAll` in `addNote`, and `update` calls `change` before it persists, so a rejected input leaves storage exactly as it was. _(read off: `src/domain/notesService.ts` (`addNote`, `update`))_
- **A rule about *when* a field moves is written in the action's own `change` callback, never in `update`.** `editNote` stamps `updatedAt` itself; `setArchived` and `setPinned` hand `update` a callback that changes their own flag and nothing else, because archiving or pinning a note is not an edit of it. The placement rule is owned by `conventions.md` (`## Where a new responsibility goes`); the consequence here is that a new mutator sharing `update` decides field-by-field what it stamps, and a stamp added to `update` would restamp every action that ever uses it. _(read off: `src/domain/notesService.ts` (`editNote`, `setArchived`, `setPinned`, `update`))_
- **Removing a note works on records and never crosses the mapper.** `deleteNote` reads, splices the raw `NoteRecord` array and writes it back rather than routing through `update`: there is no surviving entity for a `change` callback to be handed, and routing it through `update` would put a sibling note through `toNote`/`toRecord` and restamp what the user never touched. _(read off: `src/domain/notesService.ts` (`deleteNote`, `update`), `test/notesService.test.mjs` ("the obvious refactor is to route it through `update` too"))_
- **This layer holds no state between calls.** Every function re-reads through `readAll()` at call time rather than caching, and a new one does not introduce a module-level mutable variable to remember what it read. The source of truth is owned by `conventions.md` (`## State, and where the truth lives`). _(read off: `src/domain/notesService.ts` (`listNotes`, `update`))_

## The unit of work a caller invokes

- **One exported function per thing a user can do, named verb-first over the noun it acts on**: `listNotes`, `addNote`, `editNote`, `setArchived`, `setPinned`, `deleteNote`. Where a new action belongs is owned by `conventions.md` (`## Where a new responsibility goes`); how it is shaped once it lands here is the rest of this section. _(read off: `src/domain/notesService.ts` (`addNote`, `setArchived`))_
- **A one-note mutator takes `id` first and returns what it persisted.** It reaches storage through `update`, which locates the record, hands `change` the mapped entity and writes what comes back — a new mutator uses it rather than repeating find-and-write. **What that return value is *for* is not settled here and is not a licence to render it:** `conventions.md` (`## Not determined`) records the contradiction between this file's header and the surface's, and `conventions.md` (`## State, and where the truth lives`) binds the caller — a handler renders what `listNotes` returned on the last read, and one that renders a mutator's return value instead is a defect. _(read off: `src/domain/notesService.ts` (`setPinned`, `update`))_
- **A boolean argument on a toggle is the state the note moves *to*, never the state it is in**: `setArchived(id, archived)`, `setPinned(id, pinned)`. _(read off: `src/domain/notesService.ts` (`setArchived`, `setPinned`))_
- **Three failure paths, and a new function picks from these three and adds no fourth.**
  - **Input that breaks a rule throws `ValidationError`**, the class this file owns, declared here with `this.name` set in the constructor. _(read off: `src/domain/notesService.ts` (`ValidationError`, `requireTitle`))_
  - **A missing target is a return value, never a throw, and writes nothing**: `undefined` from a mutator that returns the entity, `false` from `deleteNote`. _(read off: `src/domain/notesService.ts` (`update`, `deleteNote`))_
  - **A storage failure propagates.** `writeAll` raises `StorageWriteError` and nothing in this layer catches it — reporting a note as saved that did not persist is the failure this rule exists to prevent, so catching a storage error here — to log it, to soften it, or to turn it into a return value — is a defect. _(read off: `src/domain/notesService.ts` (file header, "nothing here catches it"), `src/data/notesStore.ts` (`writeAll`))_
- **A `ValidationError` message is user-facing text**: the surface passes `error.message` straight to the user. Write it as a statement of what is required, at the throw site — this layer has no message catalogue and no localization accessor to reach for (`conventions.md`, `## The `general` layer`). _(read off: `src/domain/notesService.ts` (`requireTitle`), `src/presentation/app.ts` (`composer.showError(error.message)`, `list.showEditError(error.message)`))_

## The mapping between the stored shape and the entity

- **`src/domain/noteMapper.ts` is the only converter, in both directions, and the domain side owns it.** `toNote` and `toRecord` are inverses: a field carried on both `NoteRecord` and `Note` that only one of them maps is a defect, because the other direction drops it silently. `src/data/` may not import from here, so the conversion cannot live on the storage side. _(read off: `src/domain/noteMapper.ts` (`toNote`, `toRecord`), `src/data/noteRecord.ts` (file header, "nothing in this file imports from `../domain/`"))_
- **`toRecord` chooses per field how an absence is written back, and the choice is made here rather than by the action that persisted.** A field whose absence carries a *meaning* is written as `undefined`, which `JSON.stringify` omits, so a note in that state stays keyless however often it is rewritten (`updatedAt`); a field whose absence is only a missing default is always written explicitly (`pinned`). Which of the two a field takes is owned by `conventions.md` (`## The wire surface`); this file is where the decision is expressed, so a new optional field is handled in `toRecord` and not by a caller pre-filling the entity. _(read off: `src/domain/noteMapper.ts` (`toRecord`, file header), `src/data/noteRecord.ts` (`UPDATED_AT_WHEN_ABSENT`))_
- **The mapper is pure**: it imports only types and constants — `NoteRecord`, `PINNED_WHEN_ABSENT` and `UPDATED_AT_WHEN_ABSENT` from `src/data/noteRecord.ts`, the `Note` type from this layer — and no behaviour: no `readAll`, no `writeAll`, no clock. Converting a stored `createdAt` or `updatedAt` number into a `Date`, or back with `getTime()`, happens only here; `addNote` calling `new Date()` and `editNote` stamping one are creating a timestamp, not converting one. _(read off: `src/domain/noteMapper.ts` (`import { PINNED_WHEN_ABSENT, UPDATED_AT_WHEN_ABSENT, type NoteRecord }`, `import type { Note }`, `toRecord`), `src/domain/notesService.ts` (`addNote`, `editNote`))_
- **`src/domain/notesService.ts` is the only module in this layer that calls the storage gateway.** Everything else here works on values it was handed. _(read off: `src/domain/notesService.ts` (`import { readAll, writeAll }`), `src/domain/noteMapper.ts`, `src/domain/note.ts`)_

## What may reach this layer, and what may not

- **Imports point inward only.** A module here may import from `src/data/`; nothing here may import from `src/presentation/`, touch the DOM, or reference `document`, `window` or `localStorage`. The gateway is the only door to storage. The direction rule itself is owned by `conventions.md` (`## The layers, and the direction a dependency may point`); the consequence here is that `src/domain/note.ts` imports nothing at all and the entity type stays usable on its own. _(read off: `src/domain/note.ts`, `src/domain/notesService.ts` (`import { readAll, writeAll }`))_
- **Shared constants are imported, never restated.** The storage key and the absent-value constants belong to `src/data/noteRecord.ts` (`NOTES_STORAGE_KEY`, `PINNED_WHEN_ABSENT`, `UPDATED_AT_WHEN_ABSENT`); this layer imports the one it needs. _(read off: `src/domain/noteMapper.ts` (`PINNED_WHEN_ABSENT`, `UPDATED_AT_WHEN_ABSENT`), `src/data/noteRecord.ts` (`NOTES_STORAGE_KEY`))_
- **Nothing this layer reaches for exists to be reached for**: no logger, no localization accessor, no theme or sizing accessor, no shared-component directory, no navigation module, no route or screen registry, and no `data-qa-*` attribute — those are the surface's concern or nobody's, and introducing one is not a task's to decide. Owners: `conventions.md` (`## Errors and logging`, `## Where a new responsibility goes`, `## Test attributes, and the helper that writes them`, `## The `general` layer`). _(read off: `src/domain/`)_

**Rule that holds whatever the stack is:** every rule here is exercisable with no network, no database, no filesystem and no screen — in this project that means the only collaborator a domain test has to stand in for is the storage gateway, replaced by `installStorageDouble()` from `test/helpers/storageDouble.mjs`. If a rule cannot be tested that way, it has absorbed something belonging to another layer — and the same rule restated in a screen or in a mapper is a defect even when the observable behaviour is right, because the next surface that needs it copies the nearest expression rather than the authoritative one.

## What accompanies a change here

- A new exported function in `src/domain/notesService.ts` ships with cases in `test/notesService.test.mjs`; a new field crossing `src/domain/noteMapper.ts` ships with cases in both directions, including a record written before the field existed and a rewrite of such a record. Which cases are required, and how the double is installed before the compiled module is imported, are owned by `conventions.md` (`## The testing bar`). The order files are created in for a new persisted field is owned by `conventions.md` (`## How a change flows, and the order files are created in`) — this layer is steps 2 to 4 of it.
- **A field this layer maps is asserted through a read path, not through the mutator that wrote it**, because a mutator's `change` callback overwrites the mapped value after `toNote` ran and its return value would pass on a mapper that never mapped. The idiom is owned by `conventions.md` (`## The testing bar`); the consequence here is that a mapping case reads back through `listNotes`. _(read off: `test/notesService.test.mjs` ("a mutator's `change` callback overwrites"), `src/domain/notesService.ts` (`update`, `listNotes`))_
- Both harness commands must pass, and the commit message follows `conventions.md` (`## Commit-message policy`), which is the whole of what the committer reads.

## One example — a rule and its unit of work

```ts
// src/domain/notesService.ts — the rule, stated once, over this project's own types.
export function editNote(id: string, patch: NotePatch): Note | undefined {
  return update(id, (note) => ({
    ...note,
    title: patch.title === undefined ? note.title : requireTitle(patch.title),
    body: patch.body ?? note.body,
    // Stamped here rather than in `update`: `setArchived` and `setPinned` share that helper, and
    // archiving or pinning a note is not an edit of it. `deleteNote` does not go through `update`
    // at all — it splices the raw record array and writes it back.
    updatedAt: new Date(),
  }));
}
```

Everything the shape decides is in those lines: `id` first; `undefined` for a note that is not there, from `update` and without a write; `ValidationError` from `requireTitle` — the one place the title rule is written, and the value it returns is the value stored — thrown before `update` persists anything; the stamp written in this action's own callback rather than in the helper it shares; and the mapped `Note` returned on success. Not here: how the record was read, how the message is shown, which control was pressed.

## Not determined

- Whether a `ValidationError` message has a required form — the messages are user-facing (`src/presentation/app.ts` passes `error.message` to the view verbatim), and nothing in the tree states whether the lower-case, unpunctuated wording `requireTitle` uses is a convention or an accident. A stated rule here, or a message written to a different form on purpose, settles it.
- Whether a newly mutable field on `Note` should become a `NotePatch` member or its own `set<Field>` mutator — `title` and `body` are patched through `editNote` while `archived` and `pinned` have their own functions, and no source states the criterion that separates them. A stated rule, or a field added one way with its reason recorded, settles it.
- Whether normalization applies beyond the field that has a rule — `requireTitle` trims the title, while `body` is stored exactly as the caller passed it, and no source says whether untrimmed body text is deliberate or simply unconsidered. A stated rule, or a second normalizing rule written either way on purpose, settles it.
- Where a pure rule — a calculation with nothing to persist — belongs in this layer: its own module, or a helper in `src/domain/notesService.ts`. Every exported function in `src/domain/notesService.ts` reaches the gateway, and the layer's gateway-free module is a converter (`src/domain/noteMapper.ts`), so neither placement has a rule of this kind to copy. The first such rule, or a decision recorded here, settles it.
- What a mutator's return value is **for** is open, and the open entry is `conventions.md`'s rather than this file's: the header of `src/domain/notesService.ts` says a mutator returns what it wrote "rather than making the caller re-read", while `src/presentation/app.ts` discards it and re-reads through `listNotes(filter)`. Cited here so a reader of this layer's mutator rule finds the same answer; a corrected header, or a cross-layer rule permitting a surface to render the return value, settles it.
