## The `commit_prefix` the unit loop derives is not in this project's prefix vocabulary, and two source commits took a wrong prefix from it
- **category:** convention
- **evidence:** `unit_loop_core.md` row `A` derives `commit_prefix` from the branch name (`feat_` → `feat`) and rows `C` / `E.3` prescribe `fix`/`chore` by finding nature. This project's `.claude/context/conventions.md` (`## Commit-message policy`) states its own code commits carry **no type prefix** and reserves `chore:` for harness artifact commits. All 6 Phase-A committer dispatches were passed `commit_prefix: feat` and all 6 dropped it, each spending part of its return explaining the override (`25be2c2`, `3f9413a`, `434885e`, `6f5e63f`, `35ec7d5`, `0c634a5`). Two Phase-C `review_item` dispatches were passed `commit_prefix: chore` per the row rule and the committer applied it to commits touching source: `956cc6c` (`src/domain/notesService.ts`) and `5314138` (`test/notesService.test.mjs`) — both now carry a prefix the policy reserves for artifact commits, and neither is covered by code-review Finding 2, which names only `25be2c2`.
- **cost this run:** 6 committer returns spent on the same override; 2 commits landed carrying a prefix this project's policy forbids on source commits.

## The plan writer reported two conventions rules this branch's work falsified
- **category:** tooling-gap
- **evidence:** The `task-plan-writer` return carried a `## Corpus staleness` section with two `stale-rule` entries. - **cost this run:** each owes a follow-up restatement — a hand edit to the named bullet and step, or a `/harness-analyze` re-run over `src/domain` and the repository root, answered `skip` for every already-filled document.
