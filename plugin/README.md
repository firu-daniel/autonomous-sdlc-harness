# harness (plugin)

This plugin carries the harness's process assets — the instruction cores and their thin forks, the agent definitions, the `branch-*` slash commands and the `/autonomous-sdlc-harness:harness-analyze` setup command, the tool-guard hooks declared in `hooks/hooks.json`, the helper scripts those assets invoke, and the sample plan/review fixtures that instruction and agent bodies dereference by path. Every intra-plugin reference is written `${CLAUDE_PLUGIN_ROOT}/…`, the only form that resolves under both a git-sourced install and a directory-sourced one.

The outer loop — `init`, `doctor`, `config` and `daemon` — is not here; it ships as the sibling `cli/` package.

Roadmap items 3–5 filled the asset directories: the instruction cores and forks with their first sample fixtures at item 3, the agent definitions at item 4, and the slash commands, the guard hooks and the helper scripts at item 5. Item 7 completed them — `docs/` now carries the flow document and its whiteboard companion, and `samples/` carries every fixture a shipped instruction, command or agent body dereferences: the plan trio, the code-review index with its per-finding files, the user-review pair, and the statistics report. The run-artifact tree's own prose landed with the same item but ships from the `cli/` package instead, as the templates `init` writes into the adopter's configured state directory. Item 15 added `/autonomous-sdlc-harness:harness-analyze` to `commands/`, the one command there that is not a `branch-*` entry point: the supervised first-session command that fills the conventions documents `init` writes as skeletons from the adopted repository's real code.
