### `<escalate>` / `<ask>` — the headless clarification reroute

Both bindings resolve to the **same** file-based channel and differ only in what triggers them. `<ask>` fires when the `user-review-fix-plan-writer` returns a `## Questions` section (the core's step 6). `<escalate>` fires when the flow is genuinely blocked — a gate that hit its 5-iteration cap without converging (steps 7 and 8), the core's step 2 finding no user-review file for the branch, or the `MAX_TOTAL_DISPATCHES` cap hit in `## Safety scaffolding` below. Either way you first apply the **`## Ask-vs-assume policy`** below: a question file is written only when that policy says *ask*.

The clarification-channel file format (`<state_dir>/clarifications/<branch>/question_<n>.md` ↔ `answer_<n>.md`, one file per park, self-containment requirements, indexing, the consume-then-archive contract) is canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_autonomous.md` → `## Clarification channel — file format`. Reference it — do **not** restate it. `clarifications/` **is** part of the run-artifact tree `init` materializes and carries its own committed `README.md`; the question and answer files inside it are machine-local and created on first write.

- **Headless / watcher entry point:** when the writer returns a `## Questions` section, **or** a gate hits its 5-iteration cap without converging, write every question of this park into **one** self-contained `<state_dir>/clarifications/<branch>/question_<n>.md` in the canonical format — naming the raising agent/gate (e.g. `user-review-fix-plan-writer`, or `business-parity-reviewer gate`), for a gate-cap hit the latest findings path, and per question why it is park-worthy per the ask-vs-assume policy below and the concrete decision needed. Emit `PARKED: <branch> — N question(s) at <state_dir>/clarifications/<branch>/` to the run log, then **truly stop and yield — end the session.** Do NOT spin, poll, sleep-loop, or re-dispatch waiting for an answer. The watcher detects the exit plus the unanswered question file, marks the run `parked`, and resumes it once the park's question file is answered (Override 2(a) consumes the answers on re-entry).
- **Manual / interactive entry point:** surface the questions live for inline answering, exactly as a supervised flow does today (the core's step 6 and gate-cap stop-and-surface behavior under the supervised fork's bindings, unchanged). No files are written — the file-based channel is the headless behavior only.

**Step 2's missing-user-review-file blocker is pre-checked upstream and routed the same way.** The calling command confirms at least one `<branch>_review[_<n>].md` exists before it reads this file, and on no match it already reports live (manual) or writes the blocker to the clarification channel and yields (headless) — see `/autonomous-sdlc-harness:branch-start-user-review-fix-autonomous`. Binding `<escalate>` here states that same behavior for the core's own step-2 site rather than adding one.

**Neither binding reaches a `STOP`-file halt.** The per-run `<state_dir>/STOP` and the global `<MAIN_REPO>/<state_dir>/AUTONOMOUS_STOP` checks in `## Safety scaffolding` below halt and report exactly as that section words them: a STOP file is a user-initiated stop, not a blocker, and routing it through the park would turn the operator's brake into a spurious park the watcher would then try to resume. The `MAX_TOTAL_DISPATCHES` cap hit, by contrast, **is** in scope — this family's cap halt parks headless, per that section's closing paragraph.

Emit a short convergence summary to the run log — the `fix_plan_path` (index), the `fix_plan_dir` (per-finding folder), the counts (`valid_must_fix`, `valid_should_fix`, `valid_nice_to_have`, `invalid`), and the mandatory `📌 Dispatch additions: …` disclosure line in the exact form `${CLAUDE_PLUGIN_ROOT}/instructions/dispatch_discipline_instructions.md` → `## The disclosure line` gives it (including its `none` form, which is a normal outcome; `<N>` is your own count of the blocks you wrote at the core's `## Convergence` record step) — as a log line and **fall straight through to fix implementation in the same session**. (The fused engine command, `/autonomous-sdlc-harness:branch-start-user-review-fix-autonomous`, chains the two phases in one uninterrupted session.) Do not pause, do not ask the user to invoke the next command. Emit the mandatory `📌 Run mode: …` disclosure line too, as its own line beside the `📌 Dispatch additions: …` line and never merged into it, in the exact form `${CLAUDE_PLUGIN_ROOT}/instructions/run_mode_instructions.md` → `## The disclosure line` gives it — including its `none` form (a prompt carrying no such section at all, a normal outcome) and its ignored-directive suffix; the core's `## Convergence` owns that obligation and the form, and this fork-held hand-off value is where it is emitted.
- User feedback on the result arrives as the next round's `<state_dir>/user_reviews/<branch>_review_<n+1>.md` drop — never as an inline rejection. **There is no rejection-with-feedback branch in this variant**, so the core's **step 11** is never entered *from a rejection* here. - **Entered from the core's `## Flow` step 4 stop outcome** (a fix-plan index for the active round already exists and is good): that outcome is `## Override 2 — resumability` case (b) here — skip the write loop and both gates and fall through to fix implementation in the same session. No command is named to run next and the session does not end; the fused engine command is already running.

## Override 2 — resumability

This section is the `<existing_artifact_decision>` value the core's `## Flow` step 4 applies. On **(re-)entry** it supplies a **non-interactive** decision in place of the supervised "extend / rewrite / stop" question, mirroring `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_autonomous.md` → `## Override 2 — resumability`. Never ask the user; decide purely from the presence of clarification answers and the state of the fix-plan index for the **active round** (the latest `<branch>_review[_<n>].md` per the core's step 2):

- **(a) Fix-plan index for the active round exists AND pending top-level answered pairs whose `question_<n>.md` was raised by the fix-plan phase.** If the index exists AND answered pairs sit at the **top level** of `<state_dir>/clarifications/<branch>/` (not under `answered/`) — each `answer_<n>.md` beside its matching `question_<n>.md` — check **which agent/phase raised each park**, read once per question file: every `question_<n>.md` names its raising agent/gate per the canonical clarification-channel format. For **every** pair raised by the fix-plan phase (`user-review-fix-plan-writer`, `business-parity-reviewer gate`, or `architecture-reviewer gate`), **resume the writer in revision mode with each such question file and its answer appended** to its prompt — that dispatch is the core's **step 11**, whose prompt and re-run-both-gates ordering are canonical there — and continue the gate loop from there. Do NOT restart the flow from scratch and do NOT re-ask an answered question. Per the **consume-then-archive contract** (canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_autonomous.md` → `## Clarification channel — file format`; referenced, not restated), a top-level `answer_<n>.md` is precisely the resume signal — an answer already moved to `answered/` has already been consumed and must not be re-processed. **A pair whose question file was instead raised by the fix-implementation phase (it names a Phase `A`/`QA`/`D` origin) is NOT consumed here** — when no pending pair was raised by the fix-plan phase, treat the plan state as case (b)/(c) accordingly — and the fix-implementation loop consumes it on its own re-entry (see `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fixes_instructions_autonomous.md` → `## Mode contract — bindings` → ``### `<escalate>` / `<ask>` — the park-and-yield clarification reroute``, its **On resume** paragraph).
- **(b) Fix-plan index for the active round exists with a `## Phase 2 Readiness — Ordered Fix List` and no pending clarification.** Treat the plan as written: skip the write loop and both gates, and fall through to fix implementation (Phase A resumes via its own readiness checkboxes).
- **(c) No fix-plan index for the active round.** Run the core's flow **fresh from its step 5** (the writer's initial-write dispatch). Note the round scoping: a round-2 review drop with an existing round-1 fix plan is case (c) **for round 2**, not case (b) — the round-1 plan belongs to a completed round.

## Override 3 — commit the fix plan + source review after the gates converge

**Autonomous fork only.** This override exists nowhere in the core, and nowhere in the supervised fork over it — that flow deliberately leaves the fix-plan family and the source review uncommitted for the human review/merge step. Only the autonomous fork self-commits them, so a watcher-driven run ends with a clean `git status`. Do **not** propagate this step into the core or back into the supervised fork. This is the user-review-fix analogue of the task flow's Override 3 / Override 4 (`task_plan_writing_instructions_autonomous.md`).

**Why a commit is needed here.** Nothing else in the autonomous user-review-fix flow commits these durable artifacts. The fix-plan **index** is only committed opportunistically by the Phase A `committer` (`mode: review_item`) as it flips a finding checkbox — so on a **zero-finding round** (Phase A dispatches no committer at all) the index dangles untracked. The per-finding `finding_<K>.md` files are never staged by the `review_item` committer (it stages only the index, the code diff, and any modified per-task plan file), and the **source review file** the watcher copied into the worktree before launch (`autonomous-watcher.sh` defers committing it to "the flow's normal commits") is likewise never committed. The same holds for the two plan-gate findings folders the core's steps 7 and 8 write. This override commits them all once, at fix-plan convergence, so they are tracked from the planning phase forward.

**Trigger / ordering.** Fires **after both gates PASS** — step 7 (business-parity) then step 8 (architecture) of the core — and **before `<terminal_handoff>` falls through to fix implementation in the same session**. Run it once, at that single convergence point.

**Active-round suffix.** Use the **round suffix of the active round** this fork already resolved via the core's steps 2–3 (latest `<branch>_review[_<n>].md`). A round-2 run commits `_fix_plan_2.md` / `_fix_plan_2/` / `_review_2.md`, never the round-1 files. Below, `${round_suffix}` is `""` for round 1 and `"_<n>"` for round N.

**Commit mechanism (via the `commit-on-branch.sh` wrapper in the fork, not a committer dispatch).** Stage and commit through the `<scripts_dir>/commit-on-branch.sh` wrapper — never a direct `git add` / `git commit` here, because a `git commit` carrying a `${branch}` expansion is what stalls a headless run on the `Bash(git commit:*)` branch-guard; the `bash <scripts_dir>/commit-on-branch.sh …` invocation is auto-allowed and never matches that guard even with the expansion in its args. That allow is withheld, though, when **anything in the command** — subject included — carries `$(…)`, a backtick, `|` (hence `||`), `>`, `<` (hence a subject naming a `<placeholder>`) or a braced expansion other than a bare `${IDENT}`; the guard scans the whole string. This is **not** a `committer` agent dispatch (the existing `committer` modes do not fit a "document produced" commit: `task` / `review_item` / `ui_test_pass` each flip a `## Phase 2 Readiness` checkbox, and `review_plan_file` is locked to a different fixed subject) — the fork calls the wrapper directly, exactly as the task flow's Override 3 / Override 4 do.

**Exact staging + commit.** Pass **only** explicit paths to the wrapper — the wrapper stages them with `git add -- <path>` and never `git add -A` / `git add .` (matches the committer's no-blanket-add rule):

- `<state_dir>/user_reviews/<branch>_fix_plan${round_suffix}.md` — the fix-plan index for the active round,
- `<state_dir>/user_reviews/<branch>_review${round_suffix}.md` — the watcher-copied source review for the active round,
- `<state_dir>/user_reviews/<branch>_fix_plan${round_suffix}/` — the per-finding folder, passed **unconditionally, with no existence guard** (a zero-finding round writes no folder, and the wrapper warns-and-skips a path that does not exist, so no shell conditional is needed here — an `if …; then` check is the headless trap the ⚠️ note below names),
- `<state_dir>/business_parity_user_review_reviews/<branch>/` — plan-mode parity findings, when the gate wrote any,
- `<state_dir>/architecture_user_review_reviews/<branch>/` — plan-mode architecture findings, when the gate wrote any.

**Why the two gate folders belong here.** They are durable evidence of what the plan gates found and what the writer had to fix, they are read at PR time, and no other flow step claims them — the same grounds `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_autonomous.md` → `Override 4` gives for the four plan-review folders it stages. The transient per-point files under `<state_dir>/user_review_fix_plan_point_reviews/` are out of scope and stay uncommitted, exactly as before.

**Neither gate folder is round-suffixed, and both pass unconditionally.** The core's steps 7 and 8 spell them `<branch>/` flat, so no `${round_suffix}` goes on them — a later round appends findings into the same folder and the wrapper stages the delta. Pass both with **no existence guard**: the wrapper warns-and-skips a path that does not exist, so a gate that PASSed first time (wrote no folder) needs no shell conditional, and an `if …; then` check is the headless trap the ⚠️ note below names.

The **whole-commit idempotency** stays a caller concern too, but it is now satisfied by the wrapper's **nothing-to-commit status** rather than a `git diff --cached --quiet`: under Override 2 resumability the index and review may already be tracked from a parked-then-resumed run, so the staged explicit set produces no diff and the wrapper returns its dedicated **nothing-to-commit code (exit 3)** — which skips the commit. Fixed subject, no `Co-Authored-By:` / trailer, no `--no-verify` / hook-skip flag — the wrapper enforces both: it builds the message from the positional args after `--` only (subject only here) and never passes `--no-verify`:

```zsh
# active-round suffix already resolved by the fork (e.g. "" or "_2")
# Pass the per-finding folder and BOTH gate folders UNCONDITIONALLY — the wrapper
# warns-and-skips a path that does not exist, so a zero-finding round and a gate
# that PASSed first time both need no shell conditional here.
bash <scripts_dir>/commit-on-branch.sh --repo "$REPO_ROOT" \
  "<state_dir>/user_reviews/${branch}_fix_plan${round_suffix}.md" \
  "<state_dir>/user_reviews/${branch}_review${round_suffix}.md" \
  "<state_dir>/user_reviews/${branch}_fix_plan${round_suffix}/" \
  "<state_dir>/business_parity_user_review_reviews/${branch}/" \
  "<state_dir>/architecture_user_review_reviews/${branch}/" \
  -- "chore: Add user-review fix plan for ${branch}"
bash <scripts_dir>/push-branch.sh "$REPO_ROOT"
```

> ⚠️ **No `if …; then … fi` anywhere in this block — deliberate, and it applies to BOTH the removed stage-path conditional and the removed push gate.** Per `${CLAUDE_PLUGIN_ROOT}/instructions/autonomous_pause_and_ledger.md` §1.6 any `if …; then … ; fi` / `for …; do … done` control-flow block is a headless trap: `allow-safe-compounds.sh` splits on `;` and the ` then …` piece begins with a non-allow-listed prefix, so the command falls through the safe-compound allow, nothing else matches it, and the run **stalls on a permission prompt it cannot answer headlessly** — **the commit silently does not land.** That is especially damaging here, because on a zero-finding round this is the *only* commit the fix flow makes. The two conditionals are therefore replaced by: (a) passing the per-finding folder unconditionally and letting the wrapper warn-and-skip it when absent, and (b) an unconditional push — `push-branch.sh` is non-fatal and only fast-forwards already-committed work, so it is a harmless no-op ("Everything up-to-date") whenever the wrapper made no new commit. `$?` would also be unreliable across separate Bash calls, since each runs in a fresh shell.

If a hook fails, surface the error — do not bypass it with a hook-skip flag and do not create a partial commit; the wrapper returns a loud non-zero on a hook failure, which the fork surfaces.

**Push after the commit.** The `<scripts_dir>/push-branch.sh` call above is **unconditional**, per the ⚠️ note above: it pushes the worktree branch to its upstream whenever a commit landed — Override 3 commits on every non-zero-finding round and, even on a zero-finding round, commits the source-review + index (that is its whole point), so a commit at convergence is the normal case — and is a harmless "Everything up-to-date" no-op when the wrapper returned its nothing-to-commit status (a parked-then-resumed run whose index + review are already tracked, exit 3). Do **not** add an exit-code gate — `$?` is unreliable across separate Bash calls, and the `if …; then` compound is the headless trap the note describes. It uses the `$REPO_ROOT` the calling command (`/autonomous-sdlc-harness:branch-start-user-review-fix-autonomous`) derived at session start (see the `<repo_root>` binding above). The helper is best-effort (exits 0 and logs on any failure — non-git dir, detached HEAD, protected branch, transient push failure) and reaches only the run's own non-protected branch; it never extends the flow or fails the fix-plan phase. The shared rationale for this post-commit push is the clean-tree invariant cited under "Shared rationale" below — not restated here.

**Interaction with the Phase A `review_item` commits (complementary, not conflicting).** Phase A later flips the index's per-finding readiness checkboxes one at a time and commits the index (and code diff) via `committer` `review_item`. That is **unchanged and complementary**: this override commits the *initial* fix plan family + source review at convergence so they are tracked from the planning phase; Phase A commits the per-finding checkbox flips on top later. On a zero-finding round Phase A commits nothing, which is exactly why this convergence commit is the only thing that keeps those artifacts tracked.

**Shared rationale.** This commit is one of the autonomous-fork commit points that collectively keep the clean-tree precondition honest — see **Autonomous-fork commit points — the clean-tree invariant** in `${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_autonomous.md`.

## Override 4 — pause/resume + flow-progress ledger (fix-planning half)

**Autonomous fork only.** The mechanism is canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/autonomous_pause_and_ledger.md`; this override names only the fix-planning points where it applies.
