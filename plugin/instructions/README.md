# instructions/

The orchestration instructions the `branch-*` commands and the orchestrating agents load: the mode-free **cores** that carry the flow itself (the orchestrator loop, plan writing, the per-unit implement/review loop, code review and its fix flow, user-review fix-plan writing and the user-review fix loop, the documentation phase, QA execution, pause/resume and the observations ledger), the **thin forks** that adapt a core to supervised, semi-autonomous or autonomous operation by overriding only what the mode changes, and the **mode contract** that states which behaviours a fork may override and which are the core's alone — so a rule is stated once and a mode difference is visible as a fork, never as a second copy that drifts. Roadmap item 3 landed twenty-four of the twenty-seven instruction files beside this README (the `.md` files here, minus this README; the run-mode, dispatch-discipline and clarification-digest modules came later): four core/fork families — the orchestrator loop, task-plan writing, user-review fix-plan writing and user-review fixing — together with the mode contract they compose through and the shared unit loop their per-unit phases cite; the mode-free code-review and code-review-fix files, the task-plan implementation hand-off, the documentation phase with its autonomous orchestration companion, and QA execution; and the pause/resume, observations and clarification-digest modules. The agent definitions these instructions dispatch (`task-plan-writer`, `layer-implementer`, `layer-reviewer`, `branch-reviewer`, `qa-tester`, `committer` and the rest) landed with roadmap item 4, and the `branch-*` slash commands that load an instruction file, the hook guards an unattended run needs and the plugin helper scripts a QA phase calls landed with item 5 — each of those three directories' own README states what it holds. The project-command wrappers and the outer-loop scripts these instructions invoke by `<scripts_dir>/` path — the commit and push wrappers most of all — landed with item 6, shipped as templates the CLI writes into the adopting repository's configured scripts directory, so those paths resolve in a wired repository rather than naming something the tree does not hold.
