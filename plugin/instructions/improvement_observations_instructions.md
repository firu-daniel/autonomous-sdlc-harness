A **terminal, best-effort intake step** for the two autonomous flows (the autonomous task flow and the autonomous user-review-fix flow). Once a run's work is finished, the orchestrator records the harness / workflow / architecture problems it **encountered during this run** — the dispatch that stalled, the command that was gated, the phase that silently skipped, the work that was regenerated after a resume. The orchestrator is the only participant that sees a whole run end-to-end, and that knowledge otherwise dies with the session. The observations go to a **per-branch intake file**, which a human later folds into the triage ledger `<state_dir>/improvement_suggestions.md` on the default branch (intake path and entry format: the mechanics sections below).

This file is the canonical policy. A flow **activates** it by adding one `Override I` (see `## Activation`); this file is otherwise inert.

**What the activating flow's Override I supplies.** This file states everything that is fork-independent. Each activating Override states only what its own fork binds:

1. The exact Phase-D placement point, and **which flow-progress ledger entry the write must precede** (the write has no `[ ]`/`[x]` flip of its own, so it must land before the flip that would let a resume skip past it).
2. That flow's **unit** definition and its **review-artifact roots** — the inputs the mechanical diff below operates on.
3. Whose `## Setup` binds its `MAX_TOTAL_DISPATCHES`, and that flow's `<per_unit_review>` value.
4. The emission of the D.2 Done-summary bullet, and the fork-side half of the read exception in `## Reading review findings — the narrow Phase-D exception` below.

**Placeholder resolution.** Per `${CLAUDE_PLUGIN_ROOT}/instructions/mode_contract.md` → `### Bindings vs. path placeholders`, every `<…>` **path placeholder** this file uses (`<branch>`) and the `$REPO_ROOT` shell value resolve from the **activating flow's own entry core `## Setup`** and that flow's `<repo_root>` binding — never from the immediate citing file, and never from this file. Being a shared file reached by two cores confers no ownership of a path (same rule `${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md` → `### Placeholder resolution` states). **Not every `<…>` name here is a path placeholder**, and the exceptions do not resolve there: the `## Resolved values` tokens above resolve from `harness.config.json`; `<i>` / `<i-1>` below are **locally-defined round counters** (as are `<fix_round>`, `<n>` and `<N>`, each defined at its own use site); and `<per_unit_review>` is a **mode-contract binding** supplied by the activating fork's binding table (`mode_contract.md` rule (5); seam item 3 above), never by a `## Setup`. **`<fix_round>` is deliberately *not* spelled `<round>`: the user-review-fix flow's own `## Setup` binds `<round>` to its next-free *QA-review* folder suffix, which is a different number.** If a placeholder here is unresolved, you arrived without your entry core's `## Setup` — go read it.

**Worked examples are kept and generalized, never invented and never dropped.** The category gloss in `## The entry format` teaches by naming real past failures, because a category with no example is a category nobody assigns; each one is therefore stated as the *class* of failure it belongs to, with no project, branch or product name attached.

## Where it runs & the non-blocking rule

- Runs at **Phase D**, **after** the flow's branch-statistics commit + push and **before** its D.2 Done summary — late enough to observe the whole run, the docs phase and the statistics phase included, with only the clarification digest written after it. The exact anchors in that flow's phase sequence are the activating Override's to name.
- **One write per run**, at that single point. Never scatter edits across the run as observations occur: repeated edits mean repeated commits, more churn, and a distracted orchestrator. Carry the observations in-session and write them once, here.
- **Retained during the run, written at the end.** The freely-observed class (rules 1–8) exists only in the orchestrator's session: nothing on disk records the command that was gated or the phase that skipped, so an observation not noted **when it happened** is not recoverable at Phase D — the same reason a resumed session cannot reproduce the pre-pause session's observations (`## Where it is written`). Note each one in-session at the moment it occurs, carrying rule 2's evidence as it stood then (the exact command and its failure, the dispatch that was redone, the phase that skipped, the file). Reconstructing evidence at Phase D from memory is what rule 7 forbids — *fluency is not evidence*. This is a **note, not a write**: the one-write-per-run rule above is unchanged. The **trip-wire** class needs no retention — it is re-derived at Phase D from artifacts on disk (`## Optimization observations — trip-wires, not reflection`).
- **These two passages arrive before the run; everything else at Phase D.** The bullet above and `## What the orchestrator may log — rules` are **mid-run** behaviour specs — rule 1 forbids acting on the harness mid-run, rule 2 sets evidence that is only capturable as it happens, and rules 3, 7 and 8 bound what is worth retaining — so each activating flow's **entry-point command** has its orchestrator read **those two passages only** at session start, before its first half runs. Each command supplies only what is fork-specific (which of its halves are in scope, which step reaches `Override I`, and note-only/write-nothing) and points here for the duty itself rather than restating it. The write mechanics, the trip-wire table and the entry format stay Phase-D reading, reached through `Override I`.
- **Skip the whole step when this session observed nothing and the branch has no tracked intake file yet** — no file, no empty commit, no error, no Done-summary bullet. This mirrors the statistics override's `error:` gate: a skipped write is a normal outcome, not a failure. When the branch's intake file **is** already tracked (a resumed session, or a later round) the step is still entered: the session appends only what it observed — nothing, in the common case — and calls the wrapper on the resulting, possibly byte-unchanged file, which is the **exit 3** case `## Commit mechanics` / `## Push` / `## Ledger / resume` name.
- **Best-effort — never a gate.** Any failure here (write error, a machine-path check that could not run or a hit it could not clear, wrapper refusal, push failure) is logged and the flow proceeds to its D.2 Done summary unchanged, exactly as the docs phase does — but it never simply walks away from a failed commit: `## Commit mechanics` states, per wrapper exit code, what to revert, what to re-stage, and what to report in the Done summary where the headless profile leaves no way to clean up. This step must never block "branch ready for review."

## What the orchestrator may log — rules

These guardrails matter more than the format. An orchestrator that starts editorialising about architecture mid-run burns tokens and derails the actual task.

1. **Observe, never act.** Never fix the harness, edit an agent def, or change a permission mid-run. Log and continue. The run's task is the run's task.
2. **Encountered, not imagined.** Only things that actually happened *in this run*, each with concrete evidence: the exact command and its failure, the dispatch that was redone, the phase that skipped, the file. No speculation, no "it would be nicer if", no general architecture opinions.
3. **Hard cap of 5 per run** for freely-observed problems. If a run generates more than five, it has a bigger problem that belongs in the escalation path, not a suggestions file. Trip-wire entries (below) are exempt — they are mechanically triggered and bounded by the number of trip-wire types.
4. **Never a gate.** Best-effort exactly like the docs phase (Override H) — any failure here is logged and the flow proceeds to D.2 unchanged, but without walking away from a failed commit — see `## Commit mechanics` for what to revert, re-stage or report, per wrapper exit code.
5. **Do not dedupe against the ledger.** Do not grep `<state_dir>/improvement_suggestions.md` first: the branch's copy may be stale, and *N runs independently reporting the same gap is priority signal, not noise*. Dedupe at triage.
6. **Harvest from sub-agent returns, don't add reporting duties to sub-agents.** The orchestrator already receives every sub-agent's `notes:` / `summary:` contract field. Use those. Do **not** modify sub-agent contracts to write this file — N agents editing one file mid-run is both a conflict source and token churn.
7. **Measured, never invented.** Every optimization observation must be a **count or a comparison over this run's own dispatch history**, not a judgment about how the flow ought to work. If you cannot express it as a number backed by artifacts on disk, do not log it. An LLM asked "what could be better?" always produces a fluent answer; fluency is not evidence. See the trip-wires below — they exist to turn this from a creativity task into a detection task.
8. **Never propose a structural change.** Do not recommend splitting an agent, reordering phases, dropping a reviewer, or rewriting a prompt. One run cannot see cost, other flows, what was already tried, or why something was designed as it was. Report what happened; the human decides what it means. At most one line of hypothesis, explicitly labelled as such.

## Optimization observations — trip-wires, not reflection

**Do not ask yourself whether anything could be improved.** Instead, check these countable conditions at Phase D. If one fires, log it; if none fire, log nothing in this class.

| Trip-wire | Fires when | Report |
|---|---|---|
| **Convergence churn** | one unit (plan, task, review item) needed **≥3** review rounds | the unit, the round count, and — per round — whether findings were **net-new** or **re-raised** from the prior round |
| **Repeated defect class** | the same finding category hit **≥3** units in this run | the category, the units, the citing reviewer |
| **Reviewer overlap** | two reviewers raised substantially the same finding on the same unit | the reviewers, the unit, the duplicated finding |
| **Zero-yield phase** | a phase or reviewer ran on every unit and produced **no** change all run | which one, and the unit count it passed |
| **Rework after resume** | work was regenerated because it wasn't committed before a pause | which unit, and roughly what was redone |
| **Cap pressure** | dispatches reached **≥70%** of `MAX_TOTAL_DISPATCHES` | the count and the cap |
| **Index-only commit** | a unit's commit staged nothing but the readiness index and the unit's own detail file — no work file — which its subject records as `mark <unit token> done — <staged set>` | one entry listing each such commit: its unit token, its short SHA, and the staged-set description its subject gives |

Four notes bind how these are evaluated:

- **(a) Cap pressure is a percentage, never a literal.** Read the count from `<state_dir>/.dispatch_counter` and the cap from the **activating flow's own** `MAX_TOTAL_DISPATCHES`, bound in that flow's core `## Setup` (the two flows bind different values). **Do not write any cap value, or any pre-computed absolute trigger derived from one, into this file or into either Override** — each **activating** fork's opening declares that constant **inherited from its core rather than owned by the fork**, and a copied number silently drifts out of date the moment the owning `## Setup` changes it (the task flow's has already been raised once). Compute `0.70 × cap` at Phase D from the value in force, then compare. ⚠️ **The count is session-scoped, not run-scoped.** Both cores' `## Setup (once per session)` step 5 runs `echo 0 > <state_dir>/.dispatch_counter` on **every** (re-)entry, including a pause-resume and a clarification-park resume, so on a resumed run the value at Phase D covers the post-resume session only. Report it as such — *"N dispatches this session (post-resume), cap M"* — and never present it as the run's total. If the flow-progress ledger shows this run resumed at all, say so in the same `evidence:` line; a cap-pressure number that silently omits a pre-pause session is the one figure in this table that cannot be audited afterwards, the counter being machine-local and already truncated.
- **(b) A "unit" and the review-artifact roots to diff are named by the activating flow's Override I.** This file states the *method*; the fork states its own roots (its review folders differ from the other fork's, and the two flows do not have the same unit vocabulary). Do not assume another flow's roots.
- **(c) Reviewer overlap and Zero-yield phase are only measurable where the flow actually ran the phase or reviewer in question — and a phase that never ran is not an observation, whatever removed it.** Both trip-wires report what a phase or reviewer *produced* over the run; one that was never dispatched produced nothing by construction, so logging it would report an absence the harness intended rather than a problem this run hit. That holds identically for each reason a phase can be absent: a **fork binding** that switches it off — a flow that binds `<per_unit_review>` = `off` never dispatches a per-unit layer reviewer, so those two trip-wires simply cannot fire for that class of reviewer there, and that flow's Override says so; a **repository-level decision** that it does not run here at all; and a **run mode** that excluded it for this branch — for what a run mode is, which phases it may exclude and where that exclusion is recorded, see `${CLAUDE_PLUGIN_ROOT}/instructions/run_mode_instructions.md`. This note restates none of that, activates nothing and honours no directive, so it is a **definitional** citation and not a member of that file's `## Activation` set (which lists it as definitional for exactly this reason). In none of these cases is the absence itself an observation.
- **(d) Index-only commit is read from committed history, not from review artifacts — and issues no command of its own.** Take it from the **same** `git log` output over `<default_branch>..HEAD` that `## Dispositioned units` **(b)** already produces at this write point, matching a subject framed `mark ` … ` done — ` where that bullet matches `record disposition of `, under that bullet's own leading-word case rule (both are free-form subjects, so `Mark` counts), its unit-token parse (here, the text between the two frames) and its intersection with this run's own readiness units. **The two substrings never co-occur on one commit:** the committer puts a `disposition` argument in the subject when the staged set is index-only and in a body line only when work was staged, so a `mark … done — ` subject is by construction the *no*-disposition case — the one `## Dispositioned units` cannot see, which is why this is a row here and not a second class there.

The **net-new vs re-raised** split on convergence churn is the important one: it discriminates *"the planner keeps making bad calls"* (findings re-raised because fixes didn't land) from *"the reviewer is doing partial passes"* (each round surfacing things the prior round should have caught). **Determine it mechanically — never guess it — and start by listing the unit's review root (the roots the Override names) and reading off the rounds that actually exist there: never assume a consecutive `review_<i>.md` series.** Round artifacts come in three shapes and **the listing is authoritative**, though where a root's shape is easy to get wrong the Override flags it too: a **`review_<i>.md` series** — gapped in folders written before the per-folder index landed (several reviewers driven off one shared `iteration` counter each got a *subsequence*, not `0..n`), and that gate's own consecutive series from its own next-free index in folders written after it, where a gap means a file that went missing; a **suffixed index file** whose round lives in the filename (`…_review.md`, `…_review_2.md`, …, with the per-finding folder mirroring the suffix); and a **round-suffixed folder** whose round lives in the *folder* name (`<branch>_x_review/`, `_2/`, `_3/`), each folder holding exactly one identically-named index file — for that shape the round series runs across those **sibling round folders**, so the sorted list to walk is the list of folders, not of the files inside one. **Sort each root's own artifacts and index that sorted list from 0**, then diff each entry `<i>` against its immediate predecessor `<i-1>` **in that same root's list** — not against whatever file happens to be numbered one lower (it may not exist), and **never against a different reviewer's root**, which compares two different reviewers and reports it as one reviewer's round-over-round (a sibling **round folder of the same root** is not that: it is the correct predecessor for the round-suffixed-folder shape). A finding heading present in both is *re-raised*; one present only in `<i>` is *net-new*. A unit's round **count**, by contrast, is the **total** across **every** root the Override assigns to that unit, counting a round-suffixed folder family as one artifact per round folder — never one folder's file count. Report the per-round split as counts.

**One run's trip-wire is weak evidence; frequency across runs is the diagnosis.** That is why rule 8 holds: you only have to be right about *what happened*, never about *why*. Triage decides cause once several runs agree.

These entries are **exempt from the cap of 5** — they are mechanically triggered and self-limiting (at most one per trip-wire type). Their counts are **falsifiable**: the underlying review artifacts persist on disk — as does the commit history the **Index-only commit** row reads instead — so any claimed number can be audited later. This is exactly what a structural opinion cannot offer.

## Dispositioned units — an entry per unit closed without a fix

A **dispositioned** unit is one a `layer-implementer` diagnosed as impossible for any agent in this flow, which the loop then closed rather than escalated (`${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md` → `### The dispositioned outcome`). This class is a sibling of the trip-wires above, not of the freely-observed rules 1–8: it is derived here, at the write point, from committed history.

- **(a) Trigger.** One entry per unit **this run** dispositioned — **every** such unit, including one whose other layers landed code, because the record is on the commit either way (see (b)) and this derivation reads both placements. The class is **mechanically triggered**, which is the half of the trip-wire exemption reason it shares, so it is likewise **exempt from rule 3's hard cap of 5**. Its own bound is not theirs and is stated here rather than borrowed: it is bounded by the number of units this run dispositioned, which this run's readiness index caps.
- **(b) Derivation — from committed history, never from session memory, which is what makes this class survive a pause.** At this Phase-D write point run one **plain, single-statement** command over the branch's own commits. Resolve `<default_branch>` to its config value (`## Resolved values`) **before** issuing it, so the string that reaches the tool layer carries none of `$(`, a backtick, `|`, `>` or `<`:

  ```zsh
  git log --format='%h %s%n%b' --name-only <default_branch>..HEAD
  ```

  Take every commit **any line of whose message** carries the fixed substring `record disposition of `. That is the record `${CLAUDE_PLUGIN_ROOT}/agents/committer.md` → `## Commit-message policy` puts on a commit whenever a `disposition` argument was passed: in the **subject** (`<commit_prefix>: record disposition of <unit token> — <cause>`) when the unit staged nothing but the readiness index and its own detail file, and in a commit **body line** when the unit also landed files and the subject therefore describes that work — never in both, never in neither. The substring is prefix-independent, and matching the **whole message** rather than the subject is what reaches the second placement: a unit with one dispositioned layer and one that landed code.

  **The match's one case rule.** The leading word `record` matches **however it is cased** (`record` or `Record`); every byte after it — ` disposition of `, the unit token, the ` — ` separator, the cause — matches **exactly**. That leading word is the one byte of the record the harness does not fix: the committer binds it to `<commit_conventions>`'s capitalisation like every other free-form subject's first word, so a capitalising adopter's commit reads `<commit_prefix>: Record disposition of Task 3 — <cause>`. A case-sensitive read returns the empty set there for precisely the unit this class exists for — the code-less one, whose record is in the **subject** — while still matching a mixed unit's lower-case body line. Do not tighten it.

  **Parse it as three rules.** **One entry per matched commit**, keyed on the commit's **short SHA**: the commit is the unit, so a commit carrying the substring on more than one line still yields one entry. From the matched line, the **unit token** is the text between that substring and the **first** following ` — `, and the **one-line cause** is the remainder of **that line**. The **detail-file path** comes from that commit's own changed-file list: the path under the detail-file roots the activating Override names, which is neither the readiness index nor a code file (a commit that also landed code lists those too); where the list holds none, write the entry without a pointer rather than guessing one.

  **That cause is one cause, not necessarily the unit's only one.** A unit whose readiness entry spans two layers may have had both dispositioned, and the loop passes a single `disposition:` argument carrying the **first** dispositioned layer's cause; every layer's diagnosis is in the detail file. So word `evidence:` as *the cause recorded on the commit*, never as *the unit's cause*, and let the detail-file pointer carry the rest. The committed subject may hold a sanitized form of that cause (the committer's wrapper-safe subject rule); the entry records **what was committed**, which is what a later reader can audit, and the detail file holds the verbatim diagnosis.

  **Bound the set to this run before writing anything.** `<default_branch>..HEAD` spans the whole **branch**, not the run, and a branch that reaches a user review has already had a task run over it. **Intersect** the matched unit tokens with the units of **this run's own readiness index** — an input the activating Override **supplies** (its index and its unit vocabulary), never one this file resolves — and drop every match that is not one of them. Without that intersection a second engine over the same branch re-derives the first engine's dispositions and hands the Done summary a figure that is not its own. One over-reach the intersection cannot close, disclosed rather than engineered around: where the local `<default_branch>` ref is behind, the range can inherit a disposition commit from an earlier merged branch whose unit token collides with one of this run's — the short SHA in `evidence:` is what makes such an entry identifiable at triage. Add no second range heuristic.

  **None of this opens a reviewer findings file.** It reads a commit message, a set of changed-file **paths** and this run's own readiness entries — exactly what both cores' *"Do NOT read the contents of any reviewer findings file. The path is enough."* already permits. `## Reading review findings — the narrow Phase-D exception` below is therefore neither cited nor widened by this class, and this class needs no relief from it.
- **(c) Content.** **Category — derived from the one-line cause (b) parsed**, the only input this class holds; both arms name a category `## The entry format` already lists, and neither adds one. A cause naming a **refusal the run could not lift** — a command it could not run, a write the tool layer refused — is **`tooling-gap`**, that gloss's own case. A cause naming a **condition the run could not reach because the unit's own text required it** is **`agent-contract`** — *"an instruction that made an agent do the wrong thing"*, which is what a gate authored into a unit the dispatch cannot satisfy is. Where the line is written too thinly to decide **between the two**, take **`agent-contract`** and say so in `evidence:` — **unless it names a refused command, a refused write or a permission surface, which is `tooling-gap` however tersely it is worded** (`write refused`, `settings guard`). What that exception leaves is a cause the producing contract required to name its class and which did not, so `agent-contract` — the authoring rule — is where it belongs; a wrong `tooling-gap` would send triage looking for a permission or tooling fix that does not exist. `evidence:` = the commit's short SHA, the matched line's unit token and the cause recorded on it, and the detail-file path. `cost this run:` = the unit was closed without a fix. The entry **points at** the diagnosis — the `## Disposition` section of that detail file, named by construction and never opened here — so the intake stays a routing record and the committed detail file stays the single copy.
- **(d) Resume.** The same **do-not-re-append** duty the trip-wire class carries (`## Where it is written`'s ⚠️ paragraph), cited rather than restated. The re-derivation is over committed history, so a re-entry produces the identical block.

## Reading review findings — the narrow Phase-D exception

The trip-wires above require counting findings, which crosses a rule **both** orchestration cores carry in § "What you must NOT do": *"Do NOT read the contents of any reviewer findings file. The path is enough."* Neither core is edited to accommodate this; the carve-out is stated here, once, and is bounded on **four axes** — modelled on the task-flow core's own narrow E.2 QA-aggregation exception:

1. **Only at this single Phase-D write point.** The run's implementation, fixes and reviews are all finished, so nothing read here can change an implementation, fix or review decision — which is the entire hazard the path-only rule exists to prevent.
2. **Only for a unit that has already tripped a countable threshold, or for a trip-wire that has no countable threshold to pre-qualify with.** The two thresholded cases are a unit at **≥3** review rounds and a finding category already observed on **≥3** units; you do not read findings to *discover* those, you read them only after the counts say one already fired. Those counts come from three sources, all cheap: the **artifact paths** (round counts), the **readiness indices** (finding titles, which carry the category), and the **`notes:` / `summary:` returns every sub-agent already handed you** (rule 6) — never from opening a per-unit `review_<i>.md`. The **Reviewer overlap** trip-wire has no threshold of its own — it *is* the no-threshold case this axis carves out: on a unit where two reviewers both reported, compare their finding **titles** and nothing else, taking them from an index or a return that already carries them and otherwise from those two reviewers' own findings files, **headings only** per axis 3 (a per-unit layer reviewer's `item_<K>/` folder has no index and its return carries no titles, so its headings are the only source there). If a category or an overlap cannot be established from those sources, log nothing in that class — an unmeasurable trip-wire is silence, never a guess.
3. **Only the findings' headings / titles — never their bodies.** A heading is enough to match a finding across rounds and to name a category; the body is the reviewer's reasoning, and reading it is what the core's rule forbids.
4. **Only to produce a count.** Never to make, revise, or second-guess any decision — not a verdict, not a fix, not a re-dispatch.

Outside these four axes the cores' path-only rule stands unmodified. **Each activating fork states that this exception applies to its own core's path-only rule and amends its own `## What this file does NOT redefine` bullet accordingly** — the axes have exactly one owner (this section), while the per-fork binding is necessarily per-fork, because each fork amends its own bullet against its own core.

## Where it is written

The intake file is `<state_dir>/improvement_observations/<branch>.md` — **one per branch, never shared.** This is the design decision the whole channel turns on: every run appending to one shared file at EOF is among the most reliable git-conflict generators there is, and a ledger written by *every* parallel run would re-serialise exactly the parallel runs this tree exists to allow. So **intake is per-branch and automated, while triage is shared and human-only** — a human on the default branch later folds the intake files into the triage ledger `<state_dir>/improvement_suggestions.md`, a long-lived file at the root of the run-artifact tree that `init` creates only if absent and never truncates, because it is the only copy of that history. No two runs ever touch the same intake file, so the conflict risk is **none**. The `[ ]` / `[x]` / `[~]` checklist semantics live in that triage ledger, not here.

**Write mechanics — absolute write, repo-relative commit.** Create the file with the file tool at the **absolute**, `$REPO_ROOT`-anchored path `$REPO_ROOT/<state_dir>/improvement_observations/<branch>.md`, so it lands in **this worktree** and not in the main repo — a bare `<state_dir>/…` path resolves against the main checkout, which would write this run's observations onto the default branch instead of the run's own branch (itself a logged `shared-state` failure class below). Then pass the **repo-relative** path `<state_dir>/improvement_observations/<branch>.md` to the commit wrapper, which resolves its staging paths against `--repo`. This absolute-write / relative-commit split is the same one every other autonomous artifact uses.

**A later round of the same branch appends — it never overwrites.** The file is per-**branch**, not per-round: a second user-review-fix round over the same branch, or a resumed run, writes to the **same** `<branch>.md`. **Every user-review-fix-flow write carries a label**, whether it appends to an existing file or creates it — a new `#`-level label naming the flow and its own round number: `# User-review fix round <fix_round> — <what this round fixed>`, where `<fix_round>` is this fix cycle's own round: the suffix on the fix-plan index the flow was invoked with (`<branch>_fix_plan.md` = 1, `<branch>_fix_plan_2.md` = 2, …), which mirrors the suffix on the user review it fixes (`<state_dir>/user_reviews/<branch>_review[_<n>].md`) — never a count of writes to this file. The task flow has no round concept and its single write carries **no** label, so the file's first, unlabelled block is always the task run's. Any earlier block is left untouched — except a machine path in it, which `## Commit mechanics` → **Machine-path check — before every wrapper call.** rewrites — and the `##` entries below the label keep their level.

**A resumed run is not a later round, and it does not re-observe.** Observations are held in-session (see the one-write-per-run rule above), so a session that resumes into Phase D after a pause has *not* seen the phases the pre-pause session watched and **cannot** reproduce its observations. It therefore never overwrites and never re-labels: if the intake file already exists and is tracked, the resumed run **appends only what this session itself observed, under the same round's block**, and appends nothing at all when it observed nothing. Losing the pre-pause session's observations by rewriting the file is the one outcome this step must never produce. A write that adds nothing leaves the file byte-unchanged and yields wrapper **exit 3** (see `## Commit mechanics`) — a normal outcome, not an error — unless the machine-path check rewrote an earlier block, which commits at exit 0 (`## Ledger / resume`).

⚠️ **The two observation classes resume differently.** The freely-observed class (rules 1–8) is genuinely in-session and is what the paragraph above is about. The **trip-wire** class is not: it is computed *at this write point* from artifacts that persist on disk (`## Optimization observations — trip-wires, not reflection`, whose falsifiability rests on exactly that), so a re-entry re-derives the **same** entries the pre-pause session already wrote. **Do not re-append a trip-wire block the file already carries.** Before appending, read the existing blocks and skip any whose `## <problem statement>` you are about to re-derive identically; a re-derived count that has *changed* since the earlier block replaces nothing either — note the new figure inside the existing block rather than opening a second one. This is the one place the orchestrator does compare against a file it wrote; rule 5's do-not-dedupe applies to the **triage ledger**, never to this run's own intake file.

## The entry format

Each observation is one block in this shape:

```markdown
## <one-line problem statement>
- **category:** tooling-gap | silent-failure | flow-efficiency | optimization | agent-contract | shared-state | convention
- **evidence:** what actually happened — the command / dispatch / file, or the count and the artifacts backing it — every path repo-relative (below)
- **cost this run:** e.g. "QA phase skipped silently", "task 4 re-implemented after resume", "~20 min stall"
- **hypothesis:** (optional, one line, explicitly a guess — never a structural proposal)
```

Keep `evidence` and `hypothesis` **strictly separate.** Triage must be able to trust the first without inheriting the uncertainty of the second: `evidence` is what the artifacts on disk actually show and is falsifiable, while `hypothesis` is one optional line explicitly labelled as a guess — and rule 8 above still binds it, so it is never a structural proposal.

**Every path in an entry is repo-relative.** It binds every field and every heading, `evidence:` above all. A path under the run's own checkout is written from that checkout's root (`<state_dir>/improvement_observations/<branch>.md`, `.git`). A path in **another checkout of the same repository** — the main checkout, or a sibling worktree — is written from that checkout's root with its machine prefix dropped, followed by a parenthesised label naming the checkout: `(main checkout)` or `(worktree of <other branch>)`. A location outside every checkout is named by what it is — *"the session transcript"*, *"the user-level settings file"* — never by its path. The home directory, any checkout's root and any other absolute location on the machine never appear. **Quoted command output is rewritten by the same rule, and the rewrite does not count as changing the evidence:** it replaces the machine prefix and adds the label, and the path still names the same file, so rule 2 (*"Encountered, not imagined."*) and the falsifiability `evidence` rests on both still hold. The class: a linked worktree's `.git` pointer quoted as `gitdir: <main checkout root>/.git/worktrees/<name>` is written `gitdir: .git/worktrees/<name> (main checkout)` — `<main checkout root>`, `<name>` and `<other branch>` in this paragraph are illustrative text, not tokens. The file is committed and merged into `<default_branch>`, where a path from one machine means nothing to any other reader and discloses that machine's layout; `## Commit mechanics` → **Machine-path check — before every wrapper call.** is where the rule is checked. The absolute `$REPO_ROOT`-anchored path `## Where it is written` → **Write mechanics — absolute write, repo-relative commit.** gives is the file tool's **argument**, never the file's **content**: what this intake file says is bound by this rule.

**The seven categories**, glossed with a concrete, countable gap each so assignment is not guesswork:

- **tooling-gap** — a command an agent needed but couldn't run: the `<parity_vocabulary>` reference implementation's own analyzer has no entry in the autonomous permission profile, so changes under `<reference_impl>` ship analyzer-unverified (*applies only when `phases.parity` is `true`*); the configured `commands.*` string a backend build needs is gated in the worktree, so those tasks ship without a build check; a quoted wrapper path failing the allowlist guard and stalling on `ask`.
- **silent-failure** — a phase that skipped or lied: a permission glob not matching the worktree so a whole phase was skipped with no error; a run reporting `completed` after dying mid-review; a tracked artifact omitted from the committer's explicit path list and lost at PR time.
- **flow-efficiency** — redundant or wasted work: uncommitted artifacts regenerated from scratch after a resume because the checkbox ledger is the only resume state; a reviewer whose findings are near-entirely redundant with another's; a phase that adds nothing to a given diff shape.
- **optimization** — a **fired trip-wire** from the table above, reported as a measurement: *"task 3 needed 4 review rounds; rounds 2–4 each raised net-new findings rather than re-raising unfixed ones"*, *"the same missing-localization finding hit 5 of 7 tasks"*. Never a structural proposal.
- **agent-contract** — an instruction that made an agent do the wrong thing: a reviewer that FAILs on any finding and ping-pongs the convergence loop; an ambiguous placeholder resolved differently by two agents.
- **shared-state** — cross-branch hazards: worktree agents resolving `<state_dir>/` to the *main* repo and writing the artifact onto the default branch instead of the run's branch; two runs colliding on a shared file.
- **convention** — a project convention costing more than it gives: line-number coordinates in a maintained doc, which go stale on every edit above them (the case that prompted this channel).

## Commit mechanics

**Direct wrapper, never a `committer` dispatch.** Commit through the `commit-on-branch.sh` wrapper (`<scripts_dir>/commit-on-branch.sh`) — not via a `committer` agent dispatch, and never a bare `git add` / `git commit` **to make this commit** (the single exception is the post-failure index cleanup under **Wrapper exit status** below, which is not a commit path). Two independent reasons:

- **No committer mode fits.** `task` / `review_item` / `ui_test_pass` each flip a `## Phase 2 Readiness` checkbox and this intake file is a single-file report with **no** readiness section to flip; `review_plan_file` is locked to a different fixed subject. This is the same reasoning each fork's Override D gives for `statistics.md`, and the canonical rule for non-readiness artifacts in `${CLAUDE_PLUGIN_ROOT}/instructions/autonomous_pause_and_ledger.md` §1.6.
- **A raw `git commit` stalls a headless run.** A `git commit` carrying a `${branch}` expansion is what stalls a headless run on the `Bash(git commit:*)` branch-guard, whereas the `bash <scripts_dir>/commit-on-branch.sh …` invocation is auto-allowed by the directory-based autonomous-script allowlist guard and never matches that guard, even with expansions in its args. That allow is withheld, though, when **anything in the command** — subject included — carries `$(…)`, a backtick, `|` (hence `||`), `>`, `<` (hence a subject naming a `<placeholder>`) or a braced expansion other than a bare `${IDENT}`; the guard scans the whole string.

**Machine-path check — before every wrapper call.** Resolve the needles first, each by one **bare** single-statement command whose output you read — never nested, never kept in a shell variable: every line beginning `worktree ` in `git worktree list --porcelain` gives a checkout root (the first is the main checkout; this run's `$REPO_ROOT` is among them), and `jq -nr env.HOME` gives the home directory (`jq` is already a prerequisite of the plugin's guards, `${CLAUDE_PLUGIN_ROOT}/hooks/README.md` → `## Prerequisites`). Drop a needle that is empty, is `/`, or is a single path segment — a `/` followed by a name with no further `/`, such as `/app` or `/root` — and log which source it came from: as a fixed-string match such a needle also matches inside an ordinary repo-relative path (`/src` inside `cli/src/cli.ts`), so a correct entry would read as a hit no rewrite can clear. With every needle dropped, the check could not run. Then run one single-statement command with every needle and the intake file's absolute path spelled out as literals — the angle-bracketed names below are illustrative text, not tokens:

```zsh
grep -nF -e '<home directory>' -e '<checkout root>' -e '<checkout root>' '<absolute path of the intake file>'
```

Single-quote every needle and the file path: a home directory or checkout root may contain a space, and an unquoted one splits into a word `grep` opens as a file, which yields status `2` with the hits already printed. A needle that itself contains a single quote is dropped like an empty one, and its source is logged; if the intake file's own path contains one, the check could not run. It carries no `$`, no `$(…)`, no pipe and no redirect, so `grep`'s own entry in the unattended profile allows it, as the checkout-root rule requires. `grep`'s status is the verdict: `1` clean, `0` hit, `2` could not run. **On `0`**, each printed line names a line of the file: rewrite the offending text with the file tool by `## The entry format` → **Every path in an entry is repo-relative.**, then run the same check again; run the wrapper only on status `1`, never on `0`. The check covers the **whole** file, and a hit in an earlier block is rewritten too — the one touch of an earlier block this file sanctions, because it changes a path's spelling and no observation. A hit the rewrite cannot clear means **no commit**: handle the edit as **Wrapper exit status** below handles exit 2 — a first write is left untracked, a later write is reverted with the file tool — and report it. **On `2`, or a needle command that fails**, the check could not run: log it and go on to the wrapper — best-effort, `## What the orchestrator may log — rules` → rule 4; with some needles resolved, run with those and log which source failed. The check binds this intake file only: a document that imports this section's reasoning and wrapper exit codes does not import the check.

**Exact staging + commit.** Pass **only** the intake file as the single explicit path — the wrapper stages exactly that path with `git add -- <path>` and never `git add -A` / `git add .` (matching the committer's no-blanket-add rule), and a path that does not exist is skip-with-warning rather than a hard error. Keep the fixed subject `chore: Log improvement observations for <branch>` verbatim — **the same subject in both flows**, stated once here so neither activating fork can drift it:

```zsh
bash <scripts_dir>/commit-on-branch.sh --repo "$REPO_ROOT" \
  "<state_dir>/improvement_observations/${branch}.md" \
  -- "chore: Log improvement observations for ${branch}"
```

using the `$REPO_ROOT` the activating flow resolved once at session start from its `<repo_root>` binding — the wrapper path is repo-relative, so no app-root prefix belongs on it. No `Co-Authored-By:` / trailer (project convention) and no `--no-verify` / hook-skip flag — the wrapper enforces both: it builds the message from the positional args after `--` only (subject only here) and never passes `--no-verify`. Do not bypass a hook with a hook-skip flag and do not create a partial commit.

**Wrapper exit status (surface the error).** The wrapper returns a loud non-zero on any non-commit outcome — surface it rather than retrying or bypassing. The codes are: **exit 0** (committed), **exit 1** (non-git dir / detached HEAD / hook failure — surface the error), **exit 2** (protected-branch refusal — surface the error), **exit 3** (nothing to commit). **Exit 3 is the expected outcome whenever the write added nothing** — typically a resumed run that observed nothing of its own and so appended nothing to an already-tracked file: what is there is already committed, so there is nothing to commit — not an error, and not something to retry. Surfacing an exit 1 / exit 2 means logging it, not halting: this step is best-effort and never blocks the D.2 Done summary. ⚠️ **But do not walk away from the edit you just made** — and what that takes depends on **which** non-commit status you got, because the wrapper stages *before* it commits. (A **later** write below is one whose intake file is already tracked — a user-review-fix round, or a resumed run, writing to a `<branch>.md` an earlier run already committed; **the operative condition is tracked-ness, not the shape of the write.**) **Exit 2 leaves nothing staged** — the protected-branch refusal returns before the wrapper's staging loop, as do exit 1's non-git-dir and detached-HEAD flavors: on a **first** write the intake file is merely untracked, and the engine's clean-tree checkpoints tolerate untracked `<state_dir>/…` artifacts, so a refusal is harmless there; on a **later** write the file is already **tracked**, so leaving the edit would make the tree **dirty** at the Phase-D checkpoint and break the clean-tree invariant this commit point exists to preserve — **revert your edit**, restoring the file to its committed content (on the usual append, by deleting the block you just added), which on its own restores a clean tracked tree. **Exit 1 from the failed `git commit` leaves the path already staged**, so the tree is dirty-tracked whichever kind of write this was: on a **later** write, revert as above **and then re-stage the reverted path** so the index matches HEAD again — one plain, single-statement, **bare** `git add -- <state_dir>/improvement_observations/<branch>.md` with `<branch>` spelled **literally** (no `${branch}` expansion, no `-C`), the form the autonomous profile's `Bash(git add:*)` entry allows and the run's worktree cwd resolves, on the same bare-command reasoning `${CLAUDE_PLUGIN_ROOT}/instructions/autonomous_pause_and_ledger.md` §2.2 gives for `git status --porcelain`; that single `git add` is the exception carved out of the never-a-bare-`git add`/`git commit` rule above, which governs the **commit** path. On a **first** write under exit 1 the file is left **staged, not untracked**, and there is no headless way to unstage it (`git restore --staged` and `git reset` both sit in the profile's `ask` list, so either would stall the run) — report that residue rather than treating it as harmless. **Revert with the file tool**: `git restore` / `git checkout` sit in that same `ask` list, so either would stall a headless run too. Whatever the outcome, record it — the wrapper's exit code, anything left staged, and the observations you could not land — in the Done summary instead (`## Surfacing it in the Done summary`); the `## Push` step below still runs unconditionally and is a documented no-op on exit 1 / exit 2, so the revert may come before or after it, whichever is convenient. Best-effort means the run continues, never that the tree is left dirty where the profile lets you clean it.

## Push

The push follows the commit **immediately**, as a **plain, single-statement** Bash command, using the same session-start `$REPO_ROOT`:

```zsh
bash <scripts_dir>/push-branch.sh "$REPO_ROOT"
```

> ⚠️ **No exit-code gate — this is deliberate and load-bearing.** Do **not** wrap the push in `if [ "$?" -eq 0 ]; then … fi` (or any `if …; then … fi` / `for …; do … done` block). Per the canonical rule in `${CLAUDE_PLUGIN_ROOT}/instructions/autonomous_pause_and_ledger.md` §1.6, such a control-flow block is a **headless trap**: `allow-safe-compounds.sh` splits on `;` and the ` then bash …` piece begins with a non-allow-listed prefix, so the command falls through the safe-compound allow, nothing else matches it, and the run **stalls on a permission prompt it cannot answer headlessly** — and the commit is silently **NOT** made. A `$?` test is also unreliable here for a second, independent reason: each Bash tool call runs in a **fresh shell**, so a gate issued as a separate call from the command it gates inspects the new shell's status, not the wrapper's. **No gate is needed anyway** — `push-branch.sh` is non-fatal and only fast-forwards already-committed work, so an unconditional push is a harmless no-op ("Everything up-to-date") in every non-commit case the step can reach: when the wrapper **refused** (exit 2, protected branch) or **failed** (exit 1, hook failure), and when it returned its **nothing-to-commit status** (exit 3 — a re-entry that appended nothing, typically a resumed run). **A run that observed nothing with no intake file yet tracked reaches none of these** — it skips the whole step, so no commit *and no push* is issued at all. The helper is best-effort (it exits 0 and logs on any failure — non-git dir, detached HEAD, protected branch, transient push failure), so a push problem is visible but never blocks the D.2 Done summary.

The push reaches **only** the run's own **non-protected worktree branch** — a local→remote sync of an already-landed commit, not an extension past Phase D. Each activating flow's **Hard boundary** is therefore unchanged: the flow still ends at "branch ready for review," never merges, never pushes to a protected branch, and never opens a PR.

## Ledger / resume

This step runs **inside the activating flow's Phase D re-runnable region** and gets **no** separate flow-progress-ledger entry — do **not** add a `[ ]`/`[x]` flip for it. It is **safe to re-enter, not byte-idempotent**: a pause/resume within Phase D re-enters this step, and the resumed session appends only its own observations (nothing, in the common case) on top of whatever already landed. A re-entry that appends nothing — the normal case, the freely-observed class being unrecallable and the trip-wire class already present — writes no file change and yields wrapper **exit 3** (nothing to commit, and the unconditional push is then a harmless no-op); a re-entry that appends a genuinely new observation commits normally at exit 0. The one exception is a re-entry whose machine-path check rewrote a path in an earlier block (`## Commit mechanics` → **Machine-path check — before every wrapper call.**): the file changed, so the wrapper commits at exit 0, and that commit carries no observation of this session's. Neither outcome is an error, and neither loses or duplicates an earlier block.

**Ordering constraint — the write must precede the flow's terminal Phase-D ledger flip.** That flip is the **last** ledger entry of the run, so a pause taken *after* it resumes into a Phase D that resume-from-ledger skips **entirely**: any observations not yet written would be lost permanently, with no artifact left to recover them from. The write therefore lands **before** that flip, every time. **The activating Override names which entry that is** (for reference, `D` in the task flow and `R5` in the user-review-fix flow — the Override is the owner of both) and amends its own fork's Override G bullet, so the ordering is also stated where that entry is defined.

## Surfacing it in the Done summary

When observations were logged, the run's D.2 Done summary carries one additional bullet, alongside that flow's branch-statistics bullet:

`📋 <N> improvement observation(s) logged → <state_dir>/improvement_observations/<branch>.md`

`<N>` is the count **actually written** to the file — never a rounded, intended or estimated number. **Omit the bullet entirely when this session logged no observations** — whether the whole step was skipped, or it was entered on an already-tracked file and appended nothing. Same discipline the statistics bullet uses when D.1 returns `error:`. **A reverted write is not "logged" either:** on a **later** (already-tracked) write, a wrapper exit 1 / exit 2 means the edit is reverted (`## Commit mechanics`), so the file no longer carries those observations — do not emit this bullet as though it did; report the exit code and the observations you could not land in the Done summary instead. On a **first** write nothing is reverted and the file does carry the observations, so emit the bullet — but say alongside it that the commit did not land, and on an **exit 1** that the file is left staged rather than untracked (`## Commit mechanics`). **A machine-path check that could not run, or a hit it could not clear, is reported in the Done summary beside this bullet**; a hit that was rewritten and cleared is not, and a file left uncommitted by an uncleared hit gets the same bullet treatment as a reverted or unlanded write. **Exit 3 means this session appended nothing** (any append changes the file and commits at exit 0 — but exit 0 alone does not mean this session appended, because a machine-path rewrite of an earlier block commits at exit 0 too; the bullet counts what this session appended, never the exit code), so there is nothing for this session to report: omit the bullet, and never count an earlier session's or round's blocks as this run's — including a trip-wire this session re-derived but did not re-append. Neither core's D.2 bullet list is edited to add it — the **activating Override** states that its own fork emits this additional bullet.
