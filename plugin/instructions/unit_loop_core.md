# The unit loop — canonical implement → [review] → commit loop (mode-free, family-neutral)

This file is the **single owner** of the implement → \[review\] → commit loop that every phase-driven flow runs over a readiness list: pick the next unit, route it to a layer, dispatch an implementer, optionally review, commit, repeat. Callers **cite it by reference and never restate it** — a phase says which substitution row it runs and nothing more. A family that needs its own variant **appends a row to the substitution table below**; it does not declare a copy of the loop elsewhere.

> **The bindings in effect here are those of the fork the citing flow was dispatched via** (`mode_contract.md` rule (5)). This file supplies no mode-specific values and names no fork.

---

## Resolved values

The three tokens below resolve from the adopting repository's `harness.config.json`. They are declared here once; after this table the body uses each one as an ordinary placeholder. Two other kinds of `<…>` name in this file resolve elsewhere and are deliberately **not** listed here: mode-contract **bindings** (`<escalate>`, `<per_unit_review>`, `<committer_push>`) resolve from the binding table of the fork the citing flow was dispatched via, and ordinary **path placeholders** (`<branch>`, `<story_path>`, `<task_file>`, …) resolve from the flow's entry core `## Setup`. `### Placeholder resolution` below states that split and the substitution table's `Placeholder owner` column applies it — this section changes neither, and its clause (ii) is about the remaining `<…>` names rather than the three config values here.

| Token | Class | How to resolve it |
|---|---|---|
| `<state_dir>` | config value | `harness.config.json` → `stateDir` — the run-artifact tree every artifact path in this file is relative to. Default `sdlc-harness/`. It is never dot-named: no path segment of it may begin with a dot. |
| `<layer_names>` | config value | `layers[].name`. **No substitution of the names themselves** — the configured names travel through this file unchanged, because `## Layer routing table` passes the layer as a dispatch argument rather than selecting an agent filename by it. `general` is one of the `layers[]` rows a generated config emits (`{ "name": "general", "path": ".", "conventions": … }`), not an entry beside the array. |
| `<layer_path_map>` | config value | `layers[].path` together with `layers[].conventions` — the two values `## Layer routing table` passes to the implementer and the reviewer alongside the layer name. |

## Mode contract — bindings this file uses

The three names below are Mode-contract **bindings**. This file states behaviour; the fork the citing flow was dispatched via carries the values inline. `mode_contract.md` owns the mechanism and the full vocabulary. **None of these has a default here — an unbound binding is a stop condition** (mechanism rule (1)): halt and report rather than guessing a value.

| Binding | Used at | Meaning (short) |
|---|---|---|
| `<escalate>` | `## The unit loop` step 3 (the implementer reports an **escalating** blocker — one whose line does **not** carry the `prohibited — ` marker; a marked one takes `### The dispositioned outcome` and never reaches this binding); `### Per-unit review step` (the review loop does not converge) | This flow's path for halting and reporting an **agent/flow blocker**. |
| `<per_unit_review>` | `## The unit loop` step 4 (the extension point); the whole of `### Per-unit review step`, including its `iteration >= 5` convergence cap; `## Layer routing table` (its `Reviewer` column) | `on` \| `off` — whether the per-unit reviewer step runs between implementer and committer. |
| `<committer_push>` | `## The unit loop` step 5 (the `committer` dispatch block) | The extra arg line appended to each `committer` dispatch — omitted, or `push: true`. |

This file declares no other binding. Every remaining `<…>` name it uses is a **config value** (`## Resolved values`), a **path placeholder**, or a locally-defined name — see `### Placeholder resolution`.

**The third unit outcome adds none either.** `### The dispositioned outcome` is deliberately **not** a fourth binding: it takes no per-fork value, and a fourth row here would halt every fork that has not bound it — the mechanism rule stated above.

## Layer routing table

Read the `_(layer: …)_` tag on the readiness entry selected in step 1 — it is on the line already read off the row's index. **Do NOT open the detail file to route**; that file is the implementer's (and, when per-unit review is on, the reviewer's) ground truth, not a routing source. The tag lists one or more layer names in bottom-up order. Map each tag value to its dispatch:

| Layer tag value | Implementer | Reviewer | Dispatch arguments |
|---|---|---|---|
| any one of `<layer_names>` — **one row per `layers[]` entry** in `harness.config.json`, and no other value routes | `layer-implementer` | `layer-reviewer` | the layer name (the tag value itself), plus that entry's `layers[].path` and `layers[].conventions` taken from `<layer_path_map>` |

**The table is generic because the layer set is adopter-configured**: `layers[]` is an arbitrary list, so an agent-per-layer scheme cannot be generated for it — the layer travels as a dispatch argument to two agents instead of selecting one of a fixed set of agent filenames.

**Catch-all.** Work that lands in none of the other layers' paths goes to **the layer whose `path` is `"."`** — the row every `init`-generated config supplies as `general`. If a hand-written `layers[]` carries no such row, that is a **configuration gap**: report it through `<escalate>`; never invent a layer name, widen another layer's `path`, or edit the config.

**The `Reviewer` column is consumed only when `<per_unit_review>` is `on`.** When it is `off`, the routing table selects an implementer and nothing else.

**A story-plan `**Task K**` entry always carries exactly one layer**, so for a story-plan task this step selects exactly **one** implementer (and, when per-unit review is on, its reviewer) from the table and runs that single layer through the loop.

The multi-layer case applies to **`**Finding K**` (code-review) and `**Test K**` (UI-test) entries only** — their tag is a fix-target path that can legitimately span layers. When a finding/test tag is comma-joined, the multi-layer set comes from that tag, already in bottom-up order — the layer whose `path` is `"."` runs last, because it usually documents or wires up what the other layers built (in a `layers[]` of `data`, `domain`, `presentation`, `general` that reads `data → domain → presentation → general`). Run the layers in the tag's listed order — **each one through steps 3–4 of `## The unit loop`, with step 5's commit landing once, after the last**.

## The unit loop

**Pre-dispatch rule — binding on all three dispatches this loop makes.** Before **each** of the implementer, reviewer and committer dispatches below, apply the `## Safety contract` of the **flow's own entry core** — the core named by the fork the flow was dispatched via, resolved exactly as `### Placeholder resolution` defines it, **never the immediate citing file**: STOP-file check → dispatch-counter increment → heartbeat → compose the prompt. Build the heartbeat from the **active substitution row's `Heartbeat unit label`** cell and the layer being dispatched — **or the literal `commit` in that field for the step-5 committer dispatch, which has no layer**, per the entry core's heartbeat examples. E.g. row `E.3` → `[E · Finding 2 · presentation · iter 0] → layer-implementer  (#N)`; row `A`'s commit → `[A · Task 3 · commit] → committer  (#N)`. On that fourth item: the prompt for each of the three dispatches is this row's spec and nothing more, plus at most the one sanctioned `context_notes:` line — **Knowledge, not conclusions**, canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/dispatch_discipline_instructions.md`, which this file points at and does not restate.

**This file neither owns nor restates that contract.** The STOP path, the counter commands and their headless-guard warning, and the heartbeat format all live in the entry core, and the compose step is owned by `${CLAUDE_PLUGIN_ROOT}/instructions/dispatch_discipline_instructions.md` — the boundary, the sanctioned form and the record it names are that file's, in full; this file says only *apply it, with this row's label*. That is exactly what keeps the rule mode- **and** family-neutral. A reader who reaches this file with no entry core in hand has entered it wrongly and must go read one (same resolution as `### Placeholder resolution` below).

The steps, in order:

1. **Pick the unit.** Read **only** the row's readiness index (not the detail files). Locate its `## Phase 2 Readiness — Ordered Fix List` section — positioned near the top of the file, immediately after `## Context` — and walk the entries top-to-bottom. The **first `[ ]` entry** is the next unit of work — and if **no** `[ ]` entry remains (including on first entry, e.g. a resumed run that re-enters an already-complete index), the loop is already complete: end it and return to the calling phase, exactly as step 6 does. **Strictly ignore `[ ]` markers anywhere else**: implementer agents tick `- [ ]` sub-step bullets inside detail files to track their own progress, and those are informational only, never iteration targets. Resolve the entry's reference token (the row's `Entry token`) to the row's `Detail file` path, and derive the unit's heading from the row's `Heading source`. Where the row's `Per-item findings folder` is keyed by `item_<N>`, `<N>` comes from that same walk: the first `[ ]` entry inside the section is `item_1`, the second is `item_2`, and so on.
2. **Route.** Read the entry's `_(layer: …)_` tag and map it via `## Layer routing table`. **Never open the detail file to route.**
3. **Per layer in scope.** On entering a layer, `iteration = 0`. **Apply the pre-dispatch rule**, then dispatch `layer-implementer` — with `<layer>` and its `<layer_path_map>` values as dispatch arguments, per `## Layer routing table` — carrying the row's prompt:
   - First iteration: `Implement <heading> from <detail_file>.` — plus the row's `Implementer prompt extras`, if any.
   - Fix iteration: `Fix <heading> per <findings_file> from <detail_file>.` where `<findings_file>` is the most recent `review_*.md` in the row's `Per-item findings folder`.

   Either prompt may carry one optional trailing `context_notes:` line, as `${CLAUDE_PLUGIN_ROOT}/instructions/dispatch_discipline_instructions.md` defines it, and **nothing else may be appended** to it. Step 5's committer dispatch takes that same optional line and needs no separate spec here.

   Receive its return and read a blocker line in **two arms** — the return form `layer-implementer` defines, restated here so this loop never guesses it. **A blocker whose line carries the literal marker `prohibited — `** — full form `blocker: prohibited — <one-line cause>; disposition appended to <detail_file>` — takes `### The dispositioned outcome` below. That marker is the **wire** between that agent's contract and this loop: match it as a literal string, never re-derive it from the cause's wording, and never accept a paraphrase of it. **Any other blocker stops the whole loop and `<escalate>`s**, exactly as before. No blocker: continue. **The fail-safe direction is escalate** — a return that is ambiguous, or that reports a blocker without the marker, is the escalating kind: a wrongly-escalated unit costs one hand-off, a wrongly-dispositioned one closes a finding nobody fixed.
4. **Per-unit review — extension point, governed by `<per_unit_review>`.** When it is `on`, run `### Per-unit review step` below before continuing. When it is `off`, skip the review: `iteration` stays `0`, the per-unit convergence cap does not apply, and the implementer's own blocker report (step 3) is the only per-unit stop. **Either way, when this layer finishes cleanly, continue with the next layer in scope (back to step 3); go to step 5 only after the last in-scope layer has finished** — the commit lands **once per unit**, never once per layer.
5. **Commit.** **Apply the pre-dispatch rule**, then dispatch `committer` with the row's `committer mode` as `mode:`, the row's readiness index as `plan_path:`, the row's `committer extra args`, a `commit_prefix:` chosen by the row's `commit_prefix rule`, and `<committer_push>`.
6. **Emit one progress line** naming the unit just committed — the row's `Heartbeat unit label` followed by `committed: <sha> <subject>` from the committer's return (row `A`: `Task N committed: <sha> <subject>` — the source loop's own wording, where `N` is the same task number row `A`'s `Task <K>` label calls `K`; see `### Named exceptions` → **Row A**), and when the committer's return carries a `plan_flipped: already-[x]: <entry> — not flipped by this committer` report, append that report to the same line verbatim — no halt, no park, no `<escalate>`; the run continues and the fact is on the record. **A `staged: index-only — …` line on that same return takes the same treatment** — append it to the line verbatim, no halt, no park, no `<escalate>` — it is the loop's only notice that this unit's commit staged the readiness index and no work file. **When any layer of this unit took `### The dispositioned outcome`, the line gains one more clause** — `dispositioned: ` followed by the same one-line cause step 5's `disposition:` argument carried — in that same shape: appended verbatim, no halt, no park, no `<escalate>`, the run continues. Then return to step 1. **This post-commit progress line is not the pre-dispatch heartbeat of step 5; both exist and neither replaces the other.** Do not pause for input. When every `[ ]` in the row's readiness index is `[x]`, the loop ends and the calling phase continues. **Where the dispositioned fact goes on:** a flow that keeps an improvement-observations intake and a Done summary reports it in both, through its own override; a flow that keeps neither leaves the record in the unit's detail file, on its commit and on this line. This file names no fork, no override and no phase — `mode_contract.md` rule (5)'s boundary, as the note at the top of this file states.

### Per-unit review step (`<per_unit_review>` = `on`)

This is the **one and only** statement of the per-unit review body. It runs between step 3 and step 5, once per layer in scope, and only while `<per_unit_review>` is `on`. Everywhere it is cited — this file's own cells and steps, and its callers — it is named by the short form `### Per-unit review step`; the gate suffix this heading carries is not part of that name.

`iteration` is reset to `0` at the start of each layer of each unit (step 3); the cap below exists to prevent one stuck layer from running forever, **not** to limit the whole session. Hitting it stops that layer's loop and reports — it does not end the whole flow.

**The pre-dispatch rule of `## The unit loop` applies here too**: apply the **flow's entry core's** `## Safety contract` before the reviewer dispatch, and again before each fix re-dispatch of the implementer, with the heartbeat label taken from the row's `Heartbeat unit label` cell and the layer under review.

Dispatch `layer-reviewer` — with the same `<layer>` and `<layer_path_map>` dispatch arguments the implementer took — with this fenced block, whose first line and whose `task_file:` / `task_heading:` / `findings_folder:` values all come from the **active substitution row**; `iteration:` is this loop's own counter:

```
<the row's `Review prompt first line`>
task_file: <the row's `Detail file`>
task_heading: <the row's `Heading source`>
findings_folder: <the row's `Per-item findings folder`>
iteration: <iteration>
context_notes: <omit entirely when you have no fact to pass — see ${CLAUDE_PLUGIN_ROOT}/instructions/dispatch_discipline_instructions.md>
```

Anything added to this block outside that last line is a violation the record `${CLAUDE_PLUGIN_ROOT}/instructions/dispatch_discipline_instructions.md` defines must show.

(The reviewer creates the findings folder itself only when it has findings to write — do **NOT** `mkdir -p` here.)

Parse the reviewer's return:

- `verdict: PASS` → leave this layer and continue the loop (the next layer in scope, or step 5 if this was the last).
- `verdict: FAIL` → increment `iteration`. **If `iteration >= 5`, `<escalate>`** with the path to the latest findings file and a one-paragraph summary of the situation — `5 review iterations on …, layer X, did not converge`, naming the unit with the row's `Heartbeat unit label` (row `A`: `5 review iterations on Task N, layer X, did not converge`). Otherwise loop back to **step 3's implementer dispatch** with the fix prompt — step 3's `iteration = 0` reset is per layer, per unit, and is **not** re-applied on a fix iteration.

**Ownership.** A fork binds `<per_unit_review>` and **nothing more**: no fork restates this body, and no fork may cite another fork *for it*. The review step is flow-body content owned here, so it sits squarely inside `mode_contract.md` rule (5)'s scoped prohibition — see that rule for the enumerated `### Sanctioned cross-fork anchors` that fall **outside** the prohibition; this file neither repeats nor narrows that list. Per-row wording deltas belong in that row's `Exceptions` cell, never in this body.

### The dispositioned outcome

Step 3's **third** exit for a layer, reached only by a blocker line carrying the `prohibited — ` marker. It is neither a success nor a stop: the unit is **closed**. It applies to every row of `## Substitution table` unchanged — the exit is row-neutral and no row owes a cell for it. (`<one-line cause>` and `<commit_conventions>` in the forms quoted below are the two agent contracts' own names — `layer-implementer.md`'s and `committer.md`'s — reproduced here and resolved there, per `### Placeholder resolution`'s class for names quoted out of another document.)

- **What it is.** This layer's work is accepted as correctly diagnosed and impossible for **any** agent in this flow. This file states the outcome; `layer-implementer`'s contract states the admissibility test that let the return carry the marker. Neither restates the other, and this loop re-runs no part of that test.
- **What already exists on disk.** The implementer appended a `## Disposition` section to the unit's detail file before returning. The loop writes nothing itself and opens no detail file and no findings body to decide — the marker on the return is the whole decision.
- **The review step is skipped.** Step 4 is not entered for this layer: there is no code to review. `iteration` is untouched.
- **The loop continues.** This layer is finished — continue with the next layer in scope (back to step 3), or go to step 5 if it was the last.
- **It never parks and never escalates.** This exit adds no channel, no sentinel file and no clarification question, and the flow's `<escalate>` binding is not reached from it.

**The readiness marker still flips `[ ]`→`[x]`.** `[x]` means the unit is **closed**, and the disposition is its closure — recorded in the detail file and on the unit's commit (in its subject or in a body line, per the committer's rule), the two artifacts a reader has. **No third readiness marker is minted**, and the reason binds anyone tempted to add one: step 1 walks for the first `[ ]`, the committer resolves the entry and flips `[ ]`→`[x]` and nothing else, and every completion check downstream reads those two markers — a third would have to be taught to all of them at once.

**Step 5's commit, as this exit calls it.** The dispatch is unchanged in mode, `plan_path`, `task_heading` and `<committer_push>`; it additionally carries `disposition: <one-line cause>` — the argument name and shape `committer.md` defines — taken from the implementer's return **by position, not by judgement**: in the form `blocker: prohibited — <one-line cause>; disposition appended to <detail_file>`, the cause is the text **after the first `prohibited — ` and before the last `; disposition appended to `** on that line, passed verbatim, trimmed of surrounding spaces and of nothing else, never re-worded — the committer normalises it for the wrapper and no one else touches it. That argument goes whenever **any** layer of this unit was dispositioned. **One argument, one cause, and this is the one that goes:** the **first** dispositioned layer's cause in the order this loop already processes the unit's layers — the readiness entry's `_(layer: …)_` tag order, which `## Layer routing table` states is *"one or more layer names in bottom-up order"*. Pass no second one — the commit lands once per unit, and a second record on one commit is forbidden by the committer's own rule. Nothing is lost by that: **every** dispositioned layer's diagnosis is in the unit's detail file, each written there as its own `## Disposition` section by its own implementer, so only the commit's one-line record is first-only — and an entry derived from that record says *the cause recorded on the commit*, not *the unit's cause*.

**Passing the argument is what puts the disposition on the commit's record; the committer decides only where.** Its reconciliation rule makes it the **subject** when the commit staged nothing but the index and the unit's detail file, and a commit **body line** when another layer of the same unit landed real files and the subject therefore describes that work. Do not restate the record's **case** here and do not spell it in a second case: its leading word takes `<commit_conventions>`'s capitalisation like every other free-form subject's, and the downstream reader matches that word case-insensitively — both facts are the committer's to state, named here only so this loop invents no casing rule of its own. Either way the record is on the commit, so a unit that mixes a dispositioned layer with one that landed code is not silently lost. This loop makes no second decision about the placement and emits no second commit: the commit still lands **once per unit**, as `## Layer routing table` requires.

### Placeholder resolution

The `<…>` tokens in this file's rows, cells and named exceptions are of **two kinds**, resolved from two different places.

**(i) Mode-contract bindings** — exactly the three declared in `## Mode contract — bindings this file uses` (`<escalate>`, `<per_unit_review>`, `<committer_push>`). They resolve from the **binding table of the fork the citing flow was dispatched via** (`mode_contract.md` rule (5)). An unbound one is a stop condition.

**(ii) Path placeholders** — every other `<…>` token here (`<story_path>`, `<task_file>`, `<parity_review_path>`, `<code_review_path>`, `<qa_review_findings_dir>`, `<qa_fix_findings_root>`, and any a later family's row introduces). They are **not** bindings, are defined **nowhere in this file**, and resolve from the `## Setup` of the **flow's own entry core**: *the core named by the fork the flow was dispatched via, regardless of how many core→core citations deep the text sits.* A few are stated in a row's own cells in terms of the others (`<task_file>` = `<task_files_dir>task_<K>_plan.md`; `<finding_file>`, `<task_heading>` and `<finding_heading>` likewise) — those still bottom out in that same `## Setup`, via the row's `Placeholder owner`. The exclusions are **reasons, not banned files** — being the **immediate citing file**, being the **file that contains the text**, being the **family a cited section originated in**, or being a **fork** confers no ownership of a path placeholder; only being the entry core does. When one of those files *is* the entry core for the flow in hand, it owns them for that flow — solely on that ground.

This matters because two of these names are defined **differently** by the two cores that reach this file: one family's `## Setup` defines `<qa_review_findings_dir>` and `<qa_fix_findings_root>` with no round suffix, the other's as a next-free `<round>` slot (both definitions, with sources, are in the `Placeholder owner` footnote under the table). **Worked example, two hops:** row `E.3` is reached by both. A flow whose entry core is family 1's reaches it via that core's own `## Phase E`, so both QA folders resolve from **family 1's** `## Setup`. A **family-3 flow reaches it two hops deep** — family 3's fork → family 3's core `## Phase QA` → family 1's core `## Phase E` → this row — and its entry core is **still family 3's**, so both QA folders resolve from **family 3's** `## Setup` instead: its QA.0 next-free slot, which is the unsuffixed folder while that slot is free and the round-suffixed one once it is not. **Resolve the folder; never pre-compute its shape.** Resolving it instead from the immediate citing file (family 1's core, where `## Phase E` happens to live) or from the row's originating family (also 1) lands a family-3 flow in the exact folder its round resolution exists to avoid — the moment the task-plan flow has already produced one — and that failure is silent.

**Transitional clause** (owned by `mode_contract.md` rule (5)'s `Bindings vs. path placeholders` paragraph): a flow whose family has **no core yet** resolves its path placeholders from its **entry document's** own `## Setup` — the fork itself — and that is the **only** case in which a fork owns them; it exists solely for the transitional state and ends when that family's core lands. The steady-state formulation above stays primary and the exclusion list is unchanged: the clause fixes *when* a fork owns paths, it does not reopen the exclusions, and it never applies to a flow whose family does have a core.

**Three kinds of name are neither**, and are defined in this file at their point of use: `<layer>` (the output of `## Layer routing table`), `<iteration>` (this loop's own counter, set in step 3 and advanced in `### Per-unit review step` — **not** the QA round-index `<iteration>` that appears inside row `E.3`'s `<qa_review_path>`, which is always `0` and comes from the entry core's `## Setup`), and the ellipses inside quoted literals — `<heading>` / `<detail_file>` / `<findings_file>` in step 3's prompts (each named as the row cell it comes from), `<title>` inside the quoted `### Task K — <title>` heading pattern, `<sha>` / `<subject>` / `<entry>` in step 6's progress line (all three from the committer's return), and `<task_heading>` / `<finding_heading>` / `<item_heading>` in the `committer extra args` column and the ⚠️ note (each defined by its own row's `Heading source` cell). The same applies to names quoted **out of another document**, which this file reproduces but does not resolve: `<branch>` / `<round>` inside the `## Setup` values reproduced in the `Placeholder owner` footnote (each owned by the core quoted there), and `<mode>` inside the ⚠️ note's quotation of `committer.md`'s `error: task_heading required for mode <mode>` return (owned by that agent contract).

**The reader's tell.** An unbound *binding* is a stop condition. An unresolved *path placeholder* means you entered this file without your entry core's `## Setup` — go read it, or, if your family has no core yet, use your entry document's own `## Setup` per the transitional clause above.
