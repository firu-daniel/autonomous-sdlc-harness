# samples/

The worked fixtures that instruction and agent bodies dereference **by path** rather than restate inline, so a writer agent is shown the exact shape it must produce instead of being told about it in prose. Every fixture a shipped command, instruction or agent body points at now exists here. `sample_task_plan.md` is the split-format reference that explains how a thin index and its per-item directory fit together; `sample_story_plan.md` is the story index that split produces, with `sample_story/task_1_plan.md` through `task_3_plan.md` as its per-task files; `sample_code_review.md` is the code-review index, with `sample_code_review/finding_1.md` through `finding_3.md` as its per-finding files; `sample_user_review.md` is the review a user writes by hand; `sample_user_review_fix_plan.md` is the fix plan a writer derives from it, with `sample_user_review_fix_plan/finding_1.md` through `finding_3.md` beside it; and `sample_statistics.md` is the branch-statistics report. The plan, code-review and fix-plan fixtures ship as a thin index file alongside a per-item directory, because that split is itself part of the shape being demonstrated. These fixtures are the format canon and the only fixtures any plugin asset dereferences; a worked run over a real project also exists, in the harness's own source repository rather than in this plugin, and it is a demonstration of what the pipeline produces rather than a second statement of the format.

They describe **one coherent worked branch** — the recent-searches panel on `feat/recent_searches_panel` — and that is a constraint rather than a presentation choice: the fixtures cite each other by task number, finding number and quoted title, and the statistics report's arithmetic is derived from the story index and the user review rather than chosen. A fixture edited in isolation breaks the set, so a change to a task title, a finding number or a `_(points: …)_` tag is checked against every file that names it.

The interactive-test plan fixtures — an index and its per-test files — are part of the intended set but are **owed by no item**, because nothing in the plugin dereferences one. Regenerate the demand with `grep -rno 'samples/[A-Za-z0-9_<>/]*\.md' plugin/` and diff it against `find plugin/samples -type f`; a name on the first list that is missing from the second is a broken pointer, and a file on the second that is missing from the first is a fixture nothing reads.

Every reference to a file here, from anywhere in the plugin, is written `${CLAUDE_PLUGIN_ROOT}/samples/<file>` — never a relative or sibling path, because the plugin's runtime root is machine-local and differs between a git-sourced install and a directory-sourced one, and only the `${CLAUDE_PLUGIN_ROOT}` form resolves under both. Two things in this directory are not that kind of reference and are not exceptions to it: the bare filenames above, which are this README naming its own contents, and the relative markdown link an index fixture carries to its own per-item file, which is part of the artifact shape that fixture exists to demonstrate.
