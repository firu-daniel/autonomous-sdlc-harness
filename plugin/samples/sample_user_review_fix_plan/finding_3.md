### 3. `useRecentSearches` calls `searchService` directly, bypassing the use-case layer

Parity sentences below apply **only when `phases.parity` is `true`** in `harness.config.json`; `<parity_vocabulary>` is that file's `parity.referenceName`.

**File:** `src/presentation/search/hooks/useRecentSearches.ts` (`useRecentSearches`) — "searchService.fetchRecentSearches("

Commit `deadbeef` added `useRecentSearches`, which imports `searchService` from the data layer and calls `searchService.fetchRecentSearches(...)` directly from the hook. This skips the domain layer: the call flow these `layers[]` declare is `presentation → domain → data`, i.e. `hook → use case → service`, never `hook → service`. Calling the service from presentation means the hook now depends on a data-layer type, there is no use case to unit-test the recent-searches logic in isolation, and any mapping or business rules that belong between the service and the UI have nowhere to live. The `<parity_vocabulary>` implementation routes the equivalent screen through its own recent-searches use case.

**Fix:** introduce `fetchRecentSearchesUseCase` in the domain layer (`src/domain/search/usecases/fetchRecentSearchesUseCase.ts` → `FetchRecentSearchesUseCase`) that depends on `searchService`, returns the mapped recent-search entities, and is covered by a `fetchRecentSearchesUseCase.test.ts`. Then change `useRecentSearches` to call `fetchRecentSearchesUseCase.execute(...)` and drop its direct `searchService` import, so the hook depends only on the domain layer.
