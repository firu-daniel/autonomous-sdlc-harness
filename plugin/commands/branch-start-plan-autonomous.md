# Scope: Run the current branch's task prompt end-to-end, autonomously (plan → implement → branch ready for review)

## Resolved values

The tokens below are not ordinary **path placeholders** (`<branch>`, `<n>`, `<N>`, `<MAIN_REPO>`, which this file's own text resolves — `<MAIN_REPO>` in step 2): they resolve from the adopting repository's `harness.config.json`. They are declared here once, and after this table the body uses each one as an ordinary placeholder. The mode-contract **binding** names the body cites (`<terminal_handoff>`, `<existing_artifact_decision>`, `<escalate>` / `<ask>`, `<per_unit_review>`, `<committer_push>`, `<repo_root>`, `<app_root>`) are a third vocabulary: each is declared in its own fork's `## Mode contract — bindings` table, and this command only names the value that table carries. Two of them this command **supplies** — `<repo_root>` and `<app_root>` — and step 1 derives those at runtime, as `$REPO_ROOT` and `$APP_ROOT`.

| Token | Class | How to resolve it |
|---|---|---|
| `<app_dir>` | config value | `appDir` — the app's directory inside the checkout, repo-relative. Step 1 builds `APP_ROOT=$REPO_ROOT/<app_dir>` from it, and that resolved root is the value the implementation fork's `<app_root>` binding takes. |
| `<state_dir>` | config value | `stateDir` — the run-artifact tree every artifact path in this file is relative to. Default `sdlc-harness/`. It is never dot-named: no path segment of it may begin with a dot. |
| `<scripts_dir>` | config value | `scriptsDir` — the directory the outer-loop scripts live in. This file names two of them — `autonomous-watcher.sh`, as the owner of the responsibilities this command deliberately does not have, and `push-branch.sh`, in the hard boundary — and invokes neither. |
| `<default_branch>` | config value | `defaultBranch` — the branch work starts from and merges back into. Never a remembered branch name. Bound for completeness — no step in this file consumes it. |
| `<protected_branches>` | config value | `protectedBranches` — the branches the hard boundary below forbids merging into, pushing to, or opening a PR against. The effective set is these together with `<default_branch>`. The `pre-push` git hook enforces that set; above it, the plugin's `PreToolUse` protected-branch guard together with the generated permission profile's `Bash(git push:*)` **`ask`** entry — evaluated before any `allow`, and unanswerable in an unattended run — is the best-effort layer. |
| `<reference_impl>` | config value | `parity.referenceImplPath` — the path to the reference implementation this project is kept in parity with. The parity reviewers' reads resolve from it, and **only** when `phases.parity` is `true`. |

## Context

This is the **one** autonomous engine command. It is the **execution-context-agnostic** entry point that chains autonomous **planning** straight into autonomous **implementation** in one uninterrupted session, ending at "branch ready for review" — **no** approval gate between planning and implementation, and **no** merge into a branch in `<protected_branches>`, no push to one, and no PR at the end.

It reuses the shared instruction canon by reference and only forks where the autonomous flow genuinely differs (trigger, approval gate, clarification channel, path resolution). That canon is a **mode-free core** on both halves — `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_core.md` for **planning** and `${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_core.md` for **implementation** — with a thin autonomous fork over each:

- **Planning** runs the autonomous planning fork `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_autonomous.md` — the **mode-free planning core** (`${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_core.md`: `## Setup`, `## Safety contract`, the writer/reviewer `## Loop`, the `## UI-test-plan write loop`, `## Convergence`) verbatim by reference. Its deltas are its **binding values** — `<terminal_handoff>` = no approval gate (emit the convergence summary and fall straight through), `<existing_artifact_decision>` = the non-interactive resumability cases stated in `## Override 2 — resumability`, `<escalate>` / `<ask>` = the park-and-yield clarification reroute — plus the overrides that remain pure additions: the UI-test-plan commit at convergence (3), the task-plan commit at convergence (4), and the pause/resume + flow-progress ledger (5).
- **Implementation** runs the autonomous orchestration fork `${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_autonomous.md` — the **core's** Phases A → A1.5 → A2 → B → C → C2 → E → D (`${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_core.md`, whose implement → [review] → commit unit loop is canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md`) verbatim by reference. Its deltas are its **binding values** — worktree-relative `<repo_root>` / `<app_root>`, `<escalate>` = the park-and-yield clarification reroute, `<per_unit_review>` = `off`, `<committer_push>` = `push: true` — plus the overrides that remain pure additions: the worktree-relative reads those two path bindings do not cover (A), the global kill switch (B), the branch-statistics commit and its push (D / E), the pause/resume + flow-progress ledger (G), the docs phase (H), and the improvement-observations intake (I).

You are the **orchestrator** for the whole session. You do not draft the plan, you do not review it, you do not edit code, you do not commit — you dispatch the specialist agents the two instruction files name and read only the short contracts they return.

**This command is execution-context-agnostic.** Worktree creation, central logging, and exit notification are the **watcher's** responsibility (`<scripts_dir>/autonomous-watcher.sh`), NOT this command's. This command assumes it is already running in the correct checkout (a worktree or the main repo) and resolves every path relative to that checkout. It does not create worktrees, write to a central log, or send notifications.

## Two entry points, one engine

The same command serves both entry points — there is **no** separate `-watch` command (to "watch" is simply to run this engine interactively):

- **(a) Manual / interactive** — the user invokes `/branch-start-plan-autonomous` themselves and watches the `[A · Task <N> · …]` heartbeat live. This is the de-risking validation point and is simplest in the **main** worktree on the current branch, where every path anchor already matches (`$REPO_ROOT` resolves to the main repo, and the generated permission profile's sibling-worktree path broadening is inert there). Clarification questions surface **live** for inline answering (semi-auto behavior).
- **(b) Watcher / headless** — the watcher (`<scripts_dir>/autonomous-watcher.sh`) launches this same command with `-p` plus the generated permission profile via `--settings`, inside a per-branch worktree it created. Clarification questions are written to `<state_dir>/clarifications/<branch>/question_<n>.md`, the run yields, and the watcher marks it `parked` and resumes on an answer (the channel's format and archive-on-resume mechanism are owned by the planning fork's `## Clarification channel — file format`).

A thin `-watch` wrapper is acceptable **only** if it adds ergonomics (e.g. "run in the current worktree, skip the watcher") and contains **no** duplicated orchestration. Default to not adding one.

## Steps

1. **Derive the anchors once, at session start, and use them everywhere — never hardcode an absolute machine path:**
   - `REPO_ROOT=$(git rev-parse --show-toplevel)` — the current checkout's root (the worktree, or the main repo in the manual entry point). Obtain it with a **bare** `git rev-parse --show-toplevel` and build every literal path from the result; never embed the `$(…)` substitution inside another shell command, and never stash it in a shell variable across separate Bash calls — separate calls do not share shell state.
   - `APP_ROOT=$REPO_ROOT/<app_dir>`.
   These are the values the implementation fork's `<repo_root>` / `<app_root>` binding values take. Every project command the flow runs — type-check, tests, the dev server — is invoked through its configured `commands.*` string in `harness.config.json` **exactly as written**, from `$REPO_ROOT` (each configured string is repo-relative, so running it from `$APP_ROOT` would resolve a nested `<app_dir>` twice), never rebuilt from its parts and never replaced by an absolute path; if a configured string is **refused**, the key holds a raw command line rather than the wrapper invocation, so the run uses `bash <scripts_dir>/<name>.sh`, whose body is the line `init` inlined into it and not necessarily the configured string, and the fork reports which string it ran; and the parity reviewers' reads that the fork's `## Override A` covers resolve from `<reference_impl>`, **only** when `phases.parity` is `true`.

2. **Global kill switch — check at session start.** If `<MAIN_REPO>/<state_dir>/AUTONOMOUS_STOP` exists (the global switch in the **main** repo, distinct from the per-run `<state_dir>/STOP` inside this worktree), halt immediately and report it. Do NOT delete it — the user controls it. (`<MAIN_REPO>` is the main worktree's root — the first entry of `git worktree list` (`git worktree list --porcelain | head -1 | sed 's/^worktree //'`), or the watcher-supplied env in the headless entry point.)

3. **Determine the current git branch** with `git branch --show-current` → `<branch>`.

4. **Confirm the task prompt exists** at `$REPO_ROOT/<state_dir>/task_prompts/<branch>_task_prompt.md`, **and establish its run mode**. If missing, stop and tell the user (manual) or write the blocker to the clarification channel and yield (headless). Having confirmed it exists, run `grep -nE '^#+ *Run mode' $REPO_ROOT/<state_dir>/task_prompts/<branch>_task_prompt.md`. **No hit → this run has no run mode**: carry `none` into the loop below, emit `📌 Run mode: none` at the disclosure site, and do not open `${CLAUDE_PLUGIN_ROOT}/instructions/run_mode_instructions.md`. **A hit →** read `${CLAUDE_PLUGIN_ROOT}/instructions/run_mode_instructions.md` and follow it; it owns everything else, and none of it is restated here.

5. **Planning loop.** Read `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_autonomous.md` and follow it. It is this flow's **fork**, and it is the autonomous planning entry point: the loop bodies are the core's — `${CLAUDE_PLUGIN_ROOT}/instructions/task_plan_writing_instructions_core.md`'s `## Setup`, `## Safety contract`, `## Loop` (writer/reviewer dispatch with the `>= 5` iteration caps), `## UI-test-plan write loop` and `## Convergence` run verbatim by reference. The fork's deltas are the values in its `## Mode contract — bindings` table — `<terminal_handoff>` = no approval gate, `<existing_artifact_decision>` = the non-interactive resumability cases stated in `## Override 2 — resumability`, `<escalate>` / `<ask>` = the headless-vs-manual clarification reroute — plus its surviving overrides: the UI-test-plan commit at convergence (Override 3), the task-plan commit at convergence (Override 4) and the pause/resume + flow-progress ledger (Override 5). That fork also owns `## Clarification channel — file format` and `## Ask-vs-assume policy` for every autonomous flow. Do not duplicate or reinterpret any of it here. Planning has converged when **both** loops complete per the core's `## Convergence` — read the condition there; it states the task-plan loop's terminal state and enumerates the UI-test-plan loop's **four**, two of which are that loop never running at all (`phases.qa` is `false`, or `qa` is among the recorded skipped ids). There is **no** approval gate: emit the convergence summary as a log line and **fall straight through** to step 6 in the same session.

6. **Implementation loop.** Read `${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_autonomous.md` and follow it. It is this flow's **fork**, and it is the autonomous implementation entry point: the phase bodies are the core's — `${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_core.md` Phases A → A1.5 → A2 → B → C → C2 → E → D run verbatim by reference (C2 is the adversarial skeptic review), with the unit loop canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md`. The fork's deltas are the values in its `## Mode contract — bindings` table — worktree-relative `<repo_root>` / `<app_root>`, `<escalate>` = the park-and-yield clarification reroute (stated in full in that section's `### <escalate> — the clarification reroute`), `<per_unit_review>` = `off`, `<committer_push>` = `push: true` — plus its surviving overrides: the residual worktree-relative reads (Override A), the global kill switch (Override B), the branch-statistics commit and its push (Overrides D / E), pause/resume + the flow-progress ledger (Override G), the docs phase (Override H), and the improvement-observations intake (Override I). Do not duplicate or reinterpret any of it here.

## Retaining improvement observations — read before step 1

Before you begin step 1, read **two passages and nothing else** in `${CLAUDE_PLUGIN_ROOT}/instructions/improvement_observations_instructions.md`: the **Retained during the run, written at the end.** bullet in `## Where it runs & the non-blocking rule`, and the whole of `## What the orchestrator may log — rules`. Both passages bind you from this point on, across **both** the planning half (step 5) and the implementation half (step 6). **Note only: write nothing.** The single write is `Override I`'s, at Phase D.

## Hard boundary

The flow ends at Phase D **"branch ready for review."** It must **never** merge to a branch in `<protected_branches>`, push to one, or open/push a PR. Two layers enforce this at the harness level — the `pre-push` git hook, and above it the plugin's `PreToolUse` protected-branch guard together with the generated permission profile's `Bash(git push:*)` **`ask`** entry, which is evaluated before any `allow` and which an unattended run cannot answer — and this command states the intent so the orchestrator never attempts it. The user does the final hands-on review and opens the PR out-of-band.

The flow **does** push its own **non-protected** worktree/feature branch to its upstream after each commit (via `<scripts_dir>/push-branch.sh`) — this is expected behaviour, not a boundary violation. The protected-branch prohibition above is unaffected and is enforced by `push-branch.sh` (it self-refuses a branch in `<protected_branches>`) plus the protected-branch guard.

## Note

Per-run statistics and the Done summary stay **per-worktree** (each run writes `<state_dir>/branch_statistics/<branch>/statistics.md` inside its own worktree); there is no cross-run roll-up. Worktree setup, the central run log, and exit notifications belong to the **watcher** (`<scripts_dir>/autonomous-watcher.sh`) — this command is unaware of them.
