# Scope: Run the current branch's user-review fix cycle end-to-end, autonomously (fix plan → fix implementation → branch ready for review)

## Resolved values

The tokens below are not ordinary **path placeholders** (`<branch>`, `<n>`, `<i>`, `<N>`, `<MAIN_REPO>`, which this file's own text resolves — `<MAIN_REPO>` in step 2): they resolve from the adopting repository's `harness.config.json`. They are declared here once, and after this table the body uses each one as an ordinary placeholder. The mode-contract **binding** names the body cites (`<terminal_handoff>`, `<existing_artifact_decision>`, `<escalate>` / `<ask>`, `<per_unit_review>`, `<committer_push>`, `<repo_root>`, `<app_root>`) are a third vocabulary: each is declared in its own fork's `## Mode contract — bindings` table, and this command only names the value that table carries. Two of them this command **supplies** — `<repo_root>` and `<app_root>` — and step 1 derives those at runtime, as `$REPO_ROOT` and `$APP_ROOT`. `<fix_plan_path>` and `<fix_finding_dir>` are a fourth case: they are resolved inside step 6's fix-plan loop and passed verbatim into step 7.

| Token | Class | How to resolve it |
|---|---|---|
| `<app_dir>` | config value | `appDir` — the app's directory inside the checkout, repo-relative. Step 1 builds `APP_ROOT=$REPO_ROOT/<app_dir>` from it, and that resolved root is the value both forks' `<app_root>` binding takes. |
| `<state_dir>` | config value | `stateDir` — the run-artifact tree every artifact path in this file is relative to. Default `sdlc-harness/`. It is never dot-named: no path segment of it may begin with a dot. |
| `<scripts_dir>` | config value | `scriptsDir` — the directory the outer-loop scripts live in. This file names two of them — `autonomous-watcher.sh`, as the owner of the responsibilities this command deliberately does not have, and `push-branch.sh`, in the hard boundary — and invokes neither. |
| `<default_branch>` | config value | `defaultBranch` — the branch work starts from and merges back into. Never a remembered branch name. Bound for completeness — no step in this file consumes it. |
| `<protected_branches>` | config value | `protectedBranches` — the branches the hard boundary below forbids merging into, pushing to, or opening a PR against. The effective set is these together with `<default_branch>`. The `pre-push` git hook enforces that set; above it, the plugin's `PreToolUse` protected-branch guard together with the generated permission profile's `Bash(git push:*)` **`ask`** entry — evaluated before any `allow`, and unanswerable in an unattended run — is the best-effort layer. |
| `<reference_impl>` | config value | `parity.referenceImplPath` — the path to the reference implementation this project is kept in parity with. The parity reviewers' reads resolve from it, and **only** when `phases.parity` is `true`. |

## Context

This is the **one** autonomous **user-review-fix** engine command. It is the **execution-context-agnostic** entry point that chains autonomous **fix-plan writing** straight into autonomous **fix implementation** in one uninterrupted session, ending at "branch ready for review" — **no** approval gate between the fix plan and the fixes, and **no** merge into a branch in `<protected_branches>`, no push to one, and no PR at the end.

It reuses the shared instruction canon by reference and only forks where the autonomous flow genuinely differs (approval gate, clarification channel, path resolution, resumability). That canon is a **mode-free core** on both halves — `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fix_plan_writing_instructions_core.md` for **fix-plan writing** and `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fixes_instructions_core.md` for **fix implementation** — with a thin autonomous fork over each.

- **Fix-plan writing** runs the autonomous fix-plan fork `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fix_plan_writing_instructions_autonomous.md` — the **mode-free fix-plan core** (`${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fix_plan_writing_instructions_core.md`: `## Flow` steps 1–8 and step 11 — review-file discovery, round-suffix resolution, the writer prompts, the business-parity gate, the architecture gate and their 5-iteration caps — plus `## Convergence` and `## Context discipline`) run verbatim by reference. Its deltas are its **binding values** — `<terminal_handoff>` = no approval gate (emit the convergence summary and fall straight through), `<existing_artifact_decision>` = the non-interactive cases stated in `## Override 2 — resumability`, `<escalate>` / `<ask>` = the headless clarification reroute, worktree-relative `<repo_root>` / `<app_root>` — plus what this mode purely adds: the fix-plan + source-review commit at convergence (Override 3), the pause/resume + flow-progress ledger (Override 4), the ask-vs-assume policy it carries by reference, and the safety scaffolding the core states none of.
- **Fix implementation** runs the autonomous fix fork `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fixes_instructions_autonomous.md` — the **core's** Phases A → QA → D (`${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fixes_instructions_core.md`, whose implement → [review] → commit unit loop is canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md` row `UR-A` and whose QA loop is canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_core.md` → `## Phase E — QA testing`) verbatim by reference. Its deltas are its **binding values** — worktree-relative `<repo_root>` / `<app_root>`, `<escalate>` / `<ask>` = the park-and-yield clarification reroute, `<per_unit_review>` = `on`, `<committer_push>` = `push: true` — plus the overrides that remain pure additions: the worktree-relative reads those two path bindings do not cover (A), the global kill switch (B), the post-user-review statistics commit and its push (D / E), the pause/resume + flow-progress ledger (G), the docs phase (H), and the improvement-observations intake (I).

You are the **orchestrator** for the whole session. You do not draft the fix plan, you do not review it, you do not edit code, you do not commit — you dispatch the specialist agents the two instruction files name and read only the short contracts they return.

**This command is execution-context-agnostic.** Worktree handling (reuse-else-recreate), central logging, and exit notification are the **watcher's** responsibility (`<scripts_dir>/autonomous-watcher.sh`), NOT this command's. This command assumes it is already running in the correct checkout (a worktree or the main repo) and resolves every path relative to that checkout. It does not create worktrees, write to a central log, or send notifications.

## Two entry points, one engine

The same command serves both entry points — there is **no** separate `-watch` command (to "watch" is simply to run this engine interactively):

- **(a) Manual / interactive** — the user invokes `/autonomous-sdlc-harness:branch-start-user-review-fix-autonomous` themselves on the branch and watches the heartbeat live (`[fix-plan-write · iter <i>]` lines from the fix-plan loop, then the fix loop's `[A · Item <N> · <layer> · iter <i>]` and `[QA · …]` heartbeats, whose format and examples are canonical in `user_review_fixes_instructions_core.md` → `## Safety contract — applies before EVERY Agent dispatch` step 3 and its `## Phase QA — UI-test augment + QA loop`). This is the de-risking validation point and is simplest in the **main** worktree on the current branch, where every path anchor already matches. Clarification questions surface **live** for inline answering (supervised behavior).
- **(b) Watcher / headless** — the watcher (`<scripts_dir>/autonomous-watcher.sh`) launches this same command with `claude -p` plus the generated permission profile via `--settings`, inside the branch's worktree. A park's clarification questions are written together to one `<state_dir>/clarifications/<branch>/question_<n>.md`, the run yields, and the watcher marks it `parked` and resumes once that file is answered.

A thin `-watch` wrapper is acceptable **only** if it adds ergonomics (e.g. "run in the current worktree, skip the watcher") and contains **no** duplicated orchestration. Default to not adding one.

## Steps

1. **Derive the worktree-relative anchors once, at session start, and use them everywhere — never hardcode an absolute machine path:**
   - `REPO_ROOT=$(git rev-parse --show-toplevel)` — the current checkout's root (the worktree, or the main repo in the manual entry point). Obtain it with a **bare** `git rev-parse --show-toplevel` and build every literal path from the result; never embed the `$(…)` substitution inside another shell command, and never stash it in a shell variable across separate Bash calls — separate calls do not share shell state.
   - `APP_ROOT=$REPO_ROOT/<app_dir>`.
   These flow into **both** instruction forks as their `<repo_root>` / `<app_root>` binding values: the fix-plan fork's (whose Override 3 / Override 4 wrapper calls name their `<scripts_dir>` scripts repo-relative and run from `$REPO_ROOT`), and the fix fork's (every project command the flow runs — type-check, tests, the dev server — is invoked through its configured `commands.*` string in `harness.config.json` **exactly as written**, from `$REPO_ROOT` (each configured string and each wrapper path is repo-relative, so running either from `$APP_ROOT` would resolve a nested `<app_dir>` twice), never rebuilt from its parts and never replaced by an absolute path; if a configured string is **refused**, the key holds a raw command line rather than the wrapper invocation, so the run uses `bash <scripts_dir>/<name>.sh`, whose body is the line `init` inlined into it and not necessarily the configured string, and the fork reports which string it ran) plus its `## Override A` (the raw package-manager / dev-server prohibition, and the parity reviewers' reads, which resolve from `<reference_impl>` and **only** when `phases.parity` is `true`).

2. **Global kill switch — check at session start.** If `<MAIN_REPO>/<state_dir>/AUTONOMOUS_STOP` exists (the global switch in the **main** repo, distinct from the per-run `<state_dir>/STOP` inside this worktree), halt immediately and report it. Do NOT delete it — the user controls it. (`<MAIN_REPO>` is the main worktree's root — the first entry of `git worktree list` (`git worktree list --porcelain | head -1 | sed 's/^worktree //'`), or the watcher-supplied env in the headless entry point.)

3. **Determine the current git branch** with `git branch --show-current` → `<branch>`.

4. **Confirm at least one user-review file exists** for the branch:

   ```zsh
   ls $REPO_ROOT/<state_dir>/user_reviews/ | grep -E '<branch>_review(_[0-9]+)?\.md$'
   ```

   If no match: stop and tell the user to write the review file first at `<state_dir>/user_reviews/<branch>_review.md` (manual — point them at `${CLAUDE_PLUGIN_ROOT}/samples/sample_user_review.md` for the format), or write the blocker to the clarification channel and yield (headless).

5. **Tree-state precondition.** Halt if any **tracked** file is modified — i.e. any `git status --short` line **not** beginning with `??` — because uncommitted prior-run edits must not be swept into a fix commit. Untracked files under `<state_dir>/` (the dropped review file, fix-plan files from a parked run) are **expected** and are committed by the flow's normal commits — do NOT treat them as a dirty tree. On halt: report it (manual) or write the blocker to the clarification channel and yield (headless).

**Run mode — preflight, after step 5 and before step 6.** The branch's task prompt at `$REPO_ROOT/<state_dir>/task_prompts/<branch>_task_prompt.md` **may or may not exist** for a user-review round; where it does not, not even the grep runs and there is **no run mode** — a normal outcome, not an error, and not a defect to report. Where it does, run `grep -nE '^#+ *Run mode' $REPO_ROOT/<state_dir>/task_prompts/<branch>_task_prompt.md`. **No hit → this run has no run mode**: carry `none` into the loop below, emit `📌 Run mode: none` at the disclosure site, and do not open `${CLAUDE_PLUGIN_ROOT}/instructions/run_mode_instructions.md`. **A hit →** read `${CLAUDE_PLUGIN_ROOT}/instructions/run_mode_instructions.md` and follow it; it owns everything else, and none of it is restated here.

6. **Fix-plan loop.** Read `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fix_plan_writing_instructions_autonomous.md` and follow it. It is this flow's **fork**, and it is the autonomous fix-plan entry point: the loop body is the core's — `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fix_plan_writing_instructions_core.md` `## Flow` steps 1–8 and step 11 (round resolution, the writer prompts, the business-parity and architecture gates and their 5-iteration caps), `## Convergence` and `## Context discipline`, all run verbatim by reference. The fork's deltas are the values in its `## Mode contract — bindings` table — `<terminal_handoff>` (no approval gate), `<existing_artifact_decision>` (the non-interactive cases stated in `## Override 2 — resumability`), `<escalate>` / `<ask>` (the headless-vs-manual clarification reroute), worktree-relative `<repo_root>` / `<app_root>` — plus Override 3 (the fix-plan + source-review commit at convergence), Override 4 (pause/resume + the flow-progress ledger), the ask-vs-assume policy it carries by reference, and the safety scaffolding. Do not duplicate or reinterpret any of it here. When **both** gates PASS, the fix plan has converged — and per the core's `## Convergence`, a gate that never ran counts as passed for this condition: with `phases.parity` `false` the business-parity gate never runs and convergence is the architecture gate's PASS alone, and a gate the run mode excluded is likewise passed by exclusion. There is **no** approval gate: emit the convergence summary as a log line and **fall straight through** to step 7 in the same session.

7. **Fix-implementation loop.** Read `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fixes_instructions_autonomous.md` and follow it, passing the resolved `<fix_plan_path>` (index) and `<fix_finding_dir>` (per-finding folder) for the **active round** — the round-suffix resolution already happened in step 6's fix-plan loop; pass its result. The implementation fork does **not** re-resolve the round. It is this flow's **fork**, and it is the autonomous fix-implementation entry point: the phase bodies are the core's — `${CLAUDE_PLUGIN_ROOT}/instructions/user_review_fixes_instructions_core.md` Phases A → QA → D run verbatim by reference, with the unit loop canonical in `${CLAUDE_PLUGIN_ROOT}/instructions/unit_loop_core.md` (row `UR-A`) and the QA loop in `${CLAUDE_PLUGIN_ROOT}/instructions/plan_orchestration_instructions_core.md` → `## Phase E — QA testing` (E.0–E.4). The middle phase is gated: **Skip this phase unless `phases.qa` is `true` in `harness.config.json`.** Phases A and D run either way. The fork's deltas are the values in its `## Mode contract — bindings` table — worktree-relative `<repo_root>` / `<app_root>`, `<escalate>` / `<ask>` = the park-and-yield clarification reroute (stated in full in that section's `` ### `<escalate>` / `<ask>` — the park-and-yield clarification reroute ``), `<per_unit_review>` = `on`, `<committer_push>` = `push: true` — plus its surviving overrides: the residual worktree-relative reads (Override A), the global kill switch (Override B), the post-user-review statistics commit and its push (Overrides D / E), pause/resume + the flow-progress ledger (Override G), the docs phase (Override H), and the improvement-observations intake (Override I). Do not duplicate or reinterpret any of it here.

## Hard boundary

The flow ends at Phase D **"branch ready for review."** It must **never** merge to a branch in `<protected_branches>`, push to one, or open/push a PR. Two layers enforce this at the harness level — the `pre-push` git hook, and above it the plugin's `PreToolUse` protected-branch guard together with the generated permission profile's `Bash(git push:*)` **`ask`** entry, which is evaluated before any `allow` and which an unattended run cannot answer — and this command states the intent so the orchestrator never attempts it. The user does the final hands-on review out-of-band; their feedback arrives as the next round's `<state_dir>/user_reviews/<branch>_review_<n+1>.md` drop.

The flow **does** push its own **non-protected** worktree/feature branch to its upstream after each commit (via `<scripts_dir>/push-branch.sh`) — this is expected behaviour, not a boundary violation. The protected-branch prohibition above is unaffected and is enforced by `push-branch.sh` (it self-refuses a branch in `<protected_branches>`) plus the protected-branch guard.

## Note

Per-run statistics and the Done summary stay **per-worktree** (each run writes `<state_dir>/branch_statistics/<branch>/statistics.md` inside its own worktree); there is no cross-run roll-up. Worktree setup, the central run log, and exit notifications belong to the **watcher** (`<scripts_dir>/autonomous-watcher.sh`) — this command is unaware of them.

**Round-aware by inheritance:** a dropped `<branch>_review_2.md` drives `<branch>_fix_plan_2.md` / `<branch>_fix_plan_2/` via the shared fix-plan core's latest-round resolution (canonical in `user_review_fix_plan_writing_instructions_core.md`, `## Flow` steps 2–3) — never re-implemented here.

**Manual smoke validation (after installing the plugin):** invoke `/autonomous-sdlc-harness:branch-start-user-review-fix-autonomous` interactively on a branch with a `<branch>_review.md` present and confirm it resolves the round, runs both gates, and proceeds straight into fix implementation without an approval pause.
