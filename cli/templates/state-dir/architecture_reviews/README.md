# architecture_reviews/

One `<branch>/review_<n>.md` per planning **round**, holding the plan-gate architecture review of the task plan: written by the architecture reviewer and read by the plan writer on the next round, together with every other gate's file of that round. One `<branch>` subdirectory holds one branch's set. `<n>` is the round number, shared by every plan gate's folder, so round `<n>`'s file here sits at the same index as its file in `task_plan_reviews/`; every reviewer runs in every round, so the numbers in one directory are consecutive and a gap is a file that went missing.

What is under review is the **task plan** — the story index's `## Context` plus every per-task file — and the lens is layer placement and dependency direction only: where each described file would land, which layer owns each responsibility, which way imports cross a boundary, judged against the conventions documents the configured layers name. The reader is the plan writer, which applies the Must Fix items to the story index or to the per-task files the findings name. The reviewer writes its file on `PASS` as well as on `FAIL`, and each file carries exactly one `verdict:` line, so a file is no longer a failed round: the rounds this gate failed are its `verdict: FAIL` lines.

Files stop when the loop ends — at a round every gate passed, or at the fifth round, where the gate escalates and reports the closing round's paths. A file is replaced only by its own reviewer re-running a round that was interrupted; otherwise nothing supersedes an earlier file, the accumulated set is the record of how the plan's architecture converged, and the whole directory is committed with the branch, since no ignore rule reaches it.

The mistake worth naming is justifying a deliberate architecture decision anywhere but in the plan itself. This gate returns FAIL — and so sends the round back to the writer — whenever it raises **any** gating finding, and it verifies a claimed exception rather than accepting it: it opens the authorization the justification cites and confirms that authorization is real and actually licenses the deviation. A decision defended only in the writer's head, or in a note the plan does not carry, therefore comes back every round and the loop ping-pongs to the cap over a call that was fine. The justification has to be in the plan for the gate to close.
