# architecture_user_review_reviews/

One `<branch>/user_review_<N>/review_<k>.md` per fix-plan **round**, holding the architecture reviewer's plan-gate review of a hands-on-review fix plan rather than of a task plan. One `<branch>` subdirectory holds one branch's set, and one `user_review_<N>/` subfolder inside it holds one user-review round's: `<N>` is the user-review round, `1` for the unsuffixed review, so a later user-review round's files never land on an earlier one's. `<k>` is the fix-plan round, shared by both fix-plan gates' folders, so round `<k>`'s file here sits at the same index as its file in `business_parity_user_review_reviews/` when that phase is on. The fix-plan index plays the role the story index plays at the task-plan gate, and its per-finding folder the role of the per-task files. The round number names the file; the loop's cap counts only the rounds since the last writer dispatch that was not a findings revision or since a resumed session's start, and never names a file — so a resumed session, or a re-entered gate, adds files beside the earlier ones and writes over none of them.

The writer is the architecture reviewer, the same agent and the same layering lens that grades a task plan into `<state_dir>/architecture_reviews/`; it is told which of the two it is holding by the paths it is passed, never by a flag. The reader is the fix-plan writer, re-dispatched in revision mode with every file of the round — this gate's and the parity gate's — and expected to apply their Must Fix items to the fix-plan index or to the per-finding files they name. The reviewer writes its file on `PASS` as well as on `FAIL`, and each file carries exactly one `verdict:` line, so a file is no longer a failed round: the rounds this gate failed are its `verdict: FAIL` lines.

The gate sits early: the drafted fix plan is graded **before** anyone approves it and before a single one of its fixes is implemented. Files stop at a round every gate passed or at the fifth round, where the flow escalates with the closing round's paths. A file is replaced only by its own reviewer re-running a round that was interrupted; otherwise no file supersedes an earlier one, and the numbered set is the gate's **whole** history for that user-review round. The whole directory is committed with the branch, since no ignore rule reaches it: the autonomous flow commits at each round's end, and the supervised flow names the files for the human's commit.

The mistake worth naming is writing for the orchestrator. The flow deliberately does **not** read this file to judge the review's quality; it parses the verdict line, and at the round's end it hands the paths straight to the fix-plan writer's revision dispatch. So the only consumer of the prose is that writer, and a finding stated as an observation rather than as a concrete change to a named plan file gives it nothing to apply — the gate fails again on the same point, and nothing in the loop notices why.
