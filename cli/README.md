# autonomous-sdlc-harness (cli)

```bash
npx autonomous-sdlc-harness init                              # wire a repository, in one deterministic pass
npx autonomous-sdlc-harness doctor                            # re-check a wired one; the exit status is the contract
npx autonomous-sdlc-harness config list | get <key> | set <key> <value>
npx autonomous-sdlc-harness daemon <install|start|stop|list>
npx autonomous-sdlc-harness docs <index|search <query>|serve|fetch-models>   # opt-in; needs docs.retrieval on
```

Node `>=20.11.0`. Licence Apache-2.0 — `LICENSE` and `NOTICE` ship beside this file. Every command takes `-h`, `-v`, `--dry-run`, `--force`, `--quiet` (progress narration only — results, warnings and failures still print), `--non-interactive` and `--cwd <path>`, and exits `0` (did what it was asked), `1` (a refusal or a failed check, `doctor` FAIL included) or `2` (an internal fault). What each command writes, the `init` re-run contract, the stack-detection table, the enumerated `doctor` checks and the failure modes the generated permission profile encodes are in [`docs/cli.md`](https://github.com/firu-daniel/autonomous-sdlc-harness/blob/main/docs/cli.md) — which the published tarball does not carry, so every repository link on this page is an absolute URL.

The npm package that carries the harness's **outer loop** — `init`, `doctor`, `config` and `daemon` — and `docs`, the opt-in docs-retrieval search over the docs catalog and conventions documents. The process assets those runs execute — agents, slash commands, hooks, instructions and samples — are not here; they ship as the sibling `plugin/` Claude Code plugin. This package exists at all because a plugin cannot write a repository's `settings.json`, and getting that permission profile right is the highest-friction part of adoption. Installing that plugin is a step of its own, separate from installing this package — see the harness root [`README.md`](https://github.com/firu-daniel/autonomous-sdlc-harness/blob/main/README.md) `## Quick start` for the lettered sequence an adopter runs.

**What the five subcommands do.** `init` wires an adopting repository in one deterministic pass: it detects the stack, then writes the configuration, the wrapper scripts, the run-artifact tree, the conventions stubs, the permission profile, the committable project settings, the repository-root files and the pre-push hook — creating what is absent and keeping what the adopter has edited. `doctor` re-checks a wired repository — git and worktrees, that the configured default branch still resolves, the daemon backend, the configuration, the state directory, the ignore rules, which notification settings file the notifier resolves, whether this checkout is in the machine-local registry of installed daemons, the plugin wiring and the permission profile — and reports every finding, with the exit status as the contract; [`docs/cli.md`](https://github.com/firu-daniel/autonomous-sdlc-harness/blob/main/docs/cli.md) §7 is the enumerated list and the severity each check carries. `config` reads and updates one dotted key of `harness.config.json` at a time, refusing a key the file may not carry and backing the file up before each write. `daemon` installs, starts and stops this repository's run daemon on whichever service manager the host has, and lists the repositories on this machine one has been installed for. `docs` builds and queries a local search index over `docs.root` and the conventions documents, and serves it over stdio MCP as `search_docs` when `docs.retrieval` is on. It is **off by default** and opt-in: measured once against agent navigation on a real 1,960-chunk catalog, its verdict was **withdrawn**, and it is kept opt-in by maintainer decision — [`docs/retrieval-eval-results.md`](https://github.com/firu-daniel/autonomous-sdlc-harness/blob/main/docs/retrieval-eval-results.md) → *The decision, applied to the real catalog*; the verb is in [`docs/cli.md`](https://github.com/firu-daniel/autonomous-sdlc-harness/blob/main/docs/cli.md) and the design in [`docs/retrieval.md`](https://github.com/firu-daniel/autonomous-sdlc-harness/blob/main/docs/retrieval.md).

Five decisions are recorded here so they are not re-litigated later:

- **No lockfile of its own.** `cli/` is a workspace member and the single `package-lock.json` lives at the harness root — npm workspaces resolve and hoist from the root lockfile by design, so a second lockfile inside a member is ignored by the root install and silently drifts. The package stays independently publishable with `npm publish --workspace cli`.
- **Node floor `>=20.11.0`.** Node 18 is past end-of-life and 20.11 is the first Node 20 LTS carrying `import.meta.dirname` / `import.meta.filename`, which a template-copying ESM CLI wants; Node 22 and 24 satisfy the same floor, and raising it to 22 would exclude LTS users for no capability this CLI needs.
- **`files` carries `LICENSE`, and `cli/LICENSE` is a byte-copy of the root one.** npm auto-includes a licence only from the package root, so a tarball built from this directory would otherwise declare `"license": "Apache-2.0"` and contain no licence text — which Apache-2.0 §4(a) does not allow, since every recipient of the Work must receive a copy. The duplication is the cost of publishing a workspace member as its own package; nothing enforces the two copies' identity, so a change to the root `LICENSE` is a `diff ../LICENSE LICENSE` against this one.
- **Never shell out to `rm -rf`.** A user-level `permissions.deny` rule on it is realistic, deny is evaluated before any allow and cannot be overridden, so a teardown implemented as a shelled-out `rm -rf` is silently blocked with no useful error. Use Node's in-process `fs.rm` for every removal.
- **The run watcher's path is derived from `scriptsDir`, not a config key of its own.** `init` writes the watcher into the configured scripts directory with the rest of the outer-loop set, so `daemon` resolves it as `<repoRoot>/<scriptsDir>/autonomous-watcher.sh`: `scriptsDir` is the one key that moves it, and a second key naming the same location could only ever disagree with it. That also keeps the unit's `ExecStart` inside the repository its `WorkingDirectory` names — a CLI run through `npx` lives in a cache directory that can be evicted under a long-running service. `--watcher` overrides the resolution for developing against a watcher that is not the written one. (This decision replaces an earlier package-relative one; `scripts/README.md` records why.)

TypeScript in `src/` compiles with `tsc` to `dist/`, which is what `bin` points at; `templates/` holds generator templates and is deliberately outside the compiler's `include`. Two families live there: the **wrapper** scripts `init` renders from a detected command line, and the **outer-loop** shell assets — the run watcher, its restart wrapper, the notifier and its stream formatter, the commit / push / branch-refresh / worktree / cleanup wrappers, the docs-retrieval server launcher and the library they share — which `init` copies verbatim into the same `scriptsDir` because each reads `harness.config.json` at run time. `scripts/` keeps only the daemon unit templates the `daemon` subcommand renders into the account's home directory; it is likewise uncompiled and carried into the published tarball by `files` alongside `templates/` (`scripts/README.md` records why the outer-loop set is not there). A watcher that is missing — deleted, or left behind when `scriptsDir` moved — is a `doctor` warning and a `daemon install` refusal, repaired by re-running `init`.
