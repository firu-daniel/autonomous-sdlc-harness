# The `cli` layer

> **Read this when:** the change you are implementing or reviewing lands under `cli/` — the npm package `autonomous-sdlc-harness` and the template trees it ships. **Skip when:** it lands under `plugin/` or anywhere else at the root; each has its own document, and the rules that span all of them are in `.claude/context/conventions.md`, which this file assumes has been read.

**Purpose.** The rules this layer's implementer and its reviewer both read before they start. Read the cross-layer document first: it owns the stack, the no-runtime-dependency rule, the module monopolies, the shared-constant owners, the `Reporter` and error contracts, the testing bar and the commit-message policy. What follows is this layer's own rules and its own consequences of those.

## What this layer owns, and what it is not

- **Owns:** `cli/src/` (this tool's behaviour), `cli/templates/` (the files `init` writes into an adopting repository), `cli/scripts/` (the daemon unit templates the CLI renders into the operator's home), `cli/test/`, and the package's own manifest and licence files.
- **Is not:** the process assets. Agent, command, instruction and hook contracts are the `plugin` layer's. A task that has drifted into writing prose an agent reads, or into changing a dispatch contract, has left this layer.
- **Is not:** the configuration contract's first home. A new `harness.config.json` shape starts in `schemas/`, which belongs to `general`; the model, the check and the generator here are downstream of it (`.claude/context/conventions.md` → `### The order files are created…`).

**Settle which audience a file serves before editing it.** `cli/src` changes what this CLI does in this checkout. `cli/templates` and `cli/scripts` change what a *future adopter* receives and change nothing here — an edit there is invisible to this repository's own tests until a fixture runs `init`. (`cli/src/generators/claudeContext.ts` → choice 1; `cli/templates/README.md`)

## Dependencies, and which way they point

- **The no-runtime-dependency rule, its reason and its cost are the cross-layer document's** (`## The stack…`, second bullet, with its docs-retrieval carve-out in the third). The consequence here: outside that carve-out, a problem that would ordinarily be solved by reaching for a package is solved by a hand-written module under `cli/src/core/`, and that module's header argues why it is small enough to own (`cli/src/core/prompt.ts`, `cli/src/cli.ts` → `GLOBAL_OPTIONS`).
- **Where the shared floor is and what belongs on it is the cross-layer document's** (`## Shared code, and where it lives`). The consequence here: where a `core/` module needs a shape declared above it and needs no runtime edge, it imports it with `import type` so the edge is erased at compile time (`cli/src/core/prompt.ts` → `GlobalFlags`, `cli/src/core/layerGapRemedy.ts` → `HarnessLayerReview`).
- **A command module imports its own types back from the table that lists it, type-only**, so the table can carry a real row without a runtime import cycle (`cli/src/commands/registry.ts` header; every module under `cli/src/commands/` follows it).
- **`cli/templates/` is outside the compiler.** `cli/tsconfig.json` includes `src/**/*.ts` only, so nothing under `cli/templates/` or `cli/scripts/` is type-checked or bundled; both reach the **published tarball** through the package's `files` field (`cli/package.json` → `files`). Only `cli/templates/` is written into an adopting repository; `cli/scripts/` is read out of the installed package (`cli/scripts/README.md`).

## Naming and file layout

- **The name patterns for a source module and for a test suite are the always-loaded project file's** (`.claude/CLAUDE.md` → `## File naming conventions`, rows *CLI source module* and *CLI test suite*). The rule this layer adds: **an area names one responsibility, and a module lives in the area whose responsibility it serves — a responsibility none of them names gets its own area rather than being forced into one.** The vocabulary in use: `commands/` (one verb each), `config/` (the model, its check, its io), `core/` (shared), `detect/`, `doctor/`, `generators/`, `machine/`, `daemon/`.
- **A new responsibility gets its own module with its own header rather than widening a neighbour** where the boundary is what makes it correct — `cli/src/detect/nestedApplication.ts` is a module rather than a branch of `cli/src/detect/signals.ts` precisely because nothing may be derived from its answer.
- **Every file under `cli/src/` opens with a module header** stating what it owns, and — where it exists to hold a rule — that rule in the words *"The rule this module exists to enforce"*. `cli/src/cli.ts`'s follows its shebang. The cross-layer document lists this among what accompanies a new unit; here it is also how a reviewer finds the rule a change may be breaking.
- **A template whose adopter-side name begins with a dot is stored without the dot**, and `init` adds it: `cli/templates/repo/gitignore` is written as `.gitignore`. A real dot-named file in this tree would be honoured by git here, and npm rewrites a packaged `.gitignore` on publish (`cli/templates/README.md`).
- **One template subdirectory per adopter-side home** — `claude/`, `repo/`, `githooks/`, `scripts/`, `state-dir/`. A template landing somewhere none of them names gets a new subdirectory rather than being forced into one of these (`cli/templates/README.md`).
- **`cli/scripts/` holds the daemon unit templates and nothing else** — they are the one rendered artifact that never lands in an adopting repository (`cli/scripts/README.md`).

## How a module in this layer is written

**Commands order and report; they decide nothing.** Every value a command writes comes from detection or from a generator, and every byte reaches the filesystem through one write plan applied once at the end. That is what makes `init` reproducible — a second run over the same repository produces the same result, and an adopter can re-derive the recorded preset from the detection table by hand. A mutation that cannot be enqueued is guarded explicitly at its own call site rather than covered by the plan's structure (`cli/src/commands/init.ts` → choice 1). Judgement-dependent work — reading real code to refine a layer profile, filling a conventions stub — belongs to the analyze command and is deliberately absent from this layer.

**A generator plans; it never performs.** The write engine's monopoly on writing into an adopting repository, and what a generator does instead, are the cross-layer document's (`### Where a new responsibility goes`). The consequences here: a generator may *read* the filesystem to decide but may not mutate it, so `--dry-run` cannot leak a write whatever a generator enqueued; and `WritePolicy`'s values are the whole vocabulary — a generator wanting different behaviour is asking for a different re-run contract, which is a decision for `cli/src/core/writer.ts`'s table and not for the call site.

**A generator that renders a template states and argues its `assertNoneSurvive` setting in its own header.** On means a substituted value carrying `{{…}}` is a fault; off means it is content. Both are in use and each is justified where it is set (`cli/src/generators/claudeContext.ts` and `cli/src/daemon/units.ts` argue *on*; `cli/src/generators/scripts.ts`, `cli/src/generators/repoRoot.ts`, `cli/src/generators/githooks.ts` and `cli/src/generators/permissionProfile.ts` argue *off*). The token syntax and the every-token-has-a-value check have one definition, `cli/src/core/templating.ts`, and the check scans the **template** rather than the output.

**Detection yields evidence, never a judgement.** `cli/src/detect/signals.ts` is pure file-existence and top-level manifest-key inspection, evaluated first-match-wins, and its table is exported as data so the documentation shows the rows the code evaluates. Nothing may be invented: a command that cannot be derived from a manifest that exists becomes the placeholder plus a warning naming what was looked for, never a plausible guess (`cli/src/detect/presets.ts` → `placeholderCommand`, `undetectedCommandWarning`).

**One string, one producer.** `cli/src/generators/scripts.ts` → `scriptInvocation` is the single producer of `bash <scriptsDir>/<file>`; the generated config, the wrapper file and the generated permission profile are three views of that one string, and drift between them is invisible until an unattended run stalls. A raw command line is `cli/src/detect/presets.ts`'s and is never a wrapper invocation. The shipped tables are single declarations of their sets and are read rather than copied: `WRAPPER_SCRIPTS` (`cli/src/generators/scripts.ts`), `OUTER_LOOP_SCRIPTS` (`cli/src/generators/outerLoopScripts.ts`), `STATE_DIR_ENTRIES` (`cli/src/generators/stateDir.ts`), `SIGNALS` (`cli/src/detect/signals.ts`), `CHECKS` (`cli/src/doctor/checks.ts`). A `.sh` name spelled as a string literal elsewhere in this layer is a second source for one of these tables **where it is resolved, joined or read as a path**. A name that appears only inside a message is permitted, and argues the boundary in its own doc comment (`cli/src/doctor/checks.ts` → `WORKTREE_SCRIPT`, `REFRESH_SCRIPT`).

**`doctor` asks, grades and repairs nothing.** Every check runs whatever the earlier ones answered, a thrown value becomes that check's own failure, and nothing it reports is re-derived from a second copy — the backend, the state-directory list, the ignore-rule spellings, the registry reader and the writability probe are all imported from the module that owns each (`cli/src/doctor/checks.ts` → choice 1). Grading is the contract: a `fail` means the flow cannot run as configured, a `warn` means something is worth fixing and nothing stops, and the exit status is a statement about whether the repository is *runnable*.

**Every child process is spawned with a fixed argument vector — never a shell string, no `shell: true`, no pipeline.** A path containing a space or a quote cannot become two arguments, and a compound command is not something an unattended run's permission profile can allow-list as one literal (`cli/src/core/git.ts` → the header's invariant 1; `cli/src/daemon/backend.ts` → the header's invariant 1). `execFileSync` is the form; `cli/src/commands/doctor.ts` → `runNotifier` uses `spawnSync` for the one reason its own header states, capturing a child's stderr on a zero exit. A **host** probe is additionally bounded and its output discarded (`cli/src/daemon/backend.ts` → the header's invariant 2); a git probe returns its trimmed stdout to its caller (`cli/src/core/git.ts` → `runGit`).

**The `Reporter` is constructed once, in `cli/src/cli.ts`, and reaches a module on `CommandContext.report` or as an explicit parameter.** A module that needs to say something takes a reporter; it does not make one. The output-surface rule itself is the cross-layer document's (`## Output, logging and errors`).

**A fault in this CLI or in its shipped assets throws through `internal()`**, not `new HarnessError(…, EXIT.INTERNAL)`; an adopter-fixable condition throws an ordinary `HarnessError`. Where a value could be either, screen the adopter-fixable shape **first** with the ordinary code and a message naming the value to change, so only what survives that screen is reported as this CLI's fault (`cli/src/generators/permissionProfile.ts` → `assertRepositoryValuesUsable`, `assertRunnable`).

**Every interactive decision has three parts: a flag that supplies the answer, a documented non-interactive default, and a prompt shown only when the flag was absent and both descriptors are a TTY.** A run that cannot be prompted takes the default and never blocks. No prompt may exist without its flag and its default — a prompt whose answer has no flag makes an unattended run's result unreachable rather than merely defaulted (`cli/src/core/prompt.ts`).

**Machine-scoped state is not an adopter's file.** What this layer writes outside the repository it was aimed at is enumerated and each piece has one owner: the registry (`cli/src/machine/registry.ts`), the daemon unit (`cli/src/daemon/units.ts`), the push settings (`cli/src/generators/notifications.ts`). A read never creates a directory and never mutates machine state, and a record belonging to another program is navigated rather than validated (`cli/src/machine/paths.ts`, `cli/src/machine/plugins.ts`).

## What "done" means here

The cross-layer document owns the runner, the mocking substitutes and the full verification bar (`## The testing bar`). In this layer that resolves to:

- **A change to a command or a generator lands with a case that drives the compiled CLI against a throwaway fixture repository** built by the test under the system temp directory and torn down in process (`cli/test/helpers/fixture.mjs`).
- **What a detection row and a written artifact must each land with is the cross-layer document's** (`## What accompanies a new unit of each kind`). The one addition this layer carries: where a written artifact's policy is `create-if-absent`, a `--force`-takes-a-`.bak` assertion sits beside the idempotence one (`cli/test/init.test.mjs`).
- **A refusal is asserted on the bytes on disk, not on the message**: a refused write must leave the tree byte-identical, including the absence of a `.bak` for a write that never happened (`cli/test/config-command.test.mjs`).
- **No test loads, starts or stops a real background service, launches a browser or reaches the network** by default. A lifecycle is exercised through `--dry-run`, which computes against the real host and runs nothing.
- **A reviewer holds a change to its module's own header.** Where the header states a rule, the change either satisfies it or amends the header in the same edit — a header a review reads as a guarantee is worth exactly what the code under it still does.

## One example — the shape a rule takes here

> A generator that renders a template states its `assertNoneSurvive` setting in its own header and argues it, because both settings are correct somewhere and neither is a default worth inheriting. `cli/src/generators/claudeContext.ts` → `render` argues **on**: every value it substitutes is a path, a layer name or generated markup, none of which has any business carrying `{{…}}`, and one that did would ship a half-rendered always-loaded file. `cli/src/generators/scripts.ts` → `render` argues **off**: the value it substitutes is the adopter's own command line, which is allowed to contain braces, so failing on one would refuse a legal command. The shared renderer's pre-substitution check runs either way (`cli/src/core/templating.ts`), and the header is where a reviewer reads which fault the generator bought and which it declined.

## Not determined

- The application-UI questions a conventions document is normally asked — the localization accessor, the theming and sizing accessors, the shared components directory, the navigation module and its route and screen registries, the test-attribute convention an interactive test locates elements by and the shared helper that applies it — have no answer in this layer: it presents no user-facing surface for one to govern. The cross-layer document records the determination for the repository as a whole and what would settle it; nothing is added here.
- Whether a module under `cli/src/core/` may import a **value** (rather than a type) from an area above it is not stated as a rule. `cli/src/core/layerCoverage.ts` imports `DEFAULTS` and `LAYER_CATCH_ALL_PATH` from `cli/src/config/model.ts`, and `cli/src/machine/registry.ts` imports `repoSlug` from `cli/src/daemon/units.ts`, while `cli/src/core/prompt.ts` and `cli/src/core/layerGapRemedy.ts` take theirs `import type`, with no header stating why. What would settle it: a stated layering rule in `cli/README.md` or in `cli/src/core/`'s modules saying which edges are allowed to be runtime ones.
- Whether a new suite under `cli/test/` must reuse a shared fixture helper or may define its own is not settled: `cli/test/stack-presets.test.mjs`'s header records that `fixtureFor` and `initOk` exist as file-local copies under two different signatures and that unifying them is a refactor it does not take. What would settle it: exporting one signature from `cli/test/helpers/fixture.mjs` and stating that new suites use it.
- Whether a new `Subcommand` must carry a `roadmapItem` is not settled: the field is optional in the interface (`cli/src/commands/registry.ts`) and every shipped command sets it from a module-local `ROADMAP_ITEM`. What would settle it: making the field required, or a line in that module's header saying it is provenance a command may omit.
